## Корень: чем приложение является

Корень объявляется `makeApp` и отвечает на один вопрос — из чего состоит
это приложение. Состав описывается ровно одной из трёх форм:

```typescript
// плоский слой провайдеров
makeApp({ endpoints: [ListUsers], providers: [UsersRepository] });

// тот же состав, уже разложенный модулями
makeApp({ endpoints: [ListUsers], modules: [UsersModule] });

// несколько единиц с именами
makeApp({ features: [UsersFeature, QuotasFeature] });
```

Смешать формы нельзя, и это проверяет тип: `endpoints:` рядом с
`features:` не компилируется. Первые две формы — состав одной фичи без
имени: её endpoint'ы и провайдеры получают метку `app`. Сервису из
нескольких маршрутов этого хватает, и `makeFeature` в нём не встречается.

## Провайдеры: то, что живёт в графе

Провайдер описывает, как получить значение для DI-токена: класс с ролью,
готовое значение, фабрика или ресурс. Экземпляры создаёт контейнер, а не
код приложения. Подробно — [6. Откуда хендлер берёт
репозиторий](./06-repository.md).

## Модули: группировка провайдеров под именем

Модуль — объект `makeModule({ name, providers, dependsOn })`. Контейнеру
он даёт ровно одно: метку принадлежности на узлах графа. Границей модуль
не является — видимость держится на экспортах ES-модулей, а не на списке
`exports`.

Модули нужны, когда провайдеров становится много и хочется читать граф
по частям. Приложению из десятка провайдеров они не нужны: плоский список
короче.

## Фичи: единицы выбора и границы

Фича — `makeFeature({ name, providers | modules, endpoints })`. Это
единица приложения, которая может оказаться в другом процессе, и отсюда
все её свойства:

- к фиче обращаются **операциями**, а не DI-токенами: DI-токен границу
  процесса не переживает, а операция переживает;
- фичу можно не включать в сборку — тогда её нет целиком: ни провайдеров
  в графе, ни endpoint'ов в транспортах;
- поля `dependsOn` у фичи нет: связь с соседями выводится из объявленных
  операций.

Сквозная инфраструктура — логирование, метрики, документация — фичей не
является: она есть в каждом процессе по определению. Её объявляет
`makePlugin` и перечисляет `plugins:` корня; к плагину обращаются
DI-токенами. Подробно — [13. Выделить вторую
область](./13-features.md).

## Переключатели: второе измерение состава

Выбор фич — одно измерение состава: какие области поднимает этот процесс.
Переключатель — второе: какой из вариантов одной и той же области.

```typescript
import { makeSwitch } from '@nestling/container';

export const Storage = makeSwitch('storage', ['s3', 'local']);

export const UploadsModule = makeModule({
  name: 'module:uploads',
  providers: [
    UploadsService,
    Storage.pick({ s3: [S3Client, S3Storage], local: [LocalStorage] }),
  ],
});
```

Обе ветки перечислены таблицей и читаются без выполнения кода: `check()`
видит их обе, и человек тоже. Словарь переключателей объявляет корень,
значение приходит аргументом сборки:

```typescript
export const app = makeApp({
  features: [UsersFeature, UploadsFeature],
  switches: [Storage],
  transports: [http()],
});

await app.assemble({ features: 'all', storage: 's3' }).run();
```

Инжектировать выбор нельзя: DI-токена у переключателя нет, и состав не
протекает в код приложения. Подробно — [17. Запускать только часть
фич](./17-select.md).

## Аргумент сборки: что собирает этот процесс

Декларация говорит, чем приложение является; аргумент сборки — что из
этого поднимает конкретный процесс. Формы: `'all'`, `'users,uploads'`,
`['users', 'uploads']` или объект `{ features?, includeDeps?, …значения
переключателей }`. Тип объектной формы выводится из `switches:`, поэтому
опечатка в имени переключателя не компилируется.

Читает аргумент пользовательский код — обычно из секции конфига, до
контейнера:

```typescript
const cfg = load(RootConfig); // { features: 'all', storage: 's3' }

await app.assemble(cfg).run();
```

## Split: следствие, а не отдельный механизм

Когда фичи разъезжаются по процессам, меняется только аргумент сборки и
роль `intercom:` у объявленного транспорта. Код фич не меняется: они и так
общались операциями. Подробно — [18. Разнести фичи по
процессам](./18-split.md).

## Одна таблица

| Понятие | Что объявляет | Где перечисляется |
|---|---|---|
| endpoint | адрес, схемы, хендлер | `endpoints:` корня или единицы |
| провайдер | как получить значение для DI-токена | `providers:` корня, единицы или модуля |
| модуль | группировку провайдеров под именем | `modules:` корня или единицы, `dependsOn:` модуля |
| фича | единицу выбора и границу | `features:` корня |
| плагин | сквозную инфраструктуру | `plugins:` корня |
| переключатель | второе измерение состава | `switches:` корня |
