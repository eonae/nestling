# @nestlingjs/config.vault

Источник конфигурации поверх HashiCorp Vault: секрет KV v2 читается одним
запросом на фазе 0, а координаты хранилища приходят из другого источника —
например из `.env`.

> 🚧 Активная разработка, API может меняться.
> Дизайн: [`docs/design/config.md`](../../docs/design/config.md).
> Рецепт: [источники конфигурации](../../docs/recipes/config-sources.md).

## Установка

```bash
npm install @nestlingjs/config.vault zod
```

Клиента Vault пакет не берёт: запрос идёт штатным `fetch`. Рядом ставится
`zod`: схему своей секции пакет пишет им, и копия валидатора у него и у
приложения одна.

## Минимальный пример

```typescript
import { bind, defaultSources, makeApp } from '@nestlingjs/app';
import { vault, VaultConfig } from '@nestlingjs/config.vault';

export const app = makeApp({
  features: [OrdersFeature],
  transports: [http()],
});

await app.build().run({
  config: [
    bind(vault(VaultConfig, { retries: 2 }), { timeout: 3000 }),
    ...defaultSources,
  ],
});
```

Порядок списка — приоритет разрешения ключа: значение из Vault побеждает
значение из окружения. Очерёдность подъёма другая и выводится сама:
`VAULT_ADDR` и `VAULT_TOKEN` называет секция `VaultConfig`, поэтому Vault
поднимается после `env()` и `dotenv('.env')`, которые эти ключи покрывают.

## Экспорты

| Имя | Что это |
| --- | --- |
| `vault` | источник: секция координат аргументом, опции — вторым |
| `VaultConfig` | готовая секция координат с префиксом `vault` |
| `VaultCoordinates` | форма значений, которую требует `vault(section)` |
| `VaultOptions` | опции источника: `retries` |

Секция `VaultConfig` объявляет `VAULT_ADDR`, `VAULT_TOKEN` (`secret()`),
`VAULT_MOUNT` (умолчание `secret`) и `VAULT_PATH`. Приложение с двумя
хранилищами объявляет свою секцию любой формы, подходящей под
`VaultCoordinates`, и передаёт её тем же аргументом: ключи получат её
префикс.

`retries` — число дополнительных попыток при сетевом отказе и ответе
`5xx`; пауза начинается с 250 мс и удваивается. Ответы `401`, `403` и
`404` повтора не вызывают. Границу времени подъёма задаёт привязка опцией
`timeout`.

## Границы пакета

Аутентификация одна — заголовок `X-Vault-Token`. AppRole, Kubernetes и
AWS в пакет не входят: минимальный источник ходит с готовыми учётными
данными, а способ их получить остаётся за стендом.

Наблюдения за секретом нет: значение читается один раз на фазе 0 и живёт
в снимке, как у любого источника. Динамические секреты и продление аренды
пакет не поддерживает — обновление секрета доходит до процесса
перезапуском.

Движок читается один — KV v2 по пути `{mount}/data/{path}`. Ответ KV v1
отказывает подъём: у него нет рекорда `data.data`.
