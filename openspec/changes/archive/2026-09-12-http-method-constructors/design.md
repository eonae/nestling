## Context

`httpEndpoint` сегодня — функция с двумя перегрузками и статиком
`.implement` (`packages/nestling.transport.http/src/helpers.ts:443`).
Адрес объявляется полями словаря: `method: 'GET'` и `path: '/users/:id'`.
Литеральный тип пути выводится из свойства `path`, и по нему работают
`PathParams`, карта `bind` и генератор документации.

`cliEndpoint` устроен так же: имя команды — поле `command`
(`packages/nestling.transport.cli/src/index.ts:131`).

Мест вызова вне `docs/history/` около 337 для HTTP и 29 для CLI. Из них 50
лежат в сгенерированном `packages/nestling.app/type-tests/.generated/graph.ts`,
который пересобирает `type-tests/bench/generate.ts`. Записи в
`docs/history/` не меняются: папка append-only.

Правило ESLint `endpoint-has-layer` разбирает вызов синтаксически: оно
ждёт callee-идентификатор с настроенным именем и словарь первым
аргументом.

## Goals / Non-Goals

**Goals:**

- HTTP-метод называется именем конструктора, путь идёт первым аргументом.
- Вывод path-параметров и проверка `bind` не слабеют.
- Диагностика неверной декларации по-прежнему называет обе формы `handler`.
- CLI записывается так же: адрес первым аргументом.
- Бюджет типов остаётся в порогах `BUDGET.md`.

**Non-Goals:**

- Секция `http:` операции не меняется.
- Статиков по методу у `httpEndpoint.implement` не появляется.
- Проверка «`body()` у метода без тела» остаётся проверкой при создании и
  не переносится в типы.

## Decisions

### `httpEndpoint` — значение-объект, а не функция

`httpEndpoint` перестаёт быть вызываемым. Значение несёт семь свойств:
шесть конструкторов по HTTP-методу (`get`, `head`, `post`, `put`, `patch`,
`delete`) и `implement`.

```typescript
export const httpEndpoint = {
  get: makeMethodConstructor('GET'),
  head: makeMethodConstructor('HEAD'),
  post: makeMethodConstructor('POST'),
  put: makeMethodConstructor('PUT'),
  patch: makeMethodConstructor('PATCH'),
  delete: makeMethodConstructor('DELETE'),
  implement: implementOperation,
} satisfies HttpEndpointNamespace;
```

Состав статиков повторяет union `HttpMethod`. `head` включён, хотя мест
вызова у него нет: иначе один метод из шести объявлялся бы иначе, чем
остальные.

`delete` — зарезервированное слово, но имя свойства из него допустимо, и
`httpEndpoint.delete('/users/:id', { … })` разбирается без оговорок.

**Отвергнуто.** Оставить вызываемую форму `httpEndpoint({ method, … })`
рядом со статиками. Две записи одного и того же дают читателю выбор без
критерия, а словарю — поле, которое то обязательно, то запрещено.

**Отвергнуто.** Позиционная форма `httpEndpoint('GET', '/health', { … })`.
Метод остаётся строкой, и вызов начинается с двух голых литералов
подряд.

### Перегрузки объявлены один раз интерфейсом с двумя сигнатурами вызова

Шесть конструкторов принимают одно и то же. Их тип объявляется один раз
интерфейсом с двумя сигнатурами вызова: первая для хендлера-функции,
вторая для хендлера-класса.

```typescript
interface HttpMethodConstructor {
  <Path extends string, …>(
    path: Path,
    declaration: HttpEndpointDictionary<Path, …> & {
      handler: CheckedHttpHandlerFn<…>;
    },
  ): EndpointDefinition<I, O, P, PN>;
  <Path extends string, …>(
    path: Path,
    declaration: HttpEndpointDictionary<Path, …> & {
      handler: C & ValidateHandlerFails<…>;
    },
  ): EndpointDefinition<I, O, P, PN | C>;
}
```

Порядок сигнатур тот же, что у сегодняшних перегрузок: форма с функцией
стоит первой. Аргумент `handler` контекстно-чувствителен, и класс-форма
впереди побеждала бы, оставляя параметры стрелки без контекстного типа.

Сигнатур по-прежнему две, а не двенадцать: правило «ровно две перегрузки
на конструктор» из capability `endpoint-declarations` сохраняется, и
диагностика называет обе формы.

**Отвергнуто.** Объявить шесть пар перегрузок функциями. Текст сигнатур
пришлось бы держать в шести копиях, и расхождение между ними компилятор
не заметил бы.

### Метод не входит в тип декларации

Конструкторы различаются только строкой, которую передают в
`computeHttpBinding`. Тип словаря от метода не зависит, поэтому
`HttpMethodConstructor` не генерик по методу.

Это оставляет проверку «`body()` у метода без тела» там, где она сейчас, —
в `computeHttpBinding`, с ошибкой при создании декларации. Метод теперь
известен статически, и проверку можно было бы поднять в типы. Это
отдельная работа: она меняет capability `http-input-binding`, а не форму
записи.

### Путь — первый аргумент, литеральный тип берётся из него

`HttpEndpointDictionary` теряет поля `method` и `path`. Параметр `Path`
остаётся: он приходит из первого аргумента и типизирует `bind`.

Вывод литерального типа из позиции аргумента работает так же, как из
свойства объектного литерала. Переменная типа `string` в этой позиции
даёт `Path = string` и пустой набор path-параметров, как даёт и сегодня
поле `path` с той же переменной. Пример — пути проб в
`packages/nestling.transport.http/src/probes.ts`.

### `cliEndpoint('users:list', { … })`

Имя команды становится первым аргументом, `CliEndpointDictionary` теряет
поле `command`. Генерика по имени команды нет: у CLI-адреса нет
параметров, и из имени ничего не выводится.

Конструктор остаётся функцией с двумя перегрузками. Статиков по методу у
CLI быть не может, и разбивать `cliEndpoint` на пространство имён незачем.

### Тексты ошибок называют вызванный конструктор

Место ошибки описывается новой формой: `httpEndpoint.get('/users', { … })`
вместо `httpEndpoint({ method: 'GET', … })`. Строка собирается из имени
метода в нижнем регистре, поэтому каждый конструктор называет себя сам.

`cliEndpoint({ … })` в тексте ошибки пустой команды становится
`cliEndpoint('<command>', { … })`.

### Правило ESLint читает словарь из последнего аргумента

Правило `endpoint-has-layer` начинает принимать две формы callee:
идентификатор с настроенным именем (`cliEndpoint(…)`) и обращение к
свойству этого идентификатора (`httpEndpoint.get(…)`,
`httpEndpoint.implement(…)`). Словарь берётся из последнего аргумента,
если это объектный литерал.

Фильтр `pattern` сверяется с первым аргументом вызова, когда тот —
строковый литерал. В остальных случаях правило молчит, как молчало при
нелитеральном `path`.

Следствие: форма с операцией попадает под правило впервые.
`httpEndpoint.implement(CreateUser, { handler })` без `pipeline:` и без
`detached:` теперь подсвечивается. Раньше правило её не разбирало, потому
что callee был обращением к свойству.

### Миграция мест вызова

Правка механическая, но мест много, поэтому её делает разовый скрипт, а
не последовательная ручная замена. Скрипт разбирает текст
`ts.createSourceFile`, находит вызовы `httpEndpoint` и `cliEndpoint` с
объектным литералом и переписывает их: удаляет поля `method`, `path` или
`command`, ставит адрес первым аргументом, меняет имя вызываемого.

Тем же разбором обрабатываются блоки кода в Markdown: содержимое
` ```typescript `-блока разбирается как исходник. `docs/history/`
исключается из обхода.

После скрипта прогоняется `yarn lint:fix`: форматирование восстанавливает
prettier, а не скрипт.

Сгенерированный `type-tests/.generated/graph.ts` скриптом не правится:
его пересобирает `type-tests/bench/generate.ts` после правки шаблона в
генераторе.

## Risks / Trade-offs

- **Диагностика на свойстве объекта печатается хуже, чем на именованной
  функции.** TypeScript показывает сигнатуры типа свойства, и текст может
  отличаться от сегодняшнего. → Тексты закреплены снапшотами
  `type-tests` пакета `@nestlingjs/transport.http`. Если текст станет
  менее понятным, конструкторы объявляются шестью парами перегрузок
  функциями и присваиваются свойствам объекта; цена — шесть копий
  сигнатуры.
- **Скрипт миграции портит форматирование или пропускает случай.** → 337
  мест закрыты `yarn verify`: сборка, проверка типов, линт и тесты.
  Пропущенный случай перестанет компилироваться, потому что поля `method`
  в словаре больше нет.
- **Бюджет типов растёт: шесть свойств вместо одной функции.** → Замер
  `yarn workspace @nestlingjs/app type-budget` входит в `yarn verify`.
  Порог двигается только вместе со строкой в `BUDGET.md`.
- **Правило ESLint начинает предупреждать там, где молчало.** → Новые
  предупреждения на коде репозитория видит `yarn lint`. Реализации
  операций в примерах объявляют `pipeline:` либо `detached:`.

## Migration Plan

1. Конструкторы и словари в `@nestlingjs/transport.http` и
   `@nestlingjs/transport.cli`.
2. Внутренние места вызова тех же пакетов: пробы, спеки, фикстуры
   `type-tests`.
3. Правило `endpoint-has-layer` и его спеки.
4. Генератор бенча типов, пересборка `.generated/graph.ts`, замер бюджета.
5. Скрипт миграции по остальным пакетам, `examples/` и `docs/` без
   `docs/history/`.
6. Снапшоты диагностик, README пакетов, главы гайда, рецепты, скилл
   агента.

Отката нет: change идёт одним слиянием, старая форма не остаётся.
