# 12. Ревью жизненного цикла и композиции (2026-09-06)

> Замороженная запись дискуссии. Решения — десять записей
> [ideas.md [2026-09-06]](../../decisions/ideas.md); change'и 44–53 —
> [roadmap](../../decisions/roadmap.md).

## Исходный список

Автор принёс девятнадцать заметок «на подумать» и попросил оценить их
критически против `design/` и кода. Список в порядке автора:

1. Пробы liveness и readiness и их связь с фазами.
2. Фабрики только синхронные; сборка контейнера без асинхронных операций
   и, если получится, без конфига; типы вида `*Initialized`.
3. Как избежать проверок «инициализирован ли» в коде.
4. OpenAPI не формировать в рантайме.
5. Узаконить транспорто-специфичные хендлеры через generic метаданных.
6. Узаконить транспорто-специфичные юниты; транспорт поставляет юниты.
7. Описания полей конфига не в схеме.
8. Префикс секции не из имени файла, а из встроенной переменной.
9. Конфиг классами или вычисляемые поля.
10. Логгер: общий интерфейс, семейство, иерархия, `child`, адаптеры.
11. `makeApp` без фич для маленьких сервисов.
12. Строковая форма `makeFail`.
13. Сигнатура `bind` короче: `query(fields).body(otherFields)`.
14. Не говорить голое «токен».
15. Разделить `@Injectable()` и `@Inject()`.
16. Зачем DI-токенам суффикс `$`.
17. Операция и пайплайн в главе 5 гайда слишком рано.
18. У HTTP-транспорта не нужна опция `port`; нужен объект порта для
    нескольких слушателей на одном порту.
19. Как определяется порядок endpoint'ов; реэкспортов много.

## Ход обсуждения

### Раунд 1: критическая оценка

Каждый пункт сверен с design-доками и кодом. Главные находки:

- Фаза 0 BOOTSTRAP из composition.md в коде не существует: источники
  читает async-фабрика внутри графа, билдер делает `await` на фабриках
  вопреки синхронному типу `factoryProvider`.
- Проверка в `Database.users` гайда защищает от вызова, который
  жизненный цикл уже исключает; убрать её можно только конструированием
  зависимых узлов после захвата ресурса.
- Запись deferred о пробах выводила liveness из фазы, что бесполезно, и
  спорила с гайдом, где `Health` — endpoint с `detached`.
- `Location` в заголовках `Ok` — HTTP под чужим именем: CLI отбрасывает,
  NATS кладёт в заголовки сообщения без смысла.
- Transports.md противоречил себе про порт: «из секции, не из литералов»
  и «приоритет: опции фабрики». Опция существовала как обход одной
  секции `HttpConfig` на два экземпляра транспорта.
- Дубликат паттерна ловил find-my-way в `serve`, на START, после захвата
  ресурсов.
- В ядре нет логгера, и ядро пишет тремя каналами.
- `Output` определён в `operations`, а гайд импортирует его из
  `pipeline`; `makeFail` из `app` не экспортируется, вопреки памяти
  автора.
- Composition.md в примере L1 писал `Fail.badRequest('too many')`, а
  errors.md такой формы не знает.
- Container.md писал `ILogger`, `IConfig`, `IHealthCheck` против правила
  `$` из conventions.md.

Отклонено в первом раунде: generic метаданных у хендлера (воскрешает
`@Req()` из Nest), `makeApp` без фич (второй API), `@Inject` (параметрных
декораторов в стандартных ES-декораторах нет), строковая форма `makeFail`
(уже есть `makeFail(code)`), `bind` цепочкой (декларации — значения,
билдер только у пайплайна), OpenAPI без рантайма (сборка на ASSEMBLE —
не рантайм, а проверка деклараций).

### Раунд 2: возражения автора

- Пробы: семейство в ядре, но читать его должен единый сервис, доступный
  из разных транспортов, в том числе gRPC. Принято: `Health$` и
  `HealthCheck$`.
- Фаза 0: автор хочет, чтобы конфиг влиял на состав контейнера, и
  спрашивает, нормален ли захват ресурсов в фабриках. Ответ: фабрика
  конструирует, ресурс захватывает; для состава — явный список секций у
  фабрики провайдеров (позже заменён переключателями).
- Проверки инициализации: автор просит удобный и типобезопасный синтаксис.
  Предложены `@Resource` со `static acquire` и `resourceProvider`;
  экземпляры создаются на INIT.
- OpenAPI: мотив — время старта. Принято с предохранителем в виде
  отпечатка состава; позже автор оставил рантайм-путь как есть и
  попросил только сборку документа без запуска.
- HTTP-хендлер: автор настаивает, что нейтральные заголовки — обход, а
  специфику надо сделать явной. Принято: `HttpHandler<Op>`,
  `HttpResponse`, `Ok` без заголовков; проверка в слоте декларации.
- Префикс секции: имелся в виду общий `.env` на несколько сервисов.
  Принято как свойство источника: `env({ prefix })`.
- `derived`: автор против провайдера-прокси. Принят явный список
  зависимостей, как у `factoryProvider`.
- Логгер: `child` нужен для замены корня одним провайдером и для серии
  записей об одном объекте. Принято: `RootLogger$`, семейство с рецептом
  `root.child({ scope })`, `child` в интерфейсе.
- `makeApp` без фич: дело не в строке, а в понятии. Принято: формы корня
  `{ endpoints, providers? }`, `{ endpoints, modules? }`, `{ features }`.
- Порт: автор предложил провайдер порта, передаваемый в транспорты.
  Уточнено: разделяемая вещь — сервер, потому что два слушателя на один
  порт не биндятся. Принято: `httpServer({ name })`, `http({ server })`.
- Термин: автор настоял на «DI-токен» везде.
- Пакет `pipeline`: автор считал укрупнение сделанным; проверка показала,
  что change 42 не начат.

### Раунд 3: уточнения

- Состав по конфигу заменён переключателями: `makeSwitch`, `pick`,
  `when`, словарь в корне, аргумент сборки. Причина: функция состава
  непрозрачна для `check()` и визуализации, а `select` уже устроен как
  закрытый словарь. Привязки `config:` под переключателем не входят в V1.
- Чем ресурс отличается от компонента: обещанием. Компонент не трогает
  внешний мир, ресурс держит его. Имя `@Component` принято вместо
  `@Injectable`, потому что соседи `@Resource` и `@Handler` называют
  роль.
- Интерфейсы `Handler<Op>` и `HttpHandler<Op>` выводятся из операции, а
  не пишутся руками; `@Handler([deps])` без перегрузки с операцией.
- Сигнатура логгера принимает объект ошибки, в том числе без `message`:
  три формы на каждый уровень, ключ `err` зарезервирован.
- Средняя форма корня `{ modules }` в одиночку ничего не обслуживает:
  модули не несут endpoint'ов.
