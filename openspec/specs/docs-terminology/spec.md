# docs-terminology

## Purpose

Слово «токен» в текстах репозитория означало две разные вещи: ключ
контейнера и токен доступа. Различить их можно было только по контексту.
Спека закрепляет два термина с приставкой и проверку, которая ловит голое
слово.

## Requirements

### Requirement: Тексты называют DI-токен с приставкой

Тексты репозитория SHALL называть ключ контейнера «DI-токен», а токен
доступа — «Bearer-токен». Голое слово «токен» в любом падеже
запрещено. Правило действует в гайде, design-доках, README пакетов,
JSDoc, комментариях кода, заголовках тестов и текстах сообщений об
ошибках, включая комментарии внутри примеров кода.

Правило не действует в `docs/history/` и `docs/decisions/`: первая папка
заморожена, вторая пополняется только новыми записями. Идентификаторы кода
и имена файлов правилу не подчиняются: `makeToken`, `tokenId`, `API_TOKEN`,
`@nestlingjs/container/tokens`, `token-family.ts`.

#### Scenario: Глава об аутентификации различает два значения

- **WHEN** глава гайда описывает проверку заголовка `authorization` и
  отбор endpoint'ов по транспорту
- **THEN** первое называется «Bearer-токен», второе — «DI-токен»

#### Scenario: Сообщение ядра об отсутствующем провайдере

- **WHEN** контейнер не находит провайдер для запрошенного DI-токена
- **THEN** текст ошибки содержит `DI token`, а не `token`

### Requirement: Линтер стиля ловит голое «токен»

Скрипт `.claude/skills/docs-style/scripts/lint.mjs` SHALL сообщать ERROR
на слове «токен» без приставки. Формы с приставками `DI-` и `Bearer-`
SHALL проходить проверку. Любая другая приставка через дефис SHALL
считаться находкой.

Подсказка находки SHALL называть обе разрешённые формы. Строка про
«токен» SHALL стоять в таблице замен `.claude/skills/docs-style/SKILL.md`.

#### Scenario: Голое слово в прозе

- **WHEN** строка Markdown вне блока кода содержит «проверяет токен»
- **THEN** линтер сообщает ERROR с номером строки и exit-код 1

#### Scenario: Разрешённые формы

- **WHEN** строка содержит «DI-токен», «Bearer-токена» или «семейство
  DI-токенов»
- **THEN** линтер находок не даёт

#### Scenario: Приставка не из списка

- **WHEN** строка содержит «access-токен»
- **THEN** линтер сообщает ERROR

### Requirement: Список целей линтера покрывает обе папки гайда и документы корня

Список целей по умолчанию `DEFAULT_TARGETS` SHALL включать `docs/guide`,
`docs/recipes`, `docs/conventions.md`, `docs/guarantees.md` и
`docs/from-nestjs.md`.

#### Scenario: Прогон без аргументов

- **WHEN** линтер запускается без путей
- **THEN** проверяются главы `docs/guide/*.md`, рецепты
  `docs/recipes/*.md`, `docs/conventions.md`, `docs/guarantees.md` и
  `docs/from-nestjs.md`

### Requirement: Глоссарий называет семейство одним именем

`docs/glossary.md` SHALL называть семейство «семейство DI-токенов» и в
таблице терминов, и в определении раздела о контейнере.

#### Scenario: Таблица и определение совпадают

- **WHEN** читатель ищет термин в таблице и переходит к определению
- **THEN** обе записи говорят «семейство DI-токенов»
