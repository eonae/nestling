# Генератор документации

Собирает один HTML-файл из источников, перечисленных в `sections.mjs`:
папок [`docs/guide/`](../../docs/guide/) и
[`docs/recipes/`](../../docs/recipes/) и страниц
[`docs/guarantees.md`](../../docs/guarantees.md) и
[`docs/from-nestjs.md`](../../docs/from-nestjs.md). **Не источник
истины**: текст живёт в этих файлах, а источник намерения — в
[`docs/design/`](../../docs/design/) и
[`docs/decisions/`](../../docs/decisions/).

```bash
yarn docs:build   # собрать один раз
yarn docs:dev     # пересобирать при каждом сохранении
```

Вывод — `docs/.site/index.html`, и других файлов в каталоге нет. Каталог
не отслеживается git и создаётся каждой сборкой заново, поэтому правка
HTML в нём теряется на следующей сборке.

Файл самодостаточен: оформление, поведение и подсветка кода лежат внутри
него. Его пересылают, кладут рядом с релизом и открывают двойным кликом —
соседние файлы и сервер для этого не нужны.

```
scripts/site/
├── build.mjs     ← генератор
├── sections.mjs  ← источники сборки и их порядок
├── layout.html   ← каркас документа: шапка, разметка, места под тему
├── styles.css    ← оформление; сборка встраивает файл в <style>
└── app.js        ← тема, меню, ведение по прокрутке; встраивается в <script>
```

## Источники

`sections.mjs` перечисляет источники в порядке разделов собранного файла.
Источник двух видов.

| Вид | Что даёт |
|---|---|
| `folder` | Папка с оглавлением `README.md`: README открывает разделы источника, каждый файл папки становится своим разделом |
| `page` | Отдельный файл: один раздел |

Слаг раздела — имя файла без папки; у оглавления папки — имя самой папки.
Слаг главы начинается с цифры, слаг рецепта и страницы — с буквы, поэтому
столкнуться они не могут. Совпадение слагов останавливает сборку.

## Что делает генератор

- Раздел на каждый файл источника: `<section class="chapter">` с якорем
  по имени файла. Источник открывает его README.
- Группы сайдбара: у папки с заголовками `## Часть N. …` группу даёт
  каждый такой заголовок, а пункты группы — строки таблицы под ним; папка
  без них даёт одну группу, названную в `sections.mjs`; страница даёт один
  пункт. Перечислены все группы и пункты сразу; `##`-разделы
  раскрываются у того файла, который читатель сейчас видит.
- Пейджер в конце раздела ведёт на предыдущий и следующий раздел в
  порядке `sections.mjs`.
- Ссылка на файл источника переписывается в якорь по имени файла:
  `./NN-имя.md` — в `#NN-имя`, `../recipes/имя.md` — в `#имя`,
  `./NN-имя.md#якорь` — в `#NN-имя--якорь`. Ссылка в файл вне источников
  разрешается от каталога исходного файла и записывается относительно
  `docs/.site/`: у главы запись не меняется, у страницы корня `docs/`
  путь получает ведущий `../`.
- Идентификатор заголовка получает приставку файла: `## Проверка` есть в
  доброй десятке файлов, и без приставки якоря столкнулись бы.
- Блок кода получает шапку с именем файла и языком, а его текст —
  разметку синтаксиса. Подпись берётся из первой строки-комментария с
  путём; сама строка остаётся в коде.
- `styles.css` и `app.js` встраиваются в файл: ссылок на соседей в выводе
  не остаётся.

Сборка падает, если состав README и файлы папки-источника разошлись:
названный в README файл отсутствует, файл лежит в папке без строки в
README или ссылка ведёт на файл источника, которого нет. Проверка идёт по
каждой папке отдельно, а текст ошибки называет файл.

## Добавить главу или рецепт

1. Новый файл: `docs/guide/<NN-имя>.md` или `docs/recipes/<имя>.md`.
2. Строка в таблице оглавления той же папки.
3. `yarn docs:build`.

Новый источник целиком — запись в `sections.mjs`.

## Разметка текста

Главы и рецепты пишутся обычным Markdown: специальной разметки они не
требуют. Генератор понимает несколько дополнительных блоков этой темы
оформления; пользоваться ими необязательно.

### Заголовки

`#` — заголовок главы, `##` — раздел, `###` — подраздел. Якорь раздела
генератор строит сам из его текста и приставляет к нему имя главы,
поэтому подпункты сайдбара работают без ручной разметки. Явный якорь
задаётся так:

```md
## Модульный монолит {#monolith}
```

Приставку получает и он: в главе `19-select` такой заголовок станет
`19-select--monolith`.

### Блоки кода

Язык указывается после забора. Подпись над блоком генератор берёт из
первой строки-комментария с путём — той самой, с которой главы гайда
начинают сниппет:

````md
```typescript
// examples/users-service/src/app.ts
export const app = makeApp({ features: [UsersFeature] });
```
````

Строка-комментарий остаётся в коде: скопированный сниппет не теряет
адрес файла.

### Ссылки

Ссылка на соседний файл пишется как обычная ссылка на файл:
`[глава 7](./07-config.md#секреты)` станет `#07-config--секреты`, а
`[рецепт](../recipes/cli.md#repl)` — `#cli--repl`. Ссылка в файл вне
источников пишется относительным путём, а генератор пересчитывает его от
`docs/.site/`: `../design/errors.md` из главы остаётся собой.

### Врезки

```md
:::note Почему «nestling»
Nestling — птенец: младший, лёгкий родственник большого Nest.
:::

:::note good Что осталось
Три знакомых типа провайдеров, декораторы ролей, инъекционные DI-токены.
:::

:::note warn Осторожно
Ранний `listen()` при захвате ресурса невозможен by design.
:::
```

Заголовок врезки обязателен. Вариантов оформления три: без модификатора,
`good` (зелёная) и `warn` (жёлтая).

### Карточки

Сетка на первом экране. Внешний блок — четыре двоеточия, карточки — три.
После `:::card` идут иконка и заголовок, дальше текст карточки.

```md
::::cards
:::card 🧩 Модули — это значения
Не классы с декораторами, а plain-объекты.
:::
:::card ⚡ Жадный контейнер
Весь граф строится на старте.
:::
::::
```

### Таблицы и списки

Обычные GFM-таблицы: генератор сам заворачивает их в горизонтальный
скроллер. Ячейку-отказ помечают классом `{.no}`, тогда она красится в
красный. Вертикальную черту внутри ячейки экранируют: `\|`.

Списки обычные; класс `body` навешивается сам.

### Сырой HTML

Работает как escape-hatch для одиночной вёрстки. Внутри HTML-блока
**не должно быть пустых строк**: пустая строка закрывает блок, и остаток
попадёт в текст.

### Чего генератор не делает

Оформление он не придумывает: `styles.css` и `app.js` правятся напрямую,
сборка только встраивает их в файл. Правила подсветки лежат в `build.mjs`
и покрывают TypeScript — язык примеров. Состав и порядок разделов внутри
папки берутся из её README, а не из отдельного файла навигации; порядок
самих источников — из `sections.mjs`.
