## Context

Термин уже определён. `docs/glossary.md` описывает DI-токен и требует
приставку, `docs/conventions.md` задаёт суффикс `$` для DI-токенов
интерфейсов. Не сделано остальное: тексты написаны до этого правила, а
линтер стиля про «токен» не знает.

Линтер — скрипт `.claude/skills/docs-style/scripts/lint.mjs`. Он читает
прозу Markdown вне блоков кода и вне инлайн-кода, комментарии TypeScript и
заголовки тестов. Список запрещённых слов лежит в массиве `BANNED`: пара
«регулярное выражение, подсказка». Границы слова заданы вручную, потому что
`\b` не работает с кириллицей.

Сейчас линтер даёт 5 находок на текущем коде и не проверяет гайд: в списке
целей по умолчанию стоит `docs/guides`, а папка называется `docs/guide`.

## Goals / Non-Goals

**Goals:**

- Голое «токен» не встречается в текстах репозитория за пределами
  `docs/history/` и `docs/decisions/`.
- Линтер ловит голое «токен» и падает на нём.
- Линтер проверяет гайд и `docs/conventions.md`.

**Non-Goals:**

- Идентификаторы кода и имена файлов не переименовываются.
- Английские тексты, кроме сообщений об ошибках, не правятся.
- Автоматической проверки комментариев внутри примеров кода в Markdown не
  появляется: линтер по-прежнему не читает блоки кода.

## Decisions

### Правило линтера — одно выражение с двумя исключениями

Запись в `BANNED` — отдельное регулярное выражение, а не вызов
хелпера `word()`:

```js
[
  /(?<!DI-)(?<!Bearer-)(?<![а-яёa-z])[Тт]окен(а|у|ом|е|ы|ов|ам|ами|ах)?(?![а-яё])/iu,
  '«DI-токен» — или «Bearer-токен», если речь о токене доступа',
]
```

Хелпер `word()` не подходит: его приставка `(?<![а-яёa-z])` пропускает
дефис, поэтому «DI-токен» считался бы находкой. Два негативных lookbehind
разрешают ровно две формы.

Альтернатива — разрешить любую приставку через дефис, `(?<![\p{L}-])`.
Отвергнута: тогда «access-токен» и «refresh-токен» проходят молча, а
именно за такими формами прячется вторая ошибка.

### Цели по умолчанию

`DEFAULT_TARGETS` перечисляет `docs/guides` — такой папки нет, гайд не
проверяется. Строка меняется на `docs/guide`, рядом добавляется
`docs/conventions.md`. Проверка правки: прогон линтера сообщает большее
число файлов, чем текущие 492.

### Замена делается по смыслу, файл за файлом

Одна `sed`-замена «токен» → «DI-токен» испортит текст в трёх местах:
глава 9 гайда и слой `authed` говорят про Bearer, `docs/glossary.md`
перечисляет запрещённые формы в блоке `docs-style: off`, а примеры
`API_TOKEN` и `apiToken` про конфиг. Каждый файл читается, и вхождение
получает ту приставку, которая верна по контексту.

Список работ даёт сам линтер: после правки правила его вывод —
перечень мест с номерами строк. Отсюда порядок: сначала правило и цели,
потом тексты.

Линтер не видит двух видов вхождений: комментарии внутри блоков кода в
Markdown и текст внутри инлайн-кода. Они ищутся отдельно, поиском по
шаблону `(^|[^-A-Za-zА-Яа-яёЁ])[Тт]окен`.

### Английские сообщения об ошибках говорят `DI token`

`Provider for token 'X' not found` становится
`Provider for DI token 'X' not found`. Правило то же, что для русских
текстов: слово называет DI-токен, значит приставка нужна. Затронуты
`@nestling/container`, `@nestling/app` и `common.graphs`; тесты, которые
сверяют текст сообщения, обновляются вместе с ним.

Альтернатива — оставить английские сообщения как есть, потому что Bearer
в них не встречается. Отвергнута: сообщение об ошибке читает тот же
человек, что и гайд, и одно слово в двух значениях он видит в один день.

### Глоссарий называет семейство одинаково

Таблица терминов пишет «семейство токенов», а определение ниже —
«Семейство DI-токенов». Остаётся вторая форма, таблица приводится к ней.

## Risks / Trade-offs

- **Массовая замена меняет смысл там, где речь о Bearer.** → Файлы гайда
  09, слой `authed` в примерах и тесты HTTP-транспорта правятся отдельно и
  первыми, до сплошного прохода.
- **Правило ловит слово в чужих цитатах.** Заголовки записей журнала вида
  «…» `[ГГГГ-ММ-ДД]` линтер уже вырезает, остальные цитаты — нет. →
  Найденное в цитате оборачивается в инлайн-код или в блок
  `docs-style: off`.
- **Числа в спеке устаревают.** → Спека формулирует правило, а не
  количество вхождений; счёт живёт в `proposal.md`.
- **Гайд начинает проверяться и может дать новые находки.** → Прогон по
  `docs/guide` сейчас даёт 0 запрещённых слов, поэтому исправление цели
  само по себе gate не ломает.
