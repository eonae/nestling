## Context

Профиль сервера Nestling на Node 24 под `GET /users/:id` (d/10 §5,
`scripts/bench/README.md`): собственный код около 8% сэмплов, из них
`transport.http` 4.4% и `pipeline` 2.2%; `_storeHeader` 1.1% против 0.4%
у Fastify; микротаски 2%. На запрос Nestling тратит около 20 µs, Fastify
около 16 µs. Гарантии (проверка входа, область контекста, проверка по
`errors:`, `.finally`, сигнал отмены) стоят около 1 µs и остаются.

## Goals / Non-Goals

**Goals:**

- Убрать с горячего пути работу, которая зависит только от декларации или
  от структуры пайплайна: вычислять её при регистрации маршрута и в
  конструкторе пайплайна.
- Уменьшить число аллокаций и `await` на запрос.
- Сохранить наблюдаемое поведение: заголовки, коды, тела ответов, порядок
  фаз, `meta.signal`, `Ctx`.

**Non-Goals:**

- Всё из раздела Non-goals proposal.

## Decisions

### Заголовки одним `writeHead`

`sendResponse` для формы `value` собирает объект заголовков: `content-type`
формы, затем заголовки `Ok` с именами в нижнем регистре, затем
`content-length` по длине буфера. Один `writeHead(status, headers)` и
`end(buffer)`. Node при `setHeader` проверяет имя регулярным выражением
и хранит заголовки в отдельной таблице, а при `end(string)` считает длину
второй раз; буфер и `writeHead` убирают обе работы.

Регистр: `setHeader` приводил имена к нижнему регистру сам, поэтому
`Ok.created(v, { 'Content-Type': … })` перекрывал заголовок формы. У
`writeHead` с объектом такого слияния нет, и без приведения ушли бы два
заголовка. Приведение делает транспорт.

Потоковые формы остаются на `setHeader`: они не горячие, а `writeSse` и
`writeNdjson` пишут кадры отдельно.

### Адрес без `new URL`

`new URL()` строит полный объект с хостом и нормализует путь; транспорту
нужны путь для `raw.pattern` и query-строка для bind-карты. Путь берётся
срезом до `?`, query разбирается `URLSearchParams` только когда запись
маршрута говорит, что карта читает query, и в запросе есть `?`.
Маршрутизацию `find-my-way` делает по сырому `req.url`, как и раньше.

`raw.pattern` при этом несёт путь как прислан клиентом. Поле
информационное: его читают `.finally`-юниты для лога. Нормализованный
путь не нужен ни маршрутизации, ни bind-карте.

### Запись маршрута

`HttpRouter.route()` вычисляет bind-карту, формы `input` и `output`,
`needsBody` и `readsQuery` один раз и кладёт их в store `find-my-way`
рядом с проекцией декларации. `find()` возвращает запись целиком.
Тип записи внутренний для пакета. `readsQuery` истинен, если источник
«остальное» — query или хотя бы одно поле помечено `query()`.

### Пайплайн без копий на запрос

Слои `PipelineImpl` не меняются после конструктора: каждый метод билдера
возвращает новый экземпляр. Поэтому первый нерезолвленный класс-юнит и
признак «есть `.finally`» вычисляются в конструкторе. `execute` заменяет
массив активированных слоёв счётчиком: слои активируются строго по
порядку, и ответная фаза обходит префикс с конца по индексу.

### Меньше `async`-обёрток

`executeWithHandler` возвращает промис `execute` напрямую, без
собственного `async`. `dispatch.call` остаётся `async` ради контракта
«неизвестный паттерн — отклонённый промис», но возвращает промис без
`return await`. `.finally` не вызывается при пустом списке. `sendResponse`
остаётся `async`: это публичная функция, и потоковый путь ждёт внутри.

### Накопление контекста в одном объекте

Результат pre-юнита дописывается `Object.assign` в `ctx.input`, а не
собирается новым объектом. Ячейка `AsyncLocalStorage` создаётся ссылкой
на тот же объект, поэтому отдельное обновление ячейки после юнита
не нужно. Стартовый `input` всегда свежий объект на запрос: транспорт
строит его сам, `makeEmptyContext` подставляет `{}`.

Наблюдаемое отличие одно: юнит, сохранивший ссылку на `ctx.input`, после
следующих юнитов увидит их поля. Спеки пайплайна требуют накопления, а
не снимков; тесты, которые проверяют снимок, если найдутся, правятся
вместе с изменением.

## Risks / Trade-offs

- [Дубликат заголовка при разном регистре] → приведение имён к нижнему
  регистру до слияния, тест на `Ok.created(v, { 'Content-Type': … })`.
- [`raw.pattern` изменился для путей с кодированием] → README транспорта
  называет поле сырым путём; тест `.finally` с `%20` в пути.
- [Пропущенный query] → `readsQuery` считается по bind-карте, тесты
  query-параметров и `query({ multiple: true })` проходят без правок.
- [Юнит полагался на снимок контекста] → прогон всех спеков пайплайна;
  найденные случаи правятся явной копией в юните.
- [Выигрыш в шуме] → каждый пункт принимается по медиане из трёх прогонов
  `nestling,fastify`; пункт без выигрыша не меньше 1% откатывается, если
  усложняет код.
