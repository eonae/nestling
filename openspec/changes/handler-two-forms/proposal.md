# handler-two-forms

## Why

Поле `handler` принимает три формы: функцию, объект `{ deps, handle }` с
каррированной фабрикой и класс. Объектная форма нарушает правило, по
которому живут провайдеры и юниты пайплайна: зависимости из контейнера
получает класс. Она не поддерживает `Family.auto`, потому что у неё нет
класса-потребителя; она держит по одной-две лишних перегрузки у каждого
конструктора деклараций и позиционную перегрузку `resolve(instances)`;
её преимущество, вывод типов зависимостей из токенов, работает только
инлайн, а `conventions.md` выносит хендлер в именованную константу.
Решение и его логика — [ideas.md [2026-09-04]](../../../docs/decisions/ideas.md)
«Две формы хендлера: функция без зависимостей и класс» и «`@Injectable`
сверяет длину списка зависимостей с конструктором»; обсуждение —
[d/09](../../../docs/history/discussions/09-framework-review.md). Change
идёт первым в серии 33–36: `layer-fails` меняет те же перегрузки, и
удаление формы до него сокращает работу вдвое.

## What Changes

- **BREAKING** Поле `handler` принимает две формы: функцию без
  зависимостей и класс с `@Injectable` и методом `handle`. Объектная форма
  `{ deps, handle }` удаляется целиком: тип `HandlerWithDeps`, ветка в
  `AnyEndpointHandler`, перегрузки `httpEndpoint` (шесть становятся
  четырьмя), `cliEndpoint` и `implement` (три становятся двумя),
  позиционная перегрузка `resolve(instances)`, ветка discovery, читающая
  `deps` с объекта. Объект в поле `handler` из JS — ошибка при создании
  декларации с указанием на класс-форму.
- **BREAKING** `@Injectable` сверяет длину списка зависимостей с числом
  параметров конструктора: лишний токен становится ошибкой компиляции с
  литералом `__error`. Список короче числа обязательных параметров
  отвергается и в рантайме при декорировании.
- Диагностики двух форм `httpEndpoint` фиксируются снапшот-тестами:
  пакет `@nestling/transport.http` получает каталог `type-tests` по образцу
  `@nestling/pipeline`.
- Примеры: 20 мест объектной формы в 14 файлах переписываются в классы;
  `conventions.md` получает правило именования класса-хендлера реализации
  операции.
- Гайд: главы 5, 12, 13, 17 и остальные главы, где встречается форма;
  приложение А теряет раздел «Функция с `deps`»; приложение В и README
  гайда обновляются. README пакетов `pipeline`, `transport.http`,
  `transport.cli`, `ports`, `app`, `container` — таблицы форм и плашки.
- `design/endpoints.md` §3 и `design/container.md` уже описывают целевое
  состояние; change доводит до него код, спеки, примеры и гайд.

## Capabilities

### New Capabilities

- `injectable-dependency-list`: список зависимостей `@Injectable`
  сверяется с конструктором по типам, порядку и длине; рантайм отвергает
  список короче обязательных параметров.
- `endpoint-type-diagnostics`: тексты диагностик форм `httpEndpoint`
  зафиксированы снапшот-тестами в `@nestling/transport.http`.

### Modified Capabilities

- `endpoint-handler-di`: две формы вместо трёх; требование о
  каррированной фабрике удалено; `resolve` принимает только резолвер;
  получение зависимостей сборкой описано без `handler.deps`.
- `contract-implementations`: сценарии `implement` с формой хендлера —
  класс вместо объекта; «те же три формы» становятся «те же две».
- `endpoint-declarations`: форма с `operation:` — сценарий реализации
  через класс; «три формы `handler`» становятся «обе формы».
- `endpoint-error-contract`: вывод типа отказов «в обеих формах»; сценарий
  каррированной фабрики заменён сценарием функции без зависимостей.

## Impact

- Пакеты: `@nestling/pipeline` (`metadata/endpoint.ts`, типы форм,
  `resolve`, экспорты), `@nestling/transport.http` (`helpers.ts`, новый
  `type-tests/`), `@nestling/transport.cli`, `@nestling/ports`
  (`implement.ts`), `@nestling/app` (discovery, регистрация
  класса-хендлера), `@nestling/container` (`injectable.decorator.ts`).
- Примеры: `examples.app-with-http`, `examples.split-nats`,
  `examples.container`, `examples.simple-cli`, `examples.users-service`,
  `examples.simple-http-server` — везде, где `grep 'deps: \['` находит
  поле `handler`.
- Документация: гайд, приложения А–В, README пакетов, `conventions.md`,
  `glossary.md` (термин «хендлер»), спеки.
- Зависимые changes: `layer-fails` (#34) строится поверх сокращённого
  набора перегрузок.

## Non-goals

- Удаление голой функции: на ней держится первая глава и пробы вроде
  `/health`.
- Формы юнитов пайплайна (функция, инстанс, класс) не меняются.
- Отказы слоя, отказы ядра в `Output`, `void` без `output` — change
  `layer-fails`.
- Рантайм-проверка лишнего токена: `Function.length` не отличает
  необязательный параметр от отсутствующего, поэтому рантайм проверяет
  только нехватку.
