# @nestlingjs/agent-skill

Скилл Claude Code про Nestling и команда, которая кладёт его в проект.
Скилл даёт агенту форму кода и правила, которых нельзя вывести из практики
NestJS: декларации значениями, явный список зависимостей, отказы значениями,
вызов соседней фичи операцией.

> 🚧 Активная разработка, API может меняться. Текст скилла английский:
> его читает модель, а не разработчик.
> Дизайн: [`docs/design/principles.md`](../../docs/design/principles.md).
> Гайд: [оглавление](../../docs/guide/README.md).

## Установка

```bash
npx @nestlingjs/agent-skill
```

Команда пишет `.claude/skills/nestling/` в текущем каталоге: `SKILL.md`,
четырнадцать файлов `references/` и манифест `.manifest.json`. Другой
каталог задаёт `--dir <путь>`.

Манифест — то, чем повторная установка отличает правленый файл от просто
старого. Он несёт версию пакета и хэш каждого файла, который команда
положила, поэтому:

- файла нет — команда его создаёт;
- хэш файла манифест признаёт — команда заменяет его новой версией молча,
  это обычное обновление;
- хэш файла манифест не признаёт — команда называет файл, оставляет его
  как есть и завершается кодом 1, потому что правки пользователя молча не
  теряются; `--force` перезаписывает.

У копии, поставленной прежней версией команды, манифеста нет. Сравнивать
не с чем, поэтому каждый файл сравнивается с источником, и один `--force`
— цена первого обновления. Дальше манифест есть, и обновления идут молча.

## Минимальный пример

```typescript
import { installSkill } from '@nestlingjs/agent-skill';

const report = await installSkill({ dir: './apps/api', force: false });

console.log(report.created.length, report.updated.length);

if (report.diverged.length > 0) {
  console.log(`расходятся: ${report.diverged.join(', ')}`);
}
```

## Экспорты

| Имя | Что делает |
|---|---|
| `installSkill` | кладёт файлы скилла в `.claude/skills/nestling/` внутри каталога проекта, пишет манифест и возвращает отчёт значением |
| `InstallOptions` | опции установки: каталог проекта и разрешение перезаписать расходящиеся файлы |
| `InstallReport` | отчёт: каталог назначения, версия, созданные, обновлённые, совпавшие и разошедшиеся файлы |
| `SkillManifest` | что несёт манифест: версию пакета и хэш каждого файла по его пути |
| `SKILL_PATH` | путь скилла внутри проекта — `.claude/skills/nestling` |
| `MANIFEST_NAME` | имя манифеста внутри этого каталога — `.manifest.json` |

Команда `nestling-agent-skill` — та же установка из терминала. Её и
запускает `npx @nestlingjs/agent-skill`: команда в пакете одна, и имя ей
указывать не нужно.

## Границы пакета

Пакет несёт текст и копирует файлы. Кода фреймворка в нём нет: `dist` не
зависит ни от чего, кроме модулей Node. Скилл описывает только написание
приложения на Nestling — работу над самим фреймворком ведут скиллы
репозитория.

Манифест команда пишет в проект, и в тарбол он не едет: иначе версия жила
бы в трёх местах и расходилась бы с двумя первыми.

Сниппеты скилла лежат в `snippets/` компилируемыми файлами и в тарбол не
едут: они существуют ради того, чтобы `yarn verify` роняло скилл,
разошедшийся с API. Блоки кода сверяет `scripts/snippets.mjs`, переписывает
их `yarn workspace @nestlingjs/agent-skill snippets`. Блок может показывать
не файл целиком, а его названный участок: `<!-- snippet: файл.ts#участок -->`
против `// #region участок` и `// #endregion` в файле. Ограда блока всегда
называет язык — снятие языка было бы обходом сверки.

Текст скилла держат ещё две проверки, `scripts/freshness.mjs` и
`src/skill.spec.ts`: версия в `SKILL.md` совпадает с `package.json`, имя,
удалённое выпуском, в тексте не встречается, таблица пакетов называет
каждый публикуемый пакет, перечень правил линтера совпадает с правилами
плагина, а таблица фаз идёт без пропусков.

Сниппеты проверяются не только компиляцией. Те из них, до которых
`snippets/app.ts` достаёт импортами, спека собирает в приложение через
`buildTest`: политика корня, слой endpoint'а, ребро между фичами и
провайдер шага слоя ловятся так же, как у пользователя.
