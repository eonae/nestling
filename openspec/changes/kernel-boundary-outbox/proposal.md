# kernel-boundary-outbox

## Why

Замер границы ядра на `@nestling/outbox` нашёл четыре места, в которые
сателлит упёрся, и намеренно не починил ни одного: правка ядра ради
сателлита обесценила бы сам замер. Места остались, а вместе с ними —
цена, которую платит каждое приложение с транзакционным emit'ом: лишний
класс-мост в слое транзакции, ключ идемпотентности события мимо типов,
подсказка о недостающей шине, вписанная в идентификатор DI-токена, и
раздел записи, назначаемый функцией плагина вместо места вызова.

Все четыре зафиксированы живыми тестами
`packages/nestling.outbox/src/core-limits.spec.ts` и описаны в разделе
«Результат замера границы» записи
[ideas.md [2026-09-07] «Транзакционный outbox»](../../../docs/decisions/ideas.md).
Change закрывает их правкой ядра — теперь, когда замер состоялся и
записан.

## What Changes

- **Находка №1.** `Var.provide` получает вторую форму — с зависимостями
  из контейнера: `Tx.provide([Database], (ctx, db) => db.begin())`.
  Зависимости резолвятся на WIRE тем же резолвером, что и классы-юниты
  пайплайна. Класс-мост, который сегодня кладёт соединение в контекст
  только затем, чтобы писатель прочитал его из `ctx.input`, перестаёт
  быть нужен: слой транзакции состоит из одного юнита вместо двух.
- **Находка №2.** `idempotencyKey` появляется в `meta` у операций вида
  `event` — рядом с `command`. У `request` его по-прежнему нет.
  Генерация ключа не меняется: ядро чеканит недостающий ключ только
  команде, у события ключ едет, если его передал издатель. Так уже
  устроен конверт: `PublishOptions.idempotencyKey` и
  `BusMessageMeta.idempotencyKey` кладутся при любой публикации, и
  relay outbox'а публикует событие с ключом, равным идентификатору
  записи.
- **Находка №3.** `makeToken` принимает подсказку: `makeToken<T>(id,
  { hint })`. Ошибка о недостающих зависимостях печатает подсказку
  недостающего DI-токена и подсказки потребителей, у которых она есть.
  Пакет перестаёт вписывать текст починки в идентификатор DI-токена, и
  алиас шины, заведённый ради этого, уходит.
- **Находка №4.** Словарь `meta` вызывающей стороны открыт для
  расширения: `Port<C, M>` и `Emitter<C, M>` принимают вторым
  тип-параметром словарь `meta`, по умолчанию — `MetaOf<C>`. Сателлит
  объявляет свой словарь и остаётся совместимым: значение
  `Emitter<C, MetaOf<C> & { partitionKey?: string }>` присваивается
  переменной типа `Emitter<C>`, потому что параметр метода
  контравариантен.
- **BREAKING** `@nestling/outbox` переезжает на новые примитивы: раздел
  записи задаётся аргументом `emit` (`emit(payload, { partitionKey })`),
  опция `partitionKey` у `outbox({ … })` удаляется, DI-токен-алиас шины
  удаляется, `core-limits.spec.ts` удаляется целиком.
- **BREAKING** `examples/users-service` мигрирует: класс `ProvideDb` и
  его регистрация в `providers:` уходят, раздел записи переезжает в
  вызов `emit`.

## Capabilities

### New Capabilities

- `dependency-hints`: подсказка на объявлении DI-токена и её печать в
  ошибке о недостающих зависимостях — у недостающего DI-токена и у
  каждого потребителя, который её объявил.

### Modified Capabilities

- `async-context-vars`: у `Var.provide` появляется форма с зависимостями
  из контейнера; писатель по-прежнему строит сама переменная, а объявление
  переменной по-прежнему совпадает с фактом записи.
- `pipeline-unit-forms`: пайплайн резолвит зависимости писателя переменной
  на `bind` — тем же резолвером, что и классы-юниты. Публичного
  конструктора юнита с зависимостями для произвольной фазы не появляется.
- `container-accessor-contract`: ошибка о недостающих зависимостях несёт
  подсказки — механизм описан в `dependency-hints`.
- `port-idempotency`: `idempotencyKey` доступен видам `command` и `event`;
  чеканка недостающего ключа остаётся привилегией команды.
- `port-invocation`: словарь `meta` — тип-параметр вызывающей стороны со
  значением по умолчанию `MetaOf<C>`.
- `transactional-outbox`: раздел записи задаётся аргументом `emit`; слой
  транзакции описывается одним юнитом; подсказка о недостающей шине
  живёт в объявлении DI-токена, а не в его идентификаторе.

## Non-goals

- Публичный конструктор юнита с зависимостями для произвольной фазы
  (`withDeps([...], fn)` для `.pre`/`.ok`/`.catch`/`.finally`). Запроса
  на него замер не дал: у остальных фаз класс-форма читается не хуже
  функции, а писатель переменной — единственное место, где класс
  существует только ради переезда значения через `ctx.input`.
- Чеканка ключа идемпотентности событию. Ключ команды — идентичность
  намерения, и вызыватель может её выдумать. У факта такой
  идентичности нет: сгенерированный ключ выглядел бы как основание для
  дедупликации, не будучи им.
- Дедупликация в ядре. Она остаётся satellite-концерном, как записано
  в `port-idempotency`.
- Понятие раздела и упорядоченной доставки в ядре. Шина V1 порядка не
  обещает, и поле в `meta` ядра было бы обещанием без гарантии. Раздел
  остаётся словарём `@nestling/outbox`, который его и исполняет.
- Подсказка на семействах DI-токенов (`makeTokenFamily`) и на классах.
  Класс несёт имя, семейство — имя и параметр; отдельного места для
  текста починки у них нет.
- Открытые вопросы записи об outbox'е: константа DDL, факт
  `outbox.lag`, правило о значениях композиционного корня в
  `conventions.md` и третье правило `@nestling/eslint-plugin`.

## Impact

- `packages/nestling.app`: `src/pipeline/core/context/variable.ts` —
  вторая форма `provide`; `src/pipeline/core/pipeline.ts` — резолв
  зависимостей юнита на `bind`; `src/ports/bus.ts`,
  `src/ports/invoker.ts`, `src/ports/profile.ts` — ключ идемпотентности
  события.
- `packages/nestling.operations`: `src/families.ts` — тип-параметр
  словаря `meta` у `Port` и `Emitter`, `MetaOf` для вида `event`.
  Бюджет типов (`type-tests/BUDGET.md`) сверяется после правки.
- `packages/nestling.container`: `src/common.ts` — опции `makeToken`;
  `src/builder/container.builder.ts` — печать подсказок в ошибке о
  недостающих зависимостях.
- `packages/nestling.outbox`: `src/emitter.ts`, `src/plugin.ts`,
  `src/types.ts` — раздел аргументом `emit`; удаление алиаса шины и
  `src/core-limits.spec.ts`.
- `examples/users-service`: `src/persistence.ts`, `src/app.ts`,
  `src/users/endpoints/create-user.endpoint.ts`.
- Документация: `docs/design/pipeline.md`, `docs/design/operations.md`,
  `docs/design/container.md`, главы гайда 14 и 27, README пакетов
  `@nestling/app`, `@nestling/container`, `@nestling/operations` и
  `@nestling/outbox`, находки записи
  [ideas.md [2026-09-07]](../../../docs/decisions/ideas.md), строка 57 в
