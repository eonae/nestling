## Why

Секция конфига умеет читать ключи и проверять их схемами, но три соседние
задачи ей не по силам. Вычисляемое значение — адрес базы, собранный из хоста,
порта, пользователя и пароля, — выражается только классом-прокси поверх секции.
Общий `.env` на несколько сервисов не поддерживается: ключи секций
относительные, а способа сказать «этот сервис читает свои значения под
префиксом `SERVICE_1_`» нет. Описания полей, написанные `.describe()` рядом со
схемой, в снимок реестра не попадают, поэтому таблицу переменных для
документации по развёртыванию собрать не из чего.

Решение зафиксировано записью
[ideas.md [2026-09-06] «Конфиг: `derived`, `env({ prefix })`, описания полей
через конвертеры»](../../../docs/decisions/ideas.md) по ревью
[d/12](../../../docs/history/discussions/12-lifecycle-and-composition-review.md),
пункты 7–9. Целевое описание — [design/config.md](../../../docs/design/config.md),
разделы 1, 3 и 8.

## What Changes

- **`derived` — вычисляемое поле секции.** `makeConfig(prefix, record, derive)`
  принимает третий аргумент: функцию, которая получает типизированный
  конструктор `derived` и возвращает рекорд вычисляемых полей.
  `derived([deps], fn)` называет зависимости именами полей первого рекорда;
  `fn` получает их значения по порядку. Значение считается при валидации секции
  и заново при перезагрузке, если изменилась хотя бы одна зависимость. Ключа у
  поля нет, в `.keys` оно не входит.
- **Три правила `derived` держатся типами, а не проверками.** Имя зависимости
  берётся из `keyof` первого рекорда, поэтому опечатка — ошибка компиляции.
  Типы аргументов `fn` выводятся из схем зависимостей, поэтому неверная
  аннотация — тоже. Зависеть от другого вычисляемого поля нельзя: вычисляемых
  полей в первом рекорде нет.
- **Секретность наследуется.** Вычисляемое поле секретно, если секретна хотя бы
  одна его зависимость: печать проекции показывает вместо него `***`.
- **`env({ prefix })` — явный источник окружения с префиксом.** Читает
  `<prefix><KEY>` и отдаёт значение под `KEY`. Привязка
  `[[env({ prefix: 'SERVICE_1_' }), ['*']]]` перекрывает неявный `process.env`,
  поэтому `SERVICE_1_HTTP_PORT` выигрывает у `HTTP_PORT`, а `DATABASE_URL`
  остаётся общим. Секции и `.keys` остаются относительными.
- **`describeConfig({ converters })` — описания листьев в снимке.** Снимок
  берёт JSON Schema листа тем же диспетчером `leafJsonSchema`, что и OpenAPI:
  описание, умолчание и перечисление приходят из неё. Исход конвертации
  различим, поэтому «конвертера для вендора нет» не путается с «описания у поля
  нет». Вычисляемые поля помечены в снимке со списком зависимостей.
- `makeConfig.reloadable` и `makeConfig.family` принимают тот же третий
  аргумент.

## Capabilities

### New Capabilities

Новых нет: изменение расширяет существующие способности слоя конфига.

### Modified Capabilities

- `config-sections`: вычисляемое поле как часть объявления секции — форма,
  правила зависимостей, момент вычисления, ошибка `fn`.
- `config-registry`: `describeConfig(options)` принимает конвертеры и кладёт в
  снимок JSON Schema листа с исходом конвертации; вычисляемые поля помечены со
  списком зависимостей.
- `config-secrets`: секретность вычисляемого поля считается по его
  зависимостям.
- `config-reloadable`: вычисляемые поля пересчитываются при перезагрузке
  секции.
- `config-sources-binding`: `env({ prefix })` как источник окружения с
  префиксом и его место в порядке приоритета.

## Non-goals

- **Генератор таблицы переменных.** Фреймворк отдаёт снимок; markdown,
  колонки и порядок строк выбирает тот, кто пишет документацию.
- **Зависимости между секциями.** `derived` видит поля своей секции и только
  их.
- **Цепочки вычисляемых полей.** Зависеть от другого `derived` нельзя; правило
  держится типом.
- **Ленивое вычисление и кеш по обращению.** Значение считается один раз при
  валидации секции.
- **Префикс приложения в `makeApp` или в секции.** Отвергнут журналом: ключи
  перестали бы быть статическими, а `.keys` и глобы зависели бы от корня.
- **Обёртка `described(text, leaf)`.** Отвергнута журналом: описание живёт в
  схеме, как в OpenAPI.
- **Готовые источники `file()` и `vault()`.** Живут пакетами поверх
  `ConfigSource`, в ядре их нет и не будет.

## Impact

- **Код.** `packages/nestling.app/src/config/`: `declaration.ts` (тип
  вычисляемого поля и его вывод), `section.ts` (третий аргумент у трёх
  конструкторов), `project.ts` и `load.ts` (вычисление после валидации,
  пересчёт при перезагрузке), `redact.ts` (наследование секретности),
  `registry.ts` (опции снимка), `source.ts` (`env({ prefix })`), `index.ts`
  (экспорт `derived` и `env`).
- **Публичное API.** `makeConfig`, `makeConfig.reloadable`,
  `makeConfig.family` получают необязательный третий аргумент; `describeConfig`
  — необязательный аргумент опций. Существующие вызовы остаются валидными.
- **Зависимости.** Новых нет: диспетчер `leafJsonSchema` уже живёт в
  `@nestling/app` на схемном слое.
- **Документация.** `docs/design/config.md` (разделы 1, 3, 8),
  `docs/design/schemas.md` (строка таблицы потребителей конвертеров),
  `docs/guide/22-config-sources.md` (вычисляемое поле, префикс окружения,
  снимок с описаниями), README пакета `@nestling/app`, `docs/glossary.md`.
