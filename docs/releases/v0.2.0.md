# 0.2.0

> Все пакеты `@nestlingjs/*` выходят одной версией. В выпуск вошли
> коммиты от тега `v0.1.3` до тега `v0.2.0`, 12–13 сентября 2026. Старое
> имя удалено вместе с появлением замены: алиасов и обёрток в пакетах
> нет.

## Коротко

Декларация endpoint'а записывается иначе, и сразу в трёх местах.
HTTP-декларацию создаёт конструктор по методу: `httpEndpoint.get('/users',
{ … })` вместо словаря с полями `method` и `path`. Реализация операции
получила своё имя `httpEndpoint.implement(Operation, { … })`, а ключ
`operation` из словаря исчез. Команда называется первым аргументом
`cliEndpoint('users:list', { … })`. Пакет `@nestlingjs/openapi.zod`
переименован в `@nestlingjs/schema.zod`. Барели семи пакетов перестали
отдавать имена оператором `export *`, и имя без читателя наружу больше не
выходит. Появились три пакета: `@nestlingjs/drizzle.pg`,
`@nestlingjs/inbox` и `@nestlingjs/mcp`. В ядре появились две подсистемы,
трасса и метрики, и третий исход pre-шага — досрочный успех `done()`.
Документация вышла на сайт двумя языками.

## Декларация endpoint'а: было и стало

Два файла показывают обе формы конструктора: анонимную и реализацию
операции.

```typescript
// src/users/endpoints/upload-avatar.endpoint.ts — 0.1.3
export const UploadAvatar = httpEndpoint({
  method: 'POST',
  path: '/users/:id/avatar',
  input: multipart({
    fields: AvatarFields,
    files: { avatar: upload({ maxSize: 2 * MiB, mime: ['image/png'] }) },
  }),
  output: User,
  errors: [UserNotFound, AvatarRequired],
  doc: { summary: 'Загрузить аватар', tags: ['users'] },
  pipeline: transactional,
  handler: UploadAvatarHandler,
});

// src/users/endpoints/create-user.endpoint.ts — 0.1.3
export const CreateUser = httpEndpoint({
  operation: CreateUserOperation,
  pipeline: transactional,
  handler: CreateUserHandler,
});
```

```typescript
// src/users/endpoints/upload-avatar.endpoint.ts — 0.2.0
export const UploadAvatar = httpEndpoint.post('/users/:id/avatar', {
  input: multipart({
    fields: AvatarFields,
    files: { avatar: upload({ maxSize: 2 * MiB, mime: ['image/png'] }) },
  }),
  output: User,
  errors: [UserNotFound, AvatarRequired],
  doc: { summary: 'Загрузить аватар', tags: ['users'] },
  pipeline: transactional,
  handler: UploadAvatarHandler,
});

// src/users/endpoints/create-user.endpoint.ts — 0.2.0
export const CreateUser = httpEndpoint.implement(CreateUserOperation, {
  pipeline: transactional,
  handler: CreateUserHandler,
});
```

Дальше каждое изменение описано отдельно: что стало, как этим
пользоваться и где читать подробности.

## Декларация endpoint'а

### Конструктор по HTTP-методу

`httpEndpoint` перестал быть функцией и стал значением с шестью
конструкторами: `get`, `head`, `post`, `put`, `patch` и `delete`. Каждый
принимает путь первым аргументом и словарь вторым. Поля `method` и `path`
из словаря удалены.

```typescript
// src/users/endpoints/list-users.endpoint.ts — 0.1.3
export const ListUsers = httpEndpoint({
  method: 'GET',
  path: '/users',
  input: ListUsersInput,
  output: z.array(User),
  doc: { summary: 'Список пользователей', tags: ['users'] },
  pipeline: observability,
  handler: ListUsersHandler,
});
```

```typescript
// src/users/endpoints/list-users.endpoint.ts — 0.2.0
export const ListUsers = httpEndpoint.get('/users', {
  input: ListUsersInput,
  output: z.array(User),
  doc: { summary: 'Список пользователей', tags: ['users'] },
  pipeline: observability,
  handler: ListUsersHandler,
});
```

Литеральный тип пути берётся из первого аргумента. Path-параметры
выводятся по нему, и правило размещения полей проверяется так же, как
раньше. Обновление механическое: метод переезжает в имя конструктора,
путь становится первым аргументом, остальной словарь не меняется.

Правило ESLint `endpoint-has-layer` распознаёт вызов-член и берёт словарь
из последнего аргумента. Тексты отказов создания называют новую форму:
`httpEndpoint.get('/users', { … })` вместо
`httpEndpoint({ method: 'GET', path: '/users' })`. Подробнее — [глава 1](../guide/01-first-service.md).

> Почему: [deferred.md [2026-09-03] «Конструктор HTTP-декларации с методом в имени»](../decisions/deferred.md).

### Имя команды — первый аргумент `cliEndpoint`

`cliEndpoint` принимает имя команды первым аргументом. Поле `command` из
словаря удалено.

```typescript
// src/commands/greet.command.ts — 0.1.3
export const Greet = cliEndpoint({
  command: 'greet',
  input: GreetInput,
  output: GreetOutput,
  handler: async ({ args, shout }) => ({ greeting: greet(args[0], shout) }),
});
```

```typescript
// src/commands/greet.command.ts — 0.2.0
export const Greet = cliEndpoint('greet', {
  input: GreetInput,
  output: GreetOutput,
  handler: async ({ args, shout }) => ({ greeting: greet(args[0], shout) }),
});
```

Адрес endpoint'а стоит на одном месте у обоих транспортов: первым
аргументом конструктора. Подробнее — рецепт
[«CLI-утилита на тех же примитивах»](../recipes/cli.md).

### `httpEndpoint.implement` вместо ключа `operation`

Форма с операцией получила своё имя. Операция идёт первым аргументом, а
словарь называет только `pipeline`, `detached` и `on`. Ключ `operation`
удалён.

```typescript
// src/users/endpoints/create-user.endpoint.ts — 0.1.3
export const CreateUser = httpEndpoint({
  operation: CreateUserOperation,
  pipeline: transactional,
  handler: CreateUserHandler,
});
```

```typescript
// src/users/endpoints/create-user.endpoint.ts — 0.2.0
export const CreateUser = httpEndpoint.implement(CreateUserOperation, {
  pipeline: transactional,
  handler: CreateUserHandler,
});
```

Вместе с ключом ушли девять полей `never`, которыми словарь запрещал
объявлять то, что принадлежит операции: `method`, `path`, `bind`,
`rawBody`, `sse`, `input`, `output`, `errors` и `doc`. Словарь их теперь
просто не имеет. Рантайм-проверка осталась: она ловит переобъявление у
потребителя на JavaScript, которому типы не помогают. Подробнее —
[глава 14](../guide/14-features.md).

> Почему: [ideas.md [2026-09-12] «Две декларации HTTP вместо четырёх перегрузок `httpEndpoint`»](../decisions/ideas.md).

### Незаявленный отказ назван в диагностике

Хендлер, который возвращает отказ сверх списка `errors:`, отвергается
компилятором с текстом правила. Проверка называется
`ValidateHandlerFails` и печатает три поля: `returned` с кодами сверх
объявленных, `declared` с кодами из `errors:` и `hint` с починкой.

```text
Type '{ __error: "Handler returns a failure that is not declared in 'errors:'";
        returned: "conflict:alias_taken";
        declared: "not_found:link";
        hint: "add the definitions to 'errors:', or stop returning them from
               the handler"; }' ...
```

Литерал анонимный, а не именованный алиас. Компилятор печатает имя
алиаса вместо содержимого, и правило до читателя не доходило бы.

Позиция проверки у двух форм хендлера разная. У класса она стоит в слоте
`handler`. У функции — в возвращаемом типе: тип-параметр слота нужен
компилятору, чтобы типизировать параметры стрелки, и проверка в слоте
видела бы всё множество отказов вместо возвращённого.

## Пайплайн и ядро

### Досрочный успех pre-шага — `done()`

Pre-шаг завершается тремя исходами вместо двух: добавкой к контексту,
отказом и досрочным успехом. Досрочный успех приходит значением `done()`
из `@nestlingjs/app`. Следующие pre-шаги и хендлер не вызываются,
ответная фаза начинается с успеха без значения.

```typescript
// src/features/notifications/dedupe.layer.ts — 0.2.0
import { done, makePipeline } from '@nestlingjs/app';

const deduped = makePipeline().pre(
  async (ctx) => ((await seen(ctx)) ? done() : undefined),
  { done: true },
);
```

Шаг подключается с признаком `{ done: true }`. Без признака возврат
`done()` роняет запрос отказом: пайплайн, который досрочного успеха не
объявлял, обязан дойти до хендлера. Декларация обязана быть без
`output` — значения досрочный успех не несёт.

Правка аддитивная: приложение, которое `done()` не вызывает, ведёт себя
как раньше. Канал общий и про пайплайн, а не про дедупликацию: ни ключа,
ни хранилища, ни повтора в нём нет. На нём построен слой приёма
`@nestlingjs/inbox`. Подробнее —
[глава 16](../guide/16-durable-events.md).

> Почему: [ideas.md [2026-09-12] «Транзакционный приём: inbox как вторая половина гарантии outbox'а»](../decisions/ideas.md).

### Писатель переменной с зависимостями из контейнера

У `Var.provide` появилась вторая форма: список DI-токенов первым
аргументом, вычисление вторым. Зависимости резолвятся на фазе WIRE тем же
резолвером, что и классы-шаги пайплайна.

```typescript
// src/persistence.ts — 0.1.3
@Handler([Database])
export class ProvideDb {
  constructor(private readonly db: Database) {}

  handle(): { db: Database } {
    return { db: this.db };
  }
}

export const transactional = compose(
  authed,
  makePipeline()
    .pre(ProvideDb)
    .pre(Tx.provide<{ db: Database }>((ctx) => ctx.input.db.begin())),
);
```

```typescript
// src/persistence.ts — 0.2.0
export const transactional = compose(
  authed,
  makePipeline().pre(Tx.provide([Database], (_ctx, db) => db.begin())),
);
```

Класс-мост, который клал соединение в контекст только затем, чтобы
писатель прочитал его из `ctx.input`, перестал быть нужен. Слой
транзакции состоит из одного шага вместо двух, и регистрация моста в
`providers:` уходит вместе с ним.

Пример `users-service` этот слой не пишет вовсе: с этого выпуска
транзакцию везёт `db.transaction()` из `@nestlingjs/drizzle.pg`. Форма с
зависимостями остаётся для переменных, которые приложение строит само.

### Подсказка DI-токена — `makeToken(id, { hint })`

`makeToken` принимает вторым аргументом словарь с полем `hint` — текстом
починки на случай, когда провайдера для DI-токена в графе нет. Подсказка
печатается в отказе сборки и на идентичность DI-токена не влияет.

```typescript
// 0.1.3: текст починки вписан в идентификатор
const OutboxBus$ = makeToken<IMessageBus>(
  "@nestlingjs/outbox relay (add a bus transport to 'transports:', or remove " +
    'the outbox plugin)',
);
```

```typescript
// 0.2.0: идентификатор остаётся именем, починка стоит подсказкой
const OutboxBus$ = makeToken<IMessageBus>('@nestlingjs/outbox relay', {
  hint: 'or remove the outbox plugin',
});
```

Отказ о недостающих зависимостях печатает подсказку недостающего
DI-токена и подсказки потребителей, у которых она объявлена. Подробнее —
[design/container.md](../design/container.md).

### Ключ идемпотентности у события и свой словарь `meta`

`idempotencyKey` появился в `meta` у операций вида `event`, рядом с
`command`. У `request` его по-прежнему нет. Генерация ключа не
изменилась: ядро чеканит недостающий ключ только команде, а у события
ключ есть тогда, когда его передал издатель.

`Port<C, M>` и `Emitter<C, M>` принимают вторым тип-параметром словарь
`meta`, по умолчанию — `MetaOf<C>`. Сателлит объявляет свой словарь и
остаётся совместимым с ядром: значение
`Emitter<C, MetaOf<C> & { partitionKey?: string }>` присваивается
переменной типа `Emitter<C>`, потому что параметр метода контравариантен.
На этом стоит раздел записи outbox'а.

## Данные и доставка

### `@nestlingjs/drizzle.pg`

Новый пакет: соединение с PostgreSQL, транзакция запроса и адаптеры
хранилищ поверх drizzle-orm. Зависимости `drizzle-orm` и `pg` —
peer-зависимости.

```typescript
// src/persistence.ts — 0.2.0
import { drizzlePg } from '@nestlingjs/drizzle.pg';
import { pgOutboxStore } from '@nestlingjs/drizzle.pg/outbox';
import { pgInboxStore } from '@nestlingjs/drizzle.pg/inbox';

export const db = drizzlePg({ schema });
export const outboxStore = pgOutboxStore(db);
export const inboxStore = pgInboxStore(db);

export const transactional = compose(authed, db.transaction());
```

Соединение объявляется значением. Несколько соединений — несколько
вызовов с разными `name`, и конфиг-секция каждого становится членом
семейства: `DATABASE_URL` у соединения по умолчанию,
`DATABASE_ANALYTICS_URL` у `name: 'analytics'`. Соединение — ресурс: пул
открывается на фазе INIT, закрывается на SHUTDOWN и объявляет `health`,
поэтому каждое соединение попадает в `/readyz` отдельной проверкой.

Транзакция запроса — слой пайплайна `db.transaction()`. Он берёт
соединение из пула и открывает транзакцию, коммитит на успехе,
откатывает на отказе и возвращает соединение в пул на любом исходе.
Значение переменной контекста `tx` — экземпляр drizzle, привязанный к
этой транзакции, поэтому репозиторий пишет обычный запрос. Политика
`db.requiresTransaction(filter)` останавливает сборку на фазе ASSEMBLE,
если endpoint под фильтром слоя не объявил.

Подпути `./outbox` и `./inbox` дают реализации `OutboxStore` и
`InboxStore`: таблица объявлением drizzle и константа DDL у каждой.
Подробнее — [глава 11](../guide/11-database.md). Фабрики пакета в 0.3.0
получили префикс `make`: [заметка 0.3.0](./v0.3.0.md).

> Почему: [ideas.md [2026-09-11] «Соединение с базой: сателлит `drizzle.pg`, транзакция запроса переменной контекста»](../decisions/ideas.md).

### `@nestlingjs/inbox`

Новый пакет: транзакционный приём. Плагин `inbox({ transaction, store })`
отдаёт слой, политику предпосылки и секцию конфига. Внешних зависимостей
и драйверов базы у пакета нет.

```typescript
// src/users/endpoints/welcome-email.endpoint.ts — 0.1.3
@Handler([Logger$.auto, SeenKeys$])
export class WelcomeEmailHandler {
  constructor(
    private readonly logger: Logger,
    private readonly seen: Set<string>,
  ) {}

  async handle(payload: UserCreatedPayload, meta: { idempotencyKey: string }) {
    if (this.seen.has(meta.idempotencyKey)) {
      return new Ok(undefined); // повтор отсекался Set'ом в памяти
    }

    this.seen.add(meta.idempotencyKey);

    return this.send(payload);
  }
}

export const WelcomeEmail = implement(UserCreated, {
  subscriber: 'welcome-email',
  pipeline: makePipeline().pre(withIdempotencyKey()),
  handler: WelcomeEmailHandler,
});
```

```typescript
// src/users/endpoints/welcome-email.endpoint.ts — 0.2.0
@Handler([Logger$.auto])
export class WelcomeEmailHandler {
  constructor(private readonly logger: Logger) {}

  async handle(payload: UserCreatedPayload, meta: { idempotencyKey: string }) {
    return this.send(payload); // повтор до хендлера не доходит
  }
}

export const WelcomeEmail = implement(UserCreated, {
  subscriber: 'welcome-email',
  pipeline: compose(subscribed, appInbox.layer),
  handler: WelcomeEmailHandler,
});
```

Слой `appInbox.layer` читает ключ идемпотентности из конверта сообщения и
вызывает `claim` хранилища транзакцией вызывающего. Повторное сообщение
до хендлера не доходит: слой отвечает досрочным успехом. Ключ записи
составной — паттерн endpoint'а и ключ идемпотентности. Одно событие
уходит нескольким подписчикам с одним идентификатором записи outbox'а, и
каждый дедуплицирует сам.

Интерфейс `InboxStore` объявляет `claim` и `sweep`. Реализация в памяти
лежит подпутём `./testing`, адаптер к PostgreSQL — в
`@nestlingjs/drizzle.pg/inbox`. Ресурс `sweep` удаляет отметки старше
срока хранения по интервалу из секции конфига. Политика
`appInbox.requiresInbox(filter)` проверяет на фазе ASSEMBLE, что каждый
подписчик под фильтром композирован от слоя.

Сообщение без ключа идемпотентности роняет обработку. Слой читает
конверт, а не переменную контекста: отчеканенный ключ различался бы у
двух доставок одного сообщения.

Однократной отправку письма приём не делает. Он сужает окно повтора до
промежутка между эффектом и коммитом отметки. Подробнее —
[глава 16](../guide/16-durable-events.md).

### Outbox на новых примитивах

Раздел записи задаётся аргументом `emit`. Опция `partitionKey` у
`outbox({ … })` удалена.

```typescript
// src/users/endpoints/create-user.endpoint.ts — 0.1.3
await this.userCreated.emit({ id: user.id, name: user.name, email: user.email });

// src/app.ts — раздел объявлялся функцией на плагине
export const appOutbox = outbox({
  transaction: Tx,
  store: OutboxStore$,
  operations: [UserCreated],
  partitionKey: (payload) => payload.id,
});
```

```typescript
// src/users/endpoints/create-user.endpoint.ts — 0.2.0
await this.userCreated.emit(
  { id: user.id, name: user.name, email: user.email },
  { partitionKey: user.id },
);
```

Раздел называет место вызова, где значение уже есть. Тип зависимости
хендлера при этом называется `OutboxEmitter<typeof Op>`: это эмиттер ядра
с расширенным словарём `meta`, и он присваивается переменной типа
`Emitter<C>`. Хендлер, которому раздел не нужен, объявляет зависимость
прежним типом.

Вместе с опцией ушёл DI-токен-алиас шины, который существовал ради текста
починки в идентификаторе. Теперь починку несёт подсказка `makeToken`.

> Почему: [ideas.md [2026-09-07] «Транзакционный outbox: точка врезки, предпосылка транзакции и результат замера границы»](../decisions/ideas.md).

### `Nats-Msg-Id` и окно дедупликации потока

Долговечная публикация ставит заголовок `Nats-Msg-Id`, когда в конверте
есть ключ идемпотентности. Значение — тот же ключ, что едет в
`Nl-Idempotency-Key`.

Определение потока несёт окно дедупликации. Величина берётся из опции
фабрики `dedupeWindowMs`, умолчание — 5 минут.

```typescript
// src/main.ts — 0.2.0
const bus = nats({ servers: ['nats://localhost:4222'], dedupeWindowMs: 600_000 });
```

Существующий поток с более узким окном даёт запись `warn`. Переписать его
транспорт не может: retention, storage и лимиты остаются зоной
эксплуатации. Подтверждение записи несёт поле `duplicate`, и двойник
брокера дедуплицирует так же, как настоящий, поэтому тесты идут без сети.

Дедупликация брокера сужает поток повторов и транзакционной гарантии не
даёт: у транспорта нет транзакции приложения. Слой приёма
`@nestlingjs/inbox` остаётся обязательным.

## Наблюдаемость

### Трасса

Ядро объявило well-known ambient-переменную `Trace` со значением
`{ traceId, spanId, parentSpanId?, sampled }` и признаком
`propagate: true`. Pre-шаг `withTracing()` читает родительский контекст
из `ctx.raw.attributes`, создаёт идентификатор участка и кладёт
переменную.

```typescript
// src/observability.ts — 0.2.0
import { makePipeline, withRequestId, withTracing } from '@nestlingjs/app';

export const observability = makePipeline()
  .pre(withRequestId())
  .pre(withTracing())
  .finally(AuditOutcome);
```

Формат — W3C trace-context: заголовок `traceparent` по HTTP и поле
конверта по шине. Запись логгера несёт поле `traceId` рядом с
`requestId`. Типизированный HTTP-клиент отправляет `traceparent` текущего
контекста: клиент принимает читалку опцией `trace`, а саму читалку
экспортирует `@nestlingjs/app`.

```typescript
// src/api/client.ts — 0.2.0
import { traceparent } from '@nestlingjs/app';

export const api = makeClient(
  { createUser: CreateUser, getUser: GetUser },
  { baseUrl, trace: traceparent },
);
```

Переменную кладёт шаг, объявленный в пайплайне, как и `requestId`.
Подробнее — [глава 23](../guide/23-tracing.md).

### Метрики

Ядро получило интерфейс `Metrics` с методами `counter` и `histogram`,
корневой DI-токен `RootMetrics$` и семейство `Metrics$(scope)` по образцу
`Logger$`. Реализация по умолчанию ничего не делает и ничего не создаёт
на горячем пути. Настоящая задаётся опцией `makeApp({ metrics })`.

```typescript
// src/app.ts — 0.2.0
const exporter = prometheusExporter();

export const app = makeApp({
  features: [UsersFeature, QuotasFeature],
  plugins: [metricsPlugin(exporter)],
  transports: [nats({ name: 'events' }), http()],
  metrics: exporter,
});
```

Счётчик и длительность на endpoint и на вызов порта ядро считает само.
Точка записи — ответная фаза пайплайна, где известен исход. Инструментовка
включается сравнением корня с пустой реализацией по ссылке, поэтому
приложение без опции за метрики не платит.

Формат экспозиции ядро не знает. Пример `split-nats` получил адаптер
Prometheus на шестьдесят строк и endpoint `/metrics`: им и проверяется,
что публичной границы ядра стороннему экспортёру хватает.

В 0.3.0 подсистема переписана целиком: метрика стала декларацией, а
`Metrics`, `RootMetrics$`, `Metrics$` и опция `makeApp({ metrics })`
удалены. Что писать сегодня — [заметка 0.3.0](./v0.3.0.md).

> Почему: [ideas.md [2026-09-12] «Разбор обзоров d/10 и d/13: семь change'ей и одно отложение»](../decisions/ideas.md).

## MCP: инструмент агента — endpoint

Новый пакет `@nestlingjs/mcp` — транспорт-сателлит на публичных
примитивах ядра. Транспорт объявляется в `transports:` корня и
присоединяется к уже объявленному HTTP-серверу. Второго сокета не
появляется: обработчик встаёт в цепочку сервера рядом с обработчиком
`http()`.

```typescript
// src/app.ts — 0.2.0
import { mcp } from '@nestlingjs/mcp';

export const api = httpServer();

export const app = makeApp({
  features: [UsersFeature],
  transports: [
    api,
    http({ server: api }),
    mcp({
      server: api,
      info: { name: 'users-service', version: '1.0.0' },
      converters: [zodConverter()],
    }),
  ],
});
```

Инструмент — endpoint этого транспорта, и форм у него две, как у всех
транспортов.

```typescript
// src/features/users/tools/get-user.tool.ts — 0.2.0
export const GetUserTool = mcpTool.implement(GetUserOperation, {
  annotations: { readOnlyHint: true },
  pipeline: observability,
  handler: GetUserHandler,
});

// src/features/users/tools/search-users.tool.ts — 0.2.0
export const SearchUsersTool = mcpTool('search_users', {
  description: 'Найти пользователей по подстроке в адресе почты',
  annotations: { readOnlyHint: true },
  input: SearchUsersInput,
  output: SearchUsersOutput,
  pipeline: observability,
  handler: SearchUsersHandler,
});
```

Состав инструментов — это endpoint'ы, объявленные на транспорте MCP.
Отдельного списка `tools:` нет: состав виден там же, где состав любого
другого транспорта. Метод протокола `tools/list` строится в `serve` из
таблицы маршрутов, до того как сервер откроет сокет. Схемы переводятся в
JSON Schema теми же конвертерами, что у OpenAPI, и от валидатора пакет не
зависит. Метод `tools/call` исполняет endpoint через диспетчер: инструмент
проходит пайплайн своей декларации, её слои и её политики.

Отказ операции попадает к агенту отдельным исходом с кодом и деталями, а
не исключением протокола. Подробнее — рецепт
[«Отдать операции агенту по MCP»](../recipes/mcp.md).

## Схемы и OpenAPI

### `@nestlingjs/openapi.zod` стал `@nestlingjs/schema.zod`

Пакет-конвертер переименован. Экспорты не изменились: `zodConverter` и
`ZodConverterOptions`.

```typescript
// 0.1.3
import { zodConverter } from '@nestlingjs/openapi.zod';

// 0.2.0
import { zodConverter } from '@nestlingjs/schema.zod';
```

Обновление механическое: имя в `package.json` и в импортах. Конвертер
нужен не только документу — с этого выпуска его просит транспорт
командной строки для вопросов о недостающем входе.

> Почему: [ideas.md [2026-09-12] «Имя пакета-конвертера не называет потребителя: `openapi.zod` → `schema.zod`»](../decisions/ideas.md).

### Параметр описывается разобранной формой

Параметр `in: 'path'` или `in: 'query'` описывается схемой разобранной
формы, если она скалярная. Раньше он описывался входной формой всегда, и
поле со строкой на входе получало в документе `type: 'string'`.

```typescript
// src/api/operations.ts — схема поля
const CreateUserInput = z.object({
  dryRun: z.stringbool().optional(),
});
```

```json
// openapi.json — 0.1.3
{ "name": "dryRun", "in": "query", "schema": { "type": "string" } }
```

```json
// openapi.json — 0.2.0
{ "name": "dryRun", "in": "query", "schema": { "type": "boolean" } }
```

Схема `input` конвертируется до двух раз. Прогон с `io: 'input'` остаётся
источником тела и обязательности параметров. Прогон с `io: 'output'`
даёт схемы параметров и запускается только тогда, когда bind-карта
выносит хотя бы одно поле в путь или в query. Свойство переносится
целиком: вместе с типом приходят `description`, `default` и ограничения.

Схема с преобразованием во втором прогоне отказывает, и параметр
остаётся описанным входной формой. Сборка от этого не падает: вход уже
описан первым прогоном. Тело запроса описывается входной формой и после
изменения — в JSON строка и есть строка. Подробнее —
[глава 13](../guide/13-openapi-and-client.md).

## CLI: недостающий вход спрашивается

`cliEndpoint` принимает поле `missing: 'error' | 'prompt'`. Умолчание —
`'error'`, поэтому команда без поля ведёт себя как раньше.

```typescript
// src/commands/deploy.command.ts — 0.2.0
const DeployInput = z.object({
  env: z.enum(['dev', 'prod']).describe('Target environment'),
  force: z.boolean().describe('Skip the safety checks'),
  host: z.string().describe('Deployment host').meta({ default: 'localhost' }),
});

export const Deploy = cliEndpoint('deploy', {
  input: DeployInput,
  output: DeployOutput,
  missing: 'prompt',
  handler: async ({ env, force, host }) => ({ env, host, forced: force }),
});
```

Транспорт строит план вопросов на `serve` для каждой команды с
`missing: 'prompt'`. Вопрос выводится из формы поля: `enum` даёт выбор из
списка, `boolean` — подтверждение, скаляр — ввод строки. Описание поля
становится подсказкой, умолчание — значением по «Enter». Спрашиваются
только отсутствующие обязательные поля верхнего уровня скалярной формы.
Ответ подставляется в той же форме, в какой его дал бы флаг.

Неинтерактивная среда вопросы отключает: команда отвечает отказом
валидации, если поток ввода не терминал или задана переменная `CI`.
Команда с потоковым входом и `missing: 'prompt'` роняет `serve`: вопросы
и поток читают один `stdin`.

Фабрика `cli()` приняла четыре опции: `converters` для схем команд с
вопросами, `interactive` для явного решения вместо определения по среде,
`input` и `output` для потоков вместо `process.stdin` и `console`.
Подробнее — рецепт [«CLI-утилита на тех же примитивах»](../recipes/cli.md).

## Барели перечисляют имена

Корневые барели семи пакетов и барель подпути
`@nestlingjs/container/tokens` переписаны операторами `export { … }` и
`export type { … }`. Оператора `export *` из собственного модуля в них не
осталось.

Имя без читателя наружу больше не выходит. Внутри пакета оно работает как
раньше, и возврат в барель — одна строка. Затронуты `@nestlingjs/container`,
`@nestlingjs/transport.http`, `@nestlingjs/transport.nats`,
`@nestlingjs/common.misc`, `@nestlingjs/common.graphs`,
`@nestlingjs/models` и `@nestlingjs/common.static-server`. Импорт имени,
ушедшего из бареля, перестаёт разрешаться; перечень публичных имён
каждого пакета печатает раздел «Экспорты» его README.

> Почему: [ideas.md [2026-09-09] «Публичное имя — имя с читателем; барель перечисляет имена поимённо»](../decisions/ideas.md).

## Runtime-строки — английские

Всё, что процесс печатает или отдаёт наружу, написано по-английски:
сообщения отказов, логи, причины `hidden` и `detached`, `summary` и
`description` встроенных операций. Русскими остаются README, JSDoc,
комментарии и документация.

Правило держит линтер, а не дисциплина: общий конфиг ESLint запрещает
кириллицу в строковых литералах и шаблонных строках файлов `src/`. Спеки,
фикстуры и примеры под правило не попадают.

Вместе с переводом вышли четыре починки. Пустой ответ HTTP несёт
`content-length: 0` для всех статусов, кроме 204 и 304, поэтому редирект
перестал уходить с `transfer-encoding: chunked`. Диагностика формы класса
у `@Component` перестала срабатывать на `any`. Три JSDoc перестали
называть несуществующий метод `Ok.of`. Пакет `find-my-way` поднят до
`^9.7.0`, где закрыт advisory GHSA-c96f-x56v-gq3h.

## Удалено

- Ключ `operation` в словаре `httpEndpoint` и девять полей `never` рядом
  с ним: `method`, `path`, `bind`, `rawBody`, `sse`, `input`, `output`,
  `errors`, `doc`.
- Поля `method` и `path` в словаре анонимной HTTP-декларации.
- Поле `command` в словаре `cliEndpoint`.
- Опция `partitionKey` у `outbox({ … })`.
- Имя пакета `@nestlingjs/openapi.zod`.
- Имена, ушедшие из барелей семи пакетов и подпути
  `@nestlingjs/container/tokens`.

## Тестирование

- `spyMetrics()` из `@nestlingjs/testing` — записи метрик значениями, по
  образцу `spyLogger()`.
- Сниппеты скилла агента собираются, а не только компилируются: спека
  вызывает `assembleTest` для приложения из сниппетов, поэтому политику,
  незаявленный слой и ребро между фичами ловит `yarn verify`.
- Реализация `InboxStore` в памяти лежит подпутём
  `@nestlingjs/inbox/testing`.
- Двойник брокера NATS дедуплицирует по окну потока, поэтому тесты
  долговечной доставки идут без сети.
- Спеки примера с базой пропускаются без переменной `DATABASE_URL`, а CI
  поднимает PostgreSQL сервисом.

В 0.3.0 `spyMetrics()` удалён вместе с остальной подсистемой метрик:
[заметка 0.3.0](./v0.3.0.md).

- Документация разделилась на два жанра. `docs/guide/` — путь из глав со
  сквозной нумерацией, `docs/recipes/` — самостоятельные рецепты, где имя
  файла называет задачу. Приложение о переходе с NestJS стало
  `docs/from-nestjs.md`, раздел о проверках до первого запроса —

- Сайт документации собирается деревом страниц: адрес раздела — путь
  `/guide/01-first-service/`, а не якорь. Рядом лежит
  `nestling-docs.html` — вся документация одним самодостаточным файлом.
  Источников десять, включая design-доки и README публикуемых пакетов.
  Есть поиск по индексу, метаданные страницы, `sitemap.xml` и `404.html`.
- Сайт публикуется на GitHub Pages по адресу
  `https://eonae.github.io/nestling`, выкладка идёт по тегу `v*`.
- Документация вышла на двух языках. Английский основной, русский лежит в
  подпути `/ru/`; английский текст живёт в `docs/en/` зеркалом. README
  пакета стал парой: `README.md` английский и попадает на страницу пакета
  в реестре, `README.ru.md` русский.
- `yarn docs:audit` проверяет паритет пар: файл без пары, разошедшиеся

- Пример `users-service` переехал на PostgreSQL: схема drizzle, миграции

  транспорт MCP и три инструмента, `simple-cli` — команду с вопросами,
  `split-nats` — адаптер метрик.

## Для тех, кто собирает репозиторий

Публикация в реестр идёт по OIDC-обмену с доверенным издателем. Секрет
`NPM_TOKEN` и переменная `NODE_AUTH_TOKEN` из процесса публикации
удалены. Первая публикация нового имени выполняется человеком с рабочей
машины командой `node scripts/publish.mjs --interactive`, которая
спрашивает код 2FA перед отправкой каждого тарбола.

`@nestlingjs/eslint-plugin` получил третье правило `dependency-list`. Оно
выводит ожидаемый список DI-токенов из типов параметров конструктора и
сверяет его со списком в декораторе роли. Правило синтаксическое и
работает уровнем `warn`: гарантией остаётся компилятор. Расхождение длины
сообщается всегда, пустой список чинится автофиксом, а замена написанного
DI-токена предлагается как suggestion. Правило включено в общий конфиг
репозитория.
