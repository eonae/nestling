      `#modules: Set<string>` → `Map<string, Module>`; в `registerModule`

      починки — разделить одно значение импортом, дать конфигурациям разные
      имена, проверить дубли пакета в зависимостях
- [x] 1.3 Рантайм-тесты рядом с существующим «ignores duplicate module
      registration»: (а) то же значение дважды → фабрика провайдеров
      исполняется один раз; (б) общий модуль в двух ветвях `imports` → одна
      регистрация; (в) два разных значения с одним `name` → бросок с
      ожидаемым сообщением; (г) одинаковые по структуре опции не спасают —
      значения разные, бросок тот же

- [x] 4.1 `LoggerModule` → параметризованный `logging({ … })`: функция,

      фичами; параметр — то, что решает корень (D5 design.md)
- [x] 4.2 Инфра-модуль везёт свою конфиг-секцию (`makeConfig`, наружу —
      только keys-хэндл): уровень логирования приезжает из среды, а не
      параметром
- [x] 4.3 Слой наблюдаемости поставляется инфра-модулем как экспортируемое
      значение; политика в `main.ts` продолжает требовать именно его
      (идентичность ссылочная — проверить, что политика не сломалась)
- [x] 4.4 Тест: инфра фичи едет с фичей — при `select` без неё провайдеров
      инфра-модуля нет в графе; две co-located фичи, импортирующие одно
      значение, получают один инстанс
- [x] 4.5 Комментарии примера объясняют канон в двух строчках: «плагина как
