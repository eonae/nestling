# conditional-spread-rule

## Purpose

`@nestlingjs/eslint-plugin` с правилом `conditional-spread` держит одну
форму условной примеси поля в объектный литерал: `...(test && obj)` с
булевым по форме тестом. Правило синтаксическое: оно разбирает дерево
`@typescript-eslint/parser` без информации о типах, поэтому «булев» здесь
— свойство записи, а не типа. Тернарник с пустой ветвью
(`...(test ? obj : {})`) правило сворачивает в короткую форму, а автофикс
даёт только тогда, когда итоговый тест булев по форме: `x` и
`x !== undefined` расходятся на нуле и пустой строке, и выбор между ними
принадлежит автору. Короткая форма с небулевым тестом — та же ловушка с
другой стороны: `...(port && { port })` роняет поле на нулевом порте, и
замену правило предлагает suggestion'ом. Спред внутри литерала массива
правило не трогает. Рекомендуемый уровень — `error`.

## Requirements

### Requirement: Правило `conditional-spread` держит форму условной примеси

`@nestlingjs/eslint-plugin` SHALL экспортировать правило
`conditional-spread` именем `conditionalSpread` и SHALL регистрировать его
в объекте плагина по умолчанию.

Правило SHALL быть синтаксическим: оно SHALL разбирать дерево
`@typescript-eslint/parser` и SHALL NOT требовать информации о типах.
Пакет SHALL NOT получать рантайм-зависимостей.

Правило SHALL смотреть только на спред внутри объектного литерала.
Спред внутри литерала массива SHALL оставаться нетронутым: замена
`[...(test ? arr : [])]` на `[...(test && arr)]` бросает `TypeError` на
ложном тесте, потому что спред массива требует итерируемое.

Рекомендуемый уровень SHALL быть `error`: правило полно по форме, которую
разбирает, — пустой объектный литерал виден в тексте файла целиком.

#### Scenario: Правило подключается рядом с существующими

- **WHEN** конфиг подключает объект плагина по умолчанию и правило
  `@nestlingjs/conditional-spread`
- **THEN** правило работает, а `import-through-barrel`,
  `endpoint-has-layer` и `dependency-list` не меняются

#### Scenario: Спред в массиве не трогается

- **WHEN** в коде написано `const list = [...(ready ? items : [])]`
- **THEN** замечания нет

### Requirement: Примесь через тернарник с пустой ветвью

Правило SHALL сообщать о спреде в объектном литерале, аргумент которого —
тернарник с ровно одной пустой ветвью: `...(test ? obj : {})` или
`...(test ? {} : obj)`. Предлагаемой формой SHALL быть `...(test && obj)`
и `...(!test && obj)` соответственно.

Правило SHALL молчать, когда пусты обе ветви: предложить там нечего.

Замена SHALL сохранять поведение: спред ложного значения любого вида в
объектный литерал не добавляет ничего.

#### Scenario: Пустая ветвь вторая

- **WHEN** написано `{ ...(port !== undefined ? { port } : {}) }`
- **THEN** правило сообщает о длинной форме и предлагает
  `...(port !== undefined && { port })`

#### Scenario: Пустая ветвь первая

- **WHEN** написано `{ ...(port === undefined ? {} : { port }) }`
- **THEN** правило сообщает о длинной форме и предлагает
  `...(port !== undefined && { port })`

#### Scenario: Обе ветви пустые

- **WHEN** написано `{ ...(ready ? {} : {}) }`
- **THEN** замечания нет

### Requirement: Автофикс применяется только к булевому по форме итогу

Правило SHALL применять автофикс, когда **итоговый** тест — тот, что
окажется слева от `&&`, — булев по форме. Иначе правило SHALL сообщать о
длинной форме **без** автофикса: `x !== undefined` и `x` расходятся на
нуле и пустой строке, и выбор между ними принадлежит автору.

Булевыми по форме SHALL считаться: сравнение (`===`, `!==`, `==`, `!=`,
`<`, `<=`, `>`, `>=`), `in`, `instanceof`, отрицание `!x`, вызов
`Boolean(x)`, литералы `true` и `false`, а также `&&` и `||` с булевыми
обеими сторонами. Оператор `??` булевым SHALL NOT считаться.

Тип выражения SHALL NOT влиять на решение: идентификатор `ready` небулев
по форме, даже когда его тип `boolean`.

#### Scenario: Сравнение чинится автофиксом

- **WHEN** написано `{ ...(port === undefined ? {} : { port }) }` и
  запущен `eslint --fix`
- **THEN** в файле остаётся `{ ...(port !== undefined && { port }) }`

#### Scenario: Идентификатор фикса не получает

- **WHEN** написано `{ ...(ready ? { retry: true } : {}) }`
- **THEN** правило сообщает о длинной форме, `eslint --fix` файл не меняет

#### Scenario: Отрицание идентификатора фикса не получает

- **WHEN** написано `{ ...(!ready ? {} : { retry: true }) }`
- **THEN** фикса нет: итогом стал бы `ready && { retry: true }`, а он
  попадает под замечание о ловушке

#### Scenario: Связка сравнений чинится автофиксом

- **WHEN** написано `{ ...(a === 1 && b !== 2 ? { flag: true } : {}) }` и
  запущен `eslint --fix`
- **THEN** в файле остаётся `{ ...(a === 1 && b !== 2 && { flag: true }) }`

### Requirement: Отрицание пишется инверсией оператора только для равенства

При пустой первой ветви автофикс SHALL инвертировать оператор равенства:
`===` в `!==`, `!==` в `===`, `==` в `!=`, `!=` в `==`.

Реляционные операторы (`<`, `<=`, `>`, `>=`) SHALL NOT инвертироваться
заменой оператора: `!(a < b)` расходится с `a >= b` на `NaN`. Для них и
для остальных булевых форм автофикс SHALL писать `!(…)`. Внешнее
отрицание `!x` автофикс SHALL снимать.

#### Scenario: Равенство инвертируется оператором

- **WHEN** написано `{ ...(value == null ? {} : { value }) }` и запущен
  `eslint --fix`
- **THEN** в файле остаётся `{ ...(value != null && { value }) }`

#### Scenario: Реляционное сравнение оборачивается отрицанием

- **WHEN** написано `{ ...(size < limit ? {} : { size }) }` и запущен
  `eslint --fix`
- **THEN** в файле остаётся `{ ...(!(size < limit) && { size }) }`

### Requirement: Примесь через `&&` с небулевым тестом — ловушка нуля

Правило SHALL сообщать о спреде `...(x && obj)` в объектном литерале,
когда `x` небулев по форме. Сообщение SHALL называть причину: нулевое
число и пустая строка роняют поле, хотя значение задано.

Правило SHALL предлагать `x !== undefined` **suggestion'ом**, а не
автофиксом: это замена поведения, а не записи, и `eslint --fix` применять
её SHALL NOT.

#### Scenario: Число роняет поле

- **WHEN** написано `{ ...(httpPort && { port: httpPort }) }`
- **THEN** правило предупреждает о ловушке и предлагает suggestion
  `httpPort !== undefined && { port: httpPort }`

#### Scenario: Автофикс ловушку не трогает

- **WHEN** тот же код прогнан через `eslint --fix`
- **THEN** файл не изменился: suggestion применяет только редактор по
  выбору автора

#### Scenario: Булев тест замечания не получает

- **WHEN** написано `{ ...(httpPort !== undefined && { port: httpPort }) }`
- **THEN** замечания нет
