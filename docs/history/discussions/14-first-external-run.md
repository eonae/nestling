## 2. Исходный документ

Источник: тестовое приложение «сервис коротких ссылок» (2 фичи, 6 endpoint'ов, 8 тестов),
написанное по `@nestlingjs/agent-skill` 0.1.3 на Node 24.10 / TypeScript 7.0.2.
Каждый пункт подтверждён воспроизводимым наблюдением из этой сессии.

Приоритеты: **P0** — блокирует или вводит в заблуждение; **P1** — заметно стоит времени; **P2** — полировка.

### A. Скилл `@nestlingjs/agent-skill`

#### A1. Добавить `references/setup.md` — как запустить, а не только как написать — P0

**Наблюдение.** Скилл не содержит ни tsconfig, ни скриптов, ни упоминания `--conditions=testing` для node
(есть только `jest.config.js`). `--experimental-strip-types` не работает: V8 не исполняет стандартные
декораторы. Всё это пришлось выяснять опытным путём.

**Действие.** Один файл с:
- `tsconfig.json`: `target: es2023`, `module: nodenext`, `lib` с `esnext.disposable` (для `await using`),
  явно `experimentalDecorators` отсутствует;
- `package.json` scripts: `build`, `start`, `test` = `tsc && node --test --conditions=testing "dist/**/*.test.js"`;
- одно предложение: «type stripping невозможен из-за декораторов, dev-loop идёт через `tsc --watch`».

#### A2. Устранить противоречие между `pipeline.md` и `endpoints.md` про слои — P0

**Наблюдение.** `pipeline.md` показывает корень с политикой `everyEndpoint(...).hasLayer(observability)`.
`endpoints.md` показывает форму с операцией **без** `pipeline:`. Скопированные вместе — процесс не поднимается
(`it declares no pipeline, so it cannot be composed from layer 'observability'`). В разделе
«Rules the compiler or ASSEMBLE catches» этого правила нет.

**Действие.**
- Добавить правило №6 в SKILL.md: «Если корень объявил `hasLayer`, каждый endpoint — включая форму с
  операцией и `implement` — обязан объявить `pipeline:` или `detached: '<reason>'`».
- Привести примеры `endpoints.md` в соответствие: добавить `pipeline: observability` в `GetUser`.

#### A3. Упомянуть `@nestlingjs/eslint-plugin` — P1

**Наблюдение.** Плагин с правилом «подсказка про слой в декларации endpoint'а» существует и закрывает A2
дешевле, чем reference. Скилл не упоминает его ни разу.

**Действие.** В A1 (`setup.md`) — строка про установку и конфиг плагина. В SKILL.md, раздел «Where to look next»,
— строка «lint rules that enforce the module boundary and the layer hint».

#### A4. Добавить `references/diagnostics.md` — P1

**Наблюдение.** `description` скилла обещает «explaining a compile-time or assemble-time error», но
`errors.md` — про отказы-значения. Реальная ошибка незаявленного отказа выглядит как
`Type 'unknown' is not assignable to type '{ code: string; }'` и не называет причину (см. B1).

**Действие.** Таблица «что напечатал TS/ASSEMBLE → что это значит → что чинить»:
- `No overload matches this call` + `HttpHandlerClass<AnyPayload, …, never>` → хендлер возвращает отказ, которого нет в `errors:`;
- ошибка на строке `pipeline:` при форме с операцией → почти всегда ложная, смотри `handler`;
- `RoleShapeError<"A class with a handle method…">` в тексте ошибки `@Component` → игнорировать, смотри на строку про параметры;
- `DependencyLengthError<N, M>` → длина списка ≠ числу параметров;
- `1 edge(s) cross a feature boundary` → уже самодостаточное, оставить как есть.

#### A5. Покрыть транспортные вещи первого CRUD: редирект, статусы, `HttpResponse` — P1

**Наблюдение.** `redirect:` — обязательное поле декларации; без него `HttpResponse.redirect(...)`
превращается в `internal_error` в рантайме. В скилле `HttpResponse` упомянут одной строкой в `from-nest.md`,
`redirect:` — нигде.

**Действие.** В `endpoints.md` — подраздел «HTTP-форма ответа»: `redirect: 302` + `HttpResponse.redirect(url)`,
`HttpResponse.of(value, { headers, cookies })`, `Ok.created / accepted / noContent`. Правило про `redirect:`
— в список «Rules the ASSEMBLE catches».

#### A6. `testing.md`: добавить вариант для `node:test` — P2

**Наблюдение.** Раздел завязан на jest (`describe/expect`, `jest.config.js`). На Node ≥ 22 встроенного
раннера достаточно; условие резолва задаётся флагом `--conditions=testing`.

**Действие.** Второй блок с `node:test` + `node:assert/strict`, или сделать его основным.

#### A7. Закрыть дыры в покрытии пакетов — P2

**Наблюдение.** Ноль упоминаний: `outbox`, `subscriptions`, `models`, `transport.cli`, `client`, `eslint-plugin`.
`openapi()`, `nats()`, `makeClient` названы вскользь без ссылки на пакет.

**Действие.** В «Where to look next» — по строке на каждый пакет с одним предложением «когда нужен».
Для `outbox` и `client` — по короткому reference, это самые вероятные запросы после первого сервиса.

#### A8. `nestling-agent-skill --template` — P2

**Наблюдение.** Первые ~15 минут ушли на разведку структуры проекта, которую скилл описывает словами
(«Service skeleton»), но не даёт файлами.

**Действие.** Флаг у существующего bin, который кладёт `package.json`, `tsconfig.json`, `src/main.ts`,
`src/app.ts`, `src/app.config.ts` и один endpoint. Либо отдельный `create-nestling-app`.

### B. Фреймворк

#### B1. Диагностика незаявленного отказа: не называет причину и садится не на ту строку — P0

**Наблюдение.** Хендлер с `Output<X, typeof AliasTaken>` у операции, где `errors: [LinkNotFound]`:
- ошибка `TS2769: No overload matches this call … Type 'unknown' is not assignable to type '{ code: string; }'`
  — про `AliasTaken` ни слова;
- при наличии `pipeline:` в той же декларации появляется **вторая** ошибка на строке `pipeline:`
  (`typeof AuditOutcome is not assignable to type 'never'`), полностью ложная — тот же пайплайн
  компилируется в соседнем endpoint'е.

Причина — четыре перегрузки `httpEndpoint`; TS печатает последнюю. В jsdoc это признано, но про ложную
строку `pipeline:` не сказано.

**Действие (варианты, по убыванию предпочтения).**
1. Разделить перегрузки по именам: `httpEndpoint({ method, path, … })` для инлайн-формы и отдельное имя
   (например `serve({ operation, … })` / `httpHandle`) для формы с операцией. По две перегрузки на имя.
2. Брендированный тип ошибки в позиции `handler`, как уже сделано для `DependencyLengthError<1, 3>`:
   `UndeclaredFailError<'conflict:alias_taken', ['not_found:link']>`. Этот приём в контейнере работает
   отлично — перенести его.
3. Минимум: в jsdoc `httpEndpoint` добавить «ошибка на `pipeline:` при форме с операцией — побочная, смотри `handler`».

#### B2. `RoleShapeError` протекает в каждое сообщение `@Component` — P1

**Наблюдение.** При ошибке порядка/длины зависимостей у класса **без** `handle` текст содержит
`& RoleShapeError<"A class with a handle method is a handler, not a component", "@Handler">`.
Читается как утверждение о коде, и оно ложное.

**Действие.** Вынести проверку роли из интерсекции в позиции параметра в отдельный условный тип, который
срабатывает только когда у класса есть `handle`.

#### B3. Автосинхронизация списка зависимостей с конструктором — P1

**Наблюдение.** Порядок, длина и типы `@Component([...])` ловятся честно (проверены все три случая).
Но список дублирует то, что конструктор уже сказал; платит каждый файл.

**Действие.** Правило в `@nestlingjs/eslint-plugin` с автофиксом: по типам параметров конструктора
(`Config<typeof AppConfig>` → `AppConfig`, класс → класс, `Port<typeof Op>` → `Op.caller`,
`Emitter<typeof Op>` → `Op.emitter`, `Logger` → `Logger$.auto`, интерфейс с токеном `X$` в области видимости → `X$`)
генерировать/чинить список. Без reflect-metadata, только по исходнику.

#### B4. `Ok.of` — либо добавить, либо вычистить из документации — P1

**Наблюдение.** `Ok.of` встречается в 4 jsdoc (`app/dist/health/tokens.d.ts`,
`transport.http/dist/helpers.d.ts` ×2, и README транспорта показывает `new Ok({...})`). В `result.d.ts`
есть только конструктор, `created`, `accepted`, `noContent`.

**Действие.** Предпочтительно — добавить `static of<T>(value: T & NotFail<T>): Ok<T>`: симметрично
`Ok.created`, и именно его ожидают по jsdoc. Иначе — заменить в четырёх местах на `new Ok(...)` или голое значение.

#### B5. OpenAPI: `z.stringbool()` в query документируется как `type: string` — P1

**Наблюдение.** `bind: { dryRun: query() }` с `dryRun: z.stringbool().optional()` → в документе
`{"name":"dryRun","in":"query","schema":{"type":"string"}}`. Генератор клиента сделает `dryRun?: string`,
хотя семантика — булево.

**Действие.** В `@nestlingjs/openapi.zod` распознавать `stringbool` (и `z.coerce.number()` / `z.coerce.boolean()`)
и отдавать `{"type":"boolean"}` / `{"type":"number"}` для параметров `in: query`. Это единственный слой,
где строка на проводе означает не строку.

#### B6. Редирект уходит с `Transfer-Encoding: chunked` — P2

**Наблюдение.** `GET /r/:code` → `HTTP/1.1 302 Found`, `location: …`, `Transfer-Encoding: chunked`, тело пустое.
Ожидается `content-length: 0`.

**Действие.** В `sendResponse` для ответов без тела (3xx, 204) явно ставить `Content-Length: 0`
и вызывать `res.end()` без `write`.

#### B7. `find-my-way ≤ 9.6.0` с открытой CVE (GHSA-c96f-x56v-gq3h) — P2

**Наблюдение.** `npm audit` → 3 high, «No fix available». Затрагивает `transport.http` и `openapi`.

**Действие.** Пока апстрим не выпустил фикс — одно предложение в README транспорта: «уязвимость касается
HTTP/2, транспорт работает на `node:http` (HTTP/1.1); за обратным прокси не воспроизводится».
Плюс `overrides` в package.json, когда фикс появится.

#### B8. Dev-loop: watch с перезапуском и/или `create-nestling-app` — P2

**Наблюдение.** Type stripping закрыт декораторами навсегда; штатный путь — `tsc --watch` в одном
терминале и `node dist/main.js` руками в другом.

**Действие.** `nestling dev` (или скрипт в шаблоне из A8): `tsc --watch` + перезапуск `dist/main.js`
по завершении инкрементальной сборки. Реализуется на `tsc --watch --preserveWatchOutput` + `node --watch dist/main.js`
в одну строку через `concurrently` или без него — но пусть эту строку напишет фреймворк, а не пользователь.

#### B9. Один язык поверхности — P2

**Наблюдение.** README пакетов — русский; скилл — английский; сообщения компилятора и ASSEMBLE — английский;
в логе плагина OpenAPI — `reason="служебная ручка: сам документ"` внутри англоязычной строки.

**Действие.** Для OSS — английский на всей runtime-поверхности (лог, ошибки, jsdoc). README можно
оставить двуязычными, но runtime-строки перевести — это одно место в `@nestlingjs/openapi`.

#### B10. В README ядра — раздел «когда Nestling не нужен» — P2

**Наблюдение.** `GET /links/:code` = операция + отказ + хендлер + декларация + запись в фичу + слой.
В NestJS — один метод контроллера. Выигрыш реален (клиент, документация, раздельное развёртывание),
но окупается не на трёх ручках.

**Действие.** Три-четыре предложения честно: «если сервис не будет ни делиться на процессы, ни отдавать
типизированный клиент, ни документироваться из кода — возьмите Fastify». Это повышает доверие к остальному тексту.

---

### Что не трогать

Работает и не требует изменений — зафиксировано, чтобы не «улучшили» случайно:

- Сообщение об ошибке ребра между фичами (`1 edge(s) cross a feature boundary …`) — образцовое: обе фичи,
  оба класса, причина, рецепт. Это эталон для B1 и B2.
- Сообщение политики (`… declares no pipeline, so it cannot be composed from layer …` + подсказка про `detached:`).
- `DependencyLengthError<1, 3>` — брендированный тип ошибки работает, его и тиражировать.
- Прунинг по `RUN_FEATURES`: при `stats` ресурс `LinksStorage` не открывается — фазы реальные.
- `checkTopologies` как тест на раздельное развёртывание.
- Категория отказа → HTTP-статус без упоминания HTTP в хендлере.

## 3. Сверка с кодом (2026-09-12)

Каждый пункт проверен по коду, журналу решений и, где нужно, опытом.

**Скилл.**

- **A1** — подтверждено: ни tsconfig, ни скриптов; условие `testing`
  названо только для jest. Посылка про dev-loop неверна, см. B8.
- **A2** — подтверждено и шире: политика `hasLayer(observability)` в
  сниппете `app.ts` требует слой у всех HTTP-endpoint'ов, `GetUser` идёт
  без `pipeline:`, а `ListUsers` со своим `makePipeline().pre(withRequestId())`.
  Слои сравниваются по идентичности, оба endpoint'а политику не проходят.
  Спека сниппетов сверяет текст блоков с файлами и приложение из них не
  собирает.
- **A3** — подтверждено: правило `endpoint-has-layer` существует и в
  скилле не названо.
- **A4** — подтверждено. Тексты ошибок меняют change'и 67 и 68, справочник
  пишется после них.
- **A5** — подтверждено: `redirect:` обязательное поле, незаявленный
  редирект адаптер заменяет отказом. `endpoints.md` занимает 194 строки при
  потолке 200, нужен отдельный файл.
- **A6**, **A7** — подтверждено.
- **A8** — шаблона нет. Примеры репозитория собираются esbuild и
  запускаются `tsx`, шаблон требует решения о сборщике. Отложено.

**Фреймворк.**

- **B1** — подтверждено, ограничение известное. Запись [2026-09-04]
  «Отказы слоя» приняла ложную строку на `pipeline:` осознанно: перестановка
  перегрузок портит диагностику анонимной формы. Запись [2026-08-01]
  «Клиенты из контрактов: реализация» отвергла отдельный конструктор из-за
  дублирования перегрузок трёх форм хендлера; с change'а 33 форм две.
- **B2** — подтверждено, причина найдена. Когда класс не проходит
  ограничение параметра, TypeScript печатает само ограничение
  `new (...) => any`, и `any` в позиции экземпляра проходит под
  `HandlerShape`. Воспроизведено на `dist` контейнера; страховка
  `0 extends 1 & Inst` проверена на изолированном типе.
- **B3** — правило новое. Компилятор расхождение уже ловит, это эргономика;
  оценка понижена до P2.
- **B4** — подтверждено: `Ok.of` назван в трёх JSDoc и нигде не объявлен.
  В гайде и примерах `new Ok(` встречается в 20 файлах, `Ok.created(` в 14.
- **B5** — подтверждено частично. На zod 4.2.1 `z.coerce.number()` и
  `z.coerce.boolean()` в направлении `input` уже дают `number` и `boolean`;
  только `z.stringbool()` даёт `string`. Починка в `openapi.zod`
  невозможна: конвертер не знает, куда попадёт поле, а в теле запроса
  `stringbool` в JSON и есть строка.
- **B6** — подтверждено кодом и опытом на Node: `writeHead(302)` с `end()`
  без `content-length` даёт `transfer-encoding: chunked`; с
  `content-length: 0` заголовка нет; у 204 Node сам убирает тело.
- **B7** — посылка неверна. Advisory GHSA-c96f-x56v-gq3h (DDoS по HTTP/2,
  high, 2026-07-23) закрыт в 9.7.0, актуальная версия 9.9.0. Транспорт
  держит `^8.2.0` с января, и у восьмёрки починки не будет.
- **B8** — посылка неверна: `tsx` исполняет декораторы, примеры репозитория
  запускаются им (`start:dev`). Отдельная команда не нужна, нужна строка в
  `setup.md`.
- **B9** — подтверждено и шире: русские runtime-строки в четырёх пакетах.
  Причина `hidden` в `openapi`, причина пробы в `transport.http`, `summary`
  и `description` встроенных операций в `outbox` и `subscriptions`;
  последние попадают в OpenAPI-документ приложения.
- **B10** — раздела нет.

Раздел «Что не трогать» совпадает с тем, что закреплено спеками; план
ничего из него не задевает.
