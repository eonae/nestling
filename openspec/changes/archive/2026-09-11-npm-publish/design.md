# npm-publish — design

## Context

Репозиторий собирает восемнадцать пакетов и ни один не публиковал. Проверки
упаковки, которые есть, смотрят не туда: `scripts/smoke.mjs` грузит
`dist/index.js` настоящим Node'ом прямо в репозитории, поэтому видит битые
относительные специфаеры и не видит ничего из того, что отличает
установленный пакет от лежащего рядом. Замер показал: тарбол
`@nestlingjs/operations` — 97 файлов и 468 kB, из них половина — `src`,
спеки, `tsconfig.json`, `eslint.config.js` и `jest.config.js`.

Зависимости между пакетами записаны протоколом `workspace:*`. Реестр такого
протокола не знает: подставить версию обязан инструмент публикации, и
`npm publish`, вызванный напрямую, этого не делает.

Скоуп и состав первого релиза выбраны записью
[ideas.md [2026-09-10]](../../../docs/decisions/ideas.md); переименование
выполнено до этого change'а и здесь только фиксируется спеком.

## Goals / Non-Goals

**Goals:**

- Установленный пакет работает: тарбол несёт `dist`, зависимости названы
  версиями, точка входа резолвится.
- Пригодность к установке проверяется машиной, а не глазами, и до тега.
- Публикацию выполняет CI по тегу; с рабочей машины она невозможна.
- Страница пакета в реестре осмысленна: описание, лицензия, ссылка на
  репозиторий и каталог пакета в нём.

**Non-Goals:**

- Публикация `@nestlingjs/viz`, английские README, перевод `zod` в
  `peerDependencies`, автоверсионирование по conventional commits, сайт
  документации — перечислены в `proposal.md`.
- `sideEffects: false` в манифестах. Поле обещает бандлеру, что импорт
  модуля ничего не регистрирует, а реестр членов семейства DI-токенов в
  `@nestlingjs/container` — модульное состояние. Проверять это обещание
  сейчас нечем, а неверное поле молча ломает сборку потребителя.

## Decisions

### Состав тарбола задаётся `files`, а не отсутствием `.npmignore`

`files: ["dist"]` в каждом публикуемом пакете. `README.md`, `LICENSE` и
`package.json` реестр включает всегда, перечислять их не нужно.

`LICENSE` при этом лежит копией в каждом пакете: реестр берёт файл из
каталога пакета, и корневой в тарбол не попадает. Копия — цена того,
чтобы текст лицензии ехал вместе с кодом, а не только полем `license`.

Альтернатива — `.npmignore` в каждом пакете — отвергнута: список
исключений приходится пополнять при каждом новом виде файла в пакете, и
забытое исключение видно только по составу опубликованного тарбола.
Корневой `.gitignore` в этой роли не работает вовсе: `npm pack` читает
`.gitignore` только внутри самого пакета, поэтому строка `dist` в корне ни
на что не влияет — ни в плюс, ни в минус.

### Точку входа задаёт `exports`; `main` удаляется

Все пакеты — ESM (`"type": "module"`), у всех есть карта `exports`. Поле
`main` при этом либо дублирует её, либо, как у четырёх пакетов, указывает
на несуществующий `dist/out.js`. Node предпочитает `exports`, поэтому
битые значения ничего не ломали и потому дожили до сюда.

Удаление вместо починки: инструмент, который читает `main`, а не
`exports`, — это инструмент, не умеющий ESM, и рабочей точки входа для
него в пакете всё равно нет.

### Публикует CI по тегу `v*`

Workflow запускается на теге, ставит Node 24 из `.nvmrc`, делает
`yarn install --immutable`, `yarn verify`, проверку упаковки и
`node scripts/publish.mjs`. Скрипт публикует версии, уже записанные в
манифестах, — CI ничего не поднимает и ничего не коммитит. Версию
поднимает человек командой `yarn lerna version` и пушит тег.

Тарбол делает `yarn pack`, отправляет его `npm publish`. Разделение
вынужденное и полезное: подставить версии вместо протокола `workspace:`
умеет yarn, а provenance выдаёт только npm CLI. Проверка упаковки и
публикация получают при этом один и тот же артефакт, собранный одним и
тем же инструментом.

Provenance включается переменной окружения `NPM_CONFIG_PROVENANCE: true`
в шаге публикации, а не полем манифеста: с полем локальный `npm pack`
пытался бы получить OIDC-подпись там, где её взять неоткуда.

Права workflow: `id-token: write` для provenance, `contents: read`.
Ключ доступа к реестру — секрет `NPM_TOKEN` типа automation: обычный
ключ потребовал бы ввода второго фактора, которого в CI нет.

Отдельным файлом идёт workflow проверки на push и pull request: тот же
`yarn verify` без публикации. Без него тег публиковался бы из состояния,
которое никто не проверял.

### Проверка упаковки — установка тарболов в пустой проект

`scripts/pack-check.mjs`: упаковать все публикуемые пакеты, создать
временный проект вне репозитория, установить в него тарболы и
импортировать каждый пакет оттуда с `--conditions=testing`.

Это единственная проверка, которая видит три класса поломок сразу:
недостающий `files` (пакет без `dist`), неподставленный `workspace:*`
(установка падает на резолве) и зависимость, объявленная в
`devDependencies`, но импортируемая из `src`. Первые два невидимы для
`smoke.mjs` по построению, третий ловится тестом границы только там, где
тест границы есть.

Проверка не входит в `yarn verify`: она ставит пакеты из сети и занимает
минуты. Её вызывает workflow публикации и, при желании, человек — целью
`yarn pack:check`.

### Версия одна на все пакеты

`lerna.json` переходит на `version: "0.1.0"` и теряет `tagVersionPrefix:
"teamc."` — значение из другого репозитория, из-за которого теги
назывались бы `teamc.0.1.0`. Умолчание `v` даёт `v0.1.0`, на который
настроен триггер workflow.

## Risks / Trade-offs

- **Публикация необратима.** `npm unpublish` работает 72 часа и только
  когда пакетом никто не пользуется; после этого имя+версия заняты
  навсегда. → Проверка упаковки установкой обязательна до тега, и первый
  релиз идёт версией `0.1.0`, а не `1.0.0`.
- **Подстановка версий вместо `workspace:*` держится на `yarn pack`.**
  Если она не сработает, в реестр попадёт манифест, который не установится
  ни у кого. → `pack:check` упаковывает тем же `yarn pack`, ставит тарболы
  и падает раньше, чем это увидит реестр; он же читает манифест из тарбола
  и ищет в нём оставшийся `workspace:`.
- **Provenance требует публичного репозитория и запуска из GitHub
  Actions.** На приватном или при запуске из другого CI шаг публикации
  упадёт. → Репозиторий публичный; переменная задана в одном месте и
  снимается одной строкой.
- **README пакетов на русском.** Страница в реестре будет русской. Решение
  осознанное, цена — узнаваемость у внешнего читателя. → Открытый вопрос
  записи `ideas.md`, отдельная задача.
- **`@nestlingjs/common.*` публикуются как обычные пакеты.** Их можно
  установить напрямую, хотя API они не обещают. → Плашка README и
  описание в манифесте говорят, что пакет внутренний; гарантии даёт
  версия, общая с ядром.

## Migration Plan

1. Метаданные манифестов и `LICENSE` — правка, ничего не публикующая.
2. `scripts/pack-check.mjs` и цель `yarn pack:check`: прогон должен быть
   зелёным до всего остального.
3. Workflow проверки и workflow публикации.
4. Секрет `NPM_TOKEN` в настройках репозитория.
5. Тег `v0.1.0` — первая публикация.

Откат: до шага 5 откатывается git-revert'ом. После шага 5 отката нет —
только новая версия.
