# @common/misc

Внутренний пакет Nestling: общие вспомогательные типы и ядро работы со
схемами. Для самостоятельного использования не предназначен.

## Типы схем

Пакет задаёт словарь схем ядра поверх
[Standard Schema v1](https://standardschema.dev):

| Тип | Что это |
|---|---|
| `Schema` | псевдоним `StandardSchemaV1`; подходит любой валидатор, реализующий спецификацию (zod ≥ 3.24, valibot ≥ 1.0, arktype, TypeBox, Effect Schema) |
| `Infer<T>` | выходной тип схемы через `StandardSchemaV1.InferOutput`, либо `undefined`, если схема не задана |
| `DomainType<S>` | тот же выходной тип для схемы, которая задана всегда |
| `StandardSchemaV1` | реэкспорт, чтобы потребителю не устанавливать `@standard-schema/spec` |
| `Constructor<T>`, `Optional<T>`, `Nullable<T>`, `Nullish<T>` | вспомогательные типы |

Ядро не заглядывает внутрь схемы: спецификация даёт только валидацию и
вывод типов. Единственная зависимость пакета — `@standard-schema/spec`,
и она содержит только типы.

## Единая точка валидации

`validateSync(schema, value, message)` — единственное место, где ядро
проверяет данные схемой. Через него проходят `parsePayload` и
`parseMetadata`, проверка входа рантаймом пайплайна, поэлементная проверка
потоков и поля секций конфига, поэтому ошибка валидации везде выглядит
одинаково.

| Экспорт | Что делает |
|---|---|
| `assertStandardSchema(value)` | проверяет, что значение реализует спецификацию |
| `SchemaValidationError` | значение не прошло схему; несёт `issues`, нормализованные при создании (сегменты `{ key }` развёрнуты, символы приведены к строкам, индексы массивов оставлены числами), поэтому их можно сериализовать в JSON |
| `AsyncSchemaNotSupportedError` | `~standard.validate` вернул Promise. Не наследует `SchemaValidationError`: асинхронная проверка — ошибка конфигурации, а не плохой ввод |
| `NotAStandardSchemaError` | у объекта, переданного как схема, нет `~standard` с `version: 1` |
| `normalizeIssues(issues)` | нормализация, которой пользуется `SchemaValidationError`; доступна коду, который создаёт свои `issues` |

Валидация живёт здесь, а не в `@nestling/pipeline`, потому что
`@nestling/config` проверяет значения до появления первого запроса и не
должен зависеть от пайплайна. `@nestling/pipeline` реэкспортирует всё
перечисленное из своего `./schema`.
