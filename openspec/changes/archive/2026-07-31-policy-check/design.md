# design — policy-check: инварианты на собранном графе

## Context

Что уже есть и на что опираемся:

- **`App.#assemble()`** (`packages/nestling.app/src/app.ts`) — общая фаза 1 для
  `run()`, `check()` и тестового шва: регистрация kernel-модуля конфига,
  модулей, провайдеров и транспортов → `discoverEndpoints(plan.modules)` →
  `builder.build()` → `#assertRequiredTransports` → `#assertFormsSupported`.
  Всё, что может не сойтись, сходится здесь; собранный контейнер метод
  возвращает, но не запоминает. **Одна точка врезки обслуживает все три
  входа** — `run()`, `check()` и `@nestling/app/testing`.
- **`discoverEndpoints`** (`discovery.ts`) — чистая функция: обход дерева
  зарегистрированных модулей даёт `{ endpoint, moduleName }[]` и карту
  требуемых транспортов. Глобального реестра нет с #8, поэтому список ручек
  **полон и соответствует выбранной топологии** (невыбранные фичи в нём не
  участвуют вовсе) — это и есть предпосылка, которой ждал policy-check.
- **`EndpointDefinition`** (`packages/nestling.pipeline/src/metadata/endpoint.ts`)
  — значение с `transport` (токен), `pattern`, `pipeline?`, `errors?`,
  непрозрачным `binding?` и брендом. Транспортные конструкторы
  (`httpEndpoint`, `cliEndpoint`) — тонкие надстройки: свой словарь минус
  собственные ключи спредом уезжает в `makeEndpoint`.
- **`PipelineImpl`** (`packages/nestling.pipeline/src/core/pipeline.ts`) —
  иммутабельное значение: `emptyLayer()` заводит билдер с одним слоем,
  `withOwnLayer` возвращает **новый** экземпляр на каждый `.pre`/`.ok`/
  `.catch`/`.finally`, `compose` делает `flatMap` слоёв аргументов с
  `cloneLayer`, `bind` — новый экземпляр с материализованными юнитами.
- **`checkTopologies(spec, selections)`** (`@nestling/testing`) — матрица
  `select`-топологий поверх `assemble(...).check()`, перечисляющая все отказы
  разом.

Ограничения, которые формируют дизайн:

1. **`compose` плющит слои и клонирует их.** После композиции в
   `PipelineImpl.layers` не остаётся ни одной ссылки на исходное
   значение-слой: `cloneLayer` создаёт новые объекты. Значит, «идентичность
   слоя по ссылке» требует явно заведённого провенанса — из текущего
   состояния она невосстановима.
2. **Слои экспортируются константами, а юниты — нет.** `withIdentity(verify)`
   создаёт новую функцию на каждый вызов; сравнивать по юнитам нельзя.
3. **Проверка обязана предшествовать захвату ресурсов** — то есть жить в
   `#assemble()`, до `container.init()`.
4. **Пайплайн на ручке необязателен** (`pipeline?`), а декларация до `resolve`
   несёт несвязанный пайплайн — политики работают именно с ним.
5. **`TestAssemblySpec` в `@nestling/testing` — отдельный рукописный
   интерфейс**, а не `AssemblySpec & …`: новое поле корня туда не приезжает
   само.

## Goals / Non-Goals

**Goals:**

- инвариант «каждая ручка под фильтром композирована от такого-то слоя» —
  **гарантия сборки**, а не конвенция и не линт;
- идентичность слоя — ссылочная, без имён, строк и структурного сравнения;
- нарушение диагностируется до `@OnInit` и называет все провинившиеся ручки
  разом, с модулем-объявителем и способом починки;
- opt-out существует, но не бывает молчаливым: причина обязательна, список
  detached-ручек виден и на старте, и значением в отчёте;
- машинерия — открытая: `hasVar` (#16) и инварианты плагинов (#13) ложатся в
  тот же словарь, не заводя второго прохода по графу;
- ESLint остаётся честно вторым эшелоном: подсказка в редакторе, не гарантия.

**Non-Goals:** пользовательские предикаты над `explain()`, политики над графом
провайдеров, per-policy opt-out, автоматическое имя слоя, type-aware
ESLint-правило. См. Non-goals в [proposal.md](./proposal.md).

## Decisions

### D1. Словарь предикатов живёт в `@nestling/pipeline`, исполнение — в `@nestling/app`

`Policy`, `PolicySubject`, `PolicyViolation` и `everyEndpoint(...)` —
`@nestling/pipeline`. Там уже живут оба понятия, которыми оперирует словарь:
декларация (`EndpointDefinition`, `TransportRef`) и пайплайн (`Pipeline`,
провенанс композиции). `@nestling/app` политики **не понимает** — он собирает
`PolicySubject[]` из дискавери и вызывает `check`, а результат форматирует в
одну ошибку.

Форма интерфейса — минимальная и сериализуемая наружу:

```typescript
interface PolicySubject {
  readonly endpoint: AnyEndpointDefinition;
  readonly moduleName: string;
}

interface PolicyViolation {
  readonly pattern: string;
  readonly transport: string;
  readonly moduleName: string;
  readonly detail: string;   // «its pipeline is not composed from layer 'authedBase'»
}

interface Policy {
  describe(): string;                                   // для текста ошибки
  check(subjects: readonly PolicySubject[]): readonly PolicyViolation[];
}
```

`PolicySubject` структурно совпадает с `DiscoveredEndpoint` приложения —
конвертации не требуется, а зависимость остаётся однонаправленной
(`app → pipeline`).

*Отвергнуто:* держать словарь в `@nestling/app` — потребовало бы вытащить
наружу провенанс пайплайна и завести в прикладном пакете знание о внутренностях
ядра. *Отвергнуто:* отдельный пакет `@nestling/policy` — лишняя единица
упаковки ради ~150 строк, при том что оба понятия уже принадлежат ядру.

### D2. Идентичность слоя — провенанс композиции, а не имя, юниты или структура

`PipelineImpl` получает четвёртое поле — `sources: readonly PipelineImpl[]`,
ссылки на значения, из которых этот пайплайн произошёл:

| Операция | `sources` результата |
|---|---|
| `makePipeline()` | `[]` |
| `.pre` / `.ok` / `.catch` / `.finally` | `[this]` |
| `compose(a, b, …)` | `[a, b, …]` (сами аргументы, без разворачивания) |
| `bind(resolve)` | `[this]` |

`hasLayer(ref)` — обход этого DAG в ширину от пайплайна ручки: совпадение —
**ссылочное равенство** узла и `ref`. Ни одного сравнения по имени, по
`Function.name` юнита или по структуре слоёв.

Что из этого следует и почему это правильно:

- `pipeline: compose(base, authed)` содержит и `base`, и `authed`;
  `compose(compose(base, authed), extra)` — все три (обход транзитивен).
- `authed.pre(extra)` **содержит** `authed`: pre-тракт монотонен — деривация
  умеет только добавлять, снять уже объявленный юнит нельзя. Считать
  производный слой «другим» значило бы ловить ложные нарушения на честном коде.
- Связанный пайплайн (после `bind`) содержит свой несвязанный оригинал —
  политика не зависит от того, до или после WIRE её позвали. В V1 её зовут
  до, но инвариант держится и в интроспекции.
- Прибавка к памяти — цепочка ссылок длиной в число деривации слоя; живёт
  ровно столько же, сколько само значение-пайплайн (объявляется один раз на
  модуль).

*Отвергнуто:* **сравнение по имени слоя** — прямо отвергнуто в ideas.md
[2026-07-14]: заводит вторую идентичность рядом со ссылочной и ломается на
переименовании. *Отвергнуто:* **сравнение по идентичности юнитов** — юниты
рождаются фабриками (`withIdentity(verify)` — новая функция на каждый вызов),
сравнивать нечего. *Отвергнуто:* **структурное сравнение слоёв** (те же
позиции, те же виды юнитов) — эвристика, дающая и ложные срабатывания, и
ложные пропуски; «guarantee over convention» такого не терпит. *Отвергнуто:*
**идентичность объектов `Layer`** — `cloneLayer` в `compose` и в билдере
создаёт новые объекты, идентичность теряется по построению.

### D3. Фильтр — токен транспорта и RegExp по паттерну

```typescript
everyEndpoint({ transport?: TransportRef; pattern?: RegExp }).hasLayer(layer, label?)
```

- `transport` — **токен** (`HttpTransport$`), сравнение по ссылке: декларация
  несёт именно токен, и множество транспортов приложения выводится из графа.
  Строковое имя транспорта в фильтре не принимается — это была бы та же
  подмена идентичности именем, что и в D2.
- `pattern` — `RegExp` по строке `endpoint.pattern` (`'POST /api/users'`);
  метод и путь ловятся одним выражением. Строка не принимается намеренно:
  «строка — это префикс?» — ровно тот implicit, которого принцип не допускает.
- Пустой фильтр = все ручки приложения.
- `label` у `hasLayer` — свободная человекочитаемая метка **только для
  диагностики** (`hasLayer(authedBase, 'authedBase')`). Без неё текст говорит
  «the required layer»; выводить имя из переменной или стека — runtime magic.
- **Ручка без пайплайна — нарушение**, а не пропуск: «нет пайплайна» и «нет
  слоя» для инварианта неразличимы, а мягкая трактовка была бы дырой ровно в
  том месте, ради которого change делается.

Заметка для синхронизации доков: `docs/design/pipeline.md` §7 показывает набросок
`everyEndpoint({ transport: http })`, где `http` — провайдер транспорта. Пример
правится на токен (`HttpTransport$`); поведение уточняется, решение из ideas.md
не меняется.

### D4. `detached: '<причина>'` — транспорт-нейтральное поле ядра, opt-out тотальный

Поле живёт в `EndpointOptions`/`EndpointDefinition` (`@nestling/pipeline`), а не
в HTTP-словаре: причина отказа от инварианта не транспортная. Транспортные
словари объявляют `detached?: string` у себя (типизация), а рантайм уже
проезжает спредом `...rest` в `makeEndpoint` — реализация транспортов не
меняется.

- Тип поля — `string`, поэтому `detached: true` **невыразим**; для
  JS-потребителей `makeEndpoint` бросает в точке создания на не-строке и на
  пустой (после `trim`) строке — там же, где проверяются `errors:` и формы io.
- Opt-out **тотален**: detached-ручка исключается из всех политик. Адресация
  политики по имени вводила бы вторую идентичность (D2) ради случая, которого
  в V1 нет.
- Поле переживает `resolve` тем же способом, что `binding` и `errors`, —
  переносом из `EndpointState`.

**Аудит-поверхность — два канала:** `App.#announce()` печатает список
detached-ручек с причинами на старте (только когда список непуст), а
`CheckReport` несёт их значением (`CheckedEndpoint.detached?: string`) — тест
матрицы топологий сравнивает состав, а не парсит stdout. Это прямое требование
записи ideas.md: opt-out виден, а не спрятан в diff'е одного файла.

### D5. Точка проверки — конец `#assemble()`; диагностика — одна, агрегированная

Порядок внутри фазы 1: `builder.build()` → `#assertRequiredTransports` →
`#assertFormsSupported` → **`#assertPolicies`**. Сперва «граф вообще
собирается», потом инварианты на нём: политика, ругающаяся на ручку, чей
транспорт не зарегистрирован, увела бы автора не туда.

Все политики прогоняются до конца, нарушения складываются и бросаются одним
`Error`: заголовок с числом нарушений, затем строки
`  - POST /api/users (module 'module:users'): <detail>`, сгруппированные по
политике, и хвост-подсказка про `detached: '<причина>'`. Тот же принцип, что у
`checkTopologies`: ядро фейлится быстро на «не собралось», а на «собралось, но
нарушает» рассказывает всю историю — иначе починка идёт по одной ручке за
прогон.

### D6. Политики гоняются везде, где строится граф

Врезка в `#assemble()` даёт `run()`, `check()` и внутренний шов
`@nestling/app/testing` одним изменением; `checkTopologies` наследует прогон
через `check()` — матрица топологий начинает проверять инварианты по каждой
топологии, как обещано в ideas.md. Единственное, что требует явной работы, —
`TestAssemblySpec` в `@nestling/testing`: интерфейс рукописный, поэтому
`policies?` добавляется в него и пробрасывается в `wireApp`. Тестовый корень
инварианты **не ослабляет**: приложение, которое не собирается в бою, не должно
собираться в тесте.

### D7. ESLint-правило — отдельный пакет, синтаксическое, честно неполное

`packages/nestling.eslint-plugin` (`@nestling/eslint-plugin`), правило
`endpoint-has-layer`:

```jsonc
"@nestling/endpoint-has-layer": ["warn", {
  "layer": "authedBase",              // имя импортированного идентификатора
  "constructorName": "httpEndpoint",  // какой конструктор деклараций смотрим
  "pattern": "^/admin"                // необязательный фильтр по литералу path
}]
```

Опция названа `constructorName`, а не `constructor`, по факту реализации:
свойство `constructor` в JSON-схеме правила ломает валидацию конфига в
ESLint 9 (`Object.prototype.constructor` подменяется, и правило нельзя
сконфигурировать вовсе — «Value undefined should be string»).

Правило смотрит вызовы указанного конструктора с объектным литералом и
разбирает **только буквальные** случаи: `pipeline: authedBase`,
`pipeline: compose(base, authedBase)`. Оно **молчит**, когда значение
непрозрачно (идентификатор-параметр, вызов неизвестной функции, spread) и
когда есть `detached` со строкой. Сообщение прямо называет свой статус
(«hint — the graph policy is the guarantee»).

*Отвергнуто:* type-aware правило — типовая информация не отменяет фабрик и
параметров, гарантии не даёт, а стоит дорого в CI. *Отвергнуто:* класть правило
в существующий пакет — плагин ESLint обязан быть отдельной точкой установки, и
у него другой цикл релиза, чем у рантайма.

### D8. Точка расширения для #13 и #16

`everyEndpoint(...)` возвращает билдер, чьи методы возвращают `Policy`. Change
#16 добавляет в тот же билдер `hasVar(Var)` (проверка присутствия ambient-var
поверх того же обхода провенанса — переменная приезжает слоем), change #13 —
инварианты плагинов через уже существующий `hasLayer`. Ни второго прохода по
дискавери, ни второго поля в корне.

## Risks / Trade-offs

- **Политика проверяет присутствие слоя, а не его эффект** → слой, чей pre
  ничего не делает, инвариант формально удовлетворит. Митигация: это и есть
  объявленный контракт предиката (`hasLayer`, не `isAuthenticated`);
  документируется в design-доке и в README.
- **Деривация считается содержащей предшественника** (`authed.pre(x)` проходит
  `hasLayer(authed)`) → теоретически можно «содержать» слой и добавить сверху
  юнит, обесценивающий его эффект. Митигация: pre-тракт монотонен — снять
  накопленное поле нельзя; альтернатива (считать деривацию другим слоем) ловила
  бы ложные нарушения на легальном коде, что хуже.
- **Провенанс держит ссылки на предшественников** → цепочка `.pre` из N шагов
  удерживает N объектов. Митигация: пайплайны — декларационные значения,
  создаются один раз на модуль; порядок величин — десятки объектов на
  приложение.
- **`detached` может превратиться в массовый молчаливый opt-out** → митигация:
  строка-причина обязательна, список печатается на старте и приезжает в отчёт
  `check()`; политика «не более N detached» — осознанный non-goal (это
  инвариант ревью, а не сборки).
- **ESLint-правило создаёт ложное чувство гарантии** → митигация: статус
  зафиксирован в тексте сообщения, в README плагина и в гайде; правило по
  умолчанию `warn`, а не `error`.
- **Политики видят декларации, а не граф провайдеров** → «на собранном графе»
  здесь означает фазу (значения материализованы), а не источник данных.
  Митигация: для словаря v1 источник полон по построению — дискавери отдаёт
  ровно ручки выбранной топологии; расширение на граф провайдеров — отдельный
  кандидат из ideas.md [2026-07-13].

## Migration Plan

Change аддитивный, breaking-изменений нет:

1. `@nestling/pipeline` — провенанс (наблюдаемое поведение пайплайна не
   меняется: `sources` не участвуют ни в исполнении, ни в `bind`), затем поле
   `detached`, затем модуль политик.
2. `@nestling/app` — `policies?` в спеке и плане, врезка в `#assemble()`,
   detached в отчёте и в `#announce()`.
3. Транспортные словари — типизация `detached?`.
4. `@nestling/testing` — проброс `policies?`.
5. Новый пакет плагина + подключение в конфиг линта на примере.
6. Витрина и доки.

Откат — отбрасыванием верхних ступеней: без шага 2 поле политик просто не
существует в корне, без шагов 1–2 репозиторий остаётся в текущем состоянии.
Существующие приложения не трогаются: `policies` опционально, отсутствие поля
означает отсутствие проверок.

## Open Questions

- **Форма `pipeline.explain()` как публичного значения** — предпосылка для
  пользовательских предикатов; остаётся открытым вопросом ideas.md
  [2026-07-14] и в этот change не входит.
- **Метка слоя на самом значении** (`makePipeline({ as: 'authedBase' })`)
  вместо второго аргумента `hasLayer` — отложено до первого реального
  неудобства: поле на значении соблазняет использовать имя как идентичность,
  чего дизайн избегает.
