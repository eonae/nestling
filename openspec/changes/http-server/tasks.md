- [x] 1.1 Ветка перебазирована на `main` с влитым `resources-and-roles`: `@Resource`, `acquire`/`release` и создание экземпляров на INIT доступны

- [x] 1.3 `ServerDeclaration` рядом с `TransportDeclaration`: имя, токен, провайдер, дискриминатор `kind`; поля `capabilities` у сервера нет; `makeServerDeclaration` для конструкторов пакетов

- [x] 1.6 START в `App`: `container.start(signal)` → `serve` всех транспортов → `listen` всех серверов в порядке объявления
- [x] 1.7 SHUTDOWN в `App`: сигнал → `drain()` серверов в обратном порядке → `close()` транспортов → `destroy()` контейнера (`release` ресурсов, сервер среди них)

## 3. HTTP-сервер как ресурс

- [x] 3.1 Класс сервера ресурсом (`resourceProvider`: секция у экземпляра своя, поэтому не `@Resource`): захват создаёт `http.Server` без прослушивания, `release` отпускает дескриптор и идемпотентен после `drain()`
- [x] 3.2 Секция сервера: `HTTP_PORT`, `HTTP_HOST` у `'default'`, `HTTP_ADMIN_PORT`, `HTTP_ADMIN_HOST` у `name: 'admin'`
- [x] 3.3 `listen()` открывает сокет; `address()` отдаёт фактический адрес и `null` до `listen` и после дренажа
- [x] 3.4 `attach(handler)` строит цепочку обработчиков; при единственном обработчике цепочка вырождается в прямой вызов
- [x] 3.5 Ответ `404` от сервера, когда запрос не взял ни один обработчик
- [x] 3.6 `drain()`: закрытие простаивающих keep-alive, ожидание активных до `closeTimeout`, принудительное закрытие остатка
- [x] 3.7 Таймауты `node:http` (`requestTimeout`, `headersTimeout`, `keepAliveTimeout`) и `closeTimeout` — опции `httpServer()`
- [x] 3.8 `httpServer({ name?, … })` возвращает объявление ресурса; `httpServerKeys(name?)` — дескриптор ключей; `httpConfigKeys` удалён

## 4. Транспорт: что остаётся ему

- [x] 4.4 `close()` отменяет запросы в обработке и не трогает сокет
- [x] 4.5 Опции `port`, `host`, таймауты `node:http` и `closeTimeout` удалены из `HttpTransportOptions`
