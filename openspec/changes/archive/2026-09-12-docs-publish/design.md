## Context

Сайт документации собран и работает локально. `yarn docs:build` читает
источники из `scripts/site/sections.mjs`, строит модель разделов и печатает
две формы вывода: дерево страниц с адресами вида `/guide/01-first-service/`
и файл `nestling-docs.html` со всей документацией сразу. Есть поиск,
метаданные, `sitemap.xml` при заданном `--base`, локальный сервер
`docs:dev`. Вывод идёт в `docs/.site/` и не отслеживается git.

Не хватает двух вещей. Первая — сайт никуда не выкладывается: каталог
вывода живёт только на машине разработчика. Вторая — весь текст русский,
а пакеты уже в реестре, и их README читает тот, кто русского не знает.

Что есть в репозитории на входе:

| Источник | Файлов | Строк |
|---|---|---|
| `docs/guide/` | 22 | 5795 |
| `docs/recipes/` | 9 | 2446 |
| `docs/design/` | 14 | 4701 |
| `packages/*/README.md` | 21 | 1490 |
| страницы корня `docs/` | 5 | 617 |

Плюс `docs/decisions/roadmap.md` и `deferred.md` — 1215 строк, которые
сейчас тоже публикуются.

Прецедент двуязычия уже есть: корневой `README.md` английский, русская
пара лежит рядом как `README.ru.md`.

Решения, принятые до дизайна (ответы пользователя на вопросы записи
[ideas.md [2026-09-05]](../../../docs/decisions/ideas.md)):

- адрес сайта — `https://eonae.github.io/nestling`, GitHub Pages;
- публикация по тегу `v*`, не по каждому push в `main`;
- два полноценных языка, английский основной;
- английская документация — зеркало в `docs/en/`;
- README пакета в реестре — английский.

## Goals / Non-Goals

**Goals:**

- Сайт доступен по адресу и обновляется релизом без ручных действий.
- Читатель без русского получает документацию целиком: гайд, рецепты,
  design, справочник пакетов, глоссарий.
- Расхождение языков видно проверкой, а не глазами: забытая половина пары
  ломает `docs:audit`.
- Перевод 15 000 строк выполним пачками и параллельно: у переводчика есть
  словарь терминов и правила стиля.

**Non-Goals:**

- Свой домен, версионирование документации, машинный перевод на лету,
  перевод `decisions/`, `history/`, `openspec/`, `CLAUDE.md`, кода и
  `examples/` — перечислено в [proposal.md](./proposal.md).
- Автоматический перевод при сборке: сайт печатает то, что лежит в
  репозитории файлами.

## Decisions

### Р1. Английский без префикса, русский в `/ru/`

Адрес английского раздела — `/guide/01-first-service/`, русского —
`/ru/guide/01-first-service/`. Стартовые страницы: `/` и `/ru/`.

Сайт читает тот, кто нашёл пакет в реестре, поэтому язык по умолчанию —
язык реестра. Корневой README устроен так же, и правило получается одно на
репозиторий: английский — основной файл, русский — пара.

Каждая страница несёт `lang` своего языка и две ссылки `alternate`:

```html
<link rel="alternate" hreflang="en" href="…/guide/01-first-service/">
<link rel="alternate" hreflang="ru" href="…/ru/guide/01-first-service/">
<link rel="alternate" hreflang="x-default" href="…/guide/01-first-service/">
```

Ссылки печатаются только с `--base`: без него абсолютного адреса нет, а
относительный в `hreflang` не имеет смысла.

**Альтернативы.** Симметричные `/en/` и `/ru/` с развилкой в корне —
отвергнуто: развилка это лишний переход перед первым словом текста, а
пустой корень плохо выглядит в поиске. Русский по умолчанию — отвергнуто
по аудитории: внешний читатель приходит из реестра.

### Р2. Язык файла определяется его путём

Два правила вместо одного, потому что у README имя фиксировано снаружи.

| Что | Английский | Русский |
|---|---|---|
| Документация `docs/` | `docs/en/<путь от docs/>` | `docs/<путь>` |
| README пакета | `packages/<pkg>/README.md` | `packages/<pkg>/README.ru.md` |
| README репозитория | `README.md` | `README.ru.md` |

`docs/en/guide/01-first-service.md` — английская пара
`docs/guide/01-first-service.md`. Имя файла в паре совпадает: из него
берётся слаг, и адреса разделов различаются только префиксом языка. Это же
даёт переключатель языка: он меняет префикс и больше ничего.

Русские файлы остаются на месте. Ни одна ссылка из кода, скилла агента,
`decisions/` и `openspec/` не переезжает — а их сотни.

README пакета живёт по правилу реестра: страница пакета показывает
`README.md`, и подменить его нельзя. Английский текст становится основным
файлом, русский — парой `README.ru.md`. Манифесты не меняются:
`files: ["dist"]`, README реестр забирает отдельно от тарбола.

**Что не зеркалится.** Паритету подлежит ровно то, что публикуется, —
источники из `sections.mjs`. `docs/README.md` (карта папок и правила
ведения), `docs/decisions/` и `docs/history/` не публикуются и остаются
русскими.

**Известная шероховатость.** `docs/en/guide/` лежит на сегмент глубже, чем
`docs/guide/`, поэтому ссылка наружу `docs/` в переводе получает лишний
`../`. Таких ссылок семь на всю документацию (все — в `packages/`), а
битую ссылку ловит инвариант `broken-link`, который уже есть.

### Р3. Язык — измерение модели генератора, а не вторая сборка

`sections.mjs` остаётся одним списком источников: он описывает состав и
порядок, которые у языков общие. Рядом появляется список языков.

```js
export const LANGUAGES = [
  { code: 'en', prefix: [], label: 'English', default: true },
  { code: 'ru', prefix: ['ru'], label: 'Русский' },
];
```

Путь источника в `SECTIONS` записан по-русски (`docs/guide`), потому что
русский файл — оригинал. Резолвер переводит его в путь языка: для `en`
подставляет `docs/en/`, для README пакета — `README.md` против
`README.ru.md`.

`readModel(lang)` возвращает страницы одного языка; `page.route` начинается
с префикса языка. Дальше печать не меняется: адреса относительные, и
дерево языка ложится в подкаталог само.

Что печатается на язык и что один раз:

| Файл | Сколько |
|---|---|
| `<route>/index.html` | на язык (дерево целиком) |
| `nestling-docs.html` | на язык: `/nestling-docs.html`, `/ru/nestling-docs.html` |
| `search-index.json` | на язык: рядом со стартовой страницей языка |
| `favicon.svg`, `robots.txt`, `404.html`, `.nojekyll` | один на сайт |
| `sitemap.xml` | один, адреса обоих языков с `xhtml:link` |

Форма одного файла остаётся одноязычной: файл пересылают, чтобы прочесть,
а не чтобы выбрать язык.

**Альтернатива** — два запуска сборки с флагом `--lang` и разными
каталогами вывода. Отвергнуто: `sitemap.xml`, `404.html` и переключатель
языка требуют знания обоих деревьев сразу, а два запуска этого знания не
дают.

### Р4. Паритет проверяют сборка и аудит, каждый своё

Сборка падает, когда модель языка не строится: файл назван в оглавлении и
отсутствует, файл лежит в папке без строки в оглавлении. Это правило уже
есть, и для зеркала оно работает без правок — оглавление английской папки
лежит в `docs/en/<папка>/README.md`.

Аудит проверяет то, чего сборка не видит:

| Инвариант | Уровень | Что ловит |
|---|---|---|
| `lang-parity` | ERROR | у публикуемого файла нет пары в другом языке |
| `lang-outline` | ERROR | оглавления пары называют разный состав файлов |
| `lang-link` | ERROR | ссылка внутри `docs/en/` ведёт в русский файл, а внутри русского текста — в `docs/en/` |
| `lang-cyrillic` | ERROR | кириллица в английском файле вне блоков кода и имён собственных |
| `lang-glossary` | ERROR | термин русского глоссария не назван в английском |
| `lang-stale` | WARN | плашка «сверено с кодом» английской главы старше даты русской пары |

Отставание перевода — предупреждение. Перевод главы догоняет её правку
тем же change'ом, но правило, которое ломает сборку на дате, останавливало
бы работу на ровном месте.

**Плашка в английской главе** пишется по-английски:
`verified against `<пример>` (YYYY-MM-DD)`. Аудит ищет форму по языку
файла.

**Сниппеты в английских главах** несут английские комментарии. Код примера
остаётся русским: `examples/` не переводится, а сверка идёт по дате
коммита примера, не по тексту сниппета.

### Р5. Планы уходят с сайта

`docs/decisions/roadmap.md` и `deferred.md` перестают быть источниками.

Это рабочие списки того, кто пишет фреймворк: roadmap меняется каждым
change'ом, deferred — почти каждым. Их английская пара устаревала бы
быстрее, чем выходила, а польза внешнему читателю близка к нулю: он хочет
знать, что работает сегодня, и это говорят `design/` с бейджем «целевое
состояние V1» и README пакетов.

Ссылки на них из публикуемых текстов переписываются в адрес GitHub —
правило `githubHref` уже действует для `ideas.md` и `history/`.

**Альтернатива** — публиковать их только по-русски. Отвергнуто: страница
на другом языке посреди английского дерева ломает и переключатель, и
`hreflang`, и паритет как правило.

### Р6. Словарь терминов — первый переведённый файл

`docs/en/glossary.md` переводится раньше остального и дальше служит
словарём: в таблице глоссария у каждого термина стоит его русский
оригинал. 15 000 строк переводятся пачками и разными сессиями, и без
единого словаря `Fail`, «фича», «порт», «сателлит» и «пре-юнит» получат в
разных главах разные английские имена.

Инвариант `lang-glossary` держит словарь полным: термин, названный в
русском глоссарии, обязан быть в английском.

### Р7. Правила английского текста — часть скилла `docs-style`

Скилл получает раздел об английском тексте, а его линтер — второй список
запрещённых слов. Язык файла линтер определяет по пути: `docs/en/**`,
`packages/*/README.md` и корневой `README.md` — английские, остальное
русское.

Английский список начинается с того же класса слов, что русский: обороты,
которые ничего не сообщают (`leverage`, `seamless`, `robust`,
`comprehensive`, `powerful`, `simply`, `just`, `delve`). Правила те же:
сначала «что», потом «как», потом «почему»; одна мысль на предложение;
термины из глоссария.

### Р8. Публикация — отдельный workflow по тегу

`.github/workflows/docs.yml`:

- триггеры: `push` с тегом `v*` и `workflow_dispatch` (ручной запуск для
  проверки и для выкладки без релиза);
- права: `pages: write`, `id-token: write` — их требует `deploy-pages`;
- `concurrency: pages` без отмены: две выкладки подряд не должны
  перегонять друг друга;
- шаги сборки: `corepack enable`, `setup-node` по `.nvmrc`,
  `yarn install --immutable`, `yarn docs:build --base https://eonae.github.io/nestling`,
  `actions/upload-pages-artifact` с `docs/.site`;
- шаг выкладки: `actions/deploy-pages` в окружении `github-pages`.

Тег ставит человек, и тем же тегом публикуются пакеты — сайт и реестр
показывают одно состояние.

В `ci.yml` добавляются два шага: `yarn docs:audit` и `yarn docs:build`.
Расхождение оглавлений или битая ссылка тогда ломают ветку, а не тег, на
котором публикация уже идёт.

**Источник Pages выбирается в настройках репозитория** («GitHub Actions»
вместо ветки). Это единственное действие вне репозитория, и его делает
пользователь.

### Р9. Как выполняется перевод

Порядок работ внутри `apply`:

1. `docs/en/glossary.md` — словарь терминов.
2. Каркас зеркала: оглавления `docs/en/guide/README.md`,
   `docs/en/recipes/README.md`, `docs/en/design/README.md`, стартовая
   `docs/en/index.md`.
3. Страницы корня: `guarantees.md`, `from-nestjs.md`, `conventions.md`.
4. Гайд — 21 глава, пачками по части.
5. Рецепты — 8 файлов.
6. `design/` — 13 доков.
7. README 21 пакета: русский текст переезжает в `README.ru.md`,
   английский встаёт на его место.

Каждая пачка кончается линтером и `docs:audit`. Перевод механический по
готовым правилам, и его выполняют отдельные агенты, а не главная сессия.

## Risks / Trade-offs

- **Каждый следующий change правит два текста вместо одного.** →
  Инвариант `lang-parity` ловит забытую половину, а `lang-stale` остаётся
  предупреждением, чтобы отставание перевода не блокировало работу. Цена
  принята осознанно: без второй половины английский сайт мёртв через
  пять change'ей.
- **Перевод пишет агент — риск гладкого пустого текста.** → Английский
  список запрещённых слов в линтере плюс правила скилла. Текст, который
  не проходит линтер, не попадает в `main`.
- **Термины перестанут совпадать между пачками.** → Словарь переводится первым, и
  `lang-glossary` держит его полным.
- **Сайт отстаёт от `main` между релизами.** → Принято: сайт описывает
  опубликованную версию. Ручной запуск workflow даёт выкладку без тега,
  когда это нужно.
- **Pages не включены в настройках — первая выкладка упадёт.** → Шаг в
  `tasks.md` с инструкцией пользователю; ошибка `deploy-pages` называет
  причину прямо.
- **Глубина ссылок в зеркале отличается на сегмент.** → Семь ссылок на
  всю документацию, проверяет `broken-link`.
- **Объём перевода — 15 000 строк за один change.** → Дробится по
  источникам, идёт агентами, точка возобновления — чекбоксы `tasks.md`.

## Migration Plan

1. Генератор учится языкам: `LANGUAGES`, резолвер путей, печать на язык,
   переключатель, `hreflang`, `sitemap.xml` с обоими деревьями,
   `.nojekyll`. Сборка на этом шаге печатает один язык — английского
   зеркала ещё нет, и его отсутствие ломает сборку сознательно.
2. Словарь и каркас зеркала: `docs/en/glossary.md`, оглавления папок,
   стартовая страница. Сборка снова зелёная, английское дерево пустое по
   содержанию, но полное по составу.
3. Перевод по источникам (Р9), пачками, с линтером после каждой.
4. README пакетов: русский в `README.ru.md`, английский на его место.
5. Проверки: инварианты `lang-*` в `docs:audit`, английский список слов в
   `docs-style`, правила двуязычия в `docs/README.md` и `CLAUDE.md`.
6. Публикация: `docs.yml`, шаги документации в `ci.yml`, включение Pages
   пользователем.
7. Спеки, README генератора, `roadmap.md`, `ideas.md`, `archlog.md`.

Откат: `docs.yml` удаляется, Pages выключается в настройках. Зеркало и
проверки остаются — они полезны без публикации.

## Open Questions

- **Свой домен.** `nestling.dev` или `nestlingjs.dev` дают короткий адрес
  и не зависят от имени аккаунта. Решается, когда домен куплен: `CNAME`
  в выводе сборки и запись DNS.
- **Английская стартовая страница как витрина.** Сейчас `docs/index.md`
  описывает документацию. Отдельная страница проекта с примером кода и
  установкой — работа для отдельного change'а.
