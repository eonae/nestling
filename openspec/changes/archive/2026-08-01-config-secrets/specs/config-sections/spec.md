## MODIFIED Requirements

### Requirement: Секция конфига — рекорд полей со Standard-Schema-листьями

`makeConfig(prefix, record)` (пакет `@nestling/config`) SHALL объявлять секцию
конфигурации, где `record` — **объект полей**, а значение каждого поля — либо
произвольная схема Standard Schema v1, либо обёртка `from(key, schema)`, либо
обёртка `secret(leaf)` поверх любой из них.
Перечислимость полей SHALL браться с уровня JS-объекта; интроспекция вендорских
схем SHALL NOT использоваться ни для деривации ключей, ни для реестра, ни для
привязки.

Обёртки листа SHALL быть композируемы единственным порядком: `secret()`
снаружи, `from()` внутри (`secret(from('DATABASE_URL', z.url()))`). Обратный
порядок SHALL отвергаться типами и SHALL давать ошибку в точке объявления,
называющую секцию, поле и канонический порядок. Ни одна обёртка SHALL NOT
участвовать в валидации значения: проверяет только лист-схема.

Объявление SHALL быть значением: ни декоратора, ни регистрации секции в
`providers`/`imports` модуля, ни ключа `configs:` у модуля SHALL NOT
требоваться.

#### Scenario: Секция объявляется рекордом полей

- **WHEN** объявлено
  `makeConfig('orders', { maxItems: z.coerce.number().default(100) })`
- **THEN** объявление проходит без обращения к внутренностям схемы, а перечень
  полей секции берётся из ключей рекорда

#### Scenario: Лист — любая реализация Standard Schema

- **WHEN** в поле рекорда передана схема любого валидатора, реализующего
  Standard Schema v1
- **THEN** секция работает так же, как со схемой любого другого вендора —
  ветвлений по `~standard.vendor` в пакете SHALL NOT быть

#### Scenario: Объект, не реализующий спеку, отвергается

- **WHEN** в поле рекорда передано значение без `~standard` версии 1
- **THEN** бросается `NotAStandardSchemaError`, сообщение называет секцию и
  имя поля

#### Scenario: Лист обёрнут `secret()`

- **WHEN** объявлено `makeConfig('orders', { apiToken: secret(z.string()) })`
- **THEN** поле объявлено как обычное (ключ `ORDERS_API_TOKEN`, тип `string`,
  та же валидация) и дополнительно помечено секретным

#### Scenario: Композиция `secret(from(...))`

- **WHEN** объявлено `secret(from('DATABASE_URL', z.url()))`
- **THEN** ключ — `DATABASE_URL`, поле секретно, префикс не применяется

#### Scenario: Обратный порядок обёрток

- **WHEN** объявлено `from('DATABASE_URL', secret(z.url()))`
- **THEN** объявление отвергается: тип не сходится, а рантайм-ошибка называет
  секцию, поле и канонический порядок `secret(from(...))`
