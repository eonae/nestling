## ADDED Requirements

### Requirement: Привязка передаётся `run()`, `check()` и `assembleTest()` списком `bind()`

Привязки SHALL приходить опцией `config` метода, который поднимает
источники, — `run(options?)` боевого корня, `check(args?, options?)` и
`assembleTest(app, options?)` тестового корня, — а не полем декларации.
Опция SHALL принимать список `readonly Binding[]`, где каждый элемент —
результат `bind(source, options?)`:

```ts
bind(source: ConfigSource, options?: {
  keys?: ConfigKeys<string> | ConfigGlob; // умолчание '*'
  optional?: boolean;                     // умолчание false
  timeout?: number;                       // умолчание 10000 (мс)
}): Binding
```

`keys` SHALL ограничивать источник указанной секцией или глобом; без
`keys` источник SHALL отвечать за любой объявленный ключ любой секции.
`optional` SHALL пропускать источник вместо отказа фазы 0, если его
`init()` отклонился. `timeout` SHALL быть границей ввода-вывода `init()`
этой привязки; истечение срока SHALL отказывать фазой 0 с именем
источника — если привязка `optional`, то пропуском хода вместо отказа.

Порядок элементов списка SHALL задавать приоритет, как и раньше: ключ
разрешается первой привязкой, чей `keys` его покрывает и чей источник
вернул значение, отличное от `undefined`.

`@nestlingjs/app` SHALL экспортировать значение `defaultSources` —
`[bind(env()), bind(dotenv('.env'), { optional: true })]`. `run()` без
опции `config` SHALL использовать `defaultSources`; переданный список
SHALL заменять умолчание целиком, а не дополнять его. Приложению, которому
достаточно умолчания, писать про конфиг SHALL NOT требоваться.

`discover()` конфига SHALL NOT читать и SHALL NOT принимать. Поля `config`
у `makeApp` SHALL NOT существовать: тип декларации закрыт, привязка —
аргумент метода, а не декларации.

#### Scenario: Без опции — умолчание `defaultSources`

- **WHEN** вызвано `app.assemble(args).run()` без опции `config`
- **THEN** секции читаются `defaultSources`: сперва `env()`, затем
  необязательный `dotenv('.env')`

#### Scenario: Переданный список заменяет умолчание целиком

- **WHEN** вызвано `run({ config: [bind(vault())] })`
- **THEN** `env()` и `dotenv('.env')` не поднимаются вовсе — список из
  опции не дополняет `defaultSources`, а заменяет его

#### Scenario: Порядок задаёт приоритет

- **WHEN** список — `[bind(fileSource), bind(env())]`, и ключ есть в обоих
  источниках
- **THEN** побеждает значение `fileSource`

#### Scenario: `keys` ограничивает область источника

- **WHEN** привязка — `bind(fileSource, { keys: ordersKeys })`
- **THEN** источник опрашивается только для ключей секции `orders`; для
  остальных ключей он не вызывается вовсе

#### Scenario: `optional` пропускает не поднявшийся источник

- **WHEN** привязка — `bind(dotenv('missing.env'), { optional: true })`, а
  файла нет
- **THEN** фаза 0 продолжается без этого источника; ключи разрешаются
  следующей привязкой списка

#### Scenario: Источник без `optional` отказывает фазу 0

- **WHEN** привязка — `bind(dotenv('missing.env'))` без `optional`, а
  файла нет
- **THEN** сборка отказывает на фазе 0 с путём файла в сообщении

#### Scenario: `timeout` ограничивает `init()`

- **WHEN** привязка — `bind(slowSource, { timeout: 50 })`, а `init()`
  источника не завершается за 50 мс
- **THEN** фаза 0 отказывает, называя источник этой привязки

#### Scenario: Привязку нельзя передать `assemble()`

- **WHEN** написано `app.assemble({ features: 'orders', config: [bind(fileSource)] })`
- **THEN** это ошибка компиляции: `assemble` принимает только выбор фич,
  привязки — опция `run()`

## MODIFIED Requirements

### Requirement: Источник — объект `ConfigSource`, а не провайдер

Источник конфигурации SHALL быть объектом
`ConfigSource { get(key): unknown; init?(): void | Promise<void>; watch?(onChange): void; close?(): void | Promise<void> }`.
Источники SHALL NOT быть обычными провайдерами контейнера и SHALL NOT быть
видимы пользовательскому коду как DI-токены: их читает одна приватная
читалка (DI-токен ядра), не экспортируемая из пакета.

Координаты, нужные источнику (путь к файлу, адрес волта), SHALL приходить
аргументом его конструктора (`dotenv(path)`) — источник SHALL NOT читать
`process.env` внутри `init()` в их поисках. Бизнес-ключи источник SHALL
отдавать только через `get()`.

`init()` каждого привязанного источника SHALL вызываться на фазе 0, до
построения контейнера (capability `config-bootstrap-snapshot`). Порядок
«источники раньше секций» SHALL задаваться фазой, а не зависимостью секции
от читалки. `get()` SHALL оставаться синхронным: после фазы 0 чтение
значения ввода-вывода не делает.

#### Scenario: Источник инициализируется на фазе 0

- **WHEN** источник объявляет асинхронный `init()`, читающий файл
- **THEN** `init()` завершается до `assemble()`: порядок задан фазой 0, а
  не топологией графа

#### Scenario: Координаты — аргумент конструктора

- **WHEN** объявлен источник `dotenv('.env.local')`
- **THEN** путь к файлу — переданный аргумент; `init()` источника
  `process.env` не читает

#### Scenario: Читалка приватна

- **WHEN** пользовательский код пытается инжектить читалку или источник
- **THEN** такого экспортируемого DI-токена нет — kernel-граница держится
  видимостью ES-модулей

#### Scenario: Источники закрываются на shutdown

- **WHEN** приложение завершает работу
- **THEN** у каждого источника, объявившего `close()`, он вызывается —
  явным шагом фазы SHUTDOWN после разрушения контейнера

### Requirement: Привязка, не покрывшая ни одного объявленного ключа, даёт предупреждение

Читалка SHALL сверять `keys` привязок с реестром объявленных ключей на
старте и SHALL выдавать предупреждение о каждой привязке, чьи `keys` не
покрыли ни одного объявленного ключа. Предупреждение SHALL NOT быть
ошибкой: глоб легитимно может смотреть на unbound-ключи, объявляемые
семействами.

Предупреждения SHALL уходить в логгер ядра `Logger$('nestling:config')`
уровнем `warn`. До подключения логгера читалка SHALL копить их и отдавать
сразу после `assemble()`; после подключения SHALL писать напрямую. Опции
`onWarn` и типа `ConfigWarn` SHALL NOT существовать: тест перехватывает
предупреждения подменой `RootLogger$`.

#### Scenario: Опечатка в глобе видна

- **WHEN** привязка — `bind(fileSource, { keys: '*_UR' })` при объявленных
  ключах `*_URL`
- **THEN** на старте в логгер уходит `warn`, называющий `keys` и источник
  привязки, а приложение продолжает подниматься

#### Scenario: Предупреждение перехватывается в тесте

- **WHEN** тестовый корень подменяет `[RootLogger$, spyLogger().logger]`
- **THEN** предупреждение оказывается в записях подмены, а `console.warn`
  не вызывается

### Requirement: `env({ prefix })` — источник окружения с префиксом

Пакет `@nestlingjs/app` SHALL экспортировать `env(options?)` — источник, который
читает ключ `<prefix><KEY>` из `process.env` и отдаёт значение под именем
`KEY`. Без `prefix` он SHALL читать имя ключа как есть.

Источник SHALL участвовать в приоритете позицией своей привязки, как любой
другой: `bind(env({ prefix: 'SERVICE_1_' }))` SHALL перекрывать привязки,
стоящие в списке позже. Общий ключ SHALL оставаться общим не автоматически,
а явной второй привязкой: список `[bind(env({ prefix: 'SERVICE_1_' })), bind(env())]`
SHALL читать ключ без префикса второй привязкой, если первая его не
покрыла.

Секции, их поля и дескрипторы `.keys` SHALL оставаться относительными: префикс
SHALL жить в источнике и SHALL NOT входить ни в имя ключа секции, ни в
`keys` привязки.

Источник SHALL NOT объявлять `init()`, `watch()` и `close()`: читать перед
стартом нечего, следить не за чем, освобождать нечего. `process.env` он
SHALL читать живой ссылкой в момент `get()`.

#### Scenario: Один `.env` на два сервиса

- **WHEN** первый сервис привязывает `bind(env({ prefix: 'SERVICE_1_' }))`
  без `keys`, а в окружении заданы `SERVICE_1_HTTP_PORT` и `HTTP_PORT`
- **THEN** секция читает значение из `SERVICE_1_HTTP_PORT`

#### Scenario: Общий ключ остаётся общим явной второй привязкой

- **WHEN** список привязок — `[bind(env({ prefix: 'SERVICE_1_' })), bind(env())]`,
  `SERVICE_1_DATABASE_URL` не задан, а `DATABASE_URL` задан
- **THEN** секция читает `DATABASE_URL` — первая привязка вернула
  «пропускаю ход», вторая его покрыла

#### Scenario: Префикс не меняет имён ключей

- **WHEN** секция объявлена с префиксом `http`, а корень привязал
  `bind(env({ prefix: 'SERVICE_1_' }))`
- **THEN** `.keys` секции перечисляет `HTTP_PORT` и `HTTP_HOST`, и снимок
  реестра называет те же имена

## REMOVED Requirements

### Requirement: Привязка в корне — плоский список, порядок = приоритет, env — неявный пол

**Reason**: конфигурация не влияет на состав процесса, а поле декларации
утверждало обратное синтаксисом; неявный источник читалки с низшим
приоритетом (`process.env`) делал герметичный тестовый конфиг (`vars()`)
не герметичным — ключ без значения приходил из окружения машины в обход
привязки.

**Migration**: привязки передаются опцией `config` методов `run()`,
`check()` и `assembleTest()` — см. требование «Привязка передаётся
`run()`, `check()` и `assembleTest()` списком `bind()`» выше. Приложению,
которому было достаточно поля `config` без указания, достаточно и
умолчания `defaultSources` без опции.
