# Тестирование: `@nestling/testing`

> **Целевое состояние V1.** Логика решений: [ideas.md](../decisions/ideas.md) —
> «Пакет тестирования (`@nestling/testing`)» [2026-07-10].
> Статус реализации — [roadmap](../decisions/roadmap.md).

## 1. Принцип: уровень теста = граница видимости

**Тестовая поверхность — это экспортная поверхность.** Внутри пакета видно
всё (unit- и модульные тесты — приватность не мешает по построению);
приложению видны только публичные capability, и app-тесты мокают на
архитектурных швах. «Как замокать чужой приватный провайдер» — никак, и это
фича: либо модуль экспортирует тестовую capability, либо мок на шве, либо
тест написан не на том уровне. Тестируемость — следствие архитектуры;
пакет — тонкий.

## 2. Уровень 0 — без фреймворка

Провайдеры — классы/фабрики с явными deps, конфиг-срез — объектный литерал,
порт — объект с `call`, хендлер — вызов фабрики/класса с фейками. Принцип:
**у юнит-теста нет импортов из `@nestling/*`**.

## 3. `assembleTest` — тестовый composition root

```typescript
await using app = await assembleTest({
  features: [OrdersFeature],
  transports: [http()],
  overrides: [
    [OrdersRepository, inMemoryOrdersRepo()],
    familyOverride(ILogger, () => noopLogger),
  ],
  config: vars({ ORDERS_MAX_ITEMS: '10' }),
  stubs: [stub(ChargeCard, async () => new Ok({ chargeId: 'test' }))],
});

const res = await app.call(CreateOrder, { items: [...] });
```

- **Мок = подстановка в графе на ASSEMBLE**, до инстанциации — не патчинг
  и не перехват module system. Ключ `overrides: [[Token, fake]]` существует
  **только** у тестового корня (`assemble` его не принимает); право override
  — позиционное (мокаешь то, на что есть ссылка), строковой формы
  (`overrideByName('…')`) нет. Пара типизирована: фейк, не совместимый с
  типом токена, — ошибка компиляции. Override токена, которого нет в графе,
  — ошибка сборки: переименовали провайдер, и тест не мокает молча пустоту.
- **Прунинг**: осиротевшее поддерево заменённого узла выпадает из графа —
  замокал репозиторий → pg-пул не инстанцируется и не коннектится. Без
  этого жадный контейнер был бы анти-тестовым. Что именно выпало, видно в
  `app.pruned` (список id узлов). Инвариант, делающий прунинг безопасным:
  **без `overrides` он тождественен** — граф не меняется ни на один узел
  ([container.md](./container.md)).
- **Прогон без сокетов**: тестовый app проходит фазы 0–3 (BOOTSTRAP..WIRE) —
  `dispatch` рождён, START не выполняется, транспорты не в эфире,
  обработчики `SIGTERM`/`SIGINT` не ставятся. Следствие, которое надо знать:
  ресурс, захваченный в `@OnStart`, в app-тесте не захватывается — цена
  фазовой модели, а не дефект.
  `app.call(Endpoint, input)` / `app.emit(Event, payload)` — типизированы
  схемами декларации (`input` — по `input`-форме, результат —
  `ResponseContext<InferOutput<O>>`, ветка отказа несёт `status` и `code` из
  закрытого контракта `errors:`) и гонят запрос через **полный пайплайн**
  (этим app-тест отличается от юнита). `unwrap(res)` покрывает частый случай
  «ожидаю успех». Транспортный биндинг при этом не выполняется: `call`
  принимает готовый payload, а раскладка path/query/body по bind-карте —
  предмет e2e и юнит-тестов bind-карты. `await using` → честный SHUTDOWN в
  реверсе (`close()` доступен явно и идемпотентен). Настоящий e2e — обычный
  `run()` на случайном порту, вне пакета.
- `assembleTest` **асинхронна**: `await using` ждёт dispose, а не
  инициализатор, поэтому `await` перед вызовом обязателен. Форма без `using`
  (`const app = await assembleTest(…)` + `await app.close()`) поддерживается
  — для `beforeEach`/`afterEach`.

## 4. Швы app-теста

Чужие токены не нужны — мокается на публичных швах:

- **конфиг** — `vars({...})`: объектный `ConfigSource` с `watch` и
  программным `set()` → тестируется и reload-механика (пере-проекция,
  keep-last-good, `onChange`); `process.env` не трогается → параллельные
  тесты бесплатно. В тестовом корне `config:` принимает три формы:
  источник (сахар для `[[source, '*']]`), одну привязку и список привязок;
  в боевом `assemble` сахара нет;
- **меж-фичевые вызовы** — `stub(Contract, impl)`: фейк-порт, **валидируемый
  схемой контракта при каждом вызове** — мок не может разъехаться с
  реальностью; едет полем `stubs:` — «поставка недостающего», а не подмена;
- **request-контекст** — `valueProvider(Ctx(X), value)`; ALS в тестах
  не нужен;
- **cross-cutting** — `familyOverride(ILogger, () => noop)`: override
  рецепта семейства целиком, до материализации членов, поэтому боевой
  рецепт не вызывается ни разу; едет тем же списком `overrides:`;
- **транспорт** — не мокается: in-proc dispatch. Автоподстановки транспортов
  тоже нет — они перечисляются так же, как в проде, и ручка на транспорте
  вне графа даёт тот же fail-fast ASSEMBLE.

## 5. Тестовая capability модуля — subpath `./testing`

Модуль экспортирует курируемую тестовую поверхность через conditional
export (условие `"testing"` включено только в тест-раннере — прод-импорт
не резолвится на уровне Node resolution, граница структурная): токены,
разрешённые к подмене, и готовые фейки (`inMemoryOrdersRepo()`), которые
автор держит в контракте с реализацией.

Конвенция догфудится на самом ядре: внутренний шов, которым
`@nestling/testing` заводит фазы 0–3, живёт в `@nestling/app` именно таким
subpath'ом (`@nestling/app/testing`), а не публичным экспортом. Предлагать
пользователю границу, которой сам не следуешь, нечестно.

## 6. `.check()` — структурный смок топологий

Фазы 0–1 (конструкторы, без `@OnInit` → без захвата ресурсов): циклы,
port-биндинг, полнота env — по одному тесту на вариант деплоя. Метод корня
`assemble`, а не тестового приложения: `.check()` компенсирует прунинг,
поэтому обязан гонять **честный** граф — подстановок он не принимает.
Возвращает отчёт о составе (фичи, ручки по транспортам, транспорты), бросает
— теми же ошибками, что бросил бы `run()` на этих фазах, и на последующий
`run()` того же приложения не влияет.

```typescript
for (const select of ['all', 'orders', 'billing'] as const) {
  await assemble({ features: [...], select, transports: [http()] }).check();
}
```

Матрица `select`-топологий валидируется в CI без деплоя одним хелпером —
`checkTopologies(spec, selections)`: ядро фейлится быстро, а хелпер
собирает **все** отказы и падает одним сообщением, называя топологию для
каждого. Здесь же живёт отчёт совместимости схем контрактов
([contracts.md](./contracts.md)).

Ограничение, которое надо помнить: конструктор с побочкой ломает `.check()`.
Это и так нарушение фазовой модели (ресурсы — в `@OnInit`).

## 7. `testModule(M, { stubs })` — модуль в изоляции

Мини-app вокруг одного модуля (с его `imports`), kernel-модуля конфига и
стабов; те же фазы 0–3 и тот же результат, что у `assembleTest`.
Неудовлетворённые импорты обязаны быть застабаны явно — ошибка перечисляет
**все** недостающие токены с потребителем каждого, а не первый попавшийся.
Живёт внутри пакета модуля → токены видны без экспорта.
