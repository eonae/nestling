Связи между размером README и размером пакета нет. `@nestling/models` с тремя
именами занимает 284 строки, `@nestling/operations` с 67 именами — 481. Длину
задаёт объём пересказа: разделы «Быстрый старт», «Основные понятия» и «Полный
пример» повторяют главы гайда, а разделы про семантику повторяют `design/`.

Проверок сегодня нет. `docs:audit` читает `docs/`, корень репозитория и
`openspec/`, а `packages/*/README.md` не открывает. Ссылок с якорями внутрь
README пакетов из `docs/` и `examples/` не существует, поэтому перестройка
разделов ничего не ломает.

Формат README задан в двух местах, и они расходятся. Запись
[ideas.md [2026-09-05]](../../../docs/decisions/ideas.md) называет структуру «что
это, плашка статуса, установка, таблица экспортов, границы» и говорит, что
разделов «Быстрый старт» и «Полный пример» в README нет. Скилл `docs-style`
называет структуру «одна фраза → плашка → установка → минимальный пример →
основные понятия → справочник API → границы». Разделы «основные понятия» и
«справочник API» — это ровно тот пересказ, из-за которого README выросли.

## Goals / Non-Goals

**Goals:**

- README пакета отвечает на два вопроса: что этот пакет делает и какие в нём
  есть имена. Оба ответа полны.
- Один факт записан один раз. Семантика живёт в `design/`, обучение — в гайде,
  README ссылается на них и не пересказывает.
- Правило проверяемо машиной, а не соглашением: расхождение README и кода — ERROR
  в `docs:audit`.
- README читается на странице npm, где ни гайда, ни `design/` рядом нет.

**Non-Goals:**

- Сужение публичного барреля пакетов.
- Деление гайда на `guide/` и `recipes/`, разделы сайта, публикация (волны 3–5).
- Правка `design/` и гайда сверх переезда текста, у которого нет копии.
- Английский язык README.

## Decisions

### D1. Шесть разделов в фиксированном порядке

README пакета состоит из шести частей, идущих в одном порядке:

1. Заголовок `# @scope/name` и одна-две фразы «что это».
2. Плашка статуса со ссылками на design-док и главу гайда.
3. `## Установка`.
4. `## Минимальный пример`.
5. `## Экспорты`.
6. `## Границы пакета`.

Других разделов второго уровня нет. Порядок повторяет порядок изложения из
`docs-style`: сначала что это, потом как этим пользоваться, потом ограничения.

Альтернатива — задать только потолок строк и оставить состав разделов автору.
Отвергнута: потолок без состава выполняют вырезанием случайного, и восемнадцать
README разойдутся по структуре так же, как разошлись сегодня.

### D2. Минимальный пример остаётся

Раздел «Минимальный пример» содержит один фрагмент на 15–25 строк: как выглядит
работа с пакетом. Это не туториал — второго фрагмента и пошаговых объяснений в
README нет.

Причина в читателе. README публикуется в npm и открывается первым, до того как
читатель нашёл гайд; страница npm показывает только сам README. Пакет без единой
строки кода на этой странице не объясняет, о чём он.

Это уточняет запись `ideas.md`, где раздела с примером в структуре нет. Журнал
append-only, поэтому старая запись не правится: change добавляет новую запись с
уточнением, а пометка «РЕАЛИЗОВАНО» у записи [2026-09-05] ссылается на неё.
Скилл `docs-style` приводится к тому же составу разделов, и после change'а
описание структуры существует в двух местах с одинаковым текстом: в
`docs/README.md` как правило и в скилле как правило письма.

### D3. Потолок 120 строк, единый для всех пакетов

> Уточнено при реализации: бюджет раздела «Экспорты» — 60 строк, а не 40.
> Разбивка ниже опиралась на 125 публичных имён у `@nestling/app`; их
> оказалось 282, и после сужения барреля осталось 168. Перечень из 168 имён
> семью группами занимает 51 строку. Число 60 выведено из потолка файла: раздел
> не длиннее его половины. Потолок файла остался прежним — README `app` вышел
> на 107 строк.


Файл `packages/*/README.md` содержит не больше 120 строк. Считаются все строки
файла, включая код, таблицы и пустые.

Потолок один для всех, без послаблений пакетам ядра. Бюджет самого крупного
пакета показывает, что этого хватает:

| Часть | Строк для `@nestling/app` |
|---|---|
| Заголовок и «что это» | 6 |
| Плашка статуса | 8 |
| Установка | 8 |
| Минимальный пример | 25 |
| Экспорты | 40 |
| Границы пакета | 12 |
| Пустые строки между разделами | 15 |
| Итого | 114 |

Альтернатива — 120 строк базовым и 200 для пакетов ядра. Отвергнута: два числа
требуют определить, какой пакет относится к ядру, и это определение придётся
держать в проверке. Бюджет показывает, что второе число не нужно.

### D4. Перечень экспортов полон, а формат выбирается по объёму

Раздел «Экспорты» называет каждое публичное имя пакета: значения, классы, типы и
интерфейсы. Полнота — это то, ради чего от папки `docs/reference/` отказались в
пользу README: на вопрос «какие есть имена» отвечает README пакета.

Раздел занимает не больше 60 строк, и формат следует из этого бюджета.

**Пока имена помещаются по одному в строку** — таблица из двух колонок «Имя» и
«Что делает». Так выглядят четырнадцать пакетов из восемнадцати.

**Когда не помещаются** — имена группируются по подсистемам. Группа занимает
абзац: жирным имя подсистемы, ссылка на её design-док, затем имена через запятую с
переносом строк по ширине текста. Так выглядят `app`, `container`,
`transport.http` и `operations`.

Строка таблицы не переносится, поэтому таблица с ячейкой на восемнадцать имён
дала бы строку в четыреста символов и нарушила бы перенос по ширине, принятый в
репозитории. Абзац переносится свободно.

**Реэкспорт занимает одну строку.** `@nestling/app` реэкспортирует 37 имён из
`@nestling/operations` тем же модулем; в его перечне это строка со ссылкой на
пакет-источник, а не повторение его перечня.

**Подпути перечисляются отдельными группами.** Три пакета объявляют в
`package.json` второй вход: `@nestling/app/testing`, `@nestling/container/tokens`
и `@nestling/transport.nats/testing`. У группы заголовок — имя подпути. Пакет с
`bin` вместо перечня называет команду: так устроен `@nestling/viz`.

Альтернатива — называть только точки входа. Отвергнута: тогда полного перечня
имён нет нигде, и вопрос, ради которого README существует, остаётся без ответа.

### D5. Имена извлекаются из `src/index.ts` через TypeScript API

Проверка сверяет перечень с публичным барелем в обе стороны: имя из барреля
отсутствует в README — ERROR, имя из README отсутствует в барреле — тоже ERROR.

Источник имён — `src/index.ts` пакета и барели подпутей, названные в `exports`
файла `package.json`. Реэкспорты `export * from './x/index.js'` раскрываются
рекурсивно. Разбор идёт через TypeScript compiler API: `typescript` уже стоит в
корне репозитория.

Альтернатива — читать `dist/index.js`. Отвергнута по двум причинам. Проверка
потребовала бы собранного `dist`, и `yarn docs:audit` перестал бы работать на
чистом клоне. Кроме того, `Object.keys` модуля не показывает типы и интерфейсы, а
они такая же часть публичного API: `Ctx`, `Handler`, `ConfigKeys`.

Альтернатива — регулярные выражения по тексту барреля. Отвергнута: барели состоят
из `export *`, и раскрыть их без разбора модулей нельзя.

### D6. Плашка статуса различает публикуемые и внутренние пакеты

У пакетов скоупа `@nestling` плашка называет статус разработки и ведёт на
design-док и главу гайда. Ссылок может быть несколько, но не больше трёх на
каждый вид: README `@nestling/app` сегодня перечисляет шесть design-доков и семь
глав, и это список, а не ориентир.

У пакетов скоупа `@common` плашка состоит из одной строки: пакет внутренний,
публичного API вне репозитория у него нет. Главы гайда и design-дока у них не
бывает, и ссылаться не на что.

### D7. Абзац переезжает по жанру, а не удаляется

Правило работы с текстом, который вырезается из README: у каждого абзаца сначала
находится место, где тот же факт уже записан.

- Факт записан в `design/` или в гайде — абзац удаляется.
- Факта нет нигде, и это семантика или гарантия — абзац переезжает в design-док
  подсистемы.
- Факта нет нигде, и это шаг обучения — абзац переезжает в главу гайда, у главы
  обновляется дата в плашке «сверено с кодом».
- Факт описывает реализацию, а не целевое поведение — сначала сверка с кодом,
  потом переезд.

Порядок обязателен: удалить абзац, единственная копия которого лежит в README,
значит потерять описание поведения.

### D8. Четыре инварианта в `docs:audit`

Проверка добавляется в `.claude/skills/docs-audit/scripts/check.mjs` и обходит
все каталоги `packages/*`. Каждое нарушение — ERROR.

1. **Состав и порядок разделов.** Заголовки второго уровня равны списку из D1 и
   идут в этом порядке. Лишний заголовок называется по имени.
2. **Потолок.** Файл не длиннее 120 строк; в сообщении — фактическая длина.
3. **Плашка статуса.** Блок цитаты стоит сразу за первым абзацем. У пакета
   `@nestling` он содержит ссылку на `docs/design/` и ссылку на `docs/guide/`.
4. **Полнота перечня экспортов.** Множество имён в разделе «Экспорты» совпадает
   с множеством публичных имён барреля. Расхождение печатается двумя списками:
   чего нет в README и чего нет в коде.

Инвариант 4 работает и как проверка кода: имя, которое некому назвать в README,
скорее всего не задумывалось публичным.

### D9. Порядок работ: правило, затем проверка, затем файлы

Сначала правило записывается в `docs/README.md` и в скилл `docs-style`, затем
пишется проверка, затем переписываются README — от мелких к крупным.

Проверка появляется раньше файлов намеренно: она даёт список того, что осталось
сделать, и он же служит точкой возобновления. Внутри change'а `docs:audit` красный,
это нормально; DoD требует зелёного на выходе.

### D10. Барели `app` и `operations` сужаются этим же change'ом

Корневой барель пакета перечисляет имена поимённо: `export { … }` и
`export type { … }` вместо `export *`. Публичное имя — имя с читателем: его
импортируют вне `src` пакета либо называет `docs/design/` или `docs/guide/`.
Имя без читателя остаётся экспортом своего модуля и наружу не выходит.

Причина в числах. Проверка показала 282 публичных имени у `@nestling/app` и
168 у `@nestling/operations` — втрое больше оценки, на которой строился
бюджет раздела. Полный перечень из 282 имён занимает 68 строк только на
имена, и README `app` вышел бы за потолок файла. Требование полноты
(D4) при таком бареле невыполнимо.

Альтернатива — поднять оба потолка под фактический размер. Отвергнута: она
закрепляет барель, в котором публично всё подряд, включая
`readSectionSnapshot` и `ambientRequestId`. Полнота перечня тогда перестаёт
быть полезной читателю: перечень описывает не API, а содержимое каталога
`src`.

`export *` из собственного модуля в корневом бареле больше не встречается.
Реэкспорт соседнего пакета идёт отдельным оператором с его именем в
специфаере, поэтому README видит источник имени и заменяет группу одной
строкой со ссылкой.

Убрано 114 своих имён и 56 реэкспортированных у `app`, 14 и 1 у
`operations`. Перечень — в `inventory.md` change'а. Имя возвращается в барель
одной строкой, когда у него появляется читатель; это не ломающая правка.

## Risks / Trade-offs

- **Перечень `@nestling/app` не влезет в бюджет** → сработало: имён оказалось
  282, а не 125. Лишнее снял не формат, а сужение барреля (D10): осталось 168
  имён, семь групп по подсистемам и 51 строка при потолке 60.
- **Инвариант 4 назовёт имена, которых читатель не ждёт** — сработало.
  `canonicalizeJson` и `readSectionSnapshot` читателя не имеют и убраны из
  барреля (D10); `startBudget`, `parsePayload` и `bindInputStream` нужны
  авторам транспортов и остались. Отдельной группы «Расширение» не завелось:
  имена разошлись по группам подсистем.
- **Переезд текста в `design/` внесёт туда описание реализации** → в `design/`
  переезжает только то, что подтверждено кодом; при расхождении README и кода
  сначала идёт сверка, и результат сверки записывается в задачу.
- **Восемнадцать файлов — большой объём для одной сессии** → `tasks.md` даёт по
  задаче на пакет, порядок от мелких к крупным, чекбокс — точка возобновления.
- **`docs:audit` перестаёт быть проверкой одних только markdown-файлов** →
  разбор восемнадцати барелей через TypeScript API добавляет секунды; если время
  вырастет заметно, инвариант 4 уходит в полный аудит, а `docs:audit quick`
  оставляет себе первые три.
- **`@nestling/viz` объявляет вход в `exports`, но `src/index.ts` у него нет** →
  проверка найдёт это на первом же прогоне; расхождение чинится в этом change'е
  как часть задачи по пакету.

## Open Questions

1. **README как раздел сайта.** Запись `ideas.md` планирует раздел `/reference/`,
   собранный из README пакетов. Это волна 4, и на структуру из D1 она не влияет.
2. **Судьба имён без читателя.** Список появится только после инвентаря на этапе
   apply. Решение о сужении барреля принимается отдельным change'ом.
