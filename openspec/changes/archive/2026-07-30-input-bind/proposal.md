# input-bind: канон размещения HTTP-input и плоская bind-карта

## Why

Сегодня HTTP-транспорт собирает payload функцией `mergePayload(body, query,
params)`: поле принимается **отовсюду**, а одноимённый ключ в двух источниках
даёт `PayloadConflictError` → 400. Merge **необратим** — по декларации нельзя
сказать, где живёт поле, а значит:

- «поле принимается отовсюду» — implicit contract (та же категория, что
  отвергнутый warn-and-pass в модели ошибок): контракт ручки шире, чем
  задумывал автор, и сузить его нечем;
- генерации OpenAPI (change `openapi`, #20) негде взять `parameter` vs
  `requestBody`, а типизированному клиенту (change `contract-clients`, #22)
  — куда класть поле при сборке запроса. Оба — прямые потребители, оба
  заблокированы;
- повторный query-ключ (`?tag=a&tag=b`) молча теряется: `transport.ts`
  складывает `url.searchParams.entries()` в плоский объект — тихий last-wins;
- webhook-подписи (HMAC над сырыми байтами) невыразимы: тело парсится в
  значение, байты недоступны никому.

Внешнее ревью назвало HTTP-модель слабейшим местом дизайна
([d/06 §3 и П.4](../../../docs/history/discussions/06-critical-design-review.md)).
Подход согласован там же (П.4) и зафиксирован в
`docs/decisions/ideas.md`, секция «[2026-07-13] Канонизация HTTP-input: канон
размещения + bind-карта»; целевое состояние уже описано в
`docs/design/endpoints.md` §4 и `docs/design/transports.md` §2 — этот change
приводит к нему код. Change #21 из `docs/decisions/roadmap.md`, breaking-окно
волны 2, сразу после `endpoint-model` (#24), который оставил в
HTTP-конструкторе типизированную точку расширения ровно под эту работу.

## What Changes

- **Канон размещения — детерминированная функция `(pattern, метод,
  пометки) → место`.** Имя поля совпало с path-параметром шаблона → **путь**;
  явная пометка → указанное место; всё остальное → **query** для методов без
  тела (`GET`/`HEAD`/`DELETE`/`OPTIONS`/`TRACE`) и **body** для остальных.
  Заголовки — только по пометке и никогда конвенцией; в V1 канона `header()`
  нет (отложен, см. `docs/decisions/deferred.md`).
- **Сахар-пометки `query()` и `body()`** — значения-марки в поле `bind`
  HTTP-словаря (`bind: { expand: query(), tags: query({ multiple: true }) }`).
  Марки, а не строки: `header('If-Match')` при возврате из deferred
  добавляется аддитивно, не меняя носитель.
- **Bind-карта — несущий уровень.** Пометки разворачиваются **при создании
  декларации** (не при регистрации в `App`) в плоскую карту «поле → место»
  плюс правило для остального; карта едет на значении декларации и одинаково
  читается транспортом, генератором OpenAPI и типизированным клиентом —
  клиенту она нужна из одного импорта, без серверного кода.
- **BREAKING. Strict-приём вместо merge.** Payload собирается только из
  канонических мест: path-параметры — из маршрута, помеченные поля — из
  своего места, остальное — из одного источника по методу. Поле не в том
  месте в payload не попадает и проваливает обычную валидацию. `mergePayload`
  и `PayloadConflictError` удаляются как класс задач.
- **BREAKING. Fail-fast при создании декларации**: пометка на поле-path-
  параметре; `body()` у метода без тела; `bind`-пометки или path-параметры
  при неструктурном `input` (`stream`/`files`/`primitive`), куда их
  физически некуда положить; path-параметр в шаблоне при отсутствии `input`.
- **BREAKING. Query-массивы.** Повтор ключа → массив (тихий last-wins
  исчезает); пометка `query({ multiple: true })` даёт массив и для
  одиночного вхождения.
- **BREAKING (типы). Opt-in `rawBody: true` в HTTP-словаре** — сырые байты
  тела в **типизированном стартовом контексте**: слой проверки подписи
  объявляет `makePipeline<{ rawBody: Uint8Array }>()`, и забытая пометка
  ловится компилятором в точке декларации, а не в рантайме. Память платится
  только там, где запрошена; тело читается один раз и парсится из тех же
  байтов; лимит `maxBodySize` действует как обычно.
- **Kernel получает нейтральный носитель биндинга.** `makeEndpoint`
  принимает и переносит на значение декларации непрозрачное поле
  `binding` — транспортный конструктор кладёт туда свою карту; ядро в неё
  не заглядывает (`@nestling/pipeline` остаётся HTTP-слепым).
- **`makeEmptyContext` принимает стартовый input** (по умолчанию пустой) —
  точка, через которую транспорт кладёт `rawBody` в контекст.

### Non-goals

- **`header()`** — отложен (`docs/decisions/deferred.md`, «[2026-07-13]
  `header()`: параметры операции в HTTP-заголовках»). Граница meta vs input
  зафиксирована там же; ambient-заголовки остаются в meta через pre-юниты.
  Типизация ответных заголовков (`Location`, `ETag`) — та же отложенная
  тема.
- **Генерация OpenAPI** (change `openapi`, #20) — здесь только производится
  и документируется карта, которую он будет читать.
- **Сборка запроса клиентом** (change `contract-clients`, #22) — потребитель
  той же карты, приезжает в волне 5.
- **`makeContract`/`http:`-биндинг контракта** (change `ports`, #11):
  разворачивание bind-карты в именованном контракте использует ту же
  функцию, но само поле `http:` здесь не заводится.
- **Коерсия провод-строк** (`?page=2` → `number`) остаётся ответственностью
  автора схемы (`z.coerce`) — открытый вопрос записи ideas.md, решается
  вместе с клиентом (сериализация в обратную сторону).
- **Проверка «path-параметр объявлен в шаблоне, но отсутствует в схеме»** в
  полном виде невозможна: Standard Schema не отдаёт перечня ключей
  (`docs/design/schemas.md`). Реализуются только решаемые без интроспекции
  случаи (см. fail-fast выше); полная проверка — кандидат для `openapi`
  (#20), где вендор-конвертеры структуру схемы уже знают.
- **Формы io** (`stream`/`events`/`multipart`, change `streaming-v2`, #6) —
  существующие модификаторы `stream`/`withFiles`/`files` продолжают работать
  как есть; bind-карта на них не распространяется.
- **CLI-биндинг** не затрагивается: канон размещения — правило HTTP.

## Capabilities

### New Capabilities

- `http-input-binding`: канон размещения полей `input` по частям
  HTTP-запроса; пометки `query()`/`body()` и их разворачивание в плоскую
  bind-карту при создании декларации; bind-карта как читаемое свойство
  значения-декларации; fail-fast словаря; strict-приём payload транспортом;
  семантика query-массивов; opt-in `rawBody: true` и типизированный
  стартовый контекст.

### Modified Capabilities

- `endpoint-declarations`: HTTP-словарь расширяется полями `bind` и
  `rawBody`, а значение декларации — непрозрачным для ядра носителем
  `binding`; набор проверок словаря при создании пополняется правилами
  bind-карты. Требование про типизацию `path` переформулируется так, чтобы
  path-параметры были не только выводимым типом, но и источником правила
  размещения.
- `http-request-validation-errors`: требование «конфликт одноимённых ключей
  источников → 400» **удаляется** вместе с `PayloadConflictError` —
  конфликта источников больше не существует; вместо него фиксируется, что
  поле, присланное не в каноническое место, в payload не попадает и даёт
  обычную ошибку валидации (400 с issue'ами).

## Impact

**Публичный API (breaking):**

- `@nestling/transport.http` — удаляются `mergePayload` и
  `PayloadConflictError`; добавляются пометки `query`, `body`, типы
  `HttpBinding`/`BindPlacement`, чтение карты с декларации;
  `HttpEndpointDictionary` получает `bind` и `rawBody`, а слот `pipeline`
  начинает сверяться со стартовым контекстом декларации.
- `@nestling/pipeline` — `EndpointOptions`/`EndpointDefinition` получают
  поле `binding` (непрозрачное для ядра); `makeEmptyContext` получает
  четвёртый параметр — стартовый input.
- Поведение приёма запросов: поле, присланное не в каноническое место,
  молча не попадает в payload (и падает на валидации, если обязательно);
  повторный query-ключ становится массивом.

**Код:** `packages/nestling.transport.http/src/{helpers.ts,transport.ts,
merge.ts (удаляется),errors.ts,index.ts,parser.ts}`,
`packages/nestling.pipeline/src/{metadata/endpoint.ts,core/types/context.ts,
core/types/endpoint.ts}` и их тесты (`merge.spec.ts` удаляется,
`transport.integration.spec.ts` пополняется сценариями размещения).

**Примеры:** `examples.app-with-http` — `get-user`/`update-user`/
`delete-user` (`:id` → путь), `search-users` (GET → query),
`upload-avatar` (multipart + path-параметр), плюс демонстрация
`query()`-пометки и `rawBody` (webhook-ручка как показательный кейс);
`examples.simple-http-server` — проверка, что канон ничего не ломает.

**Доки:** `docs/design/endpoints.md` §4 (сверить с реализацией — форма
пометок и объём fail-fast), `docs/design/transports.md` §2,
`docs/design/schemas.md` (упоминание «bind-карта пишется руками»),
`docs/guides/http-app-di.md` и `docs/guides/http-functional.md` (плашки
«сверено с кодом» + новая дата), README `@nestling/transport.http` и
`@nestling/pipeline`, `docs/decisions/roadmap.md` (статус #21),
`docs/preview/`.

**Зависимости:** новых внешних нет. Апстрим — `endpoint-model` (#24,
заархивирован: точка расширения словаря и `PathParams<Path>` уже на месте) и
`standard-schema` (#19, определил границу «интроспекции нет»). Даунстрим —
`openapi` (#20) и `contract-clients` (#22) читают произведённую здесь карту;
`ports` (#11) переиспользует разворачивание для `http:`-биндинга контракта.
