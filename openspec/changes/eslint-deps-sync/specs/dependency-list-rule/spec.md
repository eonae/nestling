## ADDED Requirements

### Requirement: Правило `dependency-list` — подсказка в редакторе, а не гарантия

`@nestlingjs/eslint-plugin` SHALL экспортировать правило `dependency-list`
именем `dependencyList` и регистрировать его в объекте плагина по умолчанию.
Правило SHALL быть подсказкой в редакторе: гарантией совпадения списка
зависимостей с конструктором SHALL оставаться компилятор (capability
`injectable-dependency-list`).

Правило SHALL быть синтаксическим: оно SHALL разбирать дерево
`@typescript-eslint/parser` и SHALL NOT требовать информации о типах.
Пакет SHALL NOT получать рантайм-зависимостей: типы узлов дерева
подключаются только в типах.

Статус подсказки SHALL быть назван в тексте каждого сообщения, в README
пакета и в документации. Рекомендуемый уровень SHALL быть `warn`.

#### Scenario: Правило подключается рядом с двумя другими

- **WHEN** конфиг подключает объект плагина по умолчанию и правило
  `@nestlingjs/dependency-list`
- **THEN** правило работает на файлах, разобранных парсером TypeScript, а
  `import-through-barrel` и `endpoint-has-layer` не меняются

#### Scenario: Сообщение называет свой статус

- **WHEN** правило сработало
- **THEN** текст сообщения говорит, что это подсказка в редакторе, а
  гарантию даёт компилятор

### Requirement: Ожидаемый DI-токен выводится из типа параметра по таблице

Для класса с декоратором `@Component`, `@Handler` или `@Resource` правило
SHALL выводить ожидаемый список из аннотаций типов параметров: у
`@Component` и `@Handler` — параметров конструктора, у `@Resource` —
параметров `static acquire` без последнего. Свойство-параметр
(`private readonly x: T`) SHALL считаться параметром с тем же типом.

Ожидаемый элемент позиции SHALL определяться таблицей, строки которой
проверяются по порядку:

| Тип параметра | Канонический элемент |
|---|---|
| `X[]`, `readonly X[]`, `ReadonlyArray<X>`, в файле виден `X$` | `X$.all` |
| `X`, в файле виден идентификатор `X$` | `X$`; для `Logger` — `Logger$.auto` |
| `X` — класс | `X` |
| `Logger` | `Logger$.auto` |
| `Config<typeof X>` | `X` |
| `Port<typeof Op>` | `Op.caller` |
| `Emitter<typeof Op>` | `Op.emitter` |
| всё остальное | позиция непрозрачна |

Идентификатор `X$` SHALL считаться видимым, если у него есть привязка в
области видимости класса: импорт или объявление в файле. Тип без
аннотации, квалифицированное имя, объединение типов и любой тип вне
таблицы SHALL давать непрозрачную позицию.

#### Scenario: Секция конфига

- **WHEN** параметр объявлен `config: Config<typeof AppConfig>`
- **THEN** ожидаемый элемент позиции — `AppConfig`

#### Scenario: Вызыватель и эмиттер операции

- **WHEN** параметры объявлены `quotas: Port<typeof ClaimQuota>` и
  `registered: Emitter<typeof UserRegistered>`
- **THEN** ожидаемые элементы — `ClaimQuota.caller` и
  `UserRegistered.emitter`

#### Scenario: Интерфейс с DI-токеном в области видимости

- **WHEN** параметр объявлен `users: UsersRepository`, а файл импортирует
  `UsersRepository$`
- **THEN** ожидаемый элемент — `UsersRepository$`

#### Scenario: Массив вкладов семейства

- **WHEN** параметр объявлен `checks: readonly HealthCheck[]`, а файл
  импортирует `HealthCheck$`
- **THEN** ожидаемый элемент — `HealthCheck$.all`

#### Scenario: Ресурс

- **WHEN** класс с `@Resource` объявляет
  `static acquire(config: Config<typeof AppConfig>, logger: Logger, signal: AbortSignal)`
- **THEN** ожидаемый список — `[AppConfig, Logger$.auto]`, и сигнал в него
  не входит

#### Scenario: Тип вне таблицы

- **WHEN** параметр объявлен `requestId: CtxReader<string>` или
  `seen: Set<string>`
- **THEN** позиция непрозрачна, и любой написанный в ней DI-токен
  принимается

### Requirement: Класс и интерфейс различаются по объявлению и импорту

Для типа `X` без видимого `X$` правило SHALL классифицировать `X` по его
привязке в области видимости класса:

- объявление `class X` в файле или импорт значением — класс, ожидаемый
  элемент `X`;
- объявление `interface X` или `type X` в файле, импорт `import type { X }`
  или `import { type X }` — позиция непрозрачна;
- привязки нет — позиция непрозрачна.

Видимый `X$` SHALL иметь приоритет над классификацией.

#### Scenario: Класс из импорта значением

- **WHEN** параметр объявлен `db: Database`, а файл импортирует `Database`
  через `import { Database }`
- **THEN** ожидаемый элемент — `Database`

#### Scenario: Интерфейс из импорта типа без DI-токена рядом

- **WHEN** параметр объявлен `users: UsersRepository`, файл импортирует
  `UsersRepository` через `import type`, а `UsersRepository$` в файле не
  виден
- **THEN** позиция непрозрачна, и правило про неё молчит

#### Scenario: Класс, зарегистрированный под DI-токеном

- **WHEN** параметр объявлен `database: Database`, файл импортирует и класс
  `Database`, и `Database$`
- **THEN** ожидаемый элемент — `Database$`

#### Scenario: Класс с именем `Logger`

- **WHEN** параметр объявлен `logger: Logger`, файл объявляет `class Logger`
  и не видит `Logger$`
- **THEN** ожидаемый элемент — `Logger`, а не `Logger$.auto`

### Requirement: Список сверяется по позициям, совпадение — по голове выражения

Правило SHALL сравнивать написанный список с ожидаемым позиция за
позицией. Непрозрачная позиция SHALL принимать любой элемент. Известная
позиция SHALL считаться совпавшей, когда:

- ожидаемый элемент — идентификатор `X`, а написан идентификатор `X`;
- ожидаемый элемент — член `Op.caller` или `Op.emitter`, а написан тот же
  член;
- ожидаемый элемент начинается с `X$` (`X$`, `X$.auto`, `X$.all`), а
  написано выражение, крайний левый идентификатор которого — `X$`: сам
  `X$`, вызов `X$(…)`, член `X$.auto`, `X$.all`.

Расхождение в известной позиции SHALL сообщаться на элементе списка с
именем параметра, текстом его типа и ожидаемым DI-токеном.

#### Scenario: Член семейства с явным именем

- **WHEN** параметр объявлен `logger: Logger`, а в списке написано
  `Logger$('db')`
- **THEN** позиция совпала, и предупреждения нет

#### Scenario: Автоматический член семейства

- **WHEN** параметр объявлен `logger: Logger`, а в списке написано
  `Logger$.auto`
- **THEN** позиция совпала, и предупреждения нет

#### Scenario: DI-токен другого имени

- **WHEN** параметр объявлен `users: UsersRepository` при видимом
  `UsersRepository$`, а в списке написано `UsersRepo$`
- **THEN** правило сообщает расхождение на элементе `UsersRepo$`, называя
  параметр `users`, тип `UsersRepository` и ожидаемый `UsersRepository$`

#### Scenario: Непрозрачная позиция среди известных

- **WHEN** параметры объявлены `db: Database`, `logger: Logger`,
  `requestId: CtxReader<string>`, а список — `[Database, Logger$.auto, Ctx(RequestId)]`
- **THEN** предупреждения нет: две позиции совпали, третья принимает
  написанное

### Requirement: Длина списка проверяется всегда

Правило SHALL сообщать расхождение длины, когда число элементов списка
выходит за допустимые длины: от числа обязательных параметров до общего
числа параметров; rest-параметр SHALL снимать верхнюю границу. Декоратор
без аргумента SHALL считаться пустым списком. Сообщение SHALL называть
число написанных DI-токенов и число параметров.

#### Scenario: Пустой список при непустом конструкторе

- **WHEN** класс с `constructor(private readonly users: UsersRepository)`
  декорирован `@Handler()`
- **THEN** правило сообщает расхождение длины: ноль DI-токенов при одном
  параметре

#### Scenario: Необязательный параметр

- **WHEN** конструктор объявлен `constructor(repo: Repo, logger?: Logger)`
- **THEN** списки из одного и из двух элементов проходят без предупреждения,
  список из трёх — расхождение длины

#### Scenario: Rest-параметр

- **WHEN** конструктор объявлен `constructor(...deps: Dependency[])`
- **THEN** список любой длины проходит без предупреждения о длине

### Requirement: Автофикс дописывает список; замена элемента — suggestion

Сообщение о длине SHALL нести автофикс, который дописывает недостающие
позиции каноническими элементами, оставляет написанные элементы как есть и
убирает лишние. Автофикс SHALL быть доступен, только когда каждая
недостающая позиция известна; при непрозрачной недостающей позиции
автофикса SHALL NOT быть.

Сообщение о расхождении элемента SHALL NOT нести автофикса. Замена
элемента каноническим текстом SHALL предлагаться suggestion ESLint, которую
`eslint --fix` не применяет.

#### Scenario: Автофикс пустого списка

- **WHEN** класс с `constructor(users: UsersRepository, config: Config<typeof AppConfig>)`
  при видимом `UsersRepository$` декорирован `@Handler()`
- **THEN** автофикс переписывает декоратор в
  `@Handler([UsersRepository$, AppConfig])`

#### Scenario: Автофикс недостающего DI-токена

- **WHEN** конструктор объявляет `db: Database, logger: Logger`, а список —
  `[Database]`
- **THEN** автофикс переписывает список в `[Database, Logger$.auto]`

#### Scenario: Автофикс сохраняет написанный член семейства

- **WHEN** конструктор объявляет `logger: Logger, db: Database`, а список —
  `[Logger$('db')]`
- **THEN** автофикс переписывает список в `[Logger$('db'), Database]`

#### Scenario: Длина расходится при непрозрачной позиции

- **WHEN** конструктор объявляет `db: Database, requestId: CtxReader<string>`,
  а список — `[Database]`
- **THEN** правило сообщает расхождение длины без автофикса

#### Scenario: Замена — только вручную

- **WHEN** параметр объявлен `logger: Logger`, а в списке написано
  `RootLogger$`
- **THEN** правило сообщает расхождение с suggestion заменить элемент на
  `Logger$.auto`, а `eslint --fix` список не меняет

### Requirement: Правило молчит там, где список или параметры непрозрачны

Правило SHALL молчать целиком, когда:

- аргумент декоратора — не литерал массива (идентификатор, вызов) либо
  массив содержит spread;
- у класса с `@Component` или `@Handler` нет собственного конструктора;
- у класса с `@Resource` нет метода `static acquire`;
- декоратор вызван через член (`container.Component([…])`) или под другим
  именем.

#### Scenario: Список приходит переменной

- **WHEN** класс декорирован `@Component(deps)`
- **THEN** предупреждения нет

#### Scenario: Конструктор унаследован

- **WHEN** класс `extends Base` без собственного конструктора декорирован
  `@Component([])`
- **THEN** предупреждения нет: параметры базового класса в файле не видны

#### Scenario: Spread в списке

- **WHEN** класс декорирован `@Handler([...common, Logger$.auto])`
- **THEN** предупреждения нет
