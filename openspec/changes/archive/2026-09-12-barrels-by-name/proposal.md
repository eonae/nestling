## Why

Правило «корневой барель перечисляет публичные имена поимённо» записано
требованием спеки [`packages-layout`](../../specs/packages-layout/spec.md) и
действует на все пакеты. Выполняют его два пакета из восемнадцати:
`@nestlingjs/app` и `@nestlingjs/operations`, переписанные change'ом
`docs-package-readmes`. В остальных барель остался набором `export *`, и
публичным стало всё, что экспортирует любой внутренний модуль. Это открытый
вопрос №1 записи [ideas.md [2026-09-09]](../../../docs/decisions/ideas.md)
«Публичное имя — имя с читателем; барель перечисляет имена поимённо».

Правило некому проверить. `yarn docs:audit` сверяет перечень экспортов README
с барелем в обе стороны, а на `export *` не смотрит. Пока проверки нет,
следующий пакет повторит то же самое.

Сроком правит выход в реестр: пакеты опубликованы (`0.1.3`), и читатель
появился вне репозитория. Каждое имя в бареле — обещание, и снимать его
дальше дороже, чем сейчас.

## What Changes

- Корневые барели семи пакетов переписываются операторами `export { … }` и
  `export type { … }`. Оператора `export *` из собственного модуля в них не
  остаётся.
- Барель подпути `@nestlingjs/container/tokens` переписывается тем же
  правилом: он тоже назван в `exports` и тоже публичная поверхность.
- **BREAKING**: имя без читателя перестаёт выходить наружу. Внутри пакета оно
  работает как раньше; возврат в барель — одна строка и правка не ломающая.
- `yarn docs:audit` получает проверку: `export *` из собственного модуля в
  бареле, названном полем `exports`, — ERROR с именем файла и специфаером.
- Разделы `## Экспорты` затронутых README сокращаются вслед за перечнями.
- Требование спеки формулируется про каждый барель поля `exports`, а не про
  один `src/index.ts`.

Объём по пакетам. Столбец «без читателя» — оценка поиском импортов вне `src`
пакета и упоминаний в `docs/design/` и `docs/guide/`; точный список даёт
сверка сборкой, потому что часть имён нужна компилятору для вывода типов.

| Пакет | `export *` | Имён сейчас | Из них без читателя |
| --- | --- | --- | --- |
| `@nestlingjs/container` | 7 | 96 | 56 |
| `@nestlingjs/container/tokens` | 2 | 19 | — |
| `@nestlingjs/transport.http` | 13 | 62 | 37 |

## Non-goals

- **Состав API по существу не меняется.** Имя либо остаётся публичным, либо
  становится внутренним. Ни одно имя не переименовывается, не переносится
  между пакетами и не удаляется из кода.
- **Судьба `@nestlingjs/models` не решается.** У пакета нет ни одного импорта
  и ни одного упоминания его имён в `docs/design/` и `docs/guide/`. Барель
  переписывается поимённо, а вопрос «нужен ли пакет» остаётся за рамками:
  это решение про состав репозитория, а не про границу пакета.
- **Правило `import-through-barrel` не трогается.** Оно про код пользователя,
  а здесь речь про барели самого репозитория.
- **Потолок README в 120 строк не меняется.** Перечни сокращаются, и запаса
  становится больше.
- **Пакеты без поля `exports` правило не касается.** У `@nestlingjs/viz`
  только `bin`, бареля нет.

## Capabilities

### New Capabilities

Новых способностей нет: правило записано, и change приводит к нему код.

### Modified Capabilities

- `packages-layout`: требование про поимённый барель распространяется на
  каждый барель поля `exports`, а не только на `src/index.ts`, и его
  выполнение проверяет `yarn docs:audit`.

## Impact

**Код.** Барели семи пакетов и подпути `container/tokens`. Модули, которые
импортировали соседа через сузившийся барель, переходят на прямой путь либо
получают имя обратно — что именно, решается по каждому месту.

**Документация.** Разделы `## Экспорты` в README восьми пакетов; проверка
совпадения с барелем в обе стороны держит их честными. Запись `ideas.md`
[2026-09-09] получает пометку о закрытии открытого вопроса.

**Инструменты.** `.claude/skills/docs-audit/scripts/` — новая проверка рядом
с разбором барелей, который уже умеет отличать `export *` соседнего пакета от
собственного.

**Потребители снаружи.** Импорт имени, ушедшего из бареля, перестаёт
разрешаться. Список ушедших имён публикуется в change'е, как это сделал
`docs-package-readmes`.
