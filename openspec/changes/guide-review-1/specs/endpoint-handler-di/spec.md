# endpoint-handler-di Specification (delta)

## MODIFIED Requirements

### Requirement: Хендлер принимается в трёх формах

Конструктор декларации SHALL принимать поле `handler` в трёх формах:

1. **функция** `(input, meta) => …` — без зависимостей;
2. **объект** `{ deps: […], handle: (…deps) => (input, meta) => … }` —
   каррированная фабрика с явным массивом токенов;
3. **класс** с методом `handle`, экземпляр которого создаёт endpoint.

Полей `deps` и `handle` на верхнем уровне словаря декларации SHALL NOT
существовать: их присутствие SHALL быть ошибкой компиляции и ошибкой
рантайма при создании декларации. Формы SHALL различаться по типу
значения `handler`. Класс-форма SHALL быть формой подключения DI, а не
вторым стилем деклараций: сама декларация во всех трёх случаях SHALL
оставаться одним и тем же значением.

Во всех трёх формах `meta` SHALL нести зарезервированный ключ `signal` и
поля контекста; ключа `fail` в `meta` SHALL NOT существовать. Возвращаемый
тип SHALL сверяться не только со схемой `output`, но и со списком
`errors:` декларации — в точке декларации, как и сверка со схемами.

#### Scenario: Функция без зависимостей

- **WHEN** объявлено `httpEndpoint({ …, handler: async (input, meta) => Ok.of(…) })`
- **THEN** декларация исполнима сразу, без гашения зависимостей

#### Scenario: Каррированная фабрика

- **WHEN** объявлено `httpEndpoint({ …, handler: { deps: [UserService, ILogger], handle: (users, logger) => async (input, meta) => … } })`
- **THEN** типы `users` и `logger` выведены из токенов `deps`, а декларация
  несёт неразрешённые зависимости

#### Scenario: Класс-хендлер

- **WHEN** объявлено `httpEndpoint({ …, handler: CreateUserHandler })`, где
  `CreateUserHandler` — класс под `@Injectable([UserService])` с методом
  `handle`
- **THEN** код компилируется без `implements`, сигнатура `handle` сверяется
  со схемами `input`/`output` в точке декларации, а декларация несёт
  неразрешённую зависимость

#### Scenario: Старые поля не принимаются

- **WHEN** объявлено `httpEndpoint({ …, deps: [UserService], handle: (users) => … })`
- **THEN** это ошибка компиляции, а из JS — ошибка при создании
  декларации, называющая поле `handler`

#### Scenario: Несовпадение сигнатуры хендлера со схемами

- **WHEN** `handle` принимает тип, несовместимый с `InferInput<input>`, или
  возвращает тип, несовместимый с `InferOutput<output>`
- **THEN** это ошибка компиляции в точке декларации

#### Scenario: Несовпадение возвращаемого отказа с errors

- **WHEN** хендлер (в любой из трёх форм) возвращает отказ, не объявленный
  в `errors:` декларации
- **THEN** это ошибка компиляции в точке декларации

#### Scenario: В meta нет fail

- **WHEN** хендлер обращается к `meta.fail`
- **THEN** это ошибка компиляции: `meta` несёт `signal` и поля контекста

### Requirement: Тип декларации несёт неразрешённые зависимости

`EndpointDefinition` SHALL иметь тип-параметр неразрешённых зависимостей
(дефолт `never`), симметричный `TNeeds` у `Pipeline`. Форма
`handler`-функции SHALL давать `never`; объектная форма SHALL накапливать
токены из `handler.deps`; класс-форма SHALL накапливать конструктор класса.
Параметр SHALL накапливать также **классы-юниты пайплайна** декларации:
после слияния метаданных и декларации в одно значение это единственное
место, где различимы «пайплайн, требующий `bind`» и «исполнимый пайплайн»,
а без различия standalone-приём терял бы compile-time-гарантию.

#### Scenario: Классы-юниты пайплайна попадают в параметр

- **WHEN** объявлена декларация с `pipeline: makePipeline().pre(WithTracing)`,
  где `WithTracing` — класс-юнит
- **THEN** параметр неразрешённых зависимостей содержит `WithTracing`, и
  такая декларация в `server.route(...)` не проходит по типам

#### Scenario: Deps-free декларация

- **WHEN** объявлена декларация с `handler`-функцией
- **THEN** параметр неразрешённых зависимостей — `never`

#### Scenario: Декларация с зависимостями

- **WHEN** объявлена декларация с `handler: { deps: [UserService], handle }`
- **THEN** параметр неразрешённых зависимостей содержит `UserService`

### Requirement: Транспорты принимают только deps-free декларацию

`ITransport.endpoint()` и `HttpTransport.route()` SHALL принимать только
декларацию с параметром неразрешённых зависимостей `never` — так же, как
уже принимают только исполнимый `Pipeline<_, _, never>`. Передача
декларации с зависимостями напрямую транспорту SHALL быть ошибкой
компиляции.

#### Scenario: Декларация с deps не проходит в standalone-транспорт

- **WHEN** декларация с `handler: { deps: [UserService], handle }` передана
  в `server.route(...)` без гашения
- **THEN** это ошибка компиляции

#### Scenario: Deps-free декларация проходит

- **WHEN** декларация без зависимостей передана в `server.route(...)`
- **THEN** код компилируется, маршрут регистрируется и обслуживается

### Requirement: Гашение зависимостей — метод `resolve`, возвращающий новое значение

Декларация SHALL иметь метод `resolve`, возвращающий **новую** декларацию с
параметром неразрешённых зависимостей `never`; исходная декларация SHALL
оставаться неизменной. `resolve` SHALL принимать резолвер-функцию
`(token) => unknown` либо позиционный массив готовых инстансов,
соответствующих `handler.deps`. Класс-форма `handler` и пайплайн с
классами-юнитами SHALL требовать резолвер-формы: позиционному массиву
нечем их инстанцировать, и попытка SHALL давать ошибку, называющую класс
и предлагающую резолвер-форму.

#### Scenario: Гашение резолвером

- **WHEN** у декларации с `handler: { deps: [UserService], handle }` вызвано
  `resolve((token) => container.getOrThrow(token))`
- **THEN** возвращена deps-free декларация, принимаемая транспортом

#### Scenario: Гашение позиционным массивом

- **WHEN** у декларации с `handler: { deps: [UserService, ILogger], handle }`
  вызвано `resolve([userService, logger])`
- **THEN** возвращена deps-free декларация, а зависимости переданы в
  каррированную фабрику в порядке объявления `deps`

#### Scenario: Исходная декларация не мутируется

- **WHEN** одна и та же декларация погашена дважды разными наборами
  зависимостей
- **THEN** получены две независимые декларации, а исходная по-прежнему
  несёт неразрешённые зависимости

#### Scenario: Резолвер не смог отдать зависимость

- **WHEN** резолвер не возвращает значение для токена из `handler.deps`
- **THEN** `resolve` бросает ошибку, называющую токен

### Requirement: `App` гасит зависимости деклараций контейнером на старте

Сборка SHALL на старте для каждой обнаруженной декларации гасить
зависимости контейнером и передавать транспорту deps-free значение.
Зависимость (токен из `handler.deps`), недоступная в контейнере, SHALL
приводить к ошибке старта, называющей паттерн ручки, модуль-объявитель,
недостающую зависимость и способ починки, — до начала приёма запросов.

Класс-хендлер SHALL регистрировать сам endpoint: дискавери SHALL добавлять
класс из `handler` провайдером класса в модуль единицы, объявившей
endpoint, с атрибуцией к этому модулю. Перечислять класс-хендлер в
`providers:` SHALL NOT требоваться; класс, найденный и в `handler`
декларации, и в `providers:` любого модуля, SHALL быть ошибкой фазы
ASSEMBLE, называющей класс, паттерн ручки и модуль. Два endpoint'а с
одним классом-хендлером SHALL делить один экземпляр.

Резолв классов-юнитов пайплайна SHALL продолжать работать прежним
механизмом (`pipeline.bind`), вызываемым из `resolve` тем же резолвером:
для сборки это один шаг, а не два.

#### Scenario: Зависимость резолвится

- **WHEN** декларация с `handler: { deps: [UserService], handle }` объявлена
  в модуле, где `UserService` зарегистрирован провайдером
- **THEN** приложение поднимается, ручка обслуживается, а хендлер получает
  инстанс из контейнера

#### Scenario: Класс-хендлер создаёт endpoint

- **WHEN** декларация объявлена с `handler: CreateUserHandler`, а класс не
  перечислен в `providers:` ни одного модуля
- **THEN** приложение поднимается, экземпляр создан контейнером с
  зависимостями из `@Injectable`, узел графа атрибутирован модулю единицы

#### Scenario: Повторная регистрация класса-хендлера

- **WHEN** класс `CreateUserHandler` перечислен в `providers:` модуля и
  указан в `handler` декларации
- **THEN** `run()` завершается ошибкой фазы ASSEMBLE, называющей класс,
  паттерн ручки и модуль

#### Scenario: Зависимость класса-хендлера не зарегистрирована

- **WHEN** класс-хендлер объявлен под `@Injectable([ILogger])`, а
  провайдера для `ILogger` нет
- **THEN** `run()` завершается ошибкой, называющей токен, класс и паттерн
  ручки

#### Scenario: Токен из `deps` не зарегистрирован

- **WHEN** декларация объявлена с `handler: { deps: [ILogger], handle }`, а
  провайдер для `ILogger` отсутствует
- **THEN** `run()` завершается ошибкой, называющей токен, паттерн ручки
  и модуль-объявитель

#### Scenario: Хендлер тестируется без фреймворка

- **WHEN** каррированная фабрика вызвана с фейками напрямую либо
  класс-хендлер создан через `new` с фейками
- **THEN** тест не требует ни контейнера, ни транспорта, ни импортов из
  `@nestling/app`
