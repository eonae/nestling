# Документация Nestling

Правило номер один: **папка определяет статус документа**. Если док лежит
в `design/` — это целевое состояние V1, которому можно верить; если в
`history/` — это археология, читать только для контекста.

## Карта

```
docs/
├── index.md       ← стартовая страница сайта. Единственный файл, написанный для сайта.
├── en/            ← английское зеркало публикуемого: путь внутри повторяет путь оригинала.
├── design/        ← ЦЕЛЕВОЕ СОСТОЯНИЕ V1. Полное описание API, без порядка работ.
├── decisions/     ← журнал решений: когда, что, почему, отвергнутые варианты.
├── guide/         ← путь по ТЕКУЩЕМУ API: главы от первого сервиса к split-развёртыванию,
│                 читаются подряд, каждая сверена с кодом на названный коммит.
├── recipes/       ← рецепты по текущему API: один файл — одна задача, порядка чтения нет.
├── guarantees.md  ← что проверяется до первого запроса: проверка, момент, глава.
├── compatibility.md ← окружение и протоколы: версия Node, формат модулей, чужие рантаймы.
├── from-nestjs.md ← чем в Nestling записывается то, что читатель делал в NestJS.
├── glossary.md    ← термины и правила их написания.
├── conventions.md ← соглашения об именовании в коде приложения; по ним пишутся правила линтера.
└── history/       ← замороженная история. Не редактируется.
    ├── discussions/   — дискуссии, из которых рождались решения
    ├── migrations/    — гайды миграций прошлых ломающих изменений
    ├── superseded/    — дизайны, замещённые более новыми решениями
    ├── worklog/       — рабочие заметки времён реализации
    └── archlog.md     — лог заархивированных change'ей, заморожен 2026-09-12
```

Документация собирается командой `yarn docs:build` в каталог
`docs/.site/` двумя формами: деревом страниц с адресом вида
`/guide/01-first-service/` и файлом `nestling-docs.html`, где вся
документация лежит сразу. Стартовая страница дерева собирается из
[index.md](./index.md) — это единственный markdown, написанный для сайта.

Источники сборки перечисляет
[`scripts/site/sections.mjs`](../scripts/site/sections.mjs): папки
`guide/`, `recipes/` и `design/`, README каталогов `packages/` и пять
страниц — `guarantees.md`, `compatibility.md`, `from-nestjs.md`,
`glossary.md` и `conventions.md`. Ссылка в файл, который разделом сайта не стал, ведёт
на GitHub. Этот файл, `decisions/`, `history/` и `openspec/` на сайте
не публикуются.

Сайт выходит на двух языках. Английский лежит в корне
(`/guide/01-first-service/`), русский — в подпути `/ru/`. Выкладывает
сайт workflow [`docs.yml`](../.github/workflows/docs.yml) по тегу `v*`:
адрес — `https://eonae.github.io/nestling`.

Генератор, тема и правила разметки описаны в
[`scripts/site/README.md`](../scripts/site/README.md); `yarn docs:dev`
поднимает локальный сервер и пересобирает вывод при правке. Каталог
`.site/` не отслеживается git и источником истины не является: правится
глава, а не собранный файл.

Актуальное состояние **кода** документируют README пакетов
(`packages/*/README.md`) — они публикуются с npm и живут рядом с кодом.
В пакете держим только то, что нужно его пользователю сегодня.
**README есть и у каждого примера**: что он показывает, как его поднять,
что потрогать. Пример — работающее приложение, и открывают его с README,
а не с чтения `src/`.

## Два языка

Публикуемый текст существует парой. Английский — основной: его читает
тот, кто нашёл пакет в реестре.

| Что | Английский | Русский |
|---|---|---|
| документация `docs/` | `docs/en/<путь от docs/>` | `docs/<путь>` |
| README пакета | `packages/<pkg>/README.md` | `packages/<pkg>/README.ru.md` |
| README репозитория | `README.md` | `README.ru.md` |

Имя файла в паре совпадает: `docs/en/guide/03-input.md` — пара
`docs/guide/03-input.md`. Третьего места для языка нет: суффикса
`.en.md` внутри `docs/` не существует, каталога `docs/ru/` тоже.

**Паритету подлежит ровно то, что публикуется** — источники из
`sections.mjs`. Этот файл, `decisions/`, `history/`, `openspec/` и
`CLAUDE.md` пишет тот, кто работает внутри репозитория: они остаются
русскими и пары не имеют.

Правка публикуемого текста идёт парой: обе половины в одном change'е.
Забытую половину ловит `yarn docs:audit` — инвариант `lang-parity`.
Ссылка внутри английского текста ведёт в английский файл, внутри
русского — в русский; ссылка в непубликуемый файл остаётся
относительной, генератор переписывает её в адрес GitHub. Единственное
исключение — ссылка в пару этого же файла: это переключатель языка, и
подпись на нём пишется языком, в который он ведёт. Английские
имена терминов задаёт [en/glossary.md](./en/glossary.md): он же словарь
перевода, потому что у каждого термина в нём стоит русский оригинал.

## guide/ и recipes/ — документация по текущему API

Тексты о том, как решить задачу, делятся по жанру. `guide/` — путь:
главы читаются подряд, и каждая опирается на код предыдущей. Часть 1 —
«Сервис»: один процесс, который отвечает клиентам. Часть 2 —
«Приложение»: несколько фич, которые можно разнести по процессам.
Деление на части не зависит от состава `examples/`. Оглавление и порядок
чтения — [guide/README.md](./guide/README.md).

`recipes/` — рецепты: каждый файл самостоятелен и решает одну задачу,
поэтому номера у него нет, а имя файла называет задачу. Список —
[recipes/README.md](./recipes/README.md).

Глава и рецепт начинаются с плашки «сверено с кодом `<хэш>`»: хэш
называет коммит, на котором текст сверяли с кодом. Сниппеты пишутся для
текста, а не берутся из примера; подпись блока называет путь в проекте
читателя.

Вне обоих списков лежат три документа корня.
[guarantees.md](./guarantees.md) — справочник: что проверяется до первого
запроса и в какой главе вводится. [compatibility.md](./compatibility.md) —
второй справочник: версия Node, формат модулей, состояние чужих рантаймов
и то, какие протоколы обслуживает фреймворк сам.
[from-nestjs.md](./from-nestjs.md) — вход для читателя с опытом NestJS.

## design/ — целевое состояние V1

Карта и правила папки — [design/README.md](./design/README.md). Кратко:
design-доки описывают **только целевое V1** (как будто уже реализовано),
по одному доку на подсистему; статусы реализации и порядок работ живут
в [roadmap](./decisions/roadmap.md); «почему» — в записях
[ideas.md](./decisions/ideas.md), на которые ссылается плашка каждого дока.

## decisions/

- [ideas.md](./decisions/ideas.md) — основной журнал: зафиксированные
  архитектурные решения с логикой принятия и отвергнутыми вариантами.
  Формат записи: дата, контекст, решение, открытые вопросы. Реализованная
  запись несёт пометку «РЕАЛИЗОВАНО» с итогом change'а — это единственный
  рассказ о результате. В шапке файла — оглавление, его генерирует
  `node .claude/skills/docs-audit/scripts/ideas-toc.mjs`.
- [roadmap.md](./decisions/roadmap.md) — план доработок до целевого
  состояния: одна таблица OpenSpec changes с колонкой «Волна», порядок,
  зависимости, статусы. Живой документ (статусы обновляются).
- [deferred.md](./decisions/deferred.md) — отложенные темы: обсуждено и
  осознанно не принято/не запланировано; контекст, что уже придумано,
  триггер возврата. Сюда же переезжает открытый вопрос записи ideas.md,
  переживший change: одна тема — одна запись.
- Лог заархивированных change'ей до 2026-09-12 —
  [history/archlog.md](./history/archlog.md), заморожен.

## Пакеты

Двадцать три каталога `packages/`. Ядро — три из них: `@nestlingjs/container`,
`@nestlingjs/operations` и `@nestlingjs/app`; их ставят вместе, поэтому и имён
у ядра три.

### Для автора приложения

| Пакет | Что делает |
|---|---|
| [`@nestlingjs/app`](../packages/nestling.app/) | Ядро одним пакетом: пайплайн, конфигурация, порты, абстракция транспорта и composition root (`build`, фичи и плагины, `select`, фазы жизненного цикла, политики) |
| [`@nestlingjs/container`](../packages/nestling.container/) | Контейнер зависимостей: DI-токены, провайдеры, семейства DI-токенов, модули, хуки жизненного цикла |
| [`@nestlingjs/logging`](../packages/nestling.logging/) | Интерфейс логгера и штатная реализация: уровни, привязки, вывод в `stderr` текстом или JSON |
| [`@nestlingjs/operations`](../packages/nestling.operations/) | Общее для сервера и клиента: операции, `makeFail`, `Ok`/`Fail`, формы io, `Topic` и комбинаторы потоков |
| [`@nestlingjs/transport.http`](../packages/nestling.transport.http/) | HTTP на `node:http`: `httpEndpoint`, маршрутизация, JSON, NDJSON, SSE, multipart |
| [`@nestlingjs/testing`](../packages/nestling.testing/) | Тестовый composition root: `buildTest`, `overrides`, стабы операций, `checkTopologies` |

### Транспорты и шина

| Пакет | Что делает |
|---|---|
| [`@nestlingjs/transport.cli`](../packages/nestling.transport.cli/) | Команды CLI как endpoint'ы: однократный запуск и REPL |
| [`@nestlingjs/transport.nats`](../packages/nestling.transport.nats/) | NATS как шина приложения: операции между процессами, `durable`-доставка |

### Инструменты и сателлиты

| Пакет | Что делает |

| [`@nestlingjs/mcp`](../packages/nestling.mcp/) | MCP входящим транспортом: инструмент агента — endpoint, схемы и описания берутся с декларации |

## Правила ведения

1. **Папка = статус.** Никаких «наполовину актуальных» документов.
2. **`design/` — единственное место, где целевой API описан целиком.**
   Меняется решение → правится design-док по месту + добавляется запись
   в `decisions/`. «Почему» живёт в decisions, «что» — в design. В записи
   пишется и то, как к решению пришли: контекст и отвергнутые варианты, а
   не один итог.
3. **В `design/` нет порядка работ и статусов реализации** — только
   целевое V1 и ссылки: на записи ideas.md (логика) и на roadmap (статус).
   Слова «v2» в целевых доках не существует: осознанно исключённое из V1 —
   в [deferred](./decisions/deferred.md) и открытых вопросах записей.
4. **`decisions/` append-only, `history/` immutable.** Устаревшую запись
   не редактируем — помечаем superseded со ссылкой на новую.
5. **Каждый design-док начинается с плашки** «Целевое состояние V1» со
   ссылками на записи журнала и roadmap.
6. **Новые дискуссии** — сразу в `history/discussions/NN-тема.md`.
   Корень репозитория для документации закрыт: там лежат README,
   `CLAUDE.md` и `RELEASING.md` — последний описывает выпуск версии,
   то есть работу с репозиторием, а не фреймворк.
7. **Глава и рецепт читаются без примера.** Каждый файл в `guide/` и в
   `recipes/`, кроме оглавления, начинается с плашки «сверено с кодом
   `<хэш>`» — коротким хэшем коммита, на котором текст сверяли. Код в
   блоках написан для текста, подпись блока называет путь в проекте
   читателя, пути внутри `examples/` в подписи нет. Ссылка на пример
   допустима одной строкой; пересказ его файлов — нет. `yarn docs:audit`
   разрешает хэш в репозитории (ERROR, если не разрешается) и
   предупреждает, когда после него менялся код `packages/*/src`.
8. **Один стиль и один словарь.** Тексты пишутся по правилам скилла
   `docs-style` (`.claude/skills/docs-style/SKILL.md`), термины — из
   [glossary.md](./glossary.md), имена в коде примеров — по
   [conventions.md](./conventions.md).
9. **Реализованный change отмечается в журнале.** Запись `ideas.md`, по
   которой сделан change, получает пометку «**РЕАЛИЗОВАНО дата** — change
   `имя`»: реализовано целиком или частично, что уехало дальше, какие
   открытые вопросы закрылись и чем реализация уточнила решение. Статус
   живёт в [roadmap](./decisions/roadmap.md), в журнале — факт и
   уточнения, которых больше нигде нет. Отдельного лога заархивированных
   change'ей нет: пометка — единственный рассказ о результате. Пометку
   проверяет скилл `docs-audit`: change без неё — ERROR.
10. **README пакета состоит из шести разделов в этом порядке:** заголовок
    `# @scope/name` и одна-две фразы «что это», плашка статуса,
    `## Установка`, `## Минимальный пример`, `## Экспорты`,
    `## Границы пакета`. Других заголовков второго уровня нет: обучение
    живёт в `guide/` и `recipes/`, семантика — в `design/`, README отвечает на вопрос
    «что в пакете сегодня и как называется». Файл занимает не больше
    120 строк, раздел «Экспорты» — не больше 60, то есть не больше половины
    файла. «Минимальный пример»
    содержит один блок кода: README открывают на странице npm, где ни
    гайда, ни `design/` рядом нет. Плашка публичного пакета называет
    статус разработки и ведёт на design-док и на главу гайда или рецепт, не
    больше трёх ссылок каждого вида; плашка внутреннего пакета — того, чьё имя несёт
    `common.`, — состоит из одной строки о том, что пакет внутренний.
11. **Раздел «Экспорты» называет каждое публичное имя пакета** — значения,
    классы, типы и интерфейсы. Публичное имя — это имя, экспортированное
    барелем из поля `exports` файла `package.json`. Формат перечня выбирается
    по объёму. Пока имена помещаются по одному в строку, перечень записывается
    таблицей из двух колонок: «Имя» и «Что делает». Когда не помещаются, имена
    группируются по подсистемам: жирным имя подсистемы, рядом ссылка на её
    design-док, дальше имена через запятую. Список имён внутри ячейки таблицы
    не пишется, потому что строка таблицы не переносится по ширине. Имена,
    реэкспортированные из соседнего пакета, занимают одну строку со ссылкой на
    него. Каждый подпуть из `exports` получает свою группу. Пакет, у которого
    вместо барреля объявлен `bin`, называет команду запуска.

12. **Язык текста определяет его читатель.** Строка, которую процесс
    печатает или отдаёт наружу, пишется по-английски: сообщения ошибок,
    тексты логов, причины `detached` и `doc.hidden`, поля `summary` и
    `description` встроенных операций — всё, что попадает в лог
    пользователя или в его OpenAPI-документ. Текст для того, кто открыл
    репозиторий, остаётся русским: README, JSDoc, комментарии, документация
    `docs/`, спеки и фикстуры. Граница проходит по читателю, а не по файлу.

13. **Файл источника назван в оглавлении своего источника.** Глава — в
    [guide/README.md](./guide/README.md), рецепт — в
    [recipes/README.md](./recipes/README.md), design-док — в
    [design/README.md](./design/README.md), каталог `packages/` — в
    разделе «Пакеты» выше. Второго списка не заводится: сайт берёт состав
    и порядок разделов оттуда же. Файл без строки в оглавлении и строка
    без файла останавливают сборку сайта.
14. **Оглавление `ideas.md` генерируется.** Блок между
    `<!-- ideas-toc:start -->` и `<!-- ideas-toc:end -->` в шапке файла пишет
