## MODIFIED Requirements

### Requirement: Дескриптор контракта — JSON-значение

`@nestling/ports` SHALL экспортировать `describeContract`, строящий по
контракту (или по несущей его декларации-реализации) `ContractDescriptor` —
значение, целиком сериализуемое в JSON: имя, вид (`request`/`command`/
`event`), дескриптор формы `input`, дескриптор формы `output` и список
объявленных отказов (`code` и `status` каждого).

Дескриптор формы SHALL нести вид формы (`value` | `stream` | `events` |
`multipart`), её лист и — для `multipart` — перечень файловых полей с их
ограничениями. Вид формы SHALL читаться штатным описателем (`describeForm`),
а не разбором значения по месту.

Дескриптор листа SHALL быть одним из: примитив (`binary` / `text`),
JSON Schema, полученная конвертером, непрозрачный лист с известным
`vendor`, либо отсутствие листа. Непрозрачность SHALL быть явной пометкой в
значении — «схемы нет» и «схема есть, но не сконвертирована» SHALL
различаться.

Лист, аннотированный `jsonSchema(schema, json)`, SHALL описываться
дескриптором `leaf: 'schema'` с объявленной JSON Schema и вендором
исходной схемы — **независимо от того, передан ли конвертер**: аннотация
это и есть ответ на вопрос «как выглядит эта схема», и помечать такой лист
непрозрачным значило бы терять уже данный ответ.

Дескриптор SHALL NOT содержать функций, символов и ссылок на значения-схемы:
`JSON.parse(JSON.stringify(descriptor))` SHALL давать равное значение.

#### Scenario: Контракт с value-формами

- **WHEN** описан `makeContract({ name: 'billing.charge', kind: 'request', input: ChargeInput, output: ChargeResult, errors: [CardDeclined] })`
  с конвертером для вендора этих схем
- **THEN** дескриптор несёт имя, вид `request`, формы `value` с JSON Schema
  входа и выхода и список отказов с кодом `CARD_DECLINED` и его статусом

#### Scenario: Лист без конвертера

- **WHEN** тот же контракт описан без конвертеров
- **THEN** дескриптор несёт ту же структурную часть, а листы помечены
  непрозрачными с их `vendor` — вместо JSON Schema

#### Scenario: Аннотированный лист без конвертера

- **WHEN** контракт объявлен с `input: jsonSchema(ExoticSchema, { type: 'object' })`
  и описан без конвертеров
- **THEN** дескриптор входа несёт `leaf: 'schema'` с объявленной JSON
  Schema, а не пометку непрозрачности

#### Scenario: Не-value форма

- **WHEN** контракт объявлен с `output: stream(LogChunk)`
- **THEN** дескриптор выхода несёт вид формы `stream` и дескриптор листа

#### Scenario: Дескриптор переживает сериализацию

- **WHEN** дескриптор сериализован в JSON и разобран обратно
- **THEN** результат равен исходному дескриптору
