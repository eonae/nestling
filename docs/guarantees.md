# Что проверяется до первого запроса

Nestling переносит проверки как можно раньше: часть ошибок приложения
нельзя написать, остальные останавливают старт, а не запрос. Таблица
называет проверку, момент срабатывания и главу [гайда](./guide/README.md),
где проверка вводится.

| Что проверяется | Когда | Глава |
|---|---|---|
| Список зависимостей совпадает с параметрами конструктора по типам, порядку и длине | при компиляции | [6](./guide/06-repository.md) |
| Требования слоя к внешнему контексту выполнены в точке `compose` | при компиляции | [9](./guide/09-logging.md) |
| Хендлер возвращает то, что описывает схема `output` | при компиляции | [1](./guide/01-first-service.md) |
| Хендлер возвращает только объявленные в `errors:` отказы | при компиляции | [4](./guide/04-errors.md) |
| Отказ pre-шага объявлен на слое | при компиляции | [10](./guide/10-auth.md) |
| Отказы слоя входят в `errors:` операции | при компиляции | [14](./guide/14-features.md) |
| Путь endpoint'а непустой, без повторяющихся path-параметров | при создании декларации | [3](./guide/03-input.md) |
| У декларации со слоем досрочного успеха нет `output` | при создании декларации | [10](./guide/10-auth.md) |
| Флаги командной строки известны декларации, значения — её словарям | до фазы 0, при разборе аргумента | [19](./guide/19-select.md) |
| Ключи конфига заданы и проходят схемы | фаза BOOTSTRAP, до контейнера | [7](./guide/07-config.md) |
| Все зависимости зарегистрированы, циклов в графе нет | фаза BUILD | [6](./guide/06-repository.md) |
| Каждый endpoint подключил обязательный слой | фаза BUILD | [10](./guide/10-auth.md) |
| Изменяющий endpoint композирован от слоя транзакции | фаза BUILD | [11](./guide/11-database.md) |
| Подписчик шины композирован от слоя приёма | фаза BUILD | [16](./guide/16-durable-events.md) |
| Пайплайн объявил переменную, которую читают из глубины графа | фаза BUILD | [10](./guide/10-auth.md) |
| Формы io деклараций поддержаны транспортом | фаза BUILD | [12](./guide/12-files-and-streams.md) |
| Для каждой схемы есть конвертер в OpenAPI | фаза BUILD | [13](./guide/13-openapi-and-client.md) |
| Между двумя фичами нет прямого ребра графа | фаза BUILD | [14](./guide/14-features.md) |
| У каждой вызываемой операции есть владелец или шина | фаза BUILD | [20](./guide/20-split.md) |
| Отказ вне `errors:` не уходит клиенту | на запросе, заменяется на `internal_error` | [4](./guide/04-errors.md) |
| Вход соответствует схеме `input` | на запросе, ответ `400` | [3](./guide/03-input.md) |

Проверки фазы BUILD выполняются до создания экземпляров и до открытия
сокета: нарушение останавливает процесс раньше, чем он захватит ресурсы.
Те же проверки прогоняет `app.check(args)` по матрице топологий в CI
([глава 19](./guide/19-select.md)) и тестовая сборка `buildTest`
([глава 8](./guide/08-testing.md)).

Состав процесса определяет только аргумент сборки: объект либо маркер
`argv(process.argv)`. Окружение на состав не влияет — ни выбор фич, ни
значения переключателей из него не читаются. Привязки конфига,
переданные `run()`, `check()` или `buildTest()`, на состав тоже не
влияют: `discover()` строит документ OpenAPI и матрицу топологий, не
читая ни одного источника ([глава 7](./guide/07-config.md)). Неизвестный
флаг, неизвестная фича и значение переключателя вне словаря
останавливают процесс до фазы 0 — раньше любого ввода-вывода.
