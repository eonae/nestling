## ADDED Requirements

### Requirement: Установщик пишет манифест установки

Команда SHALL писать в каталог назначения файл `.manifest.json`. Манифест
SHALL нести версию пакета и хэш каждого файла, который команда положила, под
путём файла относительно каталога скилла.

Версию команда SHALL читать из `package.json` собственного пакета. Хэши SHALL
считаться от содержимого файлов источника.

Манифест SHALL переписываться на каждом запуске, который что-то записал.

Манифест SHALL NOT входить в тарбол: его пишет команда в проект, а не
упаковка в пакет. Иначе версия жила бы в трёх местах и расходилась бы с
двумя первыми.

#### Scenario: Установка в чистый проект

- **WHEN** в проекте без каталога `.claude` выполняется
  `npx @nestlingjs/agent-skill`
- **THEN** рядом с `SKILL.md` появляется `.manifest.json` с версией пакета и
  хэшем каждого положенного файла

#### Scenario: Манифеста нет в тарболе

- **WHEN** выполняется `yarn pack:check`
- **THEN** файла `package/skill/.manifest.json` в тарболе нет

## MODIFIED Requirements

### Requirement: Команда установки кладёт скилл в `.claude/skills/nestling/`

Пакет SHALL объявлять ровно одну команду в поле `bin`, чтобы
`npx @nestlingjs/agent-skill` запускал её без указания имени.

Команда SHALL писать файлы скилла в `.claude/skills/nestling/` относительно
текущего каталога. Флаг `--dir <путь>` SHALL заменять текущий каталог на
указанный. Команда SHALL NOT писать ничего за пределами этого каталога.

Источник файлов SHALL определяться относительно собственного расположения
собранной команды, а не относительно текущего каталога.

#### Scenario: Установка в чистый проект

- **WHEN** в проекте без каталога `.claude` выполняется
  `npx @nestlingjs/agent-skill`
- **THEN** создаются `.claude/skills/nestling/SKILL.md` и
  `.claude/skills/nestling/references/` с четырнадцатью файлами

#### Scenario: Другой каталог

- **WHEN** выполняется `npx @nestlingjs/agent-skill --dir ./apps/api`
- **THEN** файлы создаются в `./apps/api/.claude/skills/nestling/`

### Requirement: Повторная установка не теряет правки пользователя

Команда SHALL сравнивать каждый файл назначения с хэшем, записанным в
манифесте.

- Файла нет — команда SHALL его создать.
- Хэш совпадает с записанным, а содержимое расходится с источником — команда
  SHALL заменить файл содержимым источника и SHALL считать его обновлённым.
- Хэш совпадает с записанным, и содержимое совпадает с источником — команда
  SHALL оставить файл нетронутым.
- Хэш не совпадает с записанным — команда SHALL NOT перезаписывать файл,
  SHALL напечатать его имя и SHALL завершиться кодом 1.

Манифеста рядом с файлами нет — сравнивать не с чем, и команда SHALL
сравнивать файл с источником: совпал — оставить нетронутым, разошёлся —
назвать и завершиться кодом 1.

Флаг `--force` SHALL перезаписывать файлы, которые команда не стала трогать;
с ним команда SHALL завершаться кодом 0.

#### Scenario: Повторный запуск без изменений

- **WHEN** команда выполняется второй раз подряд из того же пакета
- **THEN** ни один файл не переписан, код выхода 0

#### Scenario: Старая копия обновляется молча

- **WHEN** в проекте лежит нетронутая копия скилла с манифестом версии
  `0.3.0`, и команда запущена из пакета `0.4.0`
- **THEN** файлы заменены версией из пакета, код выхода 0, и `--force` не
  понадобился

#### Scenario: Пользователь дописал скилл

- **WHEN** пользователь добавил абзац в `.claude/skills/nestling/SKILL.md` и
  запустил команду после обновления пакета
- **THEN** файл остаётся как есть, команда называет его в выводе и
  завершается кодом 1

#### Scenario: Копия без манифеста

- **WHEN** в проекте лежит копия, поставленная прежней версией команды, и
  манифеста рядом нет
- **THEN** команда сравнивает файлы с источником, называет разошедшиеся и
  завершается кодом 1

#### Scenario: Перезапись по флагу

- **WHEN** файл разошёлся с манифестом и команда выполняется с `--force`
- **THEN** файл заменён версией из пакета, код выхода 0

### Requirement: Команда печатает итог работы

Команда SHALL печатать по итогу четыре числа: сколько файлов создано,
сколько обновлено, сколько совпало и сколько расходится. Расходящиеся файлы
SHALL быть названы поимённо.

#### Scenario: Смешанный итог

- **WHEN** из пятнадцати файлов два созданы, одиннадцать обновлены, один
  совпал и один расходится
- **THEN** вывод содержит эти четыре числа и имя расходящегося файла
