# guide-single-file — дизайн

## Context

`scripts/site/build.mjs` собирает из `docs/guide/` двадцать восемь
страниц: `index.html` по README и по странице на каждую главу. Рядом
сборка кладёт `styles.css` и `app.js` — браузер ищет тему рядом со
страницей. Навигация построена на именах файлов: сайдбар ссылается на
`NN-имя.html`, пейджер — на соседние страницы, а ссылки между главами
переписываются из `./NN-имя.md` в `NN-имя.html`.

Такой вывод нельзя отдать одним куском. Копия страницы без темы рядом
теряет оформление, а без соседей — навигацию.

Подсветка кода сегодня живёт в браузере: `app.js` находит блоки `.code`,
прогоняет текст регулярным выражением на семь групп токенов и
переписывает `innerHTML`. Разметки токенов в самом HTML нет.

## Goals / Non-Goals

**Goals:**

- `docs/.site/` содержит один файл, и этот файл самодостаточен.
- Читатель видит все части и главы в сайдбаре и переходит по ним якорями.
- Код подсвечен без участия браузера.
- Главы остаются нетронутыми: генератор делает всю работу.

**Non-Goals:**

- Не меняем текст и разметку глав.
- Не заводим новую библиотеку подсветки.
- Не решаем публикацию сайта в сети.

## Decisions

### D1. Подсветка выполняется на сборке

Правила из `app.js` переезжают в `build.mjs` и применяются к содержимому
блока при рендере: генератор пишет `<span class="tok-key">` прямо в HTML.

Причина в том, чем файл теперь становится. Его пересылают, печатают,
открывают в режиме чтения и в конвертерах — везде, где JavaScript
выключен или не выполняется вовсе. Подсветка, сделанная на сборке,
переживает все эти способы открыть документ, браузерная — ни одного.

**Отвергнуто:** оставить подсветку в браузере, раз скрипт всё равно
встраивается в файл. Работало бы в браузере и молчало везде остальном.

**Отвергнуто:** взять `highlight.js` или `shiki`. Это новая зависимость
сборки ради результата, который дают уже написанные правила; язык в
гайде один — TypeScript.

### D2. Файл называется `index.html`

Каталог вывода остаётся `docs/.site/`, файл в нём — `index.html`.
Открытие каталога в браузере продолжает работать, `yarn docs:dev` не
меняет адрес, а спека уже называет это имя стартовой страницей.

**Отвергнуто:** `nestling-guide.html` — имя понятнее при пересылке, но
каталог перестаёт открываться сам, а переименовать копию читатель может
и без нас.

### D3. Идентификаторы получают приставку главы

`id` заголовка становится `<slug главы>--<якорь>`: `запуск` из главы 1 —
это `01-first-service--запуск`. Ссылка `./06-config.md#секреты`
переписывается в `#06-config--секреты`, ссылка `./06-config.md` — в
`#06-config`.

Приставка нужна потому, что главы писались как отдельные документы:
«Запуск», «Что дальше» и «Как это лежит в примере» встречаются в них
многократно. В одном файле такие `id` столкнулись бы, и ссылка вела бы в
первую попавшуюся главу.

Разделитель — два дефиса: имена глав и якоря содержат по одному, и
одиночный дефис не отличил бы приставку от продолжения имени.

**Отвергнуто:** дописывать номер к столкнувшимся `id`. Адрес перестаёт
быть предсказуемым и меняется у половины глав, стоит вставить главу в
середину.

### D4. Сайдбар показывает главы всегда, разделы — у читаемой главы

Части и главы перечислены целиком и видны сразу. Подпункты `##`
раскрываются у той главы, которую читатель сейчас видит, — её же пункт
отмечается активным. Ведение делает встроенный скрипт по положению
прокрутки.

Показывать разделы всех глав сразу нельзя: двадцать пять глав дают
больше сотни подпунктов, и сайдбар перестаёт быть навигацией. Без
JavaScript список глав остаётся полным и рабочим — теряется только
подсветка текущего места.

### D5. Пейджер остаётся и ведёт якорями

Внизу главы сохраняются ссылки «← Назад» и «Далее →» — теперь якорные.
Следующая глава лежит ниже по странице, но пейджер отмечает границу глав
и даёт привычный способ читать подряд.

### D6. Каркас становится документом, а не страницей

`layout.html` перестаёт быть шаблоном страницы и описывает весь
документ: `{{title}}`, `{{styles}}`, `{{sidebar}}`, `{{chapters}}`,
`{{script}}`. Тема попадает внутрь через `<style>` и `<script>`, ссылок
`href="styles.css"` и `src="app.js"` в выводе не остаётся.

Главы складываются в `<section class="chapter" id="<slug>">`. Секция
даёт якорь для навигации, границу для разрыва при печати и область, по
которой скрипт понимает, какую главу читают.

## Risks / Trade-offs

- **Файл около 400 KB, и браузер разбирает его целиком.** → Это текст:
  вес сравним с одной фотографией, а разбор происходит один раз при
  открытии. Взамен исчезают двадцать семь переходов между страницами.

- **Поиск браузера идёт по всему гайду сразу.** → Для чтения это
  выигрыш: `Ctrl+F` находит место, которое раньше требовало угадать
  главу. Проигрывает тот, кто искал внутри одной главы; ему остаётся
  сайдбар.

- **Подсветка на сборке раздувает HTML тегами `span`.** → Цена принята:
  она же делает документ независимым от JavaScript.

- **Правила подсветки переезжают из браузера, где их проверял глаз.** →
  Переносим их без изменений и сверяем результат на главах, где кода
  больше всего.

- **Печать даёт двадцать семь глав одной пачкой.** → Разрыв страницы
  ставится перед каждой секцией главы.

## Migration Plan

Миграции нет. Постраничные адреса нигде не записаны: каталог вывода не
отслеживается git, сайт не опубликован, ссылок на `NN-имя.html` за
пределами генератора не существует. Достаточно пересобрать.
