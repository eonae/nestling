# handler-two-forms — design

## Context

Поле `handler` декларации реализовано в `@nestling/pipeline`
(`src/metadata/endpoint.ts`): типы `HandlerFn`, `HandlerWithDeps`,
`HandlerFactory`, `HandlerClass`, объединение `AnyEndpointHandler`;
`makeEndpoint` нормализует форму, хранит `state.deps` для объектной формы
и предоставляет две перегрузки `resolve`: с резолвером и с позиционным
массивом инстансов. Конструкторы деклараций повторяют перегрузки на
каждую форму: `httpEndpoint` в `@nestling/transport.http/src/helpers.ts`
несёт шесть (форма с операцией и анонимная, по три формы хендлера),
`cliEndpoint` и `implement` — по три. Сборка (`@nestling/app`) читает
зависимости объектной формы с декларации и регистрирует класс-хендлер
провайдером модуля-объявителя (запись ideas.md [2026-09-03] «Поле
`handler`», уточнение о `handlerDependenciesOf` и `handlerClassOf`).

`@Injectable` в `@nestling/container/src/providers/injectable.decorator.ts`
ограничивает конструктор типом
`new (...args: UnwrapInjectionTokens<TDependencies>) => I`. Функция с
меньшим числом параметров подходит под тип функции с большим, поэтому
лишний токен в списке проходит; гайд (глава 5) это признаёт.

Снапшот-тесты диагностик есть только у `@nestling/pipeline`
(`type-tests/`: `support/compile.ts`, `support/fixture-kit.ts`,
`diagnostics.spec.ts`, каталог `fixtures`, `BUDGET.md` и раннер бюджета).
Перегрузки `httpEndpoint` снапшотами не покрыты.

Целевое состояние записано: `design/endpoints.md` §3 (две формы, правило
«зависимости из контейнера получает класс»), `design/container.md`
(сверка списка по типам, порядку и длине). Ограничения: обратной
совместимости нет; `yarn verify` включает `type-budget`; тексты — по
`docs-style`, имена — по `conventions.md`.

## Goals / Non-Goals

**Goals:**

- Поле `handler` принимает функцию без зависимостей или класс; объектная
  форма удалена из типов, рантайма, конструкторов, сборки, примеров, гайда
  и спек.
- `@Injectable` отвергает лишний токен на компиляции и нехватку токенов в
  рантайме.
- Диагностики `httpEndpoint` зафиксированы снапшотами в
  `@nestling/transport.http`.

**Non-Goals:**

- Формы юнитов пайплайна, отказы слоя, `Output` и `void` (change
  `layer-fails`).
- Общий пакет тестовой оснастки для type-tests: пока два потребителя,
  оснастка копируется.

## Decisions

### D1. Две формы различаются по значению: функция или класс с `handle`

Рантайм различает формы так же, как юниты пайплайна: значение —
функция; если у неё в прототипе есть метод `handle`, это класс, иначе
функция-хендлер. Объект в поле `handler` — `TypeError` при создании
декларации с текстом: «форма `{ deps, handle }` удалена; объявите класс с
`@Injectable([...])` и методом `handle`». Ошибка называет паттерн
endpoint'а.

Альтернатива — оставить объектную форму как deprecated-обёртку —
отвергнута правилом проекта: старое API удаляется целиком.

### D2. Тип декларации: `handler: HandlerFn | HandlerClass`, `TNeeds` — конструктор

`EndpointDefinition.handler` становится объединением двух типов;
`HandlerWithDeps` и `HandlerFactory` удаляются. `TNeeds` класс-формы —
конструктор, функции — `never`; правило «классы-юниты пайплайна тоже
попадают в `TNeeds`» не меняется. Метод `resolve` остаётся с единственной
сигнатурой `resolve(resolver)`: резолвер создаёт инстанс класса-хендлера
и связывает пайплайн. Позиционная перегрузка удаляется: единственный
потребитель был у объектной формы, а класс тестируется через `new`.

Функция `handlerDependenciesOf`, читавшая `deps` с объекта, удаляется;
`handlerClassOf` остаётся источником класса для регистрации провайдера.
Если в коде эти функции названы иначе, чем в записи ideas.md
[2026-09-03], правится то, что делает ту же работу.

### D3. Перегрузки конструкторов: по одной на форму

`httpEndpoint`: четыре перегрузки — форма с операцией и анонимная, каждая
для функции и класса; порядок прежний, форма с операцией первой.
`implement` и `cliEndpoint`: по две. Реализация перегрузок не меняется:
одна функция, различающая `operation` в словаре.

Альтернатива — одна сигнатура с условным типом по `handler` — отвергнута:
перегрузки дают лучший вывод типов и понятнее в подсказке редактора, а
рост бюджета типов от перегрузок линейный по числу деклараций.

### D4. `@Injectable`: проверка длины в типе, нехватка — ещё и в рантайме

К ограничению конструктора добавляется проверка длины: длина списка
зависимостей должна быть допустимой длиной `ConstructorParameters<T>`.
У конструктора с необязательными параметрами длина — объединение
(`1 | 2`), у конструктора с rest-параметром — `number`; проверка через
`extends` принимает оба случая. Нарушение — литерал
`{ __error: 'Dependency list is longer than the constructor parameter list'; expected: …; actual: … }`
в позиции параметра декоратора, по правилу `pipeline-type-diagnostics`.

Рантайм при декорировании сравнивает `deps.length` с
`constructor.length`. `Function.length` считает параметры до первого
параметра со значением по умолчанию или rest, то есть число обязательных.
Список короче этого числа — `TypeError` с именем класса, ожидаемым и
фактическим числом. Список длиннее в рантайме не проверяется:
необязательный параметр от отсутствующего `Function.length` не отличает,
и проверка давала бы ложные срабатывания.

Альтернатива — только рантайм — отвергнута: ошибка компиляции ближе к
месту правки.

### D5. Type-tests в `transport.http`: копия оснастки, свой каталог фикстур

`@nestling/transport.http` получает `type-tests/` той же формы, что у
`@nestling/pipeline`: `tsconfig.json`, `support/` (копия `compile.ts` и
`fixture-kit.ts` с комментарием-ссылкой на оригинал), `fixtures/`,
`diagnostics.spec.ts`, `__snapshots__`. Каталог входит в `tsconfig.json`
пакета, не входит в `tsconfig.build.json` и перечислен в `ignores`
ESLint — как у `pipeline`. Спек прогоняется обычным `yarn test` пакета.

Набор фикстур: `function-wrong-output`, `class-wrong-output`,
`function-undeclared-fail`, `class-undeclared-fail`, `class-wrong-input`,
`operation-redeclared-input`, `object-form-removed`. Последняя фиксирует
текст, который увидит автор при миграции с объектной формы.

Альтернатива — общий пакет оснастки — отложена до третьего потребителя:
два файла дешевле пакета с полным набором конфигов.

### D6. Миграция примеров и правило именования реализаций

Каждое место `handler: { deps, handle }` становится классом с
`@Injectable([...])` и методом `handle`. Класс-хендлер HTTP-endpoint'а
живёт в файле endpoint'а по `conventions.md` (`<Operation>Handler`).
Для реализаций операций (`implement`) правила именования файла и класса
в `conventions.md` нет; change добавляет его: класс
`<Operation>Handler`, подписчик события — `<Event>In<Feature>Handler` или
эквивалент по решению apply-сессии, записанному в `conventions.md`.
Реализации, объявленные инлайн в файле фичи (`quotas.feature.ts`),
выносятся по файлам, если фича перечисляет больше одной.

### D7. Гайд и README

Глава 5: раздел «Провайдеры без класса» сохраняет `valueProvider` и
`factoryProvider`, сниппет `handler: { deps }` уходит; абзац о лишнем
токене переписывается: теперь это ошибка компиляции. Главы 12, 13, 17 и
все главы, где `grep` находит форму, переводятся на классы; даты плашек
обновляются после сверки. Приложение А: строка таблицы и раздел «Функция
с `deps`» удаляются, `resolve` позиционной формой не упоминается.
Приложение В: строки, ссылающиеся на удалённые сниппеты. README гайда:
таблица «Что проверяется до первого запроса» — строка про список
зависимостей дополняется длиной. README пакетов: таблицы форм и плашки.
`glossary.md`: «Хендлер — поле `handler`: функция или класс».

## Risks / Trade-offs

- [Подписчик события в три строки становится классом] → цена признана в
  записи ideas.md; конвенция именования файлов (D6) не даёт файлу фичи
  разрастись.
- [Проверка длины `@Injectable` ломает конструктор с перегрузками или
  с параметрами, которых нет в списке намеренно] → `ConstructorParameters`
  берёт последнюю перегрузку; в type-tests контейнера фиксируется
  поведение для опциональных, rest и перегруженных конструкторов; при
  ложном срабатывании проверка ослабляется до «не длиннее максимальной
  длины».
- [Снапшоты `transport.http` дрейфуют от версии TypeScript] → тот же риск
  уже принят в `pipeline`; обновление снапшотов — часть обновления TS.
- [Рост инстанциаций от новых фикстур] → фикстуры не входят в `build`;
  бюджет `type-budget` меряет граф пайплайна, а не фикстуры.

## Migration Plan

Пользователей нет, миграционного гайда нет. Порядок внутри change: ядро
(`pipeline`) → конструкторы (`transport.http`, `transport.cli`, `ports`)
→ сборка (`app`) → контейнер → примеры → гайд и README → спеки. После
каждого шага `yarn verify` по затронутым пакетам.

## Open Questions

- Имя файла и класса для реализации операции в `conventions.md`: решает
  apply-сессия по существующим примерам и записывает правило.
- Нужна ли рантайм-проверка нехватки токенов, если тот же случай уже
  ловит компилятор: оставлена для потребителей без типов; если она
  усложняет декоратор заметно, ограничиться типом и записать это
  уточнением в ideas.md.
