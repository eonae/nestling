# Гайд по Nestling

Гайд ведёт от первого сервиса к приложению из нескольких фич,
развёрнутому в нескольких процессах. Каждая глава начинается с задачи,
которую вы и так собираетесь решать, и раскрывает ровно те возможности
фреймворка, без которых задача не решается. Возможности, которые задаче
пока не нужны, глава не называет вовсе: понятие появляется там, где его
объясняют, а не раньше.

Если вы писали на NestJS, начните с [«Из NestJS»](../from-nestjs.md). Он
построчно называет, чем в Nestling записывается то, что вы делали в
Nest.

Читатель гайда знает TypeScript и писал сервисы на Nest или Express.
Термины берутся из [глоссария](../glossary.md). Целевое описание каждой
подсистемы лежит в [`design/`](../design/README.md), причины решений в
[`decisions/ideas.md`](../decisions/ideas.md); главы ссылаются на них в
плашке.

## Как читать

Обе части читайте подряд: главы собирают одно приложение, и каждая
опирается на код предыдущей. Правила именования, которым следуют
примеры, собраны в [conventions.md](../conventions.md).

Задачи, которые встают вне этого порядка, вынесены в
[рецепты](../recipes/README.md): каждый рецепт самостоятелен и читается
по потребности. Список того, что фреймворк проверяет до первого запроса,
лежит отдельным справочником — [guarantees.md](../guarantees.md).

Код глав написан для текста: сниппет начинается с пути в вашем проекте и
читается на месте. Приложения, собранные целиком, лежат в
[`examples/`](../../examples/) — глава ссылается на них там, где это
помогает, но кода примеров не пересказывает.

## Карта понятий

Таблица называет понятие, одно предложение о нём и главу, где оно
вводится. В неё вошли понятия пути; понятия, которые вводит рецепт, в
карту не входят — карта описывает порядок чтения.

| Понятие | Одно предложение | Глава |

| декларация приложения (`makeApp`) | Значение с составом приложения: endpoint'ы корня или фичи, плагины, переключатели, транспорты, политики, привязка конфига | [1](./01-first-service.md) |
| транспорт | Узел графа, который принимает запросы извне и передаёт их в `dispatch` | [1](./01-first-service.md) |
| форма состава корня | Одна из трёх записей `makeApp`: `{ endpoints, providers? }`, `{ endpoints, modules? }` или `{ features }` | [2](./02-composition.md) |
| фича | Единица приложения с собственными endpoint'ами, которую можно вынести в отдельный процесс | [2](./02-composition.md) |
| аргумент сборки | Что собирает этот процесс: выбор фич и значения переключателей | [2](./02-composition.md) |
| схема (Standard Schema) | Любое значение, реализующее Standard Schema v1: zod, valibot, arktype | [3](./03-input.md) |

| хендлер | Функция или класс с методом `handle`, который получает проверенный вход и возвращает `Ok` или `Fail` | [5](./05-handler-class.md) |
| DI-токен | Ключ, по которому у контейнера запрашивают зависимость | [6](./06-repository.md) |

| логгер ядра | Интерфейс `Logger`, корень `RootLogger$` и семейство `Logger$` с `.auto`: через него пишут и ядро, и приложение | [9](./09-logging.md) |
| трасса | Цепочка обработки одного запроса во всех процессах, которых он коснулся; её кладёт в контекст `withTracing()` | [9](./09-logging.md) |
| политика | Инвариант над собранным графом, который проверяется на фазе BUILD | [10](./10-auth.md) |
| досрочный успех | Третий исход pre-шага: `done()` завершает endpoint успехом, не доходя до хендлера | [10](./10-auth.md) |
| HTTP-форма хендлера | Хендлер, чей `meta` содержит запрос, а результат допускает `HttpResponse`: заголовки, cookie и редирект | [10](./10-auth.md) |
| стартовый контекст транспорта | Поля, которые транспорт кладёт в контекст до первого `.pre`-шага; у HTTP это `HttpStartContext` | [10](./10-auth.md) |

| ветка состава | Элементы, попадающие в список при одном из значений переключателя: `Storage.pick({ … })`, `AuditEnabled.when(…)` | [19](./19-select.md) |
