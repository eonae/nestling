## ADDED Requirements

### Requirement: README пакета состоит из шести разделов в фиксированном порядке

`packages/*/README.md` SHALL состоять из шести частей в этом порядке: заголовок
`# @scope/name` с одной-двумя фразами «что это»; плашка статуса; `## Установка`;
`## Минимальный пример`; `## Экспорты`; `## Границы пакета`.

Других заголовков второго уровня SHALL NOT быть. Разделов «Быстрый старт»,
«Основные понятия», «Полный пример», «Справочник API» и «Отличия от NestJS» в
README SHALL NOT существовать: обучение живёт в `docs/guide/`, семантика — в
`docs/design/`.

Раздел `## Минимальный пример` SHALL содержать ровно один блок кода. Пошаговых
объяснений и второго примера в нём SHALL NOT быть.

#### Scenario: Лишний раздел

- **WHEN** в `packages/nestling.container/README.md` есть заголовок
  `## Быстрый старт`
- **THEN** `yarn docs:audit` печатает ERROR с именем файла и именем заголовка

#### Scenario: Нарушенный порядок

- **WHEN** в README раздел `## Экспорты` стоит раньше `## Установка`
- **THEN** `yarn docs:audit` печатает ERROR с фактическим порядком заголовков

#### Scenario: Полный состав

- **WHEN** README содержит шесть разделов из требования в указанном порядке
- **THEN** `yarn docs:audit` по этому файлу молчит

### Requirement: README пакета не длиннее 120 строк

`packages/*/README.md` SHALL содержать не больше 120 строк. Считаются все строки
файла, включая блоки кода, таблицы и пустые строки. Потолок SHALL быть одним для
всех пакетов: послаблений по скоупу, размеру пакета или числу экспортов не
существует.

#### Scenario: Превышение потолка

- **WHEN** `packages/nestling.app/README.md` содержит 2092 строки
- **THEN** `yarn docs:audit` печатает ERROR с фактической длиной и потолком

#### Scenario: Файл в пределах потолка

- **WHEN** README содержит 114 строк
- **THEN** `yarn docs:audit` по длине этого файла молчит

### Requirement: Плашка статуса ведёт на design-док и главу гайда

За первым абзацем README SHALL идти блок цитаты — плашка статуса.

У пакета скоупа `@nestling` плашка SHALL называть статус разработки и содержать
хотя бы одну ссылку в `docs/design/` и хотя бы одну ссылку в `docs/guide/`.
Ссылок каждого вида SHALL быть не больше трёх: перечень из шести design-доков
перестаёт быть ориентиром.

У пакета скоупа `@common` плашка SHALL состоять из одной строки о том, что пакет
внутренний. Ссылок на `docs/design/` и `docs/guide/` у него SHALL NOT быть.

#### Scenario: Плашка без ссылки на гайд

- **WHEN** README пакета `@nestling/outbox` не содержит ссылки в `docs/guide/`
- **THEN** `yarn docs:audit` печатает ERROR с именем файла

#### Scenario: Слишком много ссылок

- **WHEN** плашка README перечисляет шесть design-доков
- **THEN** `yarn docs:audit` печатает ERROR с числом ссылок

#### Scenario: Внутренний пакет

- **WHEN** README пакета `@common/graphs` содержит однострочную плашку без
  ссылок в `docs/`
- **THEN** `yarn docs:audit` по плашке этого файла молчит

### Requirement: Раздел «Экспорты» называет все публичные имена пакета

Раздел `## Экспорты` SHALL называть каждое публичное имя пакета: значения,
классы, типы и интерфейсы.

Множеством публичных имён SHALL считаться множество имён, экспортируемых
барелями, которые названы в поле `exports` файла `package.json` пакета.
Реэкспорты `export * from './x/index.js'` SHALL раскрываться рекурсивно.

Имена, реэкспортируемые из соседнего пакета репозитория, SHALL быть заменены
одной строкой со ссылкой на пакет-источник и в перечне SHALL NOT повторяться.

Каждый подпуть из `exports`, кроме корневого, SHALL быть отдельной группой с
заголовком по имени подпути. Пакет, у которого вместо барреля объявлен `bin`,
SHALL называть команду запуска вместо перечня имён.

#### Scenario: Имя есть в коде, но не в README

- **WHEN** барель `@nestling/transport.http` экспортирует `httpProbes`, а раздел
  «Экспорты» его не называет
- **THEN** `yarn docs:audit` печатает ERROR со списком имён, которых нет в README

#### Scenario: Имя есть в README, но не в коде

- **WHEN** раздел «Экспорты» называет `makeRouter`, а барель пакета такого имени
  не экспортирует
- **THEN** `yarn docs:audit` печатает ERROR со списком имён, которых нет в коде

#### Scenario: Типы считаются наравне со значениями

- **WHEN** барель экспортирует только тип `Handler` и раздел «Экспорты» его не
  называет
- **THEN** `yarn docs:audit` печатает ERROR: тип — такое же публичное имя

#### Scenario: Реэкспорт соседнего пакета

- **WHEN** `@nestling/app` реэкспортирует 37 имён из `@nestling/operations`, а
  его раздел «Экспорты» содержит одну строку со ссылкой на этот пакет
- **THEN** `yarn docs:audit` не требует называть эти 37 имён в README `app`

#### Scenario: Подпуть пакета

- **WHEN** `package.json` объявляет вход `./testing`, а в разделе «Экспорты» нет
  группы с этим именем
- **THEN** `yarn docs:audit` печатает ERROR с именем подпути

### Requirement: Формат перечня экспортов выбирается по бюджету раздела

Раздел `## Экспорты` SHALL занимать не больше 60 строк — не больше половины
потолка файла.

Пока имена помещаются по одному в строку, перечень SHALL быть таблицей из двух
колонок: имя и одна фраза о том, что оно делает. Когда не помещаются, имена
SHALL группироваться по подсистемам: у группы жирным записано имя подсистемы,
рядом ссылка на её design-док, дальше имена через запятую.

Ячейка таблицы SHALL NOT содержать список имён: строка таблицы не переносится, и
перечисление внутри ячейки нарушает перенос текста по ширине.

#### Scenario: Перечень длиннее бюджета

- **WHEN** раздел «Экспорты» занимает 70 строк
- **THEN** `yarn docs:audit` печатает ERROR с фактической длиной раздела

#### Scenario: Крупный пакет группирует имена

- **WHEN** `@nestling/app` называет 168 собственных имён семью группами по
  подсистемам и укладывается в 60 строк
- **THEN** `yarn docs:audit` по этому разделу молчит

### Requirement: Правило структуры README записано одним экземпляром

Состав и порядок разделов README пакета SHALL быть записаны в `docs/README.md` в
разделе «Правила ведения». Скилл `docs-style` SHALL описывать тот же состав
разделов в том же порядке.

#### Scenario: Скилл и правила разошлись

- **WHEN** `docs/README.md` называет шесть разделов, а `.claude/skills/docs-style/SKILL.md`
  называет среди них «Справочник API»
- **THEN** это расхождение с требованием

### Requirement: Раздел «Минимальный пример» содержит один блок кода

Раздел `## Минимальный пример` SHALL содержать ровно один блок кода. Второй
блок означает туториал, а туториал живёт в `docs/guide/`.

#### Scenario: Два блока кода

- **WHEN** в разделе «Минимальный пример» два блока кода
- **THEN** `yarn docs:audit` печатает ERROR с их числом

### Requirement: Проверки README пакетов входят в `docs:audit`

`yarn docs:audit` SHALL проверять `packages/*/README.md` по всем требованиям выше.
Каждое нарушение SHALL быть ERROR и SHALL называть файл, а для расхождения
перечня экспортов — два списка имён: чего нет в README и чего нет в коде.

Проверка SHALL извлекать имена из исходников пакета и SHALL NOT требовать
собранного `dist`: аудит запускается на чистом клоне до `yarn build`.

#### Scenario: Аудит на чистом клоне

- **WHEN** репозиторий склонирован, выполнен `yarn install` и не выполнен
  `yarn build`
- **THEN** `yarn docs:audit` проверяет перечни экспортов и не сообщает об
  отсутствии `dist`

#### Scenario: Репозиторий соответствует правилу

- **WHEN** все восемнадцать README приведены к структуре
- **THEN** `yarn docs:audit` печатает 0 ERROR
