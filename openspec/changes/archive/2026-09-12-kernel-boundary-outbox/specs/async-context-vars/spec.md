## MODIFIED Requirements

### Requirement: `Var.provide` — единственный канонический писатель

Значение переменной SHALL нести метод `provide` в двух формах —
`provide(compute)` и `provide(deps, compute)`. Обе SHALL возвращать
**pre-юнит** обычной формы `PreUnitFn<TReq, { [key]: T }>`: накопительная
типизация, проверка требований к внешнему контексту и проверка конфликтов
полей SHALL остаться прежней машинерией пайплайна.

`compute` SHALL получать контекст pre-юнита (то есть иметь доступ к
`ctx.raw`, `ctx.signal` и уже накопленному `ctx.input`) и SHALL возвращать
значение типа `T` либо промис такого значения. Добавку SHALL строить сама
переменная — из её ключа и результата `compute`.

Форма `provide(deps, compute)` SHALL принимать первым аргументом список
DI-токенов, а вторым — `compute`, получающий контекст первым параметром и
значения зависимостей следующими, по порядку списка. Значения SHALL
резолвиться один раз на `bind()` пайплайна, тем же резолвером, которым
создаются классы-юниты (capability `pipeline-unit-forms`): писатель
остаётся синглтоном, а зависимость без провайдера SHALL давать ту же
ошибку фазы ASSEMBLE, что и незарегистрированный класс-юнит.

Требования писателя к накопленному контексту SHALL объявляться
тип-аргументом у формы без зависимостей (`provide<TReq>(compute)`) и
аннотацией параметра `ctx` у формы с зависимостями: частичного вывода
тип-аргументов в TypeScript нет, а список DI-токенов выводится из
значения.

Сентинел `Family.auto` в списке зависимостей SHALL отвергаться ошибкой,
называющей переменную и предлагающей явный вызов семейства: потребителя,
чьим именем называется член, у писателя нет (capability
`consumer-aware-tokens`).

Провозимая переменная SHALL нести второй конструктор писателя —
`propagated()`, возвращающий pre-юнит той же формы, который берёт значение
**из транспортных атрибутов** (`ctx.raw.attributes`) вместо вычисления. Инвариант при этом
SHALL сохраняться: писатель всегда строится самой переменной, поэтому
«объявлено» и «положено» остаются одним действием. У непровозимой переменной
`propagated()` SHALL отсутствовать в типе и SHALL бросать в рантайме,
называя переменную и требуемую опцию.

Юнит, созданный любым из конструкторов, SHALL нести рантайм-пометку с
переменной, по которой пайплайн узнаёт объявленную переменную на сборке
(capability `pipeline-composition`). Пометка SHALL быть неперечислимой:
значение юнита SHALL оставаться обычной функцией.

Пользовательского API записи в ALS-проекцию SHALL NOT существовать: `set`,
`enrich` и любой другой второй канал записи отсутствуют.

#### Scenario: Писатель — обычный pre-юнит

- **WHEN** написано `makePipeline().pre(RequestId.provide(() => uuid()))`
- **THEN** тип пайплайна пополняется полем `{ requestId: string }`, как у
  любого pre-юнита

#### Scenario: Декларация не может разойтись с фактом

- **WHEN** юнит создан через `RequestId.provide(compute)`
- **THEN** в input попадает поле именно с ключом переменной, а пайплайн
  считает переменную объявленной — оба следствия одного действия

#### Scenario: Писатель читает накопленный контекст

- **WHEN** написано `TenantId.provide((ctx) => ctx.input.identity.tenant)` и
  юнит композирован после слоя, кладущего `identity`
- **THEN** композиция проходит проверку типов, а без слоя-писателя
  `identity` — не компилируется

#### Scenario: Писатель получает зависимость из контейнера

- **WHEN** написано `makePipeline().pre(Tx.provide([Database], (_ctx, db) => db.begin()))`
- **THEN** тип пайплайна пополняется полем `{ tx: Transaction }`, а `db`
  имеет тип значения DI-токена `Database` — класса-моста между контейнером
  и контекстом не требуется

#### Scenario: Зависимость писателя резолвится на bind

- **WHEN** пайплайн с таким писателем передаётся транспорту без `bind()`
- **THEN** это ошибка компиляции; после `bind(resolve)` пайплайн
  исполняется, а `compute` получает то же значение зависимости на каждом
  запросе

#### Scenario: Зависимость писателя не зарегистрирована

- **WHEN** endpoint использует писателя с DI-токеном, для которого в
  приложении нет провайдера
- **THEN** сборка падает на фазе ASSEMBLE, называя паттерн endpoint'а,
  модуль-объявитель и недостающую зависимость

#### Scenario: `Family.auto` в зависимостях писателя отвергается

- **WHEN** написано `Tx.provide([Logger$.auto], …)`
- **THEN** вызов бросает ошибку, называющую переменную и предлагающую
  явный вызов семейства

#### Scenario: Второго канала записи нет

- **WHEN** пользовательский код ищет способ записать переменную вне
  pre-юнита
- **THEN** такого API в экспорте нет: ридер несёт только `get`/`peek`

#### Scenario: Писатель провозимого значения

- **WHEN** написано `makePipeline().pre(TenantId.propagated())`
- **THEN** тип пайплайна пополняется полем `{ tenantId: string }`, а
  пайплайн считает переменную объявленной — так же, как для `provide`

#### Scenario: `propagated()` у непровозимой переменной

- **WHEN** JS-код зовёт `RequestId.propagated()` у переменной, объявленной
  без `propagate`
- **THEN** вызов бросает ошибку, называя переменную и требуемую опцию
