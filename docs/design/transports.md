## 1. Место транспорта

Транспорт — **переводчик провода в значения и обратно**, обычный провайдер
с lifecycle ([composition.md](./composition.md)). Разделение ответственности
жёсткое:

- pipeline и хендлер оперируют **значениями** ([pipeline.md](./pipeline.md));
- всё байтовое — парсинг, framing, сжатие, CORS, content negotiation,
  multipart — **транспорт**;
- `IncomingMessage`/`ServerResponse` и прочие нативные объекты за пределы
  транспорта не выходят.

Контракт транспорта:

- **регистрация** — принимает kernel-декларации endpoint'ов
  (роутинг + io-декларация для парсинга) в фазе WIRE;
- **go-live** — `serve(dispatch, signal)`: в эфир можно выйти, только приняв
  готовый `dispatch`; nullary `listen()` не существует — «ранний listen»
  невозможен структурно;
- **shutdown** — `close()`: дренаж активных соединений, отмена in-flight.

Транспорт строит контекст запроса из провода и отдаёт его пайплайну; о фазах
пайплайна он не знает. Отмена: транспорт взводит `meta.signal` при
дисконнекте клиента; per-request и transport-level сигналы объединяются
через `AbortSignal.any`.

## 2. Приём input: bind-карта и strict-приём

Как единая `input`-схема раскладывается по частям запроса, определяет
**bind-карта** декларации ([endpoints.md](./endpoints.md)): транспорт
карту только читает — считает её конструктор декларации. Payload
собирается **только из канонических мест** с фиксированным приоритетом
`path > пометка > остальное`: поле не в том месте не попадает в payload и
проваливает обычную валидацию. Merge «отовсюду» не существует, как и
ошибок конфликта источников. Query-массивы: повтор ключа → массив;
`query({ multiple: true })` — массив и при одном вхождении.

Тело запроса читается **только когда его требует карта** (источник
«остальное» — body, есть `body()`-пометка или взведён `rawBody`): у `GET`
без пометок тело не буферизуется вовсе. Парсинг тела управляется формой
io-декларации (значение / `stream` / `events` / `multipart`), а не
отдельным route-конфигом.

## 3. Этаж сантехники

Статика, catch-all, CORS, сжатие, редиректы, wildcard-подписки шины — **не
endpoint'ы**: это конфиг/плагины транспорта, без схем и контрактов. Escape
hatch для сырых случаев живёт на этом этаже — параллельной модели деклараций
нет ([endpoints.md](./endpoints.md), онтология).

## 4. HTTP (`@nestling/transport.http`)

- **Роутинг** — find-my-way, паттерны из деклараций (`method` + `path`
  с параметрами).
- **Парсинг по io-декларации**: JSON-тело; NDJSON — входной стрим;
  multipart — busboy, файлы отдаются хендлеру стримами
  (`FilePart { field, filename, mime, stream }`), лимиты (`upload({...})`)
  применяются **во время** парсинга, без буферизации; `rawBody: true` —
  байты в типизированный стартовый контекст одним чтением (значение
  парсится из тех же байтов), несовместим с потоковыми и multipart-формами.
- **Стриминг ответа**: `stream` → NDJSON/chunked; `events` → SSE
  (heartbeat, `id:`, реконнект по `Last-Event-ID`). Mid-stream ошибка —
  политика транспорта + исход `failed` в `finally`.
- **Hardening**: лимит тела `maxBodySize` (раннее прерывание → `413`);
  типизированные ошибки входа → `400` (не `500`); настраиваемые таймауты
  `node:http`; graceful `close()` с дренажом; детали необработанных
  500-ошибок скрыты по умолчанию (`exposeErrorDetails`). Ответ на ошибку
  валидации — стандартные `issues` ([schemas.md](./schemas.md)).
- Порт и опции — из конфиг-секции транспорта, не из литералов в корне.

## 5. CLI (`@nestling/transport.cli`)

Команды вместо маршрутов: `pattern` — имя команды; single-shot
(`execute({ command, args, options })`) и REPL. Сбор недостающего input по
схеме — политика биндинга `missing: 'prompt'`
([endpoints.md](./endpoints.md), §6). Stdin — входной стрим
(`stream('binary')`).

## 6. NATS (`@nestling/transport.nats`)

Inbound + outbound транспорт шины: remote-биндинг портов, queue-groups для
реплик (`command`), broadcast для `event`, JetStream — для durable-подписок.
NATS-специфика (wildcard, ack, KV) не протекает в контрактный API — ядро
знает только `IMessageBus` ([contracts.md](./contracts.md)). Служебные
метаданные (`deadline` как относительный timeout, `idempotencyKey`,
propagate-vars контекста) едут в headers.
