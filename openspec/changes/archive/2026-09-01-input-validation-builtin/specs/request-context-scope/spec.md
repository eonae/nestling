## ADDED Requirements

### Requirement: Scope открывает рантайм пайплайна для любого endpoint'а

Scope запроса SHALL открывать рантайм пайплайна (`executeWithHandler`)
вокруг **всего** тела исполнения: pre-юниты, проверка входа, хендлер,
ответная фаза, проверка контракта и `finally`. Endpoint без `pipeline`
SHALL исполняться тем же рантаймом с пустым пайплайном, поэтому его scope
SHALL быть тем же: `input` равен стартовому контексту транспорта (пустой,
если транспорт ничего не положил), `signal` — сигнал запроса. Второй
точки открытия scope SHALL NOT существовать.

Вложенное исполнение (in-proc вызов endpoint'а внутри запроса, `app.call`
в тесте) SHALL давать вложенный scope: внутренний перекрывает внешний на
своё время жизни, внешний SHALL восстанавливаться по завершении
внутреннего.

#### Scenario: Endpoint без пайплайна

- **WHEN** endpoint объявлен без `pipeline:` и его хендлер зовёт сервис с
  `Ctx(RequestId)`
- **THEN** `peek()` возвращает `undefined`, а `Ctx(Signal).get()` — сигнал
  запроса

#### Scenario: Ответная фаза под тем же scope'ом

- **WHEN** `.catch`- и `.finally`-юниты зовут сервис с ридером
- **THEN** они читают проекцию того же запроса

#### Scenario: Вложенный запрос

- **WHEN** внутри запроса A исполняется запрос B
- **THEN** код B видит проекцию B, а после его завершения код A снова видит
  проекцию A

## REMOVED Requirements

### Requirement: Scope открывают обе точки исполнения ручки

**Reason**: точка исполнения endpoint'а стала одна — рантайм пайплайна;
прямой путь `dispatch` без пайплайна удалён (capability
`dispatch-guarantee`).

**Migration**: поведение для endpoint'а без `pipeline` сохраняется и
описано требованием «Scope открывает рантайм пайплайна для любого
endpoint'а»; код, опиравшийся на scope, не меняется.
