# http-server-resource

## Purpose

HTTP-сервер — отдельный узел графа: ресурс, который держит `http.Server` и
владеет сокетом. Транспорты присоединяются к нему цепочкой обработчиков, так
что один сокет обслуживает несколько транспортов; запрос, который не взял
никто, получает `404`. Порт и хост сервер читает из конфиг-секции с префиксом
по имени экземпляра. `listen()` идёт последним шагом START, после `serve` всех
транспортов, поэтому запрос не приходит раньше присоединения обработчиков.

## Requirements

### Requirement: HTTP-сервер объявляется ресурсом и владеет сокетом

`@nestling/transport.http` SHALL экспортировать `httpServer({ name?, … })`,
возвращающий объявление ресурса, который держит `http.Server`. Объявление
SHALL перечисляться в `transports:` корня наравне с объявлениями
транспортов и SHALL иметь дискриминатор, отличающий его от транспорта.

Сервер SHALL владеть сокетом: `listen`, `address()`, дренаж соединений и
таймауты `node:http` (`requestTimeout`, `headersTimeout`,
`keepAliveTimeout`, `closeTimeout`) SHALL принадлежать ему. `HttpTransport`
SHALL NOT создавать `http.Server` и SHALL NOT вызывать `listen`.

Имя экземпляра SHALL по умолчанию быть `'default'`.

#### Scenario: Приложение с одним сервером

- **WHEN** корень объявлен как `transports: [http()]`
- **THEN** сборка заводит два узла — транспорт и его сервер — и сокет
  открывает сервер

#### Scenario: Транспорт не открывает сокет сам

- **WHEN** внешний код читает поверхность `HttpTransport`
- **THEN** методов `listen` и `address` у него нет

### Requirement: Порт и хост сервер читает из секции по своему имени

Сервер SHALL читать порт и хост из конфиг-секции, префикс которой
строится из имени экземпляра: `HTTP_PORT` и `HTTP_HOST` у сервера
`'default'`, `HTTP_ADMIN_PORT` и `HTTP_ADMIN_HOST` у `name: 'admin'`.
Опций `port` и `host` у `httpServer()` и у `http()` SHALL NOT быть.

Наружу из пакета SHALL уходить `httpServerKeys(name?)` — дескриптор
ключей одного экземпляра. Токен секции SHALL NOT экспортироваться.

Невалидное значение порта SHALL останавливать старт на фазе ASSEMBLE, до
захвата сокета.

#### Scenario: Два сервера читают разные ключи

- **WHEN** корень объявляет `httpServer()` и `httpServer({ name: 'admin' })`,
  а окружение задаёт `HTTP_PORT=3000` и `HTTP_ADMIN_PORT=3001`
- **THEN** первый сервер слушает 3000, второй — 3001

#### Scenario: Эфемерный порт в тестах

- **WHEN** тест задаёт `HTTP_PORT=0` через `vars`
- **THEN** сервер слушает порт, выбранный ядром ОС, и `address()`
  возвращает его после старта

#### Scenario: Невалидный порт падает на сборке

- **WHEN** задан `HTTP_PORT=abc`
- **THEN** старт падает валидацией конфига до захвата сокета

### Requirement: Транспорты присоединяются к серверу цепочкой

`http({ server })` SHALL принимать объявление сервера и присоединяться к
нему. Без `server` фабрика транспорта SHALL объявлять собственный сервер
с тем же именем, что у транспорта.

Присоединённые обработчики SHALL вызываться в порядке присоединения.
Обработчик SHALL сообщать, взял ли он запрос; запрос, который не взял
никто, SHALL получать ответ `404` от сервера.

Один и тот же сервер, названный и элементом `transports:`, и аргументом
`http({ server })`, SHALL регистрироваться один раз: дедупликация идёт по
токену. Два разных объявления сервера с одним именем SHALL быть ошибкой
ASSEMBLE.

#### Scenario: Два транспорта на одном сокете

- **WHEN** корень объявлен как
  `transports: [api, http({ server: api }), graphql({ server: api })]`
- **THEN** оба транспорта обслуживают запросы на одном порту, а запрос,
  не подошедший ни одному, получает `404`

#### Scenario: Сервер объявлен дважды

- **WHEN** объявление `api` перечислено в `transports:` и передано в
  `http({ server: api })`
- **THEN** сборка регистрирует один узел сервера

#### Scenario: Разные серверы с одним именем

- **WHEN** корень объявляет два разных `httpServer({ name: 'api' })`
- **THEN** сборка падает ошибкой ASSEMBLE, называющей имя

### Requirement: Фактический адрес доступен у сервера после старта

Сервер SHALL предоставлять `address(): { host, port } | null`. До `listen`
и после дренажа он SHALL возвращать `null`. Приложение SHALL давать
доступ к объявленным серверам так же, как к транспортам.

#### Scenario: Адрес после старта

- **WHEN** приложение поднято с `HTTP_PORT=0`
- **THEN** `address()` сервера возвращает фактически занятый порт

#### Scenario: Адреса нет до старта

- **WHEN** приложение прошло фазу INIT, но не START
- **THEN** `address()` сервера возвращает `null`
