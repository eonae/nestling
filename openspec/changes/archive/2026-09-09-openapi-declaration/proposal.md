# openapi-declaration

## Why

Документ OpenAPI собирается в CI не тем составом, которым приложение
поднимается в проде. Вход генератора собирается руками:
`discoverEndpoints([...features, ...plugins])` берёт списки единиц из
корня и обходит фазу 0 целиком. Мимо неё остаются выбор фич, ветки
переключателей и замыкание по вызываемым операциям. Приложение с
`switches:` или с выбором фич получает документ, не совпадающий ни с
одной своей сборкой, и расхождение ничем не ловится.

Решение зафиксировано записью
[ideas.md [2026-09-06] «Документ OpenAPI без запуска»](../../../docs/decisions/ideas.md)
и описано в [design/schemas.md](../../../docs/design/schemas.md) §2.1:
документ строится из декларации приложения и аргумента сборки, без графа
и без источников конфига.

## What Changes

- Декларация приложения получает метод `discover(args?): EndpointDiscovery`.
  Он выполняет фазу 0 и останавливается: разбирает аргумент сборки,
  считает значения переключателей, раскрывает ветки, разрешает выбор фич
  с замыканием `includeDeps` и проходит discovery. Метод синхронный:
  источники конфига не поднимаются, граф не строится, транспорты не
  создаются.
- Ошибки аргумента сборки метод бросает те же, что `assemble(args).run()`
  на фазе 0: неизвестное поле, неизвестное имя фичи, значение
  переключателя вне словаря, дубликат паттерна на экземпляре транспорта.
- **BREAKING** `discoverEndpoints(bundles)` перестаёт быть публичным
  экспортом `@nestling/app` и остаётся внутренней функцией пакета.
  Публичный вход в discovery — только декларация приложения, потому что
  только у неё есть аргумент сборки.
- Фаза 0 выносится в одну функцию пакета. Её зовут и `discover()`, и
  сборка: раскрытие веток и выбор фич считаются одним кодом, а не двумя
  похожими.
- Пример `users-service` получает скрипт `src/openapi.ts` и команду
  `yarn openapi`: скрипт кладёт `openapi.json` рядом со сборкой, вызывая
  `buildOpenApiDocument(app.discover(args).endpoints, options)`.
- Глава 12 гайда, README `@nestling/app` и README `@nestling/openapi`
  описывают этот путь; таблица поверхностей в `design/schemas.md` §2.1
  теряет строку про перегрузку.

## Capabilities

### New Capabilities

Новых capability нет: change меняет поверхность существующей discovery.

### Modified Capabilities

- `endpoint-discovery`: публичный вход discovery — метод декларации
  `app.discover(args?)`, а не функция от списка единиц; вход прохода
  определяется аргументом сборки; `discoverEndpoints` уходит из публичных
  экспортов.
- `openapi-document`: чистая функция документируется от результата
  `app.discover(args)`; сценарий сборки документа без поднятия
  приложения переписан на декларацию и аргумент сборки.

## Non-goals

- Перегрузка `buildOpenApiDocument(app, { args, ...options })`. Вызов и
  так однострочный, а вторая сигнатура стоила бы второго типа опций и
  двух объяснений в документации.
- Метод `app.openapi()` на декларации: `@nestling/app` зависел бы от
  satellite-пакета, направление зависимостей обратное.
- Изменения плагина `openapi()`: рантайм-путь остаётся прежним, документ
  по-прежнему строится на фазе ASSEMBLE и отдаётся endpoint'ом.
- Отпечаток состава в файле документа и генерация файла плагином.
- Кэш результата между вызовами: `discover()` считает состав заново, как
  `check()` и `assemble()`.
- AsyncAPI, генерация клиента и любой второй формат документа.

## Impact

- `packages/nestling.app`: метод `discover` у класса `App`, вынос фазы 0
  из `AssembledApp` в общую функцию, снятие экспорта `discoverEndpoints`
  в `src/root/index.ts`, спеки.
- `packages/nestling.openapi`: JSDoc `document.ts` и `types.ts`, README —
  примеры вызова с `app.discover(...)`.
- `examples/users-service`: новый `src/openapi.ts`, команда `openapi` в
  `package.json`, `openapi.json` в `.gitignore`.
- Документация: `docs/design/schemas.md` §2.1,
  `docs/design/composition.md` (раздел про состав приложения как узел
  графа), `docs/guide/12-openapi-and-client.md`, README
  `@nestling/app` и `@nestling/openapi`.
