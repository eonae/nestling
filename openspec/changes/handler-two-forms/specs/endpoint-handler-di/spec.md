# endpoint-handler-di Specification (delta)

## RENAMED Requirements

- FROM: `### Requirement: Хендлер принимается в трёх формах`
- TO: `### Requirement: Хендлер принимается в двух формах`

## MODIFIED Requirements

### Requirement: Хендлер принимается в двух формах

Конструктор декларации SHALL принимать поле `handler` в двух формах:

1. **функция** `(input, meta) => …` — без зависимостей;
2. **класс** с методом `handle`, экземпляр которого создаёт endpoint;
   зависимости класса объявлены `@Injectable`.

Объектной формы `{ deps, handle }` SHALL NOT существовать: объект в поле
`handler` SHALL быть ошибкой компиляции, а из JS — ошибкой при создании
декларации, называющей паттерн endpoint'а и предлагающей класс с
`@Injectable` и методом `handle`. Полей `deps` и `handle` на верхнем
уровне словаря декларации SHALL NOT существовать. Формы SHALL различаться
по значению `handler`: функция без метода `handle` в прототипе — хендлер,
функция с методом `handle` в прототипе — класс. Класс-форма SHALL быть
формой подключения DI, а не вторым стилем деклараций: сама декларация в
обеих формах SHALL оставаться одним и тем же значением. Правило SHALL
совпадать с правилом для юнитов пайплайна: зависимости из контейнера
получает класс.

В обеих формах `meta` SHALL нести зарезервированный ключ `signal` и поля
контекста; ключа `fail` в `meta` SHALL NOT существовать. Возвращаемый тип
SHALL сверяться не только со схемой `output`, но и со списком `errors:`
декларации — в точке декларации, как и сверка со схемами.

#### Scenario: Функция без зависимостей

- **WHEN** объявлено `httpEndpoint({ …, handler: async (input, meta) => Ok.of(…) })`
- **THEN** декларация исполнима сразу, без получения зависимостей

#### Scenario: Класс-хендлер

- **WHEN** объявлено `httpEndpoint({ …, handler: CreateUserHandler })`, где
  `CreateUserHandler` — класс под `@Injectable([UserService])` с методом
  `handle`
- **THEN** код компилируется без `implements`, сигнатура `handle` сверяется
  со схемами `input`/`output` в точке декларации, а декларация несёт
  неразрешённую зависимость

#### Scenario: Объектная форма не принимается

- **WHEN** объявлено `httpEndpoint({ …, handler: { deps: [UserService], handle: (users) => … } })`
- **THEN** это ошибка компиляции, а из JS — ошибка при создании
  декларации, называющая паттерн endpoint'а и класс-форму как замену

#### Scenario: Старые поля не принимаются

- **WHEN** объявлено `httpEndpoint({ …, deps: [UserService], handle: (users) => … })`
- **THEN** это ошибка компиляции, а из JS — ошибка при создании
  декларации, называющая поле `handler`

#### Scenario: Несовпадение сигнатуры хендлера со схемами

- **WHEN** `handle` принимает тип, несовместимый с `InferInput<input>`, или
  возвращает тип, несовместимый с `InferOutput<output>`
- **THEN** это ошибка компиляции в точке декларации

#### Scenario: Несовпадение возвращаемого отказа с errors

- **WHEN** хендлер (в любой из двух форм) возвращает отказ, не объявленный
  в `errors:` декларации
- **THEN** это ошибка компиляции в точке декларации

#### Scenario: В meta нет fail

- **WHEN** хендлер обращается к `meta.fail`
- **THEN** это ошибка компиляции: `meta` несёт `signal` и поля контекста

### Requirement: Тип декларации несёт неразрешённые зависимости

`EndpointDefinition` SHALL иметь тип-параметр неразрешённых зависимостей
(дефолт `never`), симметричный `TNeeds` у `Pipeline`. Форма
`handler`-функции SHALL давать `never`; класс-форма SHALL накапливать
конструктор класса. Параметр SHALL накапливать также **классы-юниты
пайплайна** декларации: после слияния метаданных и декларации в одно
значение это единственное место, где различимы «пайплайн, требующий
`bind`» и «исполнимый пайплайн», а без различия standalone-приём терял бы
compile-time-гарантию.

#### Scenario: Классы-юниты пайплайна попадают в параметр

- **WHEN** объявлена декларация с `pipeline: makePipeline().pre(WithTracing)`,
  где `WithTracing` — класс-юнит
- **THEN** параметр неразрешённых зависимостей содержит `WithTracing`, и
  такая декларация в `server.route(...)` не проходит по типам

#### Scenario: Deps-free декларация

- **WHEN** объявлена декларация с `handler`-функцией
- **THEN** параметр неразрешённых зависимостей — `never`

#### Scenario: Декларация с классом-хендлером

- **WHEN** объявлена декларация с `handler: CreateUserHandler`
- **THEN** параметр неразрешённых зависимостей содержит `CreateUserHandler`

### Requirement: Транспорты принимают только deps-free декларацию

`ITransport.endpoint()` и `HttpTransport.route()` SHALL принимать только
декларацию с параметром неразрешённых зависимостей `never` — так же, как
уже принимают только исполнимый `Pipeline<_, _, never>`. Передача
декларации с зависимостями напрямую транспорту SHALL быть ошибкой
компиляции.

#### Scenario: Декларация с классом-хендлером не проходит в standalone-транспорт

- **WHEN** декларация с `handler: CreateUserHandler` передана в
  `server.route(...)` без получения зависимостей
- **THEN** это ошибка компиляции

#### Scenario: Deps-free декларация проходит

- **WHEN** декларация без зависимостей передана в `server.route(...)`
- **THEN** код компилируется, маршрут регистрируется и обслуживается

## REMOVED Requirements

### Requirement: Внешний вызов каррированной фабрики происходит один раз на сборке

**Reason**: Каррированная фабрика удалена вместе с объектной формой
`handler`; роль «инстанс с зависимостями» выполняет класс-хендлер,
который контейнер создаёт один раз.

**Migration**: `handler: { deps: [A, B], handle: (a, b) => async (input) => … }`
записывается классом `@Injectable([A, B]) class XHandler { constructor(a, b) {}
async handle(input) { … } }` и подключается `handler: XHandler`.

### Requirement: Гашение зависимостей — метод `resolve`, возвращающий новое значение

**Reason**: Требование описывало позиционную форму `resolve([...])` для
каррированной фабрики. Форма удалена; требование заменено на «Получение
зависимостей — метод `resolve`, возвращающий новое значение».

**Migration**: `endpoint.resolve([instances])` заменяется на
`endpoint.resolve((token) => container.getOrThrow(token))`; класс-хендлер в
тестах создаётся через `new` с фейками.

### Requirement: `App` гасит зависимости деклараций контейнером на старте

**Reason**: Требование описывало чтение `handler.deps` с объектной формы.
Заменено на «`App` получает зависимости деклараций из контейнера на
старте» без объектной формы.

**Migration**: Зависимости хендлера объявляются `@Injectable` на классе;
сборка читает их из метаданных класса.

## ADDED Requirements

### Requirement: Получение зависимостей — метод `resolve`, возвращающий новое значение

Декларация SHALL иметь метод `resolve`, возвращающий **новую** декларацию с
параметром неразрешённых зависимостей `never`; исходная декларация SHALL
оставаться неизменной. `resolve` SHALL принимать резолвер-функцию
`(token) => unknown` и SHALL создавать через неё инстанс класса-хендлера и
инстансы классов-юнитов пайплайна. Позиционной формы `resolve([...])`
SHALL NOT существовать: класс-хендлер тестируется через `new` с фейками,
а декларация без зависимостей исполнима без `resolve`.

#### Scenario: Получение зависимостей резолвером

- **WHEN** у декларации с `handler: CreateUserHandler` вызвано
  `resolve((token) => container.getOrThrow(token))`
- **THEN** возвращена deps-free декларация, принимаемая транспортом, а
  хендлер — инстанс, который вернул резолвер для `CreateUserHandler`

#### Scenario: Исходная декларация не мутируется

- **WHEN** одна и та же декларация погашена дважды разными резолверами
- **THEN** получены две независимые декларации, а исходная по-прежнему
  несёт неразрешённые зависимости

#### Scenario: Резолвер не смог отдать зависимость

- **WHEN** резолвер не возвращает значение для класса-хендлера или
  класса-юнита
- **THEN** `resolve` бросает ошибку, называющую класс

#### Scenario: Позиционная форма не принимается

- **WHEN** вызвано `endpoint.resolve([instance])`
- **THEN** это ошибка компиляции, а из JS — ошибка, называющая форму с
  резолвером

### Requirement: `App` получает зависимости деклараций из контейнера на старте

Сборка SHALL на старте для каждой обнаруженной декларации получать
зависимости из контейнера и передавать транспорту deps-free значение.
Зависимость класса-хендлера, недоступная в контейнере, SHALL приводить к
ошибке старта, называющей паттерн endpoint'а, модуль-объявитель,
недостающую зависимость и способ починки, — до начала приёма запросов.

Класс-хендлер SHALL регистрировать сам endpoint: discovery SHALL добавлять
класс из `handler` провайдером класса в модуль единицы, объявившей
endpoint, с атрибуцией к этому модулю. Перечислять класс-хендлер в
`providers:` SHALL NOT требоваться; класс, найденный и в `handler`
декларации, и в `providers:` любого модуля, SHALL быть ошибкой фазы
ASSEMBLE, называющей класс, паттерн endpoint'а и модуль. Два endpoint'а с
одним классом-хендлером SHALL делить один экземпляр.

Резолв классов-юнитов пайплайна SHALL продолжать работать прежним
механизмом (`pipeline.bind`), вызываемым из `resolve` тем же резолвером:
для сборки это один шаг, а не два.

#### Scenario: Класс-хендлер создаёт endpoint

- **WHEN** декларация объявлена с `handler: CreateUserHandler`, а класс не
  перечислен в `providers:` ни одного модуля
- **THEN** приложение поднимается, экземпляр создан контейнером с
  зависимостями из `@Injectable`, узел графа атрибутирован модулю единицы

#### Scenario: Повторная регистрация класса-хендлера

- **WHEN** класс `CreateUserHandler` перечислен в `providers:` модуля и
  указан в `handler` декларации
- **THEN** `run()` завершается ошибкой фазы ASSEMBLE, называющей класс,
  паттерн endpoint'а и модуль

#### Scenario: Зависимость класса-хендлера не зарегистрирована

- **WHEN** класс-хендлер объявлен под `@Injectable([ILogger])`, а
  провайдера для `ILogger` нет
- **THEN** `run()` завершается ошибкой, называющей токен, класс и паттерн
  endpoint'а

#### Scenario: Хендлер тестируется без фреймворка

- **WHEN** класс-хендлер создан через `new` с фейками либо
  функция-хендлер вызвана напрямую
- **THEN** тест не требует ни контейнера, ни транспорта, ни импортов из
  `@nestling/app`
