# @nestlingjs/schema.zod

Всё, что Nestling делает с zod: конвертер схем в JSON Schema, билдеры полей
секций конфигурации и модели, которые компилятор сверяет с уже существующим
TypeScript-типом. Схемы, которые фреймворк пишет сам, написаны на zod, и
этот пакет — их единственный дом.

> 🚧 Активная разработка, API может меняться.
> Дизайн: [`docs/design/schemas.md`](../../docs/design/schemas.md) §1–§2.
> Гайд: [глава 13. Отдать фронтенду документацию и клиент](../../docs/guide/13-openapi-and-client.md).

## Установка

```bash
npm install @nestlingjs/schema.zod zod
```

`zod` — peer-зависимость: конвертер переводит схемы приложения и обязан
работать той же копией валидатора, что и оно.

Ставить пакет руками нужно не всегда. Потребители JSON Schema —
`@nestlingjs/openapi`, `@nestlingjs/mcp` и `@nestlingjs/transport.cli` —
зависят от него сами и берут `zodConverter()` умолчанием. Своя строка
`npm install` нужна тем, кому нужны билдеры, модели или свой конвертер с
другими опциями.

## Минимальный пример

```typescript
import { makeConfig } from '@nestlingjs/app';
import { flag, int } from '@nestlingjs/schema.zod';

export const RelayConfig = makeConfig('relay', {
  batchSize: int().min(1).default(100),
  enabled: flag().default(true),
});
```

## Экспорты

| Имя | Что делает |
|---|---|
| `zodConverter` | возвращает `SchemaDocConverter` с `vendor: 'zod'` поверх `z.toJSONSchema()` |
| `ZodConverterOptions` | опции `z.toJSONSchema` без `io` |
| `withZodDefault` | разрешает список конвертеров потребителя: дописывает `zodConverter()` или уступает конвертеру zod из списка |
| `int` | целое число с приведением строки; границу и умолчание дописывает вызывающий |
| `flag` | булево значение, принимающее и строковую запись (`'true'`, `'1'`, `'on'`) |
| `fromType` | `fromType<T>().makeModel(schema)` — сверка входа схемы с доменным типом на уровне типов |
| `fromScratch` | то же для случая, когда доменного типа ещё нет |
| `makeModel` | `fromScratch().makeModel(schema)` одним вызовом |

`int()` и `flag()` возвращают **открытое** значение zod: границы, описание
и умолчание дописывает вызывающий цепочкой. Позиционных аргументов у них
нет — аргумент закрыл бы остальные ограничения валидатора. Заменителей
тому, что zod даёт одним выражением, здесь тоже нет: обязательная непустая
строка это `z.string().min(1)`, перечисление — `z.enum([…])`, рекорд полей
— `z.object({ … })`.

Схема с преобразованием (`z.string().transform(Number)`, `z.stringbool()`)
описывает две формы: ту, что приходит в запросе, и ту, что получает
хендлер. Какую описать, выбирает вызывающий: генератор OpenAPI передаёт
`io: 'input'` для тела запроса и `io: 'output'` для тела ответа.
CLI-транспорт берёт форму `io: 'input'`: вход команды приходит строками из
argv.

## Границы пакета

Пакет конвертирует только схемы zod. Для другого валидатора нужен свой
конвертер — он передаётся списком `converters` и встаёт рядом с
умолчанием, не вытесняя его. Правило пустого ключа сюда тоже не входит:
`KEY=` сводит к `undefined` ядро, до вызова схемы поля
([config.md §1](../../docs/design/config.md)).
