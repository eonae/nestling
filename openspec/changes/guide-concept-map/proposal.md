# guide-concept-map

## Why

Ревью гайда ([discussions/09](../../../docs/history/discussions/09-framework-review.md))
показало: число понятий гайда велико и почти каждое несёт свою нагрузку,
слияние или переименование понятий стоит дороже, чем экономит. Проблема —
не в числе понятий, а в первом впечатлении читателя с опытом NestJS: он не
видит заранее, какой словарь ему предстоит выучить, и не знает, что часть
понятий Nest уже есть под другим именем. Решение зафиксировано в
`docs/decisions/ideas.md`, запись «[2026-09-04] Подача гайда: соответствия
из NestJS вторым документом, карта понятий в начале»: README гайда сразу
называет приложение Б вторым документом для читателя с опытом Nest и
получает раздел «Карта понятий» — таблицу «понятие → одно предложение →
глава» на один экран, перед тем как читатель откроет часть 1.

## What Changes

- README гайда (`docs/guide/README.md`) сразу после вводного абзаца
  получает одну-две фразы, называющие [приложение Б «Из
  NestJS»](../../../docs/guide/appendix-b-from-nestjs.md) вторым документом
  для читателя с опытом Nest, со ссылкой на файл.
- README гайда получает новый раздел «Карта понятий»: таблица «понятие |
  одно предложение | глава», около 20–25 строк, понятия — из
  [`docs/glossary.md`](../../../docs/glossary.md), порядок — порядок
  появления в гайде (части 1–4). Раздел умещается на один экран и не
  подменяет [приложение В](../../../docs/guide/appendix-c-coverage.md),
  которое остаётся полным списком понятий с главой и файлом примера.
- Проверка, что `yarn docs:preview` собирается без ошибок с новым разделом
  README и что `yarn docs:audit` остаётся на 0 ERROR.

Формулировка принципа прогрессивного раскрытия в
[`docs/design/principles.md`](../../../docs/design/principles.md) уже
изменена отдельной синхронизацией design/ и decisions/ и в объём этого
change не входит.

## Capabilities

### New Capabilities

Нет новых capabilities: изменение — правка состава README гайда, у
которого нет собственной спеки (гайд не описывается требованиями
`openspec/specs`, только структурными инвариантами `docs-preview-guide`).

### Modified Capabilities

- `docs-preview-guide`: ни один существующий сценарий не меняется —
  `scripts/preview/build.mjs` уже сегодня игнорирует заголовки `##`,
  отличные от «Часть N. …» / «Приложения», и строки таблиц, у которых
  первая ячейка не ссылка на главу (см. `design.md`, D3). Раздел «Карта
  понятий» впервые опирается на это поведение как на гарантию, поэтому
  оно становится явным требованием: новый `### Requirement` в дельте
  `specs/docs-preview-guide/spec.md` (операция `ADDED Requirements`,
  существующие требования не меняются).

## Impact

- Код: не затронут (документация, отдельного пакета у гайда нет).
- Документация: `docs/guide/README.md` — единственный редактируемый файл
  вне `openspec/`. Приложения Б и В, главы 1–25, `docs/glossary.md` и
  `docs/design/principles.md` не редактируются этим change (принцип уже
  синхронизирован раньше).
- Спека: `openspec/specs/docs-preview-guide/spec.md` получает новое
  требование при синхронизации спек (см. Capabilities); реализация
  `scripts/preview/build.mjs` не меняется — требование фиксирует уже
  существующее поведение парсера.
- Сборка: `yarn docs:preview` (превью гайда) и `yarn docs:audit`
  (консистентность документации) — оба должны остаться зелёными после
  правки.
- Пользователи: нет (стадия активного проектирования, пользователей у
  Nestling нет).

## Non-goals

- Переименование или слияние понятий гайда (модуль, слой, юнит и другие) —
  каждое несёт отдельное правило, отвергнуто записью ideas.md, на которую
  ссылается Why.
- Новые главы гайда.
- Перевод гайда или его частей.
- Правки глав гайда сверх добавления двух текстов в README: содержимое
  глав 1–25 и приложений А, Б, В не меняется.
