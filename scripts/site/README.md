# Генератор сайта документации

Собирает статический HTML гайда из глав `docs/guide/*.md`. **Не источник
истины**: текст живёт в [`docs/guide/`](../../docs/guide/), а источник
намерения — в [`docs/design/`](../../docs/design/) и
[`docs/decisions/`](../../docs/decisions/).

```bash
yarn docs:build   # собрать один раз
yarn docs:dev     # пересобирать при каждом сохранении
```

Вывод идёт в `docs/.site/` — каталог не отслеживается git и создаётся
каждой сборкой заново. Правка HTML в нём теряется на следующей сборке, а
страница удалённой главы не остаётся лежать в выводе.

```
scripts/site/
├── build.mjs     ← генератор
├── layout.html   ← каркас страницы: шапка, разметка, подключение стилей
├── styles.css    ← оформление; сборка копирует файл в docs/.site/
└── app.js        ← подсветка кода в браузере; копируется туда же
```

## Что делает генератор

- Страница на каждую главу и каждое приложение: имя файла главы плюс
  расширение `.html`. Стартовая страница `index.html` — README гайда.
- Группы сайдбара — заголовки `## Часть N. …` и `## Приложения` из
  README гайда; пункты группы — строки таблицы под заголовком. У
  открытой страницы группа раскрыта, а под ней перечислены её
  `##`-разделы.
- Пейджер внизу страницы ведёт на предыдущую и следующую страницу в
  порядке README.
- Ссылки `./NN-имя.md` переписываются в `NN-имя.html`, якоря
  сохраняются. Ссылки в другие папки `docs/` остаются относительными:
  `guide/` и `.site/` — соседи, и путь у них одинаков.
- Блок кода, который начинается со строки-комментария с путём, получает
  подпись `data-file`; сама строка остаётся в коде.
- `styles.css` и `app.js` копируются в каталог вывода: тема лежит рядом
  с генератором, а браузер берёт её рядом со страницей.

Сборка падает, если состав README и файлы `docs/guide` разошлись:
названная в README глава отсутствует, глава лежит в папке без строки в
README или ссылка `./*.md` ведёт на несуществующую главу. Текст ошибки
называет файл.

## Добавить страницу

1. Новая глава `docs/guide/<NN-имя>.md`.
2. Строка в таблице нужной части в `docs/guide/README.md`.
3. `yarn docs:build`.

## Разметка глав

Главы гайда пишутся обычным Markdown: специальной разметки они не
требуют. Генератор понимает несколько дополнительных блоков этой темы
оформления; пользоваться ими необязательно.

### Заголовки

`#` — заголовок главы, `##` — раздел, `###` — подраздел. Якорь раздела
генератор строит сам из его текста, поэтому подпункты сайдбара работают
без ручной разметки. Явный якорь задаётся так:

```md
## Модульный монолит {#monolith}
```

### Блоки кода

Язык указывается после забора. Подпись над блоком генератор берёт из
первой строки-комментария с путём — той самой, с которой главы гайда
начинают сниппет:

````md
```typescript
// packages/examples.users-service/src/app.ts
export const app = makeApp({ features: [UsersFeature] });
```
````

Строка-комментарий остаётся в коде: скопированный сниппет не теряет
адрес файла.

### Ссылки

Ссылка на соседнюю главу пишется как обычная ссылка на файл:
`[глава 6](./06-config.md#секреты)`. В HTML она станет
`06-config.html#секреты`. Ссылка в другую папку `docs/` пишется
относительным путём и не переписывается: `../design/errors.md`.

### Врезки

```md
:::note Почему «nestling»
Nestling — птенец: младший, лёгкий родственник большого Nest.
:::

:::note good Что осталось
Три знакомых типа провайдеров, `@Injectable`, инъекционные токены.
:::

:::note warn Осторожно
Ранний `listen()` в `@OnInit` невозможен by design.
:::
```

Заголовок врезки обязателен. Вариантов оформления три: без модификатора,
`good` (зелёная) и `warn` (жёлтая).

### Карточки

Сетка на первом экране. Внешний блок — четыре двоеточия, карточки — три.
После `:::card` идут иконка и заголовок, дальше текст карточки.

```md
::::cards
:::card 🧩 Модули — это значения
Не классы с декораторами, а plain-объекты.
:::
:::card ⚡ Жадный контейнер
Весь граф строится на старте.
:::
::::
```

### Таблицы и списки

Обычные GFM-таблицы: генератор сам заворачивает их в горизонтальный
скроллер. Ячейку-отказ помечают классом `{.no}`, тогда она красится в
красный. Вертикальную черту внутри ячейки экранируют: `\|`.

Списки обычные; класс `body` навешивается сам.

### Сырой HTML

Работает как escape-hatch для одиночной вёрстки. Внутри HTML-блока
**не должно быть пустых строк**: пустая строка закрывает блок, и остаток
попадёт в текст.

### Чего генератор не делает

Оформление и подсветку он не строит: `styles.css` и `app.js` правятся
напрямую, сборка только копирует их в вывод. Состав и порядок страниц
берутся из `docs/guide/README.md`, а не из отдельного файла навигации.
