# Генератор документации

Собирает сайт из источников, перечисленных в `sections.mjs`: папок
[`docs/guide/`](../../docs/guide/), [`docs/recipes/`](../../docs/recipes/)
и [`docs/design/`](../../docs/design/), README каталогов
[`packages/`](../../packages/) и шести отдельных страниц корня `docs/`.
**Не источник истины**: текст живёт в этих файлах, а источник намерения —
в [`docs/design/`](../../docs/design/) и
[`docs/decisions/`](../../docs/decisions/).

```bash
yarn docs:build                          # собрать один раз
yarn docs:build --base https://example.org  # ещё и canonical с sitemap.xml
yarn docs:dev                            # поднять сервер и пересобирать при правке
```

Вывод — каталог `docs/.site/`. Он не отслеживается git и создаётся каждой
сборкой заново, поэтому правка HTML в нём теряется на следующей сборке.

```
scripts/site/
├── build.mjs     ← генератор
├── sections.mjs  ← источники сборки и их порядок
├── layout.html   ← каркас страницы раздела: шапка, сайдбар, места под тему
├── home.html     ← каркас стартовой страницы: без сайдбара и пейджера
├── styles.css    ← оформление; сборка встраивает файл в <style>
└── app.js        ← тема, меню, поиск, ведение по прокрутке; встраивается в <script>
```

## Две формы вывода

Сборка идёт в два шага. Первый читает источники и строит модель разделов:
заголовок, секция, слаг, группа, размеченный HTML, заголовки второго и
третьего уровня. Второй печатает модель дважды.

| Форма | Что это | Для кого |
|---|---|---|
| Дерево страниц | `<секция>/<слаг>/index.html` на каждый раздел плюс `index.html`, `search-index.json`, `favicon.svg`, `robots.txt`, `404.html` | Читатель сайта: у раздела свой адрес, `title` и `description` |
| `nestling-docs.html` | Вся документация одним самодостаточным файлом | Пересылка, чтение без сети, печать |

Разница между формами сводится к одной функции — как раздел и якорь
превращаются в `href`.

| Что | Дерево | Один файл |
|---|---|---|
| Ссылка на раздел | `../../design/container/` | `#design--container` |
| Ссылка на заголовок | `../../design/container/#секции` | `#design--container--секции` |
| `id` заголовка | `секции` | `design--container--секции` |
| Поиск | поле в шапке | нет: текст ищет Ctrl+F |

Всё остальное — разметка markdown, врезки, карточки, подписи блоков кода,
подсветка, сайдбар, пейджер — общее.

Оформление и поведение попадают внутрь каждой печатаемой страницы:
`styles.css` встраивается в `<style>`, `app.js` — в `<script>`. Соседних
файлов за темой ни одна страница не спрашивает, поэтому
`nestling-docs.html` открывается в одиночку из любого каталога.

## Источники

`sections.mjs` перечисляет источники в порядке разделов. Источник трёх
видов, плюс `home` — стартовая страница, которая встречается один раз.

| Вид | Что даёт | Откуда состав |
|---|---|---|
| `folder` | Папка: её README открывает источник, каждый файл становится разделом | таблицы README папки |
| `page` | Отдельный файл: один раздел | — |
| `packages` | Каталоги `packages/`: README каждого становится разделом | раздел «Пакеты» файла [`docs/README.md`](../../docs/README.md) |

Поле `section` — первый сегмент адреса: глава лежит по `/guide/01-first-service/`,
оглавление гайда — по `/guide/`. У источника-страницы секции нет, и адрес
короче на сегмент: `/glossary/`. Слаг берётся из имени файла, у пакета —
из имени каталога.

Слаг уникален внутри своего источника, а не по всему сайту: `/design/container/`
и `/reference/nestling.container/` не спорят. Совпадение внутри одного
источника останавливает сборку.

Поле `badge` необязательное: страница источника показывает его в шапке. У
`docs/design/` бейдж говорит, что папка описывает целевое состояние V1.

Адреса `/reference/` без слага у сайта нет: оглавление справочника лежит в
`docs/README.md`, а этот файл адресован тому, кто работает внутри
репозитория, и разделом сайта не становится. Список пакетов читатель видит
в сайдбаре.

## Что делает генератор

- Страница на каждый раздел: `<секция>/<слаг>/index.html` в дереве,
  `<section class="chapter">` в одном файле.
- Группы сайдбара: у папки с заголовками `## Часть N. …` группу даёт
  каждый такой заголовок, а пункты группы — строки таблицы под ним; у
  пакетов группу даёт заголовок `###` раздела «Пакеты»; папка без
  заголовков и страница дают одну группу, названную в `sections.mjs`.
- Заголовки `##` раскрываются у того раздела, который читатель открыл. В
  дереве это известно на сборке, в одном файле — по прокрутке.
- Пейджер в конце раздела ведёт на предыдущий и следующий раздел в
  порядке `sections.mjs`.
- Ссылка на файл, который стал разделом, переписывается в его адрес.
  Любая другая ссылка в репозиторий становится абсолютным адресом на
  GitHub: `decisions/ideas.md`, `history/` и `openspec/` не публикуются, и
  без этого правила плашки design-доков вели бы в 404. Адрес репозитория
  берётся из поля `repository` корневого `package.json`.
- Идентификатор заголовка строится по правилам GitHub: те же ссылки
  читаются и в репозитории. В одном файле он получает приставку раздела.
- Блок кода получает шапку с именем файла и языком, а его текст —
  разметку синтаксиса. Подпись берётся из первой строки-комментария с
  путём; сама строка остаётся в коде.
- `search-index.json`: на каждый раздел заголовок, адрес, заголовки
  второго уровня и текст без разметки. Индекс весит сотни килобайт,
  поэтому страница запрашивает его при первом обращении к поиску, а не
  при загрузке.
- Метаданные страницы: `title` с заголовком раздела, `description` из
  первого абзаца, Open Graph, ссылка на `favicon.svg`. С параметром
  `--base` (или переменной `DOCS_BASE`) добавляется `canonical` и
  печатается `sitemap.xml`; без него ни того, ни другого нет — выдумывать
  домен сборка не будет.

Ссылки между страницами относительные, поэтому дерево открывается и из
корня домена, и из подпути, и с локального сервера.

Сборка падает, если состав оглавления и файлы источника разошлись:
названный в оглавлении файл отсутствует, файл лежит в папке без строки в
README, каталог `packages/` не назван в разделе «Пакеты» или ссылка ведёт
на файл, которого нет в репозитории. Проверка идёт по каждому источнику
отдельно, а текст ошибки называет файл.

## Локальный просмотр

`yarn docs:dev` собирает вывод, поднимает над ним `StaticServer` из
[`@nestlingjs/common.static-server`](../../packages/common.static-server/)
и пересобирает при изменении источника. Порт задаётся переменной
`DOCS_PORT`, по умолчанию 4173.

Сервер обязателен: дерево путей по `file://` не открывается — адрес
`/guide/01-first-service/` браузер ищет на диске от корня. Форма одного
файла печатается тоже, и её можно открыть из каталога вывода двойным
кликом.

## Добавить раздел

1. Новый файл: `docs/guide/<NN-имя>.md`, `docs/recipes/<имя>.md` или
   `docs/design/<имя>.md`.
2. Строка в таблице оглавления той же папки.
3. `yarn docs:build`.

Новый пакет попадает в справочник строкой в разделе «Пакеты» файла
`docs/README.md`. Новый источник целиком — запись в `sections.mjs`.

## Разметка текста

Тексты пишутся обычным Markdown: специальной разметки они не требуют.
Генератор понимает несколько дополнительных блоков этой темы оформления;
пользоваться ими необязательно.

### Заголовки

`#` — заголовок раздела, `##` — его часть, `###` — подраздел. Якорь
генератор строит сам из текста заголовка, поэтому подпункты сайдбара
работают без ручной разметки. Явный якорь задаётся так:

```md
## Модульный монолит {#monolith}
```

В форме одного файла приставку получает и он: в разделе `guide/19-select`
такой заголовок станет `guide--19-select--monolith`.

### Блоки кода

Язык указывается после забора; подсветка знает `typescript`,
`javascript`, `bash` и `json`. Подпись над блоком генератор берёт из
первой строки-комментария с путём — той самой, с которой главы гайда
начинают сниппет:

````md
```typescript
// examples/users-service/src/app.ts
export const app = makeApp({ features: [UsersFeature] });
```
````

Строка-комментарий остаётся в коде: скопированный сниппет не теряет
адрес файла.

### Ссылки

Ссылка на соседний файл пишется как обычная ссылка на файл:
`[глава 7](./07-config.md#секреты)` и `[рецепт](../recipes/cli.md#repl)`.
Куда она приведёт, решает форма вывода. Ссылка в файл, которого нет среди
разделов, ведёт на GitHub — писать её адресом репозитория не нужно.

### Врезки

```md
:::note Почему «nestling»
Nestling — птенец: младший, лёгкий родственник большого Nest.
:::

:::note good Что осталось
Три знакомых типа провайдеров, декораторы ролей, инъекционные DI-токены.
:::

:::note warn Осторожно
Ранний `listen()` при захвате ресурса невозможен by design.
:::
```

Заголовок врезки обязателен. Вариантов оформления три: без модификатора,
`good` (зелёная) и `warn` (жёлтая).

### Карточки

Сетка на первом экране. Внешний блок — четыре двоеточия, карточки — три.
После `:::card` идут иконка и заголовок, дальше текст карточки.

```md
::::cards
:::card 🧩 Модули — это значения
Не классы с декораторами, а plain-объекты.
:::
:::card ⚡ Жадный контейнер
Весь граф строится на старте.
:::
::::
```

Заголовок карточки якорем не становится: он оформление, а не часть
текста.

### Таблицы и списки

Обычные GFM-таблицы: генератор сам заворачивает их в горизонтальный
скроллер. Ячейку-отказ помечают классом `{.no}`, тогда она красится в
красный. Вертикальную черту внутри ячейки экранируют: `\|`.

Списки обычные; класс `body` навешивается сам.

### Сырой HTML

Работает как escape-hatch для одиночной вёрстки. Внутри HTML-блока
**не должно быть пустых строк**: пустая строка закрывает блок, и остаток
попадёт в текст.

### Чего генератор не делает

Оформление он не придумывает: `styles.css` и `app.js` правятся напрямую,
сборка только встраивает их в страницу. Правила подсветки лежат в
`build.mjs` и покрывают четыре языка документации. Состав и порядок
разделов внутри источника берутся из его оглавления, а не из отдельного
файла навигации; порядок самих источников — из `sections.mjs`.
