# http-request-cancellation Specification (delta)

## MODIFIED Requirements

### Requirement: close() взводит сигналы всех in-flight запросов

`close()` HTTP-транспорта SHALL взводить сигналы всех in-flight запросов
немедленно, до начала дренажа соединений. Транспорт SHALL держать реестр
контроллеров выполняющихся запросов: `handle` добавляет контроллер
запроса, событие `'close'` ответа удаляет его, `close()` взводит каждый
оставшийся с причиной `TransportClosingError` и очищает реестр. Сигнал
запроса SHALL быть сигналом собственного контроллера запроса; композиция
с сигналом транспорта через `AbortSignal.any` SHALL NOT создаваться на
запрос.

#### Scenario: Кооперативный хендлер завершается при shutdown

- **WHEN** in-flight запрос обрабатывается хендлером, уважающим
  `meta.signal`, и вызывается `close()`
- **THEN** сигнал запроса взводится сразу, хендлер завершается,
  и `close()` завершается дренажом — без принудительного закрытия
  по `closeTimeout`

#### Scenario: Несколько запросов в полёте при shutdown

- **WHEN** несколько запросов обрабатываются одновременно и вызывается
  `close()`
- **THEN** `meta.signal` каждого из них взводится с причиной
  `transport closing`

### Requirement: Fallback-endpoint'ы без pipeline получают meta.signal

HTTP-транспорт SHALL передавать один и тот же сигнал запроса в контекст
каждого endpoint'а. Endpoint без `pipeline` исполняется рантаймом
пайплайна с пустым пайплайном (capability `dispatch-guarantee`) и SHALL
получать `meta.signal` тем же способом, что endpoint с пайплайном:
отдельного прямого вызова хендлера SHALL NOT быть.

#### Scenario: Endpoint без pipeline при дисконнекте

- **WHEN** endpoint без pipeline обрабатывает запрос и клиент обрывает
  соединение
- **THEN** `meta.signal`, переданный хендлеру, взводится

### Requirement: Обработка сигналов не накапливает ресурсы

Реестр контроллеров SHALL NOT содержать контроллер завершённого запроса,
и на transport-level сигнал SHALL NOT ставиться слушателей на запрос:
обработка N последовательных запросов не увеличивает ни размер реестра,
ни число активных слушателей transport-level сигнала.

#### Scenario: Серия последовательных запросов

- **WHEN** транспорт обработал серию запросов, завершившихся штатно
- **THEN** реестр контроллеров пуст, а число слушателей transport-level
  сигнала не растёт пропорционально числу обработанных запросов
