# pattern-uniqueness Specification (delta)

## ADDED Requirements

### Requirement: Паттерн уникален внутри экземпляра транспорта

Сборка SHALL проверять уникальность пары «экземпляр транспорта, паттерн»
среди обнаруженных деклараций. Совпадение SHALL быть ошибкой фазы
ASSEMBLE.

Проверка SHALL жить в ядре и потому SHALL действовать для всех
транспортов, а не только для HTTP. Экземпляры различаются токеном: один
паттерн на двух разных экземплярах SHALL быть допустим.

#### Scenario: Две фичи объявили один путь

- **WHEN** две фичи объявляют `GET /users` на транспорте по умолчанию
- **THEN** старт падает на фазе ASSEMBLE, до `@OnInit` и захвата ресурсов

#### Scenario: Один паттерн на разных экземплярах

- **WHEN** `GET /health` объявлен на транспорте по умолчанию и на
  `on: 'admin'`
- **THEN** сборка проходит: экземпляры разные

#### Scenario: Метод входит в паттерн

- **WHEN** объявлены `GET /users` и `POST /users`
- **THEN** сборка проходит: паттерны различаются методом

### Requirement: Ошибка дубликата называет обе единицы и оба файла

Сообщение об ошибке SHALL содержать паттерн, имя экземпляра транспорта,
имена обеих объявивших единиц и пути обоих файлов. Ошибка SHALL
называть все найденные дубликаты, а не первый: чинить их по одному за
прогон — не режим работы.

#### Scenario: Текст ошибки

- **WHEN** `GET /users` объявлен фичами `Users` и `Admin`
- **THEN** сообщение называет паттерн, обе фичи и оба файла

#### Scenario: Несколько дубликатов сразу

- **WHEN** в сборке два разных дублирующихся паттерна
- **THEN** ошибка перечисляет оба

### Requirement: Правило шины остаётся отдельным

Правило «у `request` и `command` один владелец» SHALL оставаться
собственной проверкой топологии операций с собственным текстом ошибки.
Проверка уникальности паттернов SHALL NOT заменять и SHALL NOT дублировать
её.

#### Scenario: Два владельца операции

- **WHEN** две фичи реализуют одну операцию `request`
- **THEN** ошибка приходит от проверки топологии операций и называет
  операцию, а не паттерн
