## Why

README пакетов совмещают четыре жанра сразу: описание пакета, туториал из
гайда, семантику из `design/` и справочник имён. У `docs/` статус документа
задаёт папка, а у README пакета папки нет, и правило туда не дотягивается.
Восемнадцать файлов набрали 6277 строк — больше, чем весь `design/` (4318).
Один README `@nestling/app` занимает 2092 строки: это в 2.7 раза длиннее
самого большого design-дока и в 4.6 раза длиннее самой большой главы гайда.

Текст в них не новый, а скопированный. Семейства DI-токенов описаны в четырёх
местах: `docs/design/container.md`, глава 22 гайда, README `container` и README
`app`. Так же устроены пайплайн, секции конфигурации, `assembleTest` и модель
ошибок. Копии расходятся: правка design-дока до README не доходит, и проверки,
которая это заметит, нет ни одной — `docs:audit` про `packages/*/README.md`
сегодня не знает.

Решение записано в
[ideas.md [2026-09-05] «Структура документации»](../../../docs/decisions/ideas.md):
у каждого места один жанр и один читатель, README пакета отвечает на вопрос
«что в пакете сегодня и как называется». Уборка разбита на пять волн, первую
закрыл change `docs-layout-cleanup` (40 в roadmap), README пакетов оставлены
волне 2 — это она.

## What Changes

- **Структура README пакета фиксируется и становится обязательной**: название и
  одна фраза «что это», плашка статуса со ссылками на design-док и главу гайда,
  установка, минимальный пример, таблица экспортов, границы пакета. Других
  разделов нет.
- **Вводится потолок 120 строк** на файл. Сегодня его превышают 12 пакетов из 18.
- **Таблица экспортов называет все публичные имена пакета**, сгруппированные по
  подсистемам. Реэкспорт соседнего пакета занимает одну строку со ссылкой на
  него, а не повторяет его таблицу.
- **Восемнадцать README переписываются** под эту структуру. Уникальный текст
  переезжает по жанру: семантика — в design-док, шаги — в главу гайда; копия
  удаляется.
- **`docs:audit` получает четыре инварианта** по `packages/*/README.md`: состав и
  порядок разделов, потолок строк, плашка статуса, совпадение таблицы экспортов
  с публичным барелем в обе стороны. Нарушение — ERROR.
- **Скилл `docs-style` приводится к тому же описанию структуры.** Сейчас он
  называет разделы «основные понятия» и «справочник API», которых в новой
  структуре нет.
- **Публичные барели `@nestling/app` и `@nestling/operations` сужаются.**
  Перечни оказались втрое больше оценки: 282 имени у `app` вместо 125 и 168 у
  `operations` вместо 67, и полный перечень не укладывался ни в один разумный
  бюджет раздела. Барели переписываются поимённым `export`, из них уходят
  имена без читателя: 114 своих и 56 реэкспортированных у `app`, 14 и 1 у
  `operations`.

## Non-goals

- **Деление гайда на `guide/` и `recipes/`** — волна 3. Текст, который переезжает
  из README в обучающий жанр, попадает в существующую главу.
- **Разделы сайта и публикация README как справочника** — волны 4 и 5. Здесь
  README остаются файлами репозитория и страницами npm.
- **Сужение барелей остальных шестнадцати пакетов.** Их перечни в бюджет
  укладываются, и повода трогать публичный API у них нет. Барели `app` и
  `operations` сужены здесь: без этого требование полноты перечня выполнить
  было нельзя.
- **Корневые `README.md` и `README.ru.md`.** Их сократила волна 1.
- **Перевод README на английский.** Язык остаётся русским.
- **Правка `design/` и гайда шире переезда.** Раздел дописывается там, где текст
  из README не имеет копии; остальное содержимое обеих папок не трогается.

## Capabilities

### New Capabilities

- `docs-package-readme`: жанр и структура README пакета — обязательные разделы и
  их порядок, потолок строк, плашка статуса, полнота таблицы экспортов и
  проверка всего перечисленного в `docs:audit`.

### Modified Capabilities

- `packages-layout`: к правилам сборки пакета добавляется правило корневого
  барреля — поимённый `export` вместо `export *` и определение публичного
  имени через читателя.

`docs-site` собирает сайт из глав гайда и README пакетов не читает,
`docs-terminology` действует на README и без правки.

## Impact

- `packages/*/README.md` — восемнадцать файлов переписываются.
- `docs/design/*.md` — разделы дописываются там, куда переезжает семантика.
- `docs/guide/*.md` — главы дополняются там, куда переезжают шаги; у затронутых
  глав обновляется дата в плашке «сверено с кодом».
- `docs/README.md` — правило структуры README пакета записывается в «Правила
  ведения» единственным экземпляром.
- `.claude/skills/docs-style/SKILL.md` — раздел «README пакета» приводится к тому
  же описанию.
- `.claude/skills/docs-audit/scripts/check.mjs` — добавляются четыре инварианта;
  имена публичных экспортов извлекаются из `src/index.ts` через TypeScript API,
  поэтому проверка не требует собранного `dist`.
- `packages/nestling.app/src/index.ts` и
  `packages/nestling.operations/src/index.ts` переписываются поимённым
  `export`; публичный API этих пакетов сужается.
- `packages/nestling.viz/package.json` теряет поля `main`, `types` и
  `exports`: они вели на `dist/index.js`, которого пакет не собирает.
- Снапшоты диагностик типов в `nestling.app` и `nestling.transport.http`
  обновляются: порядок членов объединения в тексте ошибки следует за порядком
  экспорта.
