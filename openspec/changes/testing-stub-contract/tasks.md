      `stub(RequestContract, impl) → [C.port, Port<C>]` и

## 2. Валидация схемами контракта

- [x] 2.1 Разбор входа листовой схемой `contract.input` (общая процедура для
      обеих сторон): у `call` невалидный payload → `ValidationFailed(issues)`
      возвратом, у `emit` — броском; `impl` не вызывается
- [x] 2.2 Разбор успешного результата листовой схемой `contract.output`;
      значение вне схемы → `ValidationFailed`. В комментарии зафиксировать,
      почему стаб строже боевого local-порта (у стаба нет pipeline'а)
- [x] 2.3 Приведение результата `impl` к `Ok`: голое значение, `Ok` и `Fail`
      обрабатываются как у обычного хендлера
- [x] 2.4 Проверка множества отказов: код возвращённого/брошенного `Fail`
      обязан входить в `errors:` контракта ∪ `VALIDATION_FAILED` ∪ `UNKNOWN`
      ∪ `DEADLINE_EXCEEDED`; иначе бросок с текстом, называющим контракт,
      полученный код и список допустимых
- [x] 2.5 Не-`Fail`-исключение из `impl` пробрасывается как есть (не
      превращается в `UnknownError`)
- [x] 2.6 Рантайм-тесты `stub.spec.ts` по сценариям спеки: невалидный вход,
      разъехавшийся выход, объявленный отказ, незадекларированный код,
      `UnknownError()` как легальный ответ, брошенная ошибка фейка
