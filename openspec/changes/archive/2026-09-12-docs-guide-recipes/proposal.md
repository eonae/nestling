# docs-guide-recipes

## Why

Гайд держит два жанра в одном нумерованном списке. Главы 1–19 составляют
путь: они идут по общему примеру, и каждая опирается на код предыдущей.
Главы 20–27 самостоятельны и решают по одной задаче — оглавление это
признаёт словами «часть 5 читается по потребности», но файлы лежат в той
же нумерации. Читателю предъявляются 27 пунктов и два приложения там, где
подряд читаются 19.

Из общей нумерации следуют три дефекта.

1. **Вставить главу в середину нельзя.** Номер главы упомянут в 18 README
   пакетов и двух design-доках, поэтому новая глава дописывается в конец.
   Так туда попала глава 27 «База данных и транзакция»: на неё ссылаются
   вперёд шесть глав пути (6, 8, 10, 11, 12 и 14), её пример —
   `users-service`, и лежит она в части «Редкие задачи».
2. **Вход для читателя с опытом Nest лежит последним.** Приложение Б
   называет, чем в Nestling записывается то, что читатель делал в Nest.
   README гайда советует начать с него, а файл стоит после всех глав.
3. **Раздел «Что проверяется до первого запроса» лежит в оглавлении
   гайда.** Это справочник по гарантиям фреймворка, а не порядок чтения.

Решение записано в [ideas.md [2026-09-05]](../../../docs/decisions/ideas.md)
«Структура документации», волна 3, и разобрано в
[d/11](../../../docs/history/discussions/11-docs-structure-and-site.md) §3.2.
Волны 1 и 2 закрыты change'ами `docs-layout-cleanup` и
`docs-package-readmes`; это третья.

## What Changes

- **Гайд делится на две папки жанра.** `docs/guide/` — путь из 21 главы в
  двух частях: «Сервис» на примере `users-service` и «Приложение» на
  `app-with-http` и `split-nats`. `docs/recipes/` — восемь самостоятельных
  рецептов без номеров, где имя файла называет задачу: `webhook.md`,
  `cli.md`, `token-families.md`, `config-sources.md`, `ops.md`,
  `standalone.md`, `extending.md`, `alternatives.md`.
- **Глава 27 делится надвое, обе половины встают на путь.** Соединение с
  базой и транзакция запроса идут в часть 1 сразу за главой о слоях и
  политиках, транзакционный emit и приём — в часть 2 за главой о
  событиях. Из шести ссылок вперёд две становятся ссылками назад, а
  самая дальняя ведёт на восемь глав вперёд вместо девятнадцати.
- **Два документа переезжают в корень `docs/`.** Приложение Б становится
  `docs/from-nestjs.md`, раздел «Что проверяется до первого запроса» из
  README гайда — `docs/guarantees.md`.
- **BREAKING: нумерация глав переписывается сквозной.** Имя файла главы
  меняется у большинства глав; ссылки из README пакетов, design-доков и
  между главами переписываются в том же change'е.
- **Генератор сайта берёт список папок-источников** вместо одной
  `docs/guide/`. Вывод остаётся одним файлом `docs/.site/index.html`:
  разделы, URL-пути и поиск — работа волны 4.
- **`docs:audit` проверяет оба списка.** Плашка «сверено с кодом»
  требуется и от рецепта; оглавление сверяется с файлами и для `guide/`, и
  для `recipes/`; плашка README пакета ведёт в `docs/guide/` или в
  `docs/recipes/`.

## Non-goals

- **Разделы сайта, URL-пути, поиск, стартовая страница и метаданные.** Это
  волна 4, change `docs-site-sections` (#60 roadmap). Здесь генератор
  учится читать несколько папок и не больше.
- **Публикация документации.** Волна 5, change `docs-publish` (#61).
- **Переписывание текста глав по существу.** Текст переносится как есть;
  правятся заголовок, номер, плашка и ссылки. Исключение — глава 27: её
  две половины получают по вступлению и по разделу «Проверка».
- **Деление глав 10 «Пускать только своих» (462 строки) и 13 «Выделить
  вторую область» (454).** Размер сам по себе поводом не считается: обе
  главы решают одну задачу и делятся только вместе с ней.
- **Деление главы 12 «Отдать фронтенду документацию и клиент».** Повод,
  записанный в d/11, исчез: в главе 360 строк и шесть разделов вместо 471
  и девяти, а раздел про клиент занимает 75 строк.
- **Правка README пакетов по существу.** Волна 2 их закрыла; здесь
  меняются только ссылки плашек.
- **Перевод документации на английский.**

## Capabilities

### New Capabilities

- `docs-guide-layout`: две папки жанра и два документа корня `docs/`.
  Путь — сквозная нумерация и два разбиения на части, рецепт — имя файла
  вместо номера. Инварианты обоих списков и их проверки в `docs:audit`.

### Modified Capabilities

- `docs-site`: источник сборки — список папок, а не одна `docs/guide/`.
  Ссылки между папками-источниками становятся якорями одного файла.
- `docs-package-readme`: плашка статуса ведёт в `docs/guide/` или в
  `docs/recipes/`; сегодня требуется ссылка именно в `docs/guide/`.
- `examples-layout`: плашка «сверено с кодом `<пример>`» требуется от
  главы пути и от рецепта; сегодня требование записано про главу гайда.
- `docs-terminology`: список целей линтера стиля включает `docs/recipes`,
  `docs/guarantees.md` и `docs/from-nestjs.md`.

## Impact

| Что | Объём |
|---|---|
| `docs/guide/*.md` | 27 глав и два приложения: 19 глав остаются на пути с новым номером, 1 делится надвое, 7 глав и приложение А становятся рецептами, приложение Б — документом корня `docs/` |
| `docs/recipes/` | 9 новых файлов: 8 рецептов и оглавление |
| `docs/guarantees.md`, `docs/from-nestjs.md` | 2 новых файла корня |
| `docs/README.md` | карта папок и правило 7 «Главы гайда сверяются с примерами» |
| `packages/*/README.md` | 18 файлов: ссылка плашки на главу |
| `docs/design/streaming.md`, `docs/design/principles.md` | 2 ссылки на главы, ставшие рецептами |
| `scripts/site/build.mjs` | список папок-источников вместо константы `GUIDE` |
| `.claude/skills/docs-audit/scripts/check.mjs` и `SKILL.md` | проверки плашек, оглавлений и ссылок плашек README |
| `.claude/skills/docs-style/scripts/lint.mjs` и `SKILL.md` | список целей; ссылка на несуществующую главу `11-features.md` |

Код фреймворка и примеры не меняются: `yarn verify` затрагивается только
проверкой `docs:audit`, которая идёт отдельной командой.
