## Why

Успешный статус объявлен в двух местах, и никто их не сверяет. Документ
берёт код из `doc.status` (`packages/nestling.openapi/src/responses.ts`),
а в сеть уходит статус значения `Ok` (`normalizeResponse` в
`packages/nestling.app/src/pipeline/core/pipeline.ts`). Расхождение уже
лежит в нашем же примере: операция `CreateUser` объявляет
`doc: { status: 'created' }`, а ветка `dryRun` возвращает голое значение —
клиент получает 200 там, где документ обещает 201
(`examples/microservice/src/api/operations.ts`,
`examples/microservice/src/users/endpoints/create-user.endpoint.ts`).
Расходятся и умолчания: у endpoint'а без `output` генератор печатает 204, а
рантайм ставит `ok`, то есть 200.

Третьего нет вовсе: разных тел у разных исходов. Слот `output` несёт одну
форму io, поэтому endpoint, отвечающий `200 OK` телом `User` и
`202 Accepted` телом `{ jobId }`, сегодня невыразим.

Тема отложена записью
[deferred.md [2026-08-01]](../../../docs/decisions/deferred.md)
«Типизированный успешный статус декларации»; оба её триггера сработали.
Потребители статуса появились — типизированный клиент и документ OpenAPI, —
а breaking-окно открылось change'ами `http-method-constructors`,
`barrels-by-name` и `schema.zod`
([roadmap.md, строка 84](../../../docs/decisions/roadmap.md)).

## What Changes

- **BREAKING** Поле `doc.status` удаляется. Успешный статус объявляется
  полем `status` верхнего уровня словаря endpoint-декларации и конструктора
  операции: это контракт ответа в сети, а не строка документации.
- Новая форма развилки исходов в слоте `output`:
  `outputs({ ok: User, accepted: JobAccepted, no_content: none() })`. Ключи
  — статусы из словаря ядра, значения — формы io; `none()` объявляет исход
  без тела. Ключи развилки и есть объявленное множество статусов, поэтому
  `status` вместе с развилкой не объявляется.
- Поле `status` принимает ровно один статус: множественность выражается
  развилкой, и двух записей для одного и того же не будет. Умолчание
  прежнее: `ok` при объявленном `output`, `no_content` без него.
- **BREAKING** `Ok` параметризован статусом: `Ok<TValue, TStatus>`.
  `Ok.created(value)` даёт `Ok<T, 'created'>`, `Ok.noContent()` —
  `Ok<null, 'no_content'>`, `new Ok(value)` — `Ok<T, 'ok'>`. Результат
  хендлера с развилкой — дискриминированный юнион по `status`, и проверка
  `result.status === 'accepted'` сужает `value` до типа ветки.
- Голое значение без обёртки `Ok` допустимо, пока исход один, и получает
  его статус от рантайма. При развилке хендлер выбирает исход явно, иначе
  ошибка компиляции.
- Рантайм подставляет голому значению объявленный статус вместо
  сегодняшнего `ok`, валидирует ответ формой того исхода, чей статус несёт
  результат, и заменяет `Ok` со статусом вне объявленного множества на
  `internal_error`: вызов из JavaScript типами не прикрыт.
- Потоковые формы (`stream`, `events`) объявляются только единственным
  исходом: реконнект SSE, поле `sse` и выходная item-цепочка привязаны к
  форме декларации, а у развилки форма исхода известна лишь после
  результата.
- Конструктор декларации проверяет объявление при создании значения:
  развилка пустая или из одного ключа, ключ вне словаря статусов,
  потоковая форма веткой, `none()` вне развилки, `status` вместе с
  развилкой, `status` рядом с `redirect`, `no_content` при объявленном
  `output` — ошибка сразу.
- Документ OpenAPI печатает ответ на каждый объявленный исход — со своей
  схемой и своим media type; ветка `none()` уходит без `content`.
- Типизированный клиент строит таблицу «код → форма ветки», валидирует
  тело схемой пришедшего исхода и отвергает код вне объявленного множества
  как расхождение с декларацией.

## Non-goals

- Не вводит произвольные числовые коды в декларацию. Словарь успешных
  статусов ядра остаётся закрытым (`ok`, `created`, `accepted`,
  `no_content`): декларация транспорт-нейтральна, а число выбирает
  транспорт таблицей `STATUS_MAP`.
- Не трогает коды отказов и их категории (capability `error-values`,
  раздел про словарь статусов) — меняется только успешная половина.
- Не трогает `redirect`: он остаётся полем HTTP-словаря со своими кодами
  3xx, потому что редирект осмыслен только по HTTP.
- Не вводит заголовки на `Ok` — они по-прежнему задаются формой ответа
  транспорта (`HttpResponse`).
- Не снимает запрет на потоковую ветку развилки: перенос настроек
  потокового ответа на ветку — отдельная тема с триггером возврата.
- Не меняет wire-формат тела ошибки: RFC 9457 — отдельный change
  `problem-json` (строка 83 roadmap).
- Не добавляет статусу новых носителей на шине: конверт NATS уже переносит
  `status`, и формат конверта остаётся как есть.

## Capabilities

### New Capabilities

- `declared-success-status`: успешные исходы объявляются декларацией —
  статусом единственного исхода или развилкой «статус → форма», —
  ограничивают тип результата хендлера, проставляются рантаймом и
  сверяются на границе.

### Modified Capabilities

- `io-forms`: слот `output` принимает развилку исходов `outputs(...)` и
  маркер `none()`; media type выводится по каждой ветке отдельно.
- `declaration-doc-metadata`: поле `status` уходит из секции `doc` вместе
  с его проверкой — в `doc` остаются только метаданные документации.
- `error-values`: `Ok` параметризован статусом (`Ok<TValue, TStatus>`), и
  фабрики возвращают уточнённый тип вместо `Ok<T>`.
- `openapi-document`: успешные ответы строятся по объявленным исходам, у
  каждого своя схема и свой media type.
- `typed-http-client`: результат вызова типизирован объявленными исходами,
  тело валидируется схемой пришедшего исхода, а код вне множества
  становится отказом клиента.

## Impact

- `@nestlingjs/operations`: формы io получают `outputs(...)` и `none()` со
  своим описателем; `Ok` с тип-параметром статуса; `Output`/`OutputSync` с
  объявленными исходами; поле `status` в `makeRequest` и проверки
  объявления; `doc.status` удалён.
- `@nestlingjs/app`: поле `status` в `EndpointOptions` и
  `EndpointDefinition`, вывод типа хендлера из развилки, подстановка
  статуса в `normalizeResponse`, выбор схемы валидации по статусу, сверка
  статуса на границе.
- `@nestlingjs/openapi`: `planSuccess` печатает ответ на каждый исход.
- `@nestlingjs/client`: таблица «код → форма ветки», тип результата и
  сверка кода ответа с декларацией.
- `@nestlingjs/transport.http`: `httpCodeOf` и `STATUS_MAP` остаются;
  добавляется проверка «`status` рядом с `redirect`», обновляются README и
  тесты, где статус объявлялся через `doc`.
- `examples/microservice`: `api/operations.ts`, endpoint'ы `create-user`,
  `delete-user`, `ops/subscriptions`.
- Документация: `docs/design/endpoints.md`, `docs/design/errors.md`,
  `docs/design/operations.md`, `docs/design/streaming.md`,
  `docs/guide/06`, `08`, `10`, `11`, `13`, `docs/recipes/ops.md`,
  `docs/recipes/alternatives.md`, README пакетов `operations` и
  `transport.http` — вместе с английскими парами в `docs/en/`.
