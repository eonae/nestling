# composition-model

## Why

Модель композиции сложилась из частей, каждая из которых решала свою задачу,
а вместе они дают словарь, который трудно объяснить целиком.

**Модуль стоит не на своём этаже.** `Module` живёт в `@nestling/container`,
хотя контейнер использует его только как формат ввода: `registerModule`
разворачивает `providers` в плоский список с меткой, обходит `imports` и
забывает модуль. В граф попадает строка `metadata.module`, узлов-модулей
нет. При этом слой приложения дописывает к чужому типу поле `endpoints`
через `AppModule extends Module`, а `makeAppModule` — identity-функция без
рантайм-эффекта: discovery читает поле структурно с любого значения-модуля.
Вопрос «чем особый модуль отличается от обычного» не имеет ответа.

**У фичи нет границы.** `modulesOf` сплющивает фичи в плоский список,
атрибуции «провайдер → фича» не существует, `dependsOn` не сверяется с
графом. Фича `users` может заинжектить `QuotaService` фичи `quotas` напрямую
по токену: в одном процессе это работает, а при разъезде по процессам
ломается. Обещание «код фичи не меняется при split-развёртывании» держится
дисциплиной, а не структурой.

**Роль инфраструктуры не названа.** Сквозные модули уже подключаются
отдельно от фич — через `modules:` корня, — но поле не объясняет, зачем оно,
и не отличается от `features:` ничем, кроме отсутствия имени в словаре
`select`.

**Слова расходятся со смыслом.** `.port` называет вызывающую сторону, тогда
как в гексагональной архитектуре порт — это интерфейс; внутри кода та же
вещь честно зовётся invoker. Роль шины не выражена в типах корня: `nats()`
типизирован как обычный `ITransport` и отличается от `http()` только
токеном. Идентичность токена строковая, включая классы
(`stringifyToken` берёт `constructor.name`), поэтому два однофамильца из
разных пакетов молча делят один токен — а с плагинами из npm это перестаёт
быть теорией.

## What Changes

### Модуль, фича, плагин — три роли с разными правилами

- **`Module` остаётся в `@nestling/container`** и теряет `endpoints`:
  `{ name, providers, dependsOn }`. Контейнеру модуль нужен как группировка
  провайдеров с меткой, и этой роли он соответствует полностью.
- **`Module.imports` переименовывается в `dependsOn`.** Поле не даёт
  доступа к чужим провайдерам — они глобальны, — поэтому имя из Nest вводит
  в заблуждение.
- **`Feature` и `Plugin`** — новые типы слоя приложения. Они **содержат**
  модули, а не наследуют `Module`.
- **Форма обоих** — union: либо `providers`, либо `modules`, не оба.
  `endpoints` живут только на фиче и плагине.
- **`makeAppModule` и `AppModule` удаляются.**
- **`dependsOn` у фичи нет.** Связи между фичами выводятся из объявленных
  операций. У плагина `dependsOn` остаётся: npm-пакет скрывает свои
  внутренние зависимости. Зависимость от параметризованного плагина
  выражается токеном, а не `dependsOn`.
- **Имя плагина совпадает с именем npm-пакета** — иначе два чужих пакета
  роняют сборку коллизией имён.

### Граница фичи становится проверяемой

- **Ребро графа между фичами — ошибка сборки.** Обращаться к другой фиче
  разрешено только операциями. Ребро в плагин разрешено всегда.
- **Модуль, достижимый из двух фич, обязан быть плагином** — иначе карта
  «модуль → владелец» неоднозначна.
- **Discovery сводится к плоскому проходу** по `features` и `plugins`.
  Повторение контейнерного обхода дерева со своей дедупликацией исчезает.

### Композиционный корень

- **`modules:` переименовывается в `plugins:`.**
- **`select` получает объектную форму** `{ features, includeDeps }`.
  Строковая остаётся: выбор приходит из переменной окружения.
  Автоподтягивание замыкается по `request` и `command`, не по `event`.
- **Добавляется `intercom:`** — роль, назначаемая ссылкой на уже
  объявленный транспорт, с требованием `IMessageBus`.
- **Транспорты становятся именованными экземплярами**; декларация называет
  свой через `on:`. Ограничение «один HTTP на сборку» снимается.

### Операции вместо контрактов

- **`makeContract({ kind })` заменяется на `makeRequest`, `makeCommand`,
  `makeEvent`.** Правила видов переезжают из рантайм-проверок в типы.
- **`.port` переименовывается в `.caller`.**
- Слово «контракт» уходит из пользовательского словаря; собирательное имя —
  «операции».

### Токены

- **Токен становится объектом**: идентичность по ссылке, строковый `id` для
  отчётов, ошибок и `toJSON()`.
- **Класс как токен** опознаётся по ссылке; `constructor.name` остаётся
  только для отображения.
- **Члены семейств хранятся структурно**: разбор `'Family:param'` исчезает,
  `.auto` и `.all` становятся выделенными токенами.

### BREAKING

Замен и обёрток нет — стадия активного проектирования. Ломаются:
`makeAppModule`, `AppModule`, `Module.imports`, `Module.endpoints`,
`makeFeature` в прежней форме, `modules:` в корне, `makeContract`,
`Contract.port`, строковые токены.

## Capabilities

### New Capabilities

- **feature-boundary** — проверка рёбер между фичами и правило
  «общий модуль обязан быть плагином».
- **operation-map** — карта операций в отчёте `check()`: что реализовано
  здесь, что уходит наружу, через какой интерком.

### Modified Capabilities

- **module-identity** — модуль без `endpoints`, `imports` → `dependsOn`.
- **feature-bundles** — фича как тип слоя приложения, union
  `providers | modules`, без `dependsOn`.
- **infrastructure-modules** — роль плагина получает имя и поле корня;
  запрет на ambient middleware, хуки и реестр сохраняется.
- **composition-root** — `plugins:`, `intercom:`, объектная форма `select`.
- **contract-declarations** — три конструктора вместо поля `kind`.
- **token-families** — объектные токены и структурные члены семейств.

Затрагиваются без отдельных дельт в черновике: `endpoint-discovery`,
`endpoint-declarations`, `port-invocation`, `port-binding`,
`transport-providers`, `message-bus`, `structural-check`,
`container-module-attribution`.

## Дефекты, которые чинятся попутно

- `modulesOf` дедуплицирует модули по имени и молча: два разных одноимённых
  модуля из разных фич теряют провайдеры и endpoint'ы. Контейнер на такое
  бросает ошибку, но до него значение не попадает. Функция исчезает вместе
  со старой моделью; замена обязана дедуплицировать по ссылке и падать на
  одноимённых разных значениях.
- Ошибка про недостающий транспорт советует положить его в `providers:`
  модуля. Для шины это ведёт к коллизии токена, потому что ветку «шину
  поставил корень» открывает только поле `transports:`.
