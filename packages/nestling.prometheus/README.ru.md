# @nestlingjs/prometheus

Экспозиция метрик приложения в формате Prometheus. Плагин читает снимок
store ядра и отдаёт текст по `GET /metrics`: накопленное держит ядро,
пакету остаётся формат.

> 🚧 Активная разработка, API может меняться.
> Дизайн: [`docs/design/container.md`](../../docs/design/container.md),
> раздел «Метрики ядра».
> Глава гайда: [22. Считать запросы и вызовы между процессами](../../docs/guide/22-metrics.md).

## Установка

```bash
npm install @nestlingjs/prometheus
```

## Минимальный пример

```typescript
import { makeApp } from '@nestlingjs/app';
import { prometheus } from '@nestlingjs/prometheus';
import { http, server } from '@nestlingjs/transport.http';

const api = server();

export const app = makeApp({
  features: [OrdersFeature],
  plugins: [prometheus()],
  transports: [http({ server: api })],
});
```

Настраивать больше нечего: метрики ядра и метрики приложения уже лежат в
`MetricsStore$`, а плагин их сериализует. Адрес экспозиции меняет опция
`prometheus({ path: '/internal/metrics' })`.

## Экспорты

- **Плагин** ([design](../../docs/design/container.md)) — `prometheus`,
  `PrometheusOptions`.
- **Формат** — `serialize`: снимок store в текст экспозиции. Им
  пользуется сам плагин, и он же нужен тому, кто отдаёт метрики иначе.

## Границы пакета

Своих счётчиков пакет не держит: второе накопление рядом с ядром
разошлось бы с ним на первой же записи. Своего HTTP-сервера он тоже не
поднимает — экспозиция живёт на сокете приложения.

Endpoint помечен `detached` и скрыт из документа API: метрики снимает
сборщик, а не клиент. Поэтому политики сборки его не проверяют, а в
OpenAPI его пути нет.

Ряд со значением ноль печатается наравне с остальными: состав рядов
известен сборке, и дашборд с нулём ошибок отличим от дашборда без данных.
Точки имени переходят в подчёркивания, единица измерения уходит в имя
ряда, метки идут в устойчивом порядке — `le` корзины последней. Границы
корзин приходят из объявления метрики, поэтому пакет ничего не считает.

Зависимостей от OpenTelemetry у пакета нет: это один формат экспозиции, а
не модель телеметрии. Push наружу строится на `MetricsStore$.tap(sink)` и
живёт в своём пакете.
