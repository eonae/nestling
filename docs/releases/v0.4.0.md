# 0.4.0

> Все пакеты `@nestlingjs/*` выходят одной версией. В выпуск вошли
> коммиты от тега `v0.3.0` до тега `v0.4.0`, 15 сентября 2026. Старое
> имя удалено вместе с появлением замены: алиасов и обёрток в пакетах
> нет.

## Обновление

```bash
yarn up '@nestlingjs/*'
```

Версия одна на все пакеты: пакет прошлой версии рядом с новым не
работает. Требование к Node прежнее — 24 и выше.

Клиент NATS переехал в peer-зависимости, поэтому приложение с шиной
ставит его само:

```bash
yarn add nats@^2.29.3
```

Туда же переехал `zod`: его объявляют peer-зависимостью девять пакетов,
и приложению он нужен в одной копии с ними:

```bash
yarn add zod@^4.0.0
```

Приложение с сателлитом телеметрии ставит рядом и SDK:

```bash
yarn add @opentelemetry/api @opentelemetry/sdk-trace-base \
  @opentelemetry/sdk-metrics
```

Источник конфигурации поверх Vault ставится отдельно, по надобности:

```bash
yarn add @nestlingjs/config.vault
```

Полный справочник окружения — [compatibility.md](../compatibility.md).

  [раздел](#источник-берёт-координаты-из-другого-источника).
- Очерёдность подъёма источников выводится из `needs`, а порядок списка
  остаётся приоритетом разрешения ключа —
  [раздел](#источник-берёт-координаты-из-другого-источника).

- Природа шины объявляется полем `remote` декларации транспорта, а не

- Отказ под маркером `argv()` печатается в `stderr` без стека, и процесс

- Коннектор NATS собран адаптером вместо приведения через `unknown`, а

- Стороннюю библиотеку пакет объявляет peer-зависимостью: `zod` и SDK

  [раздел](#сторонняя-библиотека--peer-зависимость).
- В `@nestlingjs/eslint-plugin` два новых правила: `conditional-spread`

- Скилл агента называет версию, которую описывает, и пишет манифест

## Ломается молча

Эти изменения компилятор не покажет: код собирается и ведёт себя иначе.

- Очерёдность подъёма источников конфигурации больше не следует порядку
  списка: она выводится из `needs`. Источник, стоявший в списке первым,
  поднимается после того, чьи ключи ему нужны —
  [раздел](#источник-берёт-координаты-из-другого-источника).
- Отказ под маркером `argv()` не доходит до `catch`: граница печатает
  сообщение и завершает процесс. `try`/`catch` вокруг
  `build(argv(process.argv)).run()` перестаёт срабатывать —
  [раздел](#отказ-под-маркером-argv--сообщение-и-код-выхода-1).
- `check()` отказывает там, где раньше печатал отчёт со строкой
  `implemented: false, called: true`. Топология без владельца операции
  перестаёт проходить смок —
  [раздел](#недостижимая-операция--отказ-фазы-build).
- Клиент `nats` не приходит зависимостью транспорта. Установка без него
  проходит, а сборка падает на импорте —
  [раздел](#nats--peer-зависимость-пакета).
- `zod` и SDK телеметрии не приходят зависимостями пакетов. Установка
  без них проходит, а сборка падает на импорте —
  [раздел](#сторонняя-библиотека--peer-зависимость).

## Зависимости пакетов

### Сторонняя библиотека — peer-зависимость

Вид объявления задаёт тот, кто выбирает версию. Пакеты `@nestlingjs/*`
остаются зависимостями друг друга: их версию выбирает репозиторий.
Стороннюю библиотеку выбирает приложение, поэтому она объявляется
peer-зависимостью. Второй копии у неё быть не должно: копии расходятся
типами и внутренним устройством значений, которые пересекают границу
пакета.

Переехали двенадцать объявлений. `zod` — у `app`, `config.vault`,
`drizzle.pg`, `inbox`, `mcp`, `outbox`, `subscriptions`,
`transport.http` и `transport.nats`. `@opentelemetry/api`,
`@opentelemetry/sdk-trace-base` и `@opentelemetry/sdk-metrics` — у
`@nestlingjs/otel`.

```bash
# 0.3.0 — валидатор приходил зависимостью пакета
yarn add @nestlingjs/app @nestlingjs/transport.http
```

```bash
# 0.4.0
yarn add @nestlingjs/app @nestlingjs/transport.http zod@^4.0.0
```

Путь отказа у `zod` виден в конфигурации. Схемы секций ядра написаны
копией, вложенной в `@nestlingjs/app`, схемы приложения — копией
приложения. Конвертер ядро выбирает по полю `~standard.vendor`, и обе
копии отвечают одинаковым `'zod'`. Совпали версии — обошлось;
разошлись — отказ разбора или неверная JSON Schema в документе OpenAPI.

У сателлита телеметрии то же видно в сигнатуре. `SpanExporter` и
`PushMetricExporter` — поля `OtelOptions`, и экспортёров приложение
создаёт своей копией SDK.

`@opentelemetry/resources` и `@opentelemetry/semantic-conventions`
остались зависимостями: `Resource` собирается внутри слоя, а из
семантических соглашений берутся строковые константы имён. Границу
пакета ни то, ни другое не пересекает.

Что ставится рядом с пакетом, называет раздел «Установка» его README.

> Обновление: механическое — `zod@^4.0.0` дописывается в зависимости
> приложения, а приложению с сателлитом телеметрии — ещё три имени
> `@opentelemetry/*`.
> Почему: [ideas.md, `[2026-09-14] Зависимости пакетов: свой пакет в dependencies, библиотека в peerDependencies`](../decisions/ideas.md#2026-09-14-%D0%B7%D0%B0%D0%B2%D0%B8%D1%81%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D0%B8-%D0%BF%D0%B0%D0%BA%D0%B5%D1%82%D0%BE%D0%B2-%D1%81%D0%B2%D0%BE%D0%B9-%D0%BF%D0%B0%D0%BA%D0%B5%D1%82-%D0%B2-dependencies-%D0%B1%D0%B8%D0%B1%D0%BB%D0%B8%D0%BE%D1%82%D0%B5%D0%BA%D0%B0-%D0%B2-peerdependencies).

## Конфигурация

### Источник берёт координаты из другого источника

`ConfigSource` получает поле `needs` — DI-токен секции, значения которой
источнику нужны для подъёма. Проверенные значения приходят аргументом
`init()`.

```typescript
// src/sources/vault.ts — 0.3.0
export const vaultSource: ConfigSource = {
  name: 'vault',
  // Адрес и токен брать неоткуда: читалка ещё не проецировала ни одной
  // секции, и источник лез в process.env сам
  async init(): Promise<void> {
    this.secrets = await read(process.env.VAULT_ADDR, process.env.VAULT_TOKEN);
  },
  get: (key) => this.secrets[key],
};
```

```typescript
// src/sources/vault.ts — 0.4.0
export const vaultSource: ConfigSource<VaultCoordinates> = {
  name: 'vault',
  needs: VaultConfig,
  async init(values): Promise<void> {
    this.secrets = await read(values.addr, values.token);
  },
  get: (key) => this.secrets[key],
};
```

Тип источника стал параметризованным: `ConfigSource<Needs>` объявляет
`needs` и принимает значения секции. Источник без `needs` получает
`undefined` и объявляет `init()` без параметров, как и раньше.

Из объявления выводится очерёдность подъёма. Порядок списка привязок
остаётся приоритетом разрешения ключа и только им: Vault, стоящий в
списке выше `.env`, поднимается после него, потому что берёт оттуда
адрес.

```typescript
// src/main.ts — 0.4.0
await app.build(argv(process.argv)).run({
  config: [
    bind(vault(VaultConfig, { retries: 2 }), { timeout: 3000 }),
    ...defaultSources,
  ],
});
```

Секция координат проецируется из источников, поднятых раньше, и её
значения фиксируются в снимке. Сам Vault про `VAULT_ADDR` не
спрашивается, даже когда привязан без `keys`: иначе координаты Vault
искались бы в самом Vault.

Фаза 0 отказывает до всякого ввода-вывода в трёх случаях: привязки
ссылаются друг на друга через `needs`, секция `needs` не покрыта
поднятыми источниками, секция объявлена `makeConfig.reloadable`.
Сообщение называет источник и недостающие ключи. Подробнее —
[глава 7](../guide/07-config.md) и рецепт
[«Конфиг из файла и без перезапуска»](../recipes/config-sources.md).

> Обновление: механическое — `init()` своего источника получает параметр,
> а чтение `process.env` внутри него заменяется полем `needs`.
> Почему: [ideas.md, `[2026-09-13] Конфигурация: привязки на run(), env() и dotenv() умолчанием, bind(), needs у источника`](../decisions/ideas.md#2026-09-13-%D0%BA%D0%BE%D0%BD%D1%84%D0%B8%D0%B3%D1%83%D1%80%D0%B0%D1%86%D0%B8%D1%8F-%D0%BF%D1%80%D0%B8%D0%B2%D1%8F%D0%B7%D0%BA%D0%B8-%D0%BD%D0%B0-run-env-%D0%B8-dotenv-%D1%83%D0%BC%D0%BE%D0%BB%D1%87%D0%B0%D0%BD%D0%B8%D0%B5%D0%BC-bind-needs-%D1%83-%D0%B8%D1%81%D1%82%D0%BE%D1%87%D0%BD%D0%B8%D0%BA%D0%B0), пункты 6–8.

### `@nestlingjs/config.vault`

Пакет с одним источником: `vault(section, options?)` читает секрет KV v2
одним запросом на фазе 0.

```typescript
// src/main.ts
import { bind, defaultSources } from '@nestlingjs/app';
import { vault, VaultConfig } from '@nestlingjs/config.vault';

await app.build(argv(process.argv)).run({
  config: [
    bind(vault(VaultConfig, { retries: 2 }), { timeout: 3000 }),
    ...defaultSources,
  ],
});
```

Секция `VaultConfig` объявляет `VAULT_ADDR`, `VAULT_TOKEN` под
`secret()`, `VAULT_MOUNT` с умолчанием `secret` и `VAULT_PATH`.
Приложение с двумя хранилищами объявляет свою секцию любой формы,
подходящей под `VaultCoordinates`, и передаёт её тем же аргументом.

Клиента Vault пакет не берёт: запрос идёт штатным `fetch`, а
представляется источник заголовком `X-Vault-Token`. `retries` — число
дополнительных попыток при сетевом отказе и ответе `5xx`; пауза
начинается с 250 мс и удваивается. Ответы `401`, `403` и `404` повтора
не вызывают.

Границы у пакета три: аутентификация одна, наблюдения за секретом нет,
движок читается один — KV v2 по пути `{mount}/data/{path}`. Подробнее —
README пакета и рецепт
[«Конфиг из файла и без перезапуска»](../recipes/config-sources.md).

## Сборка

### Недостижимая операция — отказ фазы BUILD

Вызов операции, которую некому обслужить, отвергается на фазе BUILD.
Проверка переехала из фабрики вызывателя в рецепт семейства, поэтому её
видят оба входа, которые до INIT не доходят: `App.check()` и
`checkTopologies`.

```typescript
// scripts/check.ts — 0.3.0
const report = await app.check(argv(process.argv));
// топология без владельца операции проходила смок и печатала строку
// { operation: 'billing.charge', implemented: false, called: true }
```

```typescript
// scripts/check.ts — 0.4.0
const report = await app.check(argv(process.argv));
// Operation 'billing.charge' (kind 'request') is injected as '.caller',
// but no selected feature implements it and this build has no intercom,
// so the call has nowhere to go…
```

Отказ считается по двум условиям сразу: co-located реализации нет, и
шина не доставляет за пределы процесса. При remote-шине отсутствие
местного владельца законно — он может жить в другом процессе, и его
недоступность остаётся обычным отказом доставки. Событие исключением не
перестаёт быть: broadcast без подписчиков законен.

Строку «у каждой вызываемой операции есть владелец или шина»
[guarantees.md](../guarantees.md) обещал фазой BUILD и раньше — код
пришёл к обещанию. Подробнее — [глава 20](../guide/20-split.md).

> Обновление: требует решения — топология, которая раньше доходила до
> INIT, теперь отвергается на сборке: в аргумент добавляется фича-владелец
> либо выбор замыкается по вызовам через `includeDeps`.
> Почему: [ideas.md, `[2026-09-14] Разбор отчёта об обновлении до 0.3.0`](../decisions/ideas.md#2026-09-14-%D1%80%D0%B0%D0%B7%D0%B1%D0%BE%D1%80-%D0%BE%D1%82%D1%87%D1%91%D1%82%D0%B0-%D0%BE%D0%B1-%D0%BE%D0%B1%D0%BD%D0%BE%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B8-%D0%B4%D0%BE-030-%D0%B7%D0%B0%D0%BC%D0%B5%D1%82%D0%BA%D0%B0-020-%D0%B2%D0%B5%D1%80%D1%81%D0%B8%D1%8F-%D1%83-%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%B0-%D0%B4%D0%BE%D1%81%D1%82%D0%B8%D0%B6%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D1%8C-%D0%BD%D0%B0-%D1%81%D0%B1%D0%BE%D1%80%D0%BA%D0%B5), пункт 5.

### Природа шины — поле объявления

`BusDeclaration` получил обязательное поле `remote`. Признак `remote` у
`IMessageBus` удалён: способностью экземпляра природа шины быть
перестала, потому что на фазе BUILD экземпляров ещё нет.

```typescript
// src/bus/my-bus.ts — 0.3.0
export class MyBus implements IMessageBus {
  readonly remote = true;
  readonly durable = false;
  // …
}
```

```typescript
// src/bus/my-bus.ts — 0.4.0
export class MyBus implements IMessageBus {
  readonly durable = false;
  // …
}

export const myBus = (): BusDeclaration =>
  transportValue(MyBus$, new MyBus(), {
    capabilities,
    bus: true,
    remote: true,
  });
```

У экземпляра остаётся `durable`. Это та же развязка, что у
`capabilities` транспорта: данные, нужные проверке сборки, лежат в
объявлении. Встроенный `nats()` объявляет `remote: true` сам, и
приложение, которое пользуется им, правок не требует.

> Обновление: механическое — своя реализация шины переносит `remote` из
> класса в объявление транспорта.
> Почему: [ideas.md, `[2026-09-14] Разбор отчёта об обновлении до 0.3.0`](../decisions/ideas.md#2026-09-14-%D1%80%D0%B0%D0%B7%D0%B1%D0%BE%D1%80-%D0%BE%D1%82%D1%87%D1%91%D1%82%D0%B0-%D0%BE%D0%B1-%D0%BE%D0%B1%D0%BD%D0%BE%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B8-%D0%B4%D0%BE-030-%D0%B7%D0%B0%D0%BC%D0%B5%D1%82%D0%BA%D0%B0-020-%D0%B2%D0%B5%D1%80%D1%81%D0%B8%D1%8F-%D1%83-%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%B0-%D0%B4%D0%BE%D1%81%D1%82%D0%B8%D0%B6%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D1%8C-%D0%BD%D0%B0-%D1%81%D0%B1%D0%BE%D1%80%D0%BA%D0%B5), пункт 5.

## Точка входа

### Отказ под маркером `argv()` — сообщение и код выхода 1

Вход, получивший `argv(process.argv)`, завершает процесс сам не только
на `--help`, но и на отказе. Сообщение уходит в `stderr` без стека, код
выхода — `1`. Правило действует у трёх входов: `build(…).run()`,
`discover(…)` и `check(…)`.

```bash
# 0.3.0
node dist/main.js --features orders
# node:internal/process/promises:394
#             triggerUncaughtException(err, true /* fromPromise */);
#             ^
# Error: Config section 'vault' is not covered by any bound source
#     at project (/app/node_modules/@nestlingjs/app/dist/config/reader.js:214:11)
#     … ещё двенадцать кадров внутренностей пакета
```

```bash
# 0.4.0
node dist/main.js --features orders
# Error: Config section 'vault' is not covered by any bound source
#   caused by: Error: VAULT_ADDR, VAULT_TOKEN
echo $?  # 1
```

Цепочка `cause` разворачивается в текст: каждый уровень занимает свою
строку с отступом. Отказ конфигурации и отказ конструктора несут причину
в `cause`, и без неё сообщение верхнего уровня не называет виноватого.
Стека в тексте нет — кадры адресованы автору фреймворка, а текст читает
автор приложения.

Объектная форма аргумента поведения не меняет: встроенное приложение и
тест ловят промис сами, и процесс им не принадлежит. Подробнее —
[глава 19](../guide/19-select.md).

> Обновление: требует решения — приложение, которое ловило отказ вокруг
> `run()`, переходит на объектную форму аргумента; точка входа под
> маркером оставляет печать и выход границе.

## Транспорт NATS

### `nats` — peer-зависимость пакета

Клиент брокера ставит потребитель, версией под свой брокер. Манифест
`@nestlingjs/transport.nats` приведён к тому, что README пакета обещает
читателю.

```bash
# 0.3.0 — клиент приходил зависимостью транспорта
yarn add @nestlingjs/transport.nats
```

```bash
# 0.4.0
yarn add @nestlingjs/transport.nats nats@^2.29.3
```

> Обновление: механическое — `nats` дописывается в зависимости
> приложения; диапазон `^2.29.3`.

### Коннектор собран адаптером

`defaultConnector` собирает границу `NatsLike` из `NatsConnection` явно:
`headers()` берётся импортом модуля, `StreamInfo` и `ConsumerInfo`
разворачиваются до конфигурации, `ack_policy` переводится в значение
перечисления клиента. Приведение через `unknown` ушло — расхождение с
клиентом обязан ловить компилятор.

Долговечная подписка идёт упрощённым API потребителей:
`js.consumers.get(stream, durable)` и `consume()` вместо
`js.subscribe(subject, opts)`. Граница `NatsJetStreamLike.subscribe`
осталась прежней; сменилось то, чем адаптер её исполняет.

Приложения это не касается: формы io, конверт вызова, окно
дедупликации и отображение на subject не менялись.

> Почему: [ideas.md, `[2026-09-12] Коннектор к живому клиенту nats: адаптер вместо каста`](../decisions/ideas.md#2026-09-12-%D0%BA%D0%BE%D0%BD%D0%BD%D0%B5%D0%BA%D1%82%D0%BE%D1%80-%D0%BA-%D0%B6%D0%B8%D0%B2%D0%BE%D0%BC%D1%83-%D0%BA%D0%BB%D0%B8%D0%B5%D0%BD%D1%82%D1%83-nats-%D0%B0%D0%B4%D0%B0%D0%BF%D1%82%D0%B5%D1%80-%D0%B2%D0%BC%D0%B5%D1%81%D1%82%D0%BE-%D0%BA%D0%B0%D1%81%D1%82%D0%B0).

## Линтер

`@nestlingjs/eslint-plugin` получил два правила, оба уровня `error`.

`conditional-spread` ловит условную примесь в объектном литерале.
Тернарник с пустым литералом переписывается автофиксом, но только когда
тест булев по форме; примесь через `&&` с небулевым тестом сообщает о
ловушке нуля и пустой строки.

```typescript
// src/http/options.ts — было
const options = { ...(verbose ? { level: 'debug' } : {}), ...(port && { port }) };
```

```typescript
// src/http/options.ts — стало
const options = {
  ...(verbose && { level: 'debug' }),
  ...(port !== undefined && { port }),
};
```

`no-process-globals` запрещает `process.env` и `process.argv` в
исходниках. Окружение доходит до приложения источником `env()`,
командная строка — маркером `argv()`. Разрешена одна форма:
`process.argv` непосредственным аргументом `argv()`. Законное чтение —
шов адаптера, скрипт, клиент вне контейнера — глушится директивой
`eslint-disable` с причиной в самом файле.

Пресета у плагина нет: конфиг подключает правила поимённо. Подробнее —
[conventions.md](../conventions.md) и README пакета.

> Обновление: механическое — примеси переписываются связкой `&&` с явным
> сравнением, чтение глобали процесса заменяется источником `env()` либо
> глушится директивой с причиной.
> Почему: [ideas.md, `[2026-09-12] Разбор обзоров d/10 и d/13`](../decisions/ideas.md#2026-09-12-%D1%80%D0%B0%D0%B7%D0%B1%D0%BE%D1%80-%D0%BE%D0%B1%D0%B7%D0%BE%D1%80%D0%BE%D0%B2-d10-%D0%B8-d13-%D1%81%D0%B5%D0%BC%D1%8C-change%D0%B5%D0%B9-%D0%B8-%D0%BE%D0%B4%D0%BD%D0%BE-%D0%BE%D1%82%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5), пункт 11,
> и [ideas.md, `[2026-09-13] Аргумент сборки: argv() по схеме декларации`](../decisions/ideas.md), пункт 6.

## Скилл агента

`npx @nestlingjs/agent-skill` пишет рядом с файлами скилла манифест
`.manifest.json` — версию пакета и хэш каждого положенного файла. По нему
повторная установка отличает правленый файл от просто старого:

- хэш файла манифест признаёт — файл заменяется новой версией молча;
- хэш не признан — команда называет файл, оставляет его как есть и
  завершается кодом 1; `--force` перезаписывает.

У копии, поставленной прежней версией команды, манифеста нет.
Сравнивать не с чем, поэтому один `--force` — цена первого обновления.

Текст скилла называет версию Nestling, которую описывает, и агент
сверяет её с версией `@nestlingjs/app` в `package.json` проекта.
Разошлись — агент говорит об этом и предлагает переустановку.

Состав вырос до четырнадцати файлов: каталог пакетов переехал в
`references/packages.md`, появились справочники наблюдаемости и
хранилища. Одиннадцать мест переписаны на формы 0.3.0 — справочник
конфигурации целиком, `doc: { status }`, строковая форма `build('users')`
и привязки в матрице топологий.

> Обновление: механическое — первое обновление скилла идёт с `--force`,
> дальше манифест есть и обновления идут молча.
> Почему: [ideas.md, `[2026-09-14] Разбор отчёта об обновлении до 0.3.0`](../decisions/ideas.md#2026-09-14-%D1%80%D0%B0%D0%B7%D0%B1%D0%BE%D1%80-%D0%BE%D1%82%D1%87%D1%91%D1%82%D0%B0-%D0%BE%D0%B1-%D0%BE%D0%B1%D0%BD%D0%BE%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B8-%D0%B4%D0%BE-030-%D0%B7%D0%B0%D0%BC%D0%B5%D1%82%D0%BA%D0%B0-020-%D0%B2%D0%B5%D1%80%D1%81%D0%B8%D1%8F-%D1%83-%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%B0-%D0%B4%D0%BE%D1%81%D1%82%D0%B8%D0%B6%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D1%8C-%D0%BD%D0%B0-%D1%81%D0%B1%D0%BE%D1%80%D0%BA%D0%B5), пункт 4.

## Для тех, кто собирает репозиторий

Проверка репозитория стала графом задач, а не расписанием. `typecheck`,
`lint` и `test` объявили `dependsOn: ["^build", "build"]`, параллелизм по
умолчанию — шесть задач, каталог кэша nx вынесен из рабочего дерева:
сессия в новом worktree больше не начинает со 170 секунд.

Сборка перестала проверять типы. JavaScript выпускает swc, декларации —
пофайловый эмиттер TypeScript, а `typecheck` остался единственным
тайпчеком за прогон. Отсюда `isolatedDeclarations: true` в базе и явные
аннотации у публичных экспортов: 33 места в `app`, 8 в `operations`, 7 в
`transport.http`, 1 в `container`. Исключение одно — `drizzle.pg`
собирает `tsc`.

`skipLibCheck: true` переехал в `tsconfig.base.json`, а строгий проход
получил своё имя: `verify:strict` проверяет `typecheck` без этого флага
по собранному `dist`. Он живёт в релизном пути, а не в каждом прогоне.

Два метода `BuiltApp` с вычисляемыми именами объявлены слиянием
деклараций: рядом с `declare class BuiltApp` в `.d.ts` теперь стоит
`export interface BuiltApp`. Набор методов и их сигнатуры прежние.

`yarn verify` получил проверку раскладки зависимостей.
`scripts/boundary/manifest-deps.mjs` читает манифест каждого публикуемого
пакета и печатает внешнее имя, попавшее в `dependencies` мимо списка
исключений. Список — константа с причиной у каждого из пяти имён:
`busboy`, `find-my-way`, `@opentelemetry/resources`,
`@opentelemetry/semantic-conventions` и `@standard-schema/spec`.
Проверка читает манифесты, а не собранные файлы, поэтому идёт на чистом
клоне; её спека прогоняется встроенным раннером Node — своего проекта у
`scripts/` нет.

`yarn docs:audit` получил два инварианта. `deleted-names` ловит удалённое
публичное имя в живых текстах: список — разность барелей по всем тегам
выпуска и `HEAD`, 135 имён. `landing-lead` требует у `docs/index.md`
ровно один абзац прозы до первого `##`: шаблон лендинга берёт под лид
первый абзац, а второй молча выбрасывает.
