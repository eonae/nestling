# CLAUDE.md

Nestling — TypeScript-фреймворк («меньше, современнее и архитектурно лучше NestJS»).
Разрабатывается **V1** — никакого «v2» как имени API не существует.
Опорные принципы ([design/principles.md](./docs/design/principles.md)):
декларации — значения, жадный контейнер, schema-first, **no runtime magic**,
**guarantee over convention**, **explicit over implicit**.

## Документация — сначала прочитай карту

**Перед любой нетривиальной работой сверяйся с `docs/`.** Точка входа и авторитетная
карта — [`docs/README.md`](./docs/README.md). Главное правило: **папка определяет
статус документа.**

```
docs/
├── design/      ← ЦЕЛЕВОЕ СОСТОЯНИЕ V1. Полное описание API; без статусов реализации и порядка работ.
├── decisions/   ← журнал решений: что, когда, ПОЧЕМУ, отвергнутые варианты.
│   ├── ideas.md    — основной журнал принятых идей (логика + отвергнутое)
│   ├── roadmap.md  — план changes до целевого состояния (живой, статусы обновляются)
│   ├── archlog.md  — короткий лог заархивированных changes
│   └── deferred.md — отложенные темы (обсуждено, не принято; триггер возврата)
├── guides/      ← гайды по ТЕКУЩЕМУ API, сверены с кодом примеров (`packages/examples.*`)
├── preview/     ← статический HTML-превью документации; не источник истины
└── history/     ← замороженная археология. НЕ редактируется. Читать только для контекста.
    ├── discussions/  — дискуссии, из которых рождались решения (+ сырые транскрипты)
    ├── migrations/ · superseded/ · worklog/
```

Актуальное состояние **кода** — в README пакетов (`packages/*/README.md`).
При расхождении «дизайн vs код» источник истины для намерения — `design/` +
`decisions/`, для факта реализации — код и README пакета (плашки статуса это отмечают).

## Обязанность держать доки в синхроне

Меняешь дизайн или поведение — **обнови документацию тем же изменением:**

1. **«Что» живёт в `design/`, «почему» — в `decisions/`.** Поменял API/поведение →
   правишь соответствующий `design/`-док по месту **и** добавляешь запись в
   `decisions/` (контекст, решение, отвергнутые варианты).
2. **`design/` — единственное место, где целевой API описан целиком** (карта и
   правила — `docs/design/README.md`). В design-доках нет статусов реализации,
   номеров changes и порядка работ — только целевое V1 и ссылки: на записи
   ideas.md (логика) и roadmap (статус). Слова «v2» в целевых доках нет.
3. **`decisions/` append-only, `history/` immutable.** Устаревшую запись не
   переписываешь — помечаешь `~~строкой~~ — РЕШЕНО/СУПЕРСИД` со ссылкой на новую.
4. **Каждый `design/`-док начинается с плашки** «Целевое состояние V1» со ссылками
   на записи журнала и roadmap.
5. **Гайды сверяются с примерами.** Изменил `packages/examples.*` → обнови гайд и дату
   плашки «сверено с кодом <пример> (дата)».
6. **Новые дискуссии** — сразу в `history/discussions/NN-тема.md`. Корень репозитория
   для документации закрыт (кроме `README` и этого `CLAUDE.md`).
7. **Фиксируй логику, а не только вывод.** В `decisions/` важны «как мы сюда пришли»
   и отвергнутые альтернативы, а не только итог.

**В `decisions/ideas.md` записывай идею только после явного «запиши»** от
пользователя — не по своей инициативе.

Проверка консистентности доков — скилл `/docs-audit` (`quick` — только
механические инварианты, без аргументов — полный аудит с семантикой,
`fix` — применить безопасные починки).

## Workflow изменений (openspec)

Доработки до целевого состояния идут changes'ами. Порядок работ — волнами,
см. `docs/decisions/roadmap.md` (разделы «Волны реализации» и «Как работать»).
Единица работы: **один change = одна ветка `change/<имя>` = три свежих сессии**
`/opsx:propose` → `/opsx:apply` → `/opsx:archive`. Контекст между сессиями
передают файлы в `openspec/changes/<имя>/`, а не разговор; `tasks.md`
с чекбоксами — точка возобновления, если сессия прервалась.

**Definition of Done для `/opsx:apply`** — change не закончен, пока не выполнено
всё перечисленное (в `tasks.md`, сгенерированных начиная с 2026-07-28, это
последний раздел; для более ранних — держи список отсюда):

1. все задачи `tasks.md` отмечены;
2. `yarn verify` зелёный (`build` + `lint` + `test` по всем пакетам);
3. README затронутых пакетов обновлены, включая плашки статуса;
4. `design/` и `decisions/` синхронизированы по правилам выше;
5. `yarn docs:audit` → 0 ERROR;
6. затронутые `packages/examples.*` мигрированы, гайды пересверены
   с обновлённой датой в плашке «сверено с кодом»;
7. коммиты осмысленные, ветка запушена.

После `/opsx:archive` обнови статус в `roadmap.md` и добавь абзац в `archlog.md`.
