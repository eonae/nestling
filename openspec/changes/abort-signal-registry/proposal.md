# abort-signal-registry

## Why

Профиль под нагрузкой ([d/10 §5](../../../docs/history/discussions/10-framework-review-2.md))
показал, что около 20% процессорного времени HTTP-сервера уходит в
`AbortSignal.any`: транспорт собирает композитный сигнал из контроллера
запроса и сигнала остановки на каждый запрос. Замер: 2.30 µs на
композит против 0.15 µs на один `AbortController`, плюс паузы до 1.4 с
из-за накопления `WeakRef` на долгоживущем сигнале остановки. На Node 24
паузы сильнее: `POST /users` проседает до 9 600 req/s. Замена композита
реестром контроллеров поднимает `GET /users/:id` с 0.63 до 0.87 от
Fastify на Node 22 и до 0.99 на Node 24, а разброс req/s между секундами
падает с 10 000 до 300–600. Запись ideas.md [2026-09-04] «Граница
`@nestling/transport.http`» зафиксировала разрыв 0.63 как точку отсчёта
и просила перепроверить его; этот change закрывает перепроверку.

Та же конструкция стоит на пути каждого вызова операции: in-process шина
композирует сигнал вызывающего с сигналом шины, а бюджет вызова
композирует сигнал вызывающего с таймером. Оба места правятся тем же
способом в этом же change'е, чтобы горячий путь операций не остался с
той же ценой.

## What Changes

- `@nestling/transport.http`: сигнал запроса — это сигнал собственного
  `AbortController` запроса, без композиции. Транспорт держит реестр
  контроллеров выполняющихся запросов: `handle` добавляет контроллер,
  событие `'close'` ответа удаляет, `close()` взводит каждый оставшийся с
  `TransportClosingError` до дренажа соединений.
  Причины отмены (`ClientDisconnectedError`, `TransportClosingError`) и
  наблюдаемое поведение `meta.signal` не меняются.
- `@nestling/ports`, in-process шина: `request` с `options.signal`
  получает собственный контроллер вызова, который следует за сигналом
  вызывающего через слушатель, снимаемый по завершении; `close()` шины
  взводит контроллеры всех вызовов в полёте через реестр. Без
  `options.signal` шина по-прежнему передаёт свой сигнал напрямую.
- `@nestling/ports`, бюджет вызова (`startBudget`): собственный контроллер
  бюджета следует за сигналом вызывающего слушателем вместо
  `AbortSignal.any`; `release()` снимает и таймер, и слушатель. Признак
  `expired` по-прежнему считается по владению таймером.
- Бенчмарк переезжает в `scripts/bench/http.ts`: серверы Nestling,
  Fastify, Express и Hono поднимаются по очереди в отдельных процессах,
  раннер печатает таблицу на сценарий и сводку с отношением к Fastify,
  разброс req/s и максимум латентности (по одной колонке среднего паузы не
  видны), флаг `--markdown`, `BENCH_NODE` для замера на другой версии
  Node. README бенчмарка объясняет по профилю, откуда остаток разрыва с
  Fastify. Повторный замер записывается в ideas.md вместе с решением.
- Документация: `docs/design/transports.md` описывает реестр вместо
  композиции; README `@nestling/pipeline` и корневой README называют
  Node 24 рекомендуемой версией и флаг
  `--experimental-async-context-frame` для Node 22 (хуки промисов
  `AsyncLocalStorage` стоят около 14% пропускной способности, в Node 24
  новый режим включён по умолчанию).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `http-request-cancellation`: требование «close() взводит сигналы всех
  in-flight запросов» описывает реестр контроллеров вместо композиции
  `AbortSignal.any`; требование «Fallback-endpoint'ы без pipeline
  получают meta.signal» говорит об одном и том же сигнале запроса без
  слова «композитный»; требование «Обработка сигналов не накапливает
  ресурсы» получает проверяемую форму: после завершения запроса его
  контроллера нет в реестре, а на сигнал остановки слушатели на запрос
  не ставятся.
- `port-deadline`: требование «Исчерпание бюджета в полёте отменяет
  вызов» дополняется сценарием: `release()` снимает слушатель с
  `meta.signal` вызывающего, поэтому завершённый вызов не оставляет
  подписок на сигнале запроса.
- `message-bus`: новое требование к `request` с `options.signal`: сигнал
  доставки взводится и отменой вызывающего, и `close()` шины; после
  завершения вызова его контроллера нет в реестре шины.

## Impact

- `packages/nestling.transport.http/src/transport.ts` — реестр
  контроллеров, `handle`, `close()`; `transport.integration.spec.ts` —
  тесты реестра.
- `packages/nestling.ports/src/profile.ts`, `bus.ts` — контроллер
  вызова со слушателем и реестр шины; новый внутренний модуль с помощником
  «следовать за сигналом»; `profile.spec.ts`, `bus.spec.ts` — тесты.
- `scripts/bench/http.ts`, `servers.ts`, `server.ts`, `README.md` — новый
  раннер; `http-vs-fastify.ts` удалён; `express`, `hono`,
  `@hono/node-server` в devDependencies корня.
- `docs/decisions/ideas.md` — новая запись с решением и таблицей замера;
  `docs/design/transports.md` — абзац про сигнал запроса;
  `docs/decisions/roadmap.md` — строка change'а.
- `packages/nestling.pipeline/README.md`, `packages/nestling.transport.http/README.md`,
  корневой `README.md` — заметка о версии Node.
- `openspec/specs/http-request-cancellation`, `port-deadline`,
  `message-bus` — дельты при архивации.

## Non-goals

- Второй эшелон оптимизаций из d/10 §5.5: предвычисление в `bind()`,
  накопление контекста без spread, разбор адреса без `new URL()`,
  `writeHead` одним вызовом. Каждый пункт даёт 1–2% и идёт отдельным
  change'ем после замера.
- Сериализатор ответа из схемы `output`: микрозамер не показал выигрыша
  на малых телах, предложение снято.
- Отказ от `AsyncLocalStorage` или условное открытие области контекста:
  цена хуков промисов исчезает в Node 24 без правок кода.
- `AbortSignal.any` в `@nestling/subscriptions` (один раз на подписку) и
  `@nestling/transport.cli` (один раз на запуск): вызовы не на горячем
  пути, не трогаются.
- Бенчмарк как порог `yarn verify`: остаётся ручным замером.
