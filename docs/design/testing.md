# Тестирование: `@nestling/testing`

> **Целевое состояние V1.** Логика решений: [ideas.md](../decisions/ideas.md) —
> «Пакет тестирования (`@nestling/testing`)» [2026-07-10].
> Статус реализации — [roadmap](../decisions/roadmap.md).

## 1. Принцип: уровень теста = граница видимости

**Тестовая поверхность — это экспортная поверхность.** Внутри пакета видно
всё (unit- и модульные тесты — приватность не мешает по построению);
приложению видны только публичные capability, и app-тесты мокают на
архитектурных швах. «Как замокать чужой приватный провайдер» — никак, и это
фича: либо модуль экспортирует тестовую capability, либо мок на шве, либо
тест написан не на том уровне. Тестируемость — следствие архитектуры;
пакет — тонкий.

## 2. Уровень 0 — без фреймворка

Провайдеры — классы/фабрики с явными deps, конфиг-срез — объектный литерал,
порт — объект с `call`, хендлер — вызов фабрики/класса с фейками. Принцип:
**у юнит-теста нет импортов из `@nestling/*`**.

## 3. `assembleTest` — тестовый composition root

```typescript
await using app = await assembleTest({
  features: [OrdersFeature],
  transports: [http()],
  overrides: [
    [OrdersRepository, inMemoryOrdersRepo()],
    familyOverride(ILogger, () => noopLogger),
  ],
  config: vars({ ORDERS_MAX_ITEMS: '10' }),
  stubs: [stub(ChargeCard, async () => ({ chargeId: 'test' }))],
  policies: [everyEndpoint({ transport: HttpTransport$ }).hasLayer(authedBase)],
});

const res = await app.call(CreateOrder, { items: [...] });
```

- **Мок = подстановка в графе на ASSEMBLE**, до инстанциации — не патчинг
  и не перехват module system. Ключ `overrides: [[Token, fake]]` существует
  **только** у тестового корня (`assemble` его не принимает); право override
  — позиционное (мокаешь то, на что есть ссылка), строковой формы
  (`overrideByName('…')`) нет. Пара типизирована: фейк, не совместимый с
  типом токена, — ошибка компиляции. Override токена, которого нет в графе,
  — ошибка сборки: переименовали провайдер, и тест не мокает молча пустоту.
- **Поставка недостающего — `stubs:`**, а не подмена: в отличие от
  `overrides:`, поле не требует, чтобы у токена уже был провайдер. Одним
  списком едут пары «токен → значение» и контрактные стабы
  (`stub(Contract, impl)` — §4): второго поля про то же самое решение
  («здесь боевого кода не будет») не существует.
- **Прунинг**: осиротевшее поддерево заменённого узла выпадает из графа —
  замокал репозиторий → pg-пул не инстанцируется и не коннектится. Без
  этого жадный контейнер был бы анти-тестовым. Что именно выпало, видно в
  `app.pruned` (список id узлов); что было застабано контрактом — в
  `app.stubbed` (имена контрактов по алфавиту). Оба отчёта — значения, а не
  печать: их сверяют с матрицей `.check()` (§6). Инвариант, делающий прунинг
  безопасным: **без `overrides` он тождественен** — граф не меняется ни на
  один узел ([container.md](./container.md)).
- **Прогон без сокетов**: тестовый app проходит фазы 0–3 (BOOTSTRAP..WIRE) —
  `dispatch` рождён, START не выполняется, транспорты не в эфире,
  обработчики `SIGTERM`/`SIGINT` не ставятся. Следствие, которое надо знать:
  ресурс, захваченный в `@OnStart`, в app-тесте не захватывается — цена
  фазовой модели, а не дефект.
  `app.call(Endpoint, input)` / `app.emit(Contract, payload, meta?)` —
  типизированы схемами декларации (`input` — по `input`-форме, результат —
  `ResponseContext<InferOutput<O>>`, ветка отказа несёт `status` и `code` из
  закрытого контракта `errors:`) и гонят запрос через **полный пайплайн**
  (этим app-тест отличается от юнита). `emit` доставляет факт или команду
  **всем** co-located подписчикам — каждому через его собственный пайплайн —
  и возвращает их ответы с именем каждого (`{ subscriber, response }[]`):
  боевой `emit` есть fire-and-forget, потому что издатель не отвечает за
  обработку, а тест отвечает ровно за неё, и ожидание здесь безопасно —
  сокета нет, подписчики co-located. Ноль подписчиков у `event` — легальный
  broadcast и пустой список, у `command` — ошибка адресации.
  `unwrap(res)` покрывает частый случай
  «ожидаю успех». Транспортный биндинг при этом не выполняется: `call`
  принимает готовый payload, а раскладка path/query/body по bind-карте —
  предмет e2e и юнит-тестов bind-карты. `await using` → честный SHUTDOWN в
  реверсе (`close()` доступен явно и идемпотентен). Настоящий e2e — обычный
  `run()` на случайном порту, вне пакета.
- **Инварианты те же, что в бою**: `policies:` — то же поле того же
  словаря, и прогоняются они тем же проходом фазы ASSEMBLE. Тестовый корень
  инварианты **не ослабляет**: приложение, которое не собирается в проде, не
  должно собираться и в тесте ([pipeline.md §7](./pipeline.md)).
- `assembleTest` **асинхронна**: `await using` ждёт dispose, а не
  инициализатор, поэтому `await` перед вызовом обязателен. Форма без `using`
  (`const app = await assembleTest(…)` + `await app.close()`) поддерживается
  — для `beforeEach`/`afterEach`.

## 4. Швы app-теста

Чужие токены не нужны — мокается на публичных швах:

- **конфиг** — `vars({...})`: объектный `ConfigSource` с `watch` и
  программным `set()` → тестируется и reload-механика (пере-проекция,
  keep-last-good, `onChange`); `process.env` не трогается → параллельные
  тесты бесплатно. В тестовом корне `config:` принимает три формы:
  источник (сахар для `[[source, '*']]`), одну привязку и список привязок;
  в боевом `assemble` сахара нет;
- **меж-фичевые вызовы** — `stub(Contract, impl)`: фейк-вызыватель как
  значение. Возвращает пару «токен вызывателя → фейк» (`[C.port, …]` у
  `request`, `[C.emitter, …]` у `command`/`event`), которая едет полем
  `stubs:` — «поставка недостающего», а не подмена. Провайдер стаба
  **опережает** рецепт семейства вызывателей, поэтому боевой
  `buildPort`/`buildEmitter` для этого контракта не вызывается ни разу и
  проверка достижимости не срабатывает: фича-потребитель собирается и
  работает, когда контракт в этой сборке не реализован и шина наружу не
  доставляет. Фейк **валидируется схемами своего контракта при каждом
  вызове** — вход `input`-формой, успешный результат `output`-формой, а
  возвращённый или брошенный отказ обязан входить в `errors:` контракта
  (∪ kernel-коды), иначе стаб бросает: мок не может разъехаться с
  реальностью. Валидация выхода делает стаб строже боевого co-located
  порта намеренно — у боевого ответа позади pipeline реализации, у стаба
  pipeline'а нет. Профиль вызова соблюдается: исчерпанный `meta.deadline`
  даёт `DeadlineExceeded` **до** вызова фейка, `emit` команды всегда несёт
  `idempotencyKey`. Тип call-site тождествен боевому (`Port<C>`/`Emitter<C>`,
  результат — `PortResult<C>`), несовместимый фейк — ошибка компиляции.
  Своего spy у стаба нет и не будет: `impl` — обычная функция, поэтому
  `jest.fn()` в этой позиции работает без единой строки в пакете;
- **request-контекст** — `contextValue(RequestId, 'req-1')`, сахар над
  `valueProvider(Ctx(X), reader)`: ридер ambient-переменной — обычный узел
  графа, поэтому подменяется тем же списком `overrides:`, что и всё
  остальное. Подставленное значение сильнее рецепта семейства и работает
  вне запроса — ALS в тестах не нужен; тест, ридер не подменивший, видит на
  `app.call` ровно боевую проекцию ([container.md](./container.md));
- **cross-cutting** — `familyOverride(ILogger, () => noop)`: override
  рецепта семейства целиком, до материализации членов, поэтому боевой
  рецепт не вызывается ни разу; едет тем же списком `overrides:`;
- **транспорт** — не мокается: in-proc dispatch. Автоподстановки транспортов
  тоже нет — они перечисляются так же, как в проде, и ручка на транспорте
  вне графа даёт тот же fail-fast ASSEMBLE.

## 5. Тестовая capability модуля — subpath `./testing`

Модуль экспортирует курируемую тестовую поверхность через conditional
export (условие `"testing"` включено только в тест-раннере — прод-импорт
не резолвится на уровне Node resolution, граница структурная): токены,
разрешённые к подмене, и готовые фейки (`inMemoryOrdersRepo()`), которые
автор держит в контракте с реализацией.

Конвенция догфудится на самом ядре: внутренний шов, которым
`@nestling/testing` заводит фазы 0–3, живёт в `@nestling/app` именно таким
subpath'ом (`@nestling/app/testing`), а не публичным экспортом. Предлагать
пользователю границу, которой сам не следуешь, нечестно.

## 6. `.check()` — структурный смок топологий

Фазы 0–1 (конструкторы, без `@OnInit` → без захвата ресурсов): циклы,
port-биндинг, полнота env, объявленные `policies:` — по одному тесту на
вариант деплоя. Метод корня `assemble`, а не тестового приложения:
`.check()` компенсирует прунинг, поэтому обязан гонять **честный** граф —
подстановок он не принимает. Возвращает отчёт о составе (фичи, ручки по
транспортам с причинами `detached`, транспорты), бросает — теми же ошибками,
что бросил бы `run()` на этих фазах, и на последующий `run()` того же
приложения не влияет. Необязательный словарь опций (`check(options?)`)
несёт конвертеры схем; вызов без аргумента ведёт себя ровно как прежде.

```typescript
for (const select of ['all', 'orders', 'billing'] as const) {
  await assemble({ features: [...], select, transports: [http()] }).check();
}
```

Матрица `select`-топологий валидируется в CI без деплоя одним хелпером —
`checkTopologies(spec, selections, options?)`: ядро фейлится быстро, а хелпер
собирает **все** отказы и падает одним сообщением, называя топологию для
каждого. Инварианты приезжают сюда сами: `spec` с полем `policies:`
проверяется в **каждой** топологии, поэтому нарушение, возникающее только на
подмножестве фич, ловится в CI. Состав detached-ручек сравнивается значением
из отчёта — парсить stdout не нужно.

Отчёт каждой топологии несёт поле `contracts` — дескрипторы
**опубликованных** ею контрактов. Из этого же поля собирается машинная
сверка стабов: каждый застабанный контракт обязан быть опубликован хотя бы
одной честной топологией, иначе стаб прикрывает отсутствующую реализацию.

```typescript
const published = new Set(
  (await checkTopologies(spec, ['all', 'orders', 'quotas']))
    .flatMap(({ report }) => report.contracts.map((c) => c.name)),
);

expect(app.stubbed.filter((name) => !published.has(name))).toEqual([]);
```

Это и есть машинная форма правила «мокаешь — проверь топологию». Отдельного
хелпера пакет не заводит: обе стороны — уже значения, а лишняя функция
сузила бы сверку до одного её варианта.

Отсюда же собирается отчёт совместимости схем, тоже без пересборки
приложения:

```typescript
const reports = await checkTopologies(spec, ['all', 'orders'], {
  converters: [zodConverter()],
});

const report = diffContracts(readBaseline(), snapshotContracts(reports));
console.log(formatCompatibility(report));

expect(report.breaking).toEqual([]);   // ← твой expect, а не наш fail-fast
```

Сведение матрицы идёт объединением топологий, вердикты и правила —
[contracts.md](./contracts.md) §1. Фреймворк отчёт **печатает**;
превращать его в падающий тест — решение пользователя, флага «падать на
breaking» не существует. `snapshotContracts`/`diffContracts`/
`formatCompatibility` реэкспортируются из `@nestling/testing`, чтобы
CI-тест писался одним импортом.

Ограничение, которое надо помнить: конструктор с побочкой ломает `.check()`.
Это и так нарушение фазовой модели (ресурсы — в `@OnInit`).

## 7. `testModule(M, { stubs })` — модуль в изоляции

Мини-app вокруг одного модуля (с его `imports`), kernel-модуля конфига и
стабов; те же фазы 0–3 и тот же результат, что у `assembleTest`.
Неудовлетворённые импорты обязаны быть застабаны явно — ошибка перечисляет
**все** недостающие токены с потребителем каждого, а не первый попавшийся.
Живёт внутри пакета модуля → токены видны без экспорта. Поле `stubs`
принимает и контрактные стабы: меж-фичевый вызов, объявленный модулем,
поставляется тем же полем, что и недостающий провайдер.
