# docs-site-sections — дизайн

## Context

Генератор занимает 673 строки в `scripts/site/build.mjs` плюс тему:
`layout.html` (40 строк), `styles.css` (343) и `app.js` (166). Он читает
источники из `sections.mjs`, сверяет состав папки с её README, размечает
markdown через `markdown-it`, подсвечивает TypeScript своим
токенизатором и печатает один файл `docs/.site/index.html`. Сегодня это
790 КБ и 33 раздела.

После расширения списка источников разделов станет 72, а файл вырастет
примерно до 1.6 МБ. Это первая причина разделить вывод. Вторая — адрес:
у раздела внутри одного файла нет ни своего `title`, ни `canonical`, ни
строки в `sitemap.xml`.

Ограничения:

- **Внешних зависимостей не добавляется.** У генератора одна —
  `markdown-it`. Локальный сервер берётся из `@nestlingjs/common.static-server`,
  он уже в репозитории.
- **Источник текста один.** Раздел собирается из файла документации;
  отдельных markdown-файлов «для сайта» не существует. Исключение —
  стартовая страница, у которой нет другого места.
- **Оглавление остаётся одним экземпляром.** Состав раздела задаёт README
  источника, а не список в конфиге.
- **Сборка работает проверкой.** Расхождение README и папки, битая
  ссылка, совпадение слагов — ошибка сборки, а не тихий пропуск.

## Goals / Non-Goals

**Goals:**

- Адрес у каждого раздела: путь вида `/guide/01-first-service/`.
- Все десять источников из [d/11 §5.2](../../../docs/history/discussions/11-docs-structure-and-site.md)
  на сайте, включая README пакетов и `design/`.
- Документация по-прежнему отдаётся одним файлом — для пересылки и
  чтения без сети.
- Поиск по всей документации без сервера и без внешнего индексатора.
- Метаданные страницы: `title`, `description`, `canonical`, Open Graph.
- Ссылка в неопубликованный файл ведёт в репозиторий, а не в 404.

**Non-Goals:**

- Публикация: workflow, Pages, домен — волна 5 (`docs-publish`, #61).
- Замена генератора на VitePress или Starlight.
- Правка текста глав, рецептов, design-доков и README пакетов сверх
  оглавления, которого требует новый источник.
- Английская версия, версионирование, переводы.

## Decisions

### Д1. Две формы вывода из одной модели

Сборка идёт в два шага. Первый читает источники и строит модель: список
разделов с заголовком, группой, слагом, секцией и размеченным HTML.
Второй печатает модель дважды — деревом страниц и одним файлом.

Разница между формами сводится к одной функции — как раздел и якорь
превращаются в `href`:

| Форма | Ссылка на раздел | Ссылка на заголовок | `id` заголовка |
|---|---|---|---|
| Дерево | `../../design/container/` | `../../design/container/#секции` | `секции` |
| Один файл | `#design--container` | `#design--container--секции` | `design--container--секции` |

Всё остальное — разметка markdown, врезки, карточки, подписи блоков кода,
подсветка, сайдбар, пейджер — общее.

Альтернативы:

- **Два скрипта.** Правила разметки пришлось бы держать в двух местах;
  расхождение нашлось бы глазами читателя, а не сборкой.
- **Собрать один файл из готовых страниц дерева.** Потребовало бы снимать
  шапку и сайдбар с каждой страницы и переписывать ссылки обратно в
  якоря. Та же работа, но на HTML вместо модели.

### Д2. Адрес — каталог с `index.html`

Раздел печатается в `<секция>/<слаг>/index.html`. Адрес получается без
расширения: `/guide/01-first-service/`. Оглавление источника-папки лежит
в `<секция>/index.html` — адрес `/guide/`. Стартовая страница — `/`.

Слаг берётся из имени файла, как сейчас. Секция задаётся в `sections.mjs`
и совпадает с сегментом пути: `guide`, `recipes`, `reference`, `design`.
У источника-страницы секции нет, адрес — `/<слаг>/`: `/glossary/`,
`/guarantees/`.

Альтернатива — `guide/01-first-service.html`. Короче на каталог, но адрес
несёт расширение, и всякий переезд файла требует редиректа на стороне
хостинга.

### Д3. Слаг уникален внутри источника, не по всему сайту

Сейчас совпадение слагов останавливает сборку: в одном файле два раздела
с одним `id` неразличимы. С путями это ограничение снимается частично —
`/design/container/` и `/reference/nestling.container/` не спорят.

Правило: слаг уникален внутри источника. В форме одного файла `id`
раздела получает приставку секции — `design--container`. Столкнуться
могут только два раздела одной секции, а это по-прежнему ошибка сборки.

Так снимается коллизия, которой иначе не избежать: `design/container.md`
и README пакета `@nestlingjs/container` называются одинаково.

### Д4. Третий вид источника — пакеты

`sections.mjs` получает `{ kind: 'packages', path: 'packages', group: … }`.
Оглавление такого источника лежит не рядом с файлами, а в разделе
«Пакеты» файла `docs/README.md`: там уже перечислены все каталоги
`packages/` четырьмя группами со ссылками вида `](../packages/nestling.app/)`.

Чтобы группы читались машинно, вводные строки раздела становятся
заголовками третьего уровня: `### Для автора приложения`,
`### Транспорты и шина`, `### Инструменты и сателлиты`, `### Внутренние`.
Правило чтения оглавления обобщается: группу даёт заголовок `## Часть N. …`
у папки и заголовок `###` у пакетов.

Слаг раздела — имя каталога: `nestling.app`, `common.graphs`. Заголовок —
первая строка README пакета (`# @nestlingjs/app`).

Альтернативы:

- **Список пакетов в `sections.mjs`.** Второй экземпляр списка, который
  разойдётся с `docs/README.md` при первом же новом пакете.
- **Обход `packages/*` без оглавления.** Порядок разделов стал бы
  алфавитным, а деление на «для автора приложения» и «внутренние»
  пропало бы.
- **Чтение вводных строк перед таблицами.** Держится на том, что строка
  кончается двоеточием.

### Д5. Ссылки: три исхода вместо двух

Ссылка на файл репозитория разрешается от каталога исходного файла и
попадает в один из трёх случаев.

| Куда ведёт | Что получается |
|---|---|
| В файл-раздел сайта | Относительный путь до его адреса |
| В опубликованный файл вне разделов (`examples/`, `LICENSE`) | Абсолютный адрес на GitHub |
| В неопубликованный файл (`decisions/ideas.md`, `archlog.md`, `history/`, `openspec/`) | Абсолютный адрес на GitHub |

Два последних случая совпадают по результату, поэтому правило одно:
**ссылка, которая не ведёт в раздел сайта, становится адресом на
GitHub.** Так плашки design-доков с их ссылками в `ideas.md` перестают
ломаться, а страница roadmap сохраняет ссылки на архив openspec.

Адрес репозитория генератор берёт из поля `repository` корневого
`package.json`; поля там сейчас нет, оно добавляется. Ветка — `main`.

Ссылка на несуществующий файл остаётся ошибкой сборки.

### Д6. Базовый адрес — параметр, ссылки относительные

Ссылки между страницами печатаются относительными: с
`/guide/01-first-service/` на глоссарий — `../../glossary/`. Дерево
открывается и из корня домена, и из подпути `<username>.github.io/nestling/`,
и с локального сервера.

Базовый адрес нужен только двум вещам — `canonical` и `sitemap.xml`. Он
приходит параметром `--base` (или `DOCS_BASE`). Без параметра
`canonical` и `sitemap.xml` не печатаются: выдумывать домен сборка не
будет. Домен выбирается в волне 5 — там же параметр проставляется в
workflow.

### Д7. Поиск — только в дереве, индекс подгружается по требованию

Индекс печатается в `search-index.json` рядом с деревом: на каждый раздел
— заголовок, адрес, заголовки второго уровня и текст без разметки.
Порядок величины — 700 КБ на 72 раздела, поэтому страница не загружает
его вместе с собой. Индекс запрашивается при первом обращении к поиску.

Совпадения ищутся подстрокой без учёта регистра, ранг — по месту
совпадения: заголовок раздела, заголовок второго уровня, текст.
Морфология не разбирается: русский стеммер — это либо внешняя
зависимость, либо словарь в сотни строк ради того, чтобы «фичи» находили
«фича».

В форме одного файла поиска нет. Там весь текст уже в документе, и его
ищет Ctrl+F браузера — с подсветкой совпадений и переходом по ним.

### Д8. Стартовая страница — свой источник и свой шаблон

В `sections.mjs` появляется запись `{ kind: 'home', path: 'docs/index.md' }`.
Файл `docs/index.md` новый: это единственный markdown, написанный для
сайта, и другого места у него нет. В нём — что такое Nestling, карточки
`::::cards` по принципам и ссылки на первую главу, рецепты и справочник.

Печатается он шаблоном `home.html` — без сайдбара и пейджера, с широкой
сеткой карточек. В форме одного файла он остаётся первым разделом.

`docs/README.md` стартовой страницей не становится: он адресован тому,
кто работает внутри репозитория, и называет `history/`, `openspec/` и
правила ведения документации.

### Д9. `docs:dev` поднимает сервер

Дерево путей по `file://` не открывается: `/guide/01-first-service/`
браузер ищет на диске от корня. Поэтому `yarn docs:dev` запускает
`StaticServer` из `@nestlingjs/common.static-server` с `indexFile:
'index.html'` и `disableCache: true` поверх каталога вывода, а сборку
повторяет при изменении источника — как сейчас.

Форма одного файла у `docs:dev` тоже печатается: открыть её можно прямо
из каталога вывода двойным кликом.

### Д10. Бейдж раздела берётся из источника

У источника появляется необязательное поле `badge`. У `design/` это
«целевое состояние V1». Генератор печатает бейдж в шапке каждой страницы
источника. Плашки статуса внутри самих файлов остаются текстом и
разбираются как обычный markdown: их читает `docs:audit`, а не сборка.

### Д11. Подсветка: два языка правилами, не пакетом

`bash` и `json` добавляются в тот же токенизатор, где лежит TypeScript, —
это правила на регулярных выражениях. Повод: 52 блока `bash` и 3 блока
`json` сейчас показаны серым.

shiki отвергается. Её ценность — точность грамматик и темы VS Code, а
цена — мегабайты зависимости и грамматики в сборке ради двух языков, где
подсветке хватает ключевых слов, строк и комментариев.

### Д12. Новые инварианты `docs:audit`

К проверкам добавляются три: `docs/index.md` существует и назван
источником; каждый файл источника имеет строку в своём оглавлении
(включая пакеты в `docs/README.md`); ни один файл `docs/.site/` не
отслеживается git.

Первые две частично повторяют проверку сборки — это намеренно: `docs:audit`
запускается без сборки сайта и без `node_modules` генератора.

## Risks / Trade-offs

- **Прежние адреса разделов перестают работать.** Ссылка
  `#01-first-service` вела в главу, теперь ведёт в никуда → сайт ещё не
  опубликован, внешних ссылок на него не существует. Внутренние ссылки
  переписывает сборка, и неразрешённая ссылка её останавливает.
- **Два вывода — два набора адресов.** Одна и та же глава адресуется
  путём и якорем → адрес строит одна функция на форму, она же
  используется для сайдбара, пейджера и переписывания ссылок. Третьего
  места, где адрес собирается руками, не появляется.
- **Индекс поиска в 700 КБ.** На медленной сети первый ввод в поиск ждёт
  загрузки → индекс запрашивается отдельно от страницы, и до него
  страница полностью работает. Если размер окажется больше ожидаемого,
  текст раздела в индексе усекается.
- **README пакетов написаны как страница npm.** Установка, таблица
  экспортов и ссылки в `docs/` читаются на сайте иначе, чем в реестре →
  текст не правится: раздел `/reference/` отвечает на вопрос «какие есть
  имена», и этот ответ одинаков в обоих местах.
- **`roadmap.md` и `deferred.md` — живые документы.** На сайте они
  устаревают между сборками → сборка идёт на каждый push в `main`
  (волна 5), а до публикации вопрос не стоит.
- **Правка раздела «Пакеты» в `docs/README.md`.** Четыре заголовка
  вместо четырёх вводных строк меняют вид документа → изменение
  минимальное, а взамен список пакетов остаётся одним экземпляром.

## Migration Plan

1. Модель разделов отделяется от печати: `build.mjs` перестаёт печатать
   в ходе обхода источников. Вывод на этом шаге не меняется.
2. Появляется печать деревом при сохранённой печати одним файлом. Обе
   формы собираются из одной модели.
3. Добавляются источники: `design/`, пакеты, четыре страницы корня и
   `decisions/`. Вместе с ними — правило ссылок на GitHub.
4. Стартовая страница, метаданные, `sitemap.xml`, `robots.txt`,
   `404.html`, favicon.
5. Поиск: индекс на сборке и обработчик в `app.js`.
6. `docs:dev` с сервером, подсветка `bash` и `json`, инварианты
   `docs:audit`, README генератора и правила в `docs/README.md`.

Откат — обратный порядок шагов; вывод не отслеживается git, поэтому
откатывать нужно только `scripts/site/`.

## Open Questions

1. **Домен.** `nestling.dev` или `<username>.github.io/nestling`. От него
   зависят `canonical` и `sitemap.xml`. Решается в волне 5; здесь адрес —
   параметр сборки.
2. **Судьба `docs/guarantees.md`.** Остаётся страницей или собирается из
   плашек глав — вопрос записи [2026-09-12] «Глава делится по месту в
   пути». Здесь остаётся страницей.
3. **Favicon.** Сейчас в шапке стоит эмодзи 🐣. Отрисовать ли его в
   `favicon.svg` или завести рисунок — решается на apply.
