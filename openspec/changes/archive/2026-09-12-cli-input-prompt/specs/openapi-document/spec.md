## MODIFIED Requirements

### Requirement: Конвертеры поставляются отдельными пакетами

Конвертер вендора SHALL жить отдельным пакетом с peer-зависимостью на свой
валидатор. `@nestlingjs/schema.zod` SHALL экспортировать `zodConverter()`,
возвращающий `SchemaDocConverter` с `vendor: 'zod'` поверх штатного
`z.toJSONSchema()`.

Имя пакета SHALL NOT называть потребителя конвертера: результат —
JSON Schema, и её читают генератор документа, структурная проверка,
снапшот совместимости контрактов и вопросы CLI-транспорта.

Вшитого реестра конвертеров по вендору в `@nestlingjs/openapi` SHALL NOT
существовать: список конвертеров — данные вызывающего, и в
100%-zod-приложении пользователь называет конвертер явно одной строкой.

#### Scenario: Конвертер zod

- **WHEN** `zodConverter()` применён к zod-схеме
- **THEN** результат — JSON Schema, равная выводу `z.toJSONSchema()` для
  той же схемы

#### Scenario: Пустой список конвертеров

- **WHEN** модуль подключён без `converters`, а в приложении есть хоть одна
  схема
- **THEN** сборка падает с диагностикой «нет конвертера», а не строит
  документ без схем
