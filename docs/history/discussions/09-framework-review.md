## 1. Вопрос

«Есть ли реальные преимущества перед популярными фреймворками?» с
оговоркой: на незакрытые тесты и недоделанное внимания не обращать,
смотреть на структуру, типизацию, идеи и DX.

## 2. Что признано сильным

Преимущества нашлись не в «меньше и современнее», а в трёх гарантиях,
которых нет ни у Nest, ни у контрактных библиотек.

1. **Отказы как часть контракта.** Код с категорией, `Output<T, typeof
   Def>`, незадекларированный отказ становится `500`, отказ узнаётся по
   коду после сериализации. tRPC типизированных ошибок в контракте не
   имеет; ts-rest и oRPC типизируют статусы, а не значения-отказы; у Effect
   строгость выше, но ценой смены парадигмы. Nestling даёт то же в обычном
   `async/await`.
2. **Политики на собранном графе.** `everyEndpoint(...).hasLayer` и
   `hasVar` до открытия сокета, сравнение слоя по ссылке, `detached` только
   с причиной. В экосистеме аналогов нет; это лучшая иллюстрация
   «guarantee over convention».
3. **Граница фич как ошибка сборки, операции как единственный канал.**
   Один код в одном процессе и в split-развёртывании, матрица топологий в
   `check(select)`. Nest обещал это через microservices, но код с
   `ClientProxy` отличается от локального инжекта. Encore.ts ближе всех,
   но требует свой рантайм и облако.

Рядом: пайплайн без `next()` с типизированным накоплением контекста и
бюджетом типов с порогами (`BUDGET.md`); контейнер без `reflect-metadata`
с семействами токенов вместо REQUEST-скоупа; `assembleTest` с прунингом и
стабами, проверяемыми схемой операции; дисциплина документации
(`design/`, `decisions/`, `guide/`, `history/`, линтер стиля).

## 3. Недостатки и их разбор

### 3.1. Понятийная нагрузка

Претензия: токен, провайдер, модуль, фича, плагин, endpoint, три вида
операций, слой, юнит, переменная контекста и читатель, политики,
`select`, интерком, формы io — много для «меньше Nest»; `makeFeature`
появляется на первом шаге, хотя принцип обещает «как будто фич нет».

Разбор. Претензия к `makeFeature` снята: сокращение `makeApp({ endpoints })`
заставило бы переложить endpoint'ы при второй фиче, то есть L0 менялся бы,
а это нарушает аддитивность уровней. Остальные существительные перебраны:
плагин и фича различаются правилами границы; модуль самый слабый, но уже
вынесен в главу 12 и приложение А. Итог: проблема в первом впечатлении, а
не в числе понятий. Решение — подача: приложение Б вторым документом,
карта понятий на один экран в начале гайда, формулировка принципа
смягчена. Запись «Подача гайда».

### 3.2. Шов между `Output` и `PortResult`

`PortResult` включает kernel-отказы, `Output<T, E>` — нет; в
`create-user.endpoint.ts` каст `claimed as ReturnType<typeof
QuotaExceeded>`. Единственное место, где код противоречит принципу
закрытого множества. Решение: впустить четыре kernel-определения в
`Output`, тип совпадает с правилом рантайма. Запись «`Output<T, E>`
допускает отказы ядра».

### 3.3. `return undefined` у подписчиков

`InferOutput<undefined>` даёт `undefined`, `Promise<void>` не проходит,
отсюда `return undefined` и отключённое правило линтера в каждом
подписчике. Решение: принять `void` для декларации без `output`. Та же
запись.

### 3.4. Шесть перегрузок `httpEndpoint`

Перегрузки признаны правильным инструментом: один дженерик с условными
типами дал бы худший вывод. Не хватало страховки: type-tests есть только у
`@nestling/pipeline`, диагностики форм `httpEndpoint` снапшотами не
покрыты. Решение: фикстуры в `transport.http`. После удаления объектной
формы хендлера (§5) набор вдвое меньше. Попутно: лишний токен в
`@Injectable` можно поймать сравнением длины `ConstructorParameters`
со списком. Запись «`@Injectable` сверяет длину списка».

### 3.5. Свой HTTP-транспорт

Груз владения HTTP признан, но архитектура делает его ограниченным:
`ITransport` мал, транспорт поверх Fastify возможен как satellite.
Решение: записать в `transports.md` границу обещаний и границу отказа
(HTTP/2, WebSocket, TLS), убедиться, что байтовые части экспортированы,
снять бенчмарк относительно Fastify. Запись «Граница
`@nestling/transport.http`».

### 3.6. Документация только на русском

Переводить рано: гайд пересверяется с кодом при каждом изменении, перевод
удвоил бы цену, пока API движется. Момент — заморозка V1; порядок: README
пакетов, затем гайд; `design/` и `decisions/` остаются русскими. Решение
автора: пока не переводим. Записи в ideas.md нет — это не решение о
дизайне.

## 4. Отказы из pre-юнитов

Вопрос автора: «все ошибки, которые кидаются из pre, надо явно объявлять в
`errors` всех хендлеров, так? С этим можно что-то сделать?»

Подтверждено: так, и цена выше повтора — молчаливый `500` при забытом
объявлении и OpenAPI без `401`. Почему нельзя просто вывести: `throw`
компилятору не виден, а вывод из возвращаемого типа не даёт значения,
которое читают граница и OpenAPI. Значит, объявление должно быть значением
между endpoint'ом и юнитом.

Предложение, принятое автором («мне нравится твоя идея»): объявлять на
слое в точке подключения юнита, `.pre(Authenticate, { errors:
[Unauthorized] })`. Тип пайплайна получает `TFails`, значение хранит
определения рядом с объявленными переменными, `makeEndpoint` считает
эффективное множество, pre-юнит получает канал `return` для отказа, форма
с операцией проверяет `TFails ⊆ errors` операции в типах. Отвергнуты:
список на уровне `makeApp` (грубо, OpenAPI неверен), объявление на юните
(ещё одна форма), чистый вывод без значения. Запись «Отказы слоя».

## 5. Две формы хендлера

Вопрос автора: «не стоит ли полностью упразднить функциональную форму
хендлера? Я сам пользоваться этим не буду, но сомневаюсь».

Факты из кода: объектная форма `{ deps, handle }` — 20 мест в 14 файлах
примеров (10 `httpEndpoint`, 8 `implement`), класс — 8, голая функция — 8.
`Family.auto` работает только в `@Injectable`; в `handler.deps` потребителя
без класса нет по построению. Принцип «классы там, где подключение к
контейнеру» нарушен только этой формой. Для юнитов правило «зависимости —
класс» уже действует. Вывод типов из токенов работает лишь инлайн, а
конвенции выносят хендлер в константу.

Рекомендация: удалить объектную форму, оставить функцию без зависимостей и
класс. Асимметрия стоимости: удаление стоит одной правки перегрузок и
примеров, возврат формы позже — той же правки, а хранение формы платит
вниманием каждого читателя. Решение автора: «Удалять».
Запись «Две формы хендлера».
