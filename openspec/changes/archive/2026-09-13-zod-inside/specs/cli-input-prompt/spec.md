## MODIFIED Requirements

### Requirement: План вопросов строится из JSON Schema при старте

CLI-транспорт на `serve` SHALL построить план вопросов для каждой команды с
политикой `'prompt'`: схема `input` переводится в JSON Schema конвертером с
совпадающим `~standard.vendor` в направлении `io: 'input'`. План SHALL
строиться один раз и переиспользоваться при каждом вызове команды.

Список конвертеров SHALL разрешаться умолчанием: `cli({ converters })`
необязателен, и схема, написанная на вендоре фреймворка, переводится без
строки в опциях (capability `schema-zod-package`).

Отсутствие конвертера для вендора схемы SHALL ронять `serve` с именем
команды и именем вендора; текст SHALL называть способ починки — передать
конвертер этого вендора списком.

#### Scenario: Вопросы строятся без объявления конвертера

- **WHEN** объявлена команда с `missing: 'prompt'` и zod-схемой, а
  `cli()` вызван без опций
- **THEN** `serve` проходит, и недостающие обязательные поля спрашиваются

#### Scenario: Конвертера для чужого вендора нет

- **WHEN** объявлена команда с `missing: 'prompt'` и valibot-схемой, а
  конвертер valibot не передан
- **THEN** `serve` бросает ошибку, называющую команду, вендора `'valibot'`
  и способ починки

#### Scenario: Конвертер нужен только командам с политикой

- **WHEN** ни одна команда не объявляет `missing: 'prompt'`
- **THEN** `serve` схем не конвертирует и проходит

#### Scenario: Схема конвертируется один раз

- **WHEN** команда с политикой вызвана дважды
- **THEN** конвертер вызван один раз — при `serve`
