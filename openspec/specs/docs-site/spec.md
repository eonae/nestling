# docs-site Specification

## Purpose

`yarn docs:build` собирает гайд `docs/guide/*.md` и его README в один
файл `docs/.site/index.html`. Генератор и тема лежат в `scripts/site/`, а
каталог вывода не отслеживается git; оформление, поведение и подсветка
кода попадают внутрь файла, поэтому он открывается в одиночку. Отдельных
markdown-источников для сайта не существует: текст раздела берётся только
из соответствующей главы. Порядок разделов и группы боковой навигации
повторяют структуру README — заголовки `## Часть N. …` и таблицы под
ними. Ссылки между главами становятся якорями, а подписи блоков кода
переносятся в HTML без правки текста глав. Несовпадение README и
содержимого `docs/guide` — ошибка сборки.

## Requirements

### Requirement: Сайт собирается из глав гайда

Скрипт `yarn docs:build` SHALL собирать один файл `docs/.site/index.html`
из `docs/guide/README.md` и глав `docs/guide/*.md`. Других файлов `.html`
в каталоге вывода SHALL NOT быть. Генератор и тема SHALL лежать в
`scripts/site/`: `build.mjs`, `layout.html`, `styles.css`, `app.js`.

README гайда SHALL открывать документ, а каждая глава и каждое приложение
SHALL становиться его разделом с якорем по имени файла главы. Отдельных
markdown-источников для сайта SHALL NOT существовать: текст раздела
берётся только из соответствующей главы.

Порядок разделов SHALL совпадать с порядком таблиц README гайда. Глава,
названная в README, но отсутствующая в `docs/guide`, и глава, лежащая в
`docs/guide`, но не названная в README, SHALL быть ошибкой сборки с именем
файла.

Команда `yarn docs:dev` SHALL пересобирать файл при изменении файлов
`docs/guide/` и `scripts/site/`. Имён `docs:preview` и `docs:preview:watch`
SHALL NOT существовать.

#### Scenario: Сборка из гайда

- **WHEN** выполнено `yarn docs:build`
- **THEN** в `docs/.site` лежит `index.html` и ни одного другого файла
  `.html`, а в нём — раздел на каждую строку таблиц README гайда

#### Scenario: Глава без строки в README

- **WHEN** в `docs/guide` добавлен файл `26-extra.md`, а в README он не
  упомянут
- **THEN** сборка падает, называя файл

#### Scenario: Пересборка при изменении главы

- **WHEN** запущено `yarn docs:dev` и изменён файл главы
- **THEN** файл собран заново и содержит новый текст главы

#### Scenario: Старых имён команд нет

- **WHEN** выполнено `yarn docs:preview`
- **THEN** yarn сообщает, что такого скрипта нет

### Requirement: Каталог вывода не отслеживается git, тема встроена в файл

`docs/.site/` SHALL быть перечислен в `.gitignore`, и ни один файл этого
каталога SHALL NOT отслеживаться git.

Сборка SHALL встраивать `styles.css` в `<style>` и `app.js` в `<script>`
внутрь собранного файла. Файлов `styles.css` и `app.js` в каталоге вывода
SHALL NOT быть, а собранный файл SHALL NOT ссылаться на соседние файлы за
оформлением и поведением. Файл, скопированный в любой другой каталог,
SHALL открываться с оформлением и подсветкой.

#### Scenario: Результат сборки вне git

- **WHEN** выполнено `yarn docs:build` и затем `git status --short`
- **THEN** ни один файл `docs/.site/` не показан как новый или изменённый

#### Scenario: Тема не лежит рядом

- **WHEN** выполнено `yarn docs:build`
- **THEN** в `docs/.site/` нет ни `styles.css`, ни `app.js`

#### Scenario: Файл открыт в одиночку

- **WHEN** `index.html` скопирован в другой каталог без соседей и открыт
  в браузере
- **THEN** страница показана с оформлением, а код — подсвеченным

### Requirement: Навигация строится из частей гайда

Группы сайдбара SHALL соответствовать заголовкам `## Часть N. …` и
`## Приложения` README гайда; пункты группы — строкам таблицы под
заголовком, с заголовком главы из первой ячейки. Пункт SHALL вести якорем
на раздел главы внутри файла.

Все части и главы SHALL быть перечислены в сайдбаре сразу. У главы,
которую читатель видит, SHALL раскрываться список её `##`-разделов, а её
пункт SHALL быть отмечен активным; читаемая глава определяется по
положению прокрутки. Пейджер в конце главы SHALL вести якорями на
предыдущую и следующую главу в порядке README.

#### Scenario: Сайдбар открытого файла

- **WHEN** файл открыт в браузере
- **THEN** сайдбар перечисляет все части и все главы, и каждый пункт
  ведёт якорем внутрь файла

#### Scenario: Читаемая глава

- **WHEN** читатель прокрутил файл до главы 3
- **THEN** пункт главы 3 отмечен активным, под ним перечислены её
  `##`-разделы, у остальных глав подпунктов нет

#### Scenario: Пейджер

- **WHEN** читатель дошёл до конца главы 6
- **THEN** пейджер ведёт назад на `#05-repository` и вперёд на
  `#07-testing`; в конце последнего приложения ссылки «вперёд» нет

### Requirement: Ссылки и блоки кода переносятся без правки глав

Ссылки вида `./NN-имя.md` и `./appendix-*.md` SHALL переписываться в
якорь `#NN-имя`; якорь главы SHALL переноситься с приставкой:
`./NN-имя.md#якорь` → `#NN-имя--якорь`. Ссылка `./README.md` SHALL вести
на начало документа. Ссылки в другие папки `docs/` (`../design/…`,
`../decisions/…`, `../glossary.md`) SHALL оставаться как есть:
`docs/guide/` и `docs/.site/` — соседние папки, относительный путь
совпадает. Ссылка `./NN-имя.md` на несуществующую главу SHALL быть ошибкой
сборки.

Идентификатор заголовка внутри главы SHALL получать приставку из имени
главы и двух дефисов: одинаковые заголовки разных глав иначе столкнулись
бы в одном файле.

Блок кода, первая строка которого — комментарий `// путь`, SHALL получать
подпись `data-file` из этого пути; строка из кода SHALL NOT удаляться.
Путь переносится дословно и не разбирается: сборка не проверяет, что он
существует, и не знает, из какого каталога взят файл.

Подсветка синтаксиса SHALL выполняться при сборке: разметка токенов
SHALL лежать в самом HTML. Показ подсвеченного кода SHALL NOT зависеть от
выполнения JavaScript в браузере.

Текст глав SHALL NOT требовать разметки, отличной от обычного markdown:
`:::note` и `::::cards` остаются доступными, но не обязательны.

#### Scenario: Ссылка на соседнюю главу

- **WHEN** глава содержит `[глава 6](./06-config.md#секреты)`
- **THEN** файл содержит ссылку `#06-config--секреты`

#### Scenario: Ссылка на дизайн

- **WHEN** глава содержит `[design/errors.md](../design/errors.md)`
- **THEN** ссылка остаётся `../design/errors.md` и из `docs/.site/` ведёт
  в `docs/design/errors.md`

#### Scenario: Одинаковые заголовки в разных главах

- **WHEN** заголовок `## Проверка` есть и в главе 8, и в главе 20
- **THEN** идентификаторы у них разные: `08-logging--проверка` и
  `20-cli--проверка`

#### Scenario: Подпись блока кода

- **WHEN** блок кода начинается со строки `// examples/users-service/src/app.ts`
- **THEN** блок получает `data-file="examples/users-service/src/app.ts"`,
  а строка-комментарий остаётся в коде

#### Scenario: Подсветка без JavaScript

- **WHEN** файл открыт с выключенным JavaScript
- **THEN** ключевые слова, строки и комментарии в блоках кода окрашены

#### Scenario: Битая ссылка на главу

- **WHEN** глава ссылается на `./99-missing.md`
- **THEN** сборка падает, называя главу и ссылку

### Requirement: Разделы README вне «Часть N.»/«Приложения» не попадают в сайт

`docs/guide/README.md` MAY содержать заголовки `##`, отличные от «Часть
N. …» и «Приложения» — например, «Карта понятий». Такой заголовок SHALL
NOT открывать новую группу навигации сайдбара и SHALL NOT прерывать
сборку `yarn docs:build`.

Строка таблицы, первая ячейка которой не является ссылкой `[текст](./имя.md)`
на главу, SHALL NOT становиться разделом сайта — даже если ссылка на
главу встречается в другой ячейке той же строки. Такая строка SHALL NOT
считаться расхождением README и `docs/guide` при проверке полноты
состава.

#### Scenario: Раздел без ссылок на главу в первой ячейке

- **WHEN** между существующими разделами README добавлен заголовок `##
  Карта понятий` с таблицей, где первая ячейка каждой строки — понятие
  (текст или код), а не ссылка на главу
- **THEN** `yarn docs:build` собирается без ошибок, а строки этой таблицы
  не порождают новых разделов в `index.html`

#### Scenario: Ссылка на главу в непервой ячейке строки

- **WHEN** строка такой таблицы содержит ссылку на главу `./NN-имя.md` не
  в первой ячейке
- **THEN** эта ссылка не превращает строку в раздел сайта и не требует,
  чтобы заголовок раздела совпадал с «Часть N.» или «Приложения»
