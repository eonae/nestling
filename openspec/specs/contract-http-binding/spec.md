# contract-http-binding

## Purpose

Операция адресуется на шине именем; секция `http:` даёт ей адрес по HTTP.
Это данные адресации, а не описание исполнения: `method`, `path`, пометки
размещения, `rawBody`, `sse` — и ничего про `handle`, `pipeline` или `deps`.
Канон размещения разворачивается в плоскую bind-карту тем же кодом, что
обслуживает HTTP-декларацию, и в тот же момент — при создании значения.
Благодаря этому внешний потребитель читает карту из одного импорта операции,
без серверного кода и без запуска приложения, а расхождению правил между
операцией и декларацией неоткуда взяться. Наличие секции ничего не меняет для
шины: операция остаётся тем же направление-нейтральным значением со своими
`.caller`/`.emitter`.

## Requirements

### Requirement: Операция несёт HTTP-адресацию секцией `http:`

Словарь конструктора операции SHALL принимать необязательную секцию `http`,
дающую операции адрес по HTTP так же, как имя даёт адрес на шине.
Секция SHALL приниматься в двух формах:

- строкой `'<METHOD> <path>'` — сахар для случая без пометок;
- записью `{ method, path, bind?, rawBody?, sse? }` — те же поля, что
  принимает HTTP-словарь декларации.

Строковая форма SHALL разбираться строго: ровно один разделяющий пробел,
непустой метод, непустой путь. Нарушение SHALL быть ошибкой в момент
создания операции.

Секция SHALL быть **данными адресации**, а не описанием исполнения:
операция SHALL NOT принимать полей, относящихся к обработке запроса
(`handle`, `pipeline`, `deps`, `detached`).

#### Scenario: Строковая форма

- **WHEN** объявлено `makeRequest('users.create', { http: 'POST /users', input: CreateUser, output: User })`
- **THEN** операция несёт HTTP-адрес `POST /users`

#### Scenario: Развёрнутая форма с пометками

- **WHEN** объявлено `http: { method: 'POST', path: '/users', bind: { dryRun: query() } }`
- **THEN** операция несёт тот же адрес, а `dryRun` размещён в query

#### Scenario: Битая строковая форма

- **WHEN** объявлено `http: 'POST'` или `http: 'POST /users extra'`
- **THEN** конструктор бросает ошибку, называя операцию и
  ожидаемую форму записи

#### Scenario: Операция без секции остаётся операцией шины

- **WHEN** объявлена операция без `http:`
- **THEN** она создаётся как прежде, HTTP-адреса не несёт, и на реализацию
  через `implement` это никак не влияет

### Requirement: Bind-карта разворачивается в момент создания операции

Конструктор операции SHALL разворачивать канон размещения и пометки секции
`http` в ту же плоскую bind-карту, что и конструктор HTTP-декларации
(capability `http-input-binding`), **в момент создания значения операции**.
Карта SHALL быть доступна с самой операции.

Правило размещения SHALL быть тем же самым кодом, что обслуживает
декларацию: два места вызова, одна реализация канона. Расхождение правил
между операцией и декларацией SHALL NOT существовать.

#### Scenario: Карта доступна из одного импорта операции

- **WHEN** значение операции импортировано во внешний потребитель — без
  серверного кода и без запуска приложения
- **THEN** bind-карта доступна с операции и описывает метод, шаблон пути,
  размещение path-параметров и помеченных полей, правило для остальных и
  признак `rawBody`

#### Scenario: Правило совпадает с правилом декларации

- **WHEN** один и тот же набор (метод, путь, пометки, форма `input`)
  объявлен операцией и HTTP-декларацией
- **THEN** обе карты структурно совпадают

### Requirement: Секция `http` проверяется при создании операции

Конструктор операции SHALL применять к секции `http` тот же набор проверок,
что конструктор HTTP-декларации применяет к своему словарю (capability
`http-input-binding`), и SHALL отвергать в момент создания значения:

- пустой путь и путь, не начинающийся с `/`;
- повторяющиеся имена path-параметров в шаблоне;
- пометку на поле, совпадающем с path-параметром;
- пометку `body()` у метода без тела;
- непустой `bind` или path-параметр при неструктурном `input`;
- path-параметр в шаблоне при отсутствии `input`;
- `rawBody: true` вместе с потоковой или multipart-формой;
- секцию `sse` при не-`events`-выходе и зарезервированное имя события
  `error`.

Текст ошибки SHALL называть операцию по имени и нарушенное правило.

#### Scenario: Path-параметр без `input`

- **WHEN** объявлено `makeRequest('users.get', { http: 'GET /users/:id' })` без `input`
- **THEN** вызов бросает ошибку, называя операцию и параметр `:id`

#### Scenario: `body()` у метода без тела

- **WHEN** объявлено `http: { method: 'GET', path: '/users', bind: { filter: body() } }`
- **THEN** вызов бросает ошибку, называя операцию, метод и поле

#### Scenario: Ошибка срабатывает при загрузке модуля операций

- **WHEN** модуль с дефектной операцией импортирован
- **THEN** ошибка возникает на импорте — у владельца декларации, а не при
  сборке приложения и не при первом вызове клиента

### Requirement: `http:` не меняет вид операции и её вызывающие стороны

Наличие секции `http` SHALL NOT влиять ни на вид операции, ни на её
вызывающие стороны (`.caller`/`.emitter`), ни на биндинг реализации через
`implement`: операция с `http:` остаётся тем же направление-нейтральным
значением, адресуемым по шине под своим именем.

#### Scenario: Вызов по шине работает как прежде

- **WHEN** операция с `http:` реализована через `implement` и вызвана
  инжектированным `.caller`
- **THEN** вызов идёт по шине, а секция `http` в этом пути не участвует

#### Scenario: Одно значение — два пути доставки

- **WHEN** операция с `http:` реализована формой `httpEndpoint`
- **THEN** внешний клиент зовёт её по HTTP, а внутренний потребитель — по
  шине, и оба читают один и тот же интерфейс операции
