# http-input-binding

## Purpose

Где искать поле `input` в HTTP-запросе — определяет **канон**, а не
конвенция чтения «отовсюду». Размещение вычисляется детерминированной
функцией `(шаблон пути, метод, пометки) → место`, разворачивается в плоскую
bind-карту в момент создания декларации и дальше служит единственным
носителем размещения для транспорта, генератора документации и
типизированного клиента. Транспорт собирает payload strict-приёмом: каждое
поле берётся ровно из своего места, слияния источников и ошибок конфликта
не существует. Отклонения от канона выражаются пометками `query()`/`body()`
в словаре декларации и проверяются при создании значения; сырые байты тела
доступны через opt-in `rawBody`, меняющий тип стартового контекста.

## Requirements

### Requirement: Канон размещения — детерминированная функция

Размещение поля `input` в HTTP-запросе SHALL определяться детерминированной
функцией `(шаблон пути, метод, пометки) → место` по правилам, применяемым в
порядке убывания приоритета:

1. имя поля совпало с path-параметром шаблона (`:name`) → **путь**;
2. поле помечено в `bind` → указанное пометкой место;
3. всё остальное → **query** для методов без тела
   (`GET`, `HEAD`, `DELETE`, `OPTIONS`, `TRACE`) и **body** для остальных.

Заголовки SHALL быть доступны только по явной пометке и SHALL NOT
назначаться конвенцией; в V1 пометки заголовка не существует.

#### Scenario: Path-параметр выигрывает у правила по умолчанию

- **WHEN** объявлено `httpEndpoint({ method: 'PATCH', path: '/users/:id', input: UpdateUser, … })`, где схема содержит `id` и `name`
- **THEN** `id` размещается в пути, `name` — в теле

#### Scenario: Метод без тела кладёт остальное в query

- **WHEN** объявлено `httpEndpoint({ method: 'GET', path: '/users', input: ListUsers, … })`
- **THEN** все поля схемы, кроме path-параметров и помеченных, размещаются
  в query

#### Scenario: Метод с телом кладёт остальное в body

- **WHEN** объявлено `httpEndpoint({ method: 'POST', path: '/users', input: CreateUser, … })`
- **THEN** все поля схемы, кроме path-параметров и помеченных, размещаются
  в теле

### Requirement: Пометки `query()` и `body()` — значения в `bind`-записи словаря

HTTP-словарь SHALL принимать необязательное поле `bind` — запись
«имя поля → пометка». Пометки SHALL быть значениями, создаваемыми
экспортируемыми конструкторами `query(options?)` и `body()`
из `@nestling/transport.http`; строковая форма записи места SHALL NOT
приниматься. `query({ multiple: true })` SHALL объявлять поле-массив.

Ключи `bind` SHALL быть типизированы полями схемы `input` за вычетом
path-параметров шаблона: неизвестное имя поля и имя path-параметра SHALL
быть ошибками компиляции.

#### Scenario: Поле вытянуто в query из тела

- **WHEN** объявлено `httpEndpoint({ method: 'POST', path: '/users', input: CreateUser, bind: { dryRun: query() }, … })`
- **THEN** `dryRun` читается из query-строки, остальные поля — из тела

#### Scenario: Опечатка в имени поля не компилируется

- **WHEN** в `bind` указано имя, отсутствующее в схеме `input`
- **THEN** это ошибка компиляции

#### Scenario: Пометка на path-параметре не компилируется

- **WHEN** шаблон содержит `:id`, а в `bind` указано `{ id: query() }`
- **THEN** это ошибка компиляции, а при вызове из JS — ошибка в момент
  создания декларации

### Requirement: Пометки разворачиваются в плоскую bind-карту при создании декларации

Конструктор декларации SHALL разворачивать канон и пометки в плоскую
bind-карту **в момент создания значения** — не при регистрации в
приложении. Карта SHALL быть доступна с значения декларации и SHALL
содержать: явные размещения (path-параметры шаблона и помеченные поля),
правило для остальных полей (`query` или `body`), метод, шаблон пути и
признак `rawBody`.

Карта SHALL быть единственным носителем размещения для всех потребителей:
транспорта, генератора документации и типизированного клиента. Ядро
(`@nestling/pipeline`) SHALL переносить её на значение декларации, не
интерпретируя.

#### Scenario: Карта читается из одного импорта декларации

- **WHEN** значение декларации импортировано без запуска приложения и без
  серверного кода
- **THEN** bind-карта доступна с этого значения и описывает размещение
  path-параметров, помеченных полей и правило для остальных

#### Scenario: Регистрация в приложении карту не меняет

- **WHEN** та же декларация объявлена в `endpoints:` модуля и приложение
  поднято
- **THEN** транспорт использует ту же карту, что была вычислена при
  создании значения

#### Scenario: Ядро не интерпретирует носитель

- **WHEN** декларация создана kernel-примитивом `makeEndpoint` с полем
  `binding`
- **THEN** значение несёт это поле без изменений, а `@nestling/pipeline`
  не содержит понятий `path`/`query`/`body`

### Requirement: Словарь проверяется при создании декларации

Конструктор SHALL отвергать в момент создания значения:

- пометку на поле, совпадающем с path-параметром шаблона;
- пометку `body()` у метода без тела;
- непустой `bind` при неструктурном `input`
  (`stream(...)`, `files()`, примитивы `'binary'`/`'text'`);
- path-параметр в шаблоне при неструктурном `input`;
- path-параметр в шаблоне при отсутствии `input`;
- `rawBody: true` вместе с `stream(...)`, `files()` или `withFiles(...)`.

Ошибка SHALL называть нарушенное правило и проблемное имя (поля, параметра
или метода).

Проверка «path-параметр объявлен в шаблоне, но отсутствует в схеме» в общем
виде SHALL NOT входить в этот набор: Standard Schema не отдаёт перечня
ключей.

#### Scenario: `body()` у GET

- **WHEN** вызвано `httpEndpoint({ method: 'GET', path: '/users', input: ListUsers, bind: { filter: body() }, … })`
- **THEN** вызов бросает ошибку в момент создания декларации, называя метод
  и поле

#### Scenario: Path-параметр при потоковом input

- **WHEN** вызвано `httpEndpoint({ method: 'POST', path: '/users/:id/logs', input: stream(LogChunk), … })`
- **THEN** вызов бросает ошибку: path-параметру негде оказаться в payload

#### Scenario: `rawBody` со стримом

- **WHEN** вызвано `httpEndpoint({ method: 'POST', path: '/hooks', input: stream(Chunk), rawBody: true, … })`
- **THEN** вызов бросает ошибку в момент создания декларации

### Requirement: Транспорт собирает payload только из канонических мест

HTTP-транспорт SHALL собирать payload по bind-карте: path-параметры — из
совпадения с маршрутом, помеченные поля — каждое из своего места, остальные
поля — из одного источника, заданного правилом карты. Слияние значений из
всех источников SHALL NOT применяться; поле, присланное не в каноническое
место, SHALL NOT попадать в payload.

Приоритет при совпадении имён SHALL быть фиксированным: path-параметр,
затем помеченное поле, затем поле из источника «остальное». Ошибки
конфликта источников SHALL NOT существовать.

Тело запроса SHALL читаться только тогда, когда оно требуется картой
(источник «остальное» — body, есть `body()`-пометка или взведён `rawBody`).

Для формы `withFiles(...)` правило SHALL применяться к полям формы:
path-параметры и помеченные query-поля подмешиваются к разобранным полям
до валидации схемой.

#### Scenario: Поле, присланное не в своё место, отбрасывается

- **WHEN** у `POST /users` (поля по канону — в теле) приходит
  `?name=Alice` при пустом теле
- **THEN** `name` в payload отсутствует и запрос падает обычной ошибкой
  валидации (400 с issue'ами), а не принимается

#### Scenario: Одноимённые path-параметр и поле тела

- **WHEN** у `PATCH /users/:id` приходит путь `/users/42` и тело
  `{"id": "7", "name": "Alice"}`
- **THEN** в payload попадает `id: '42'` из пути и `name` из тела; ошибки
  конфликта нет

#### Scenario: Тело у GET не читается

- **WHEN** на `GET /users` приходит запрос с телом и без `body()`-пометок
- **THEN** транспорт тело не буферизует и обрабатывает запрос по query

#### Scenario: Multipart с path-параметром

- **WHEN** на `POST /users/:id/avatar` с `input: withFiles(schema)`
  приходит multipart-запрос
- **THEN** `id` из пути присутствует в `data` до валидации схемой, файлы
  доступны отдельно

### Requirement: Повторный query-ключ даёт массив

Разбор query-строки SHALL сохранять все вхождения ключа: одно вхождение —
скаляр, два и более — массив в порядке следования. Молчаливое затирание
предыдущих значений (last-wins) SHALL NOT применяться. Поле, помеченное
`query({ multiple: true })`, SHALL приходить массивом и при одном
вхождении; при нуле вхождений поле SHALL отсутствовать в payload.

#### Scenario: Повтор ключа

- **WHEN** приходит `?tag=a&tag=b`
- **THEN** в payload `tag` равно `['a', 'b']`

#### Scenario: Одиночное вхождение без пометки

- **WHEN** приходит `?tag=a` и поле не помечено `multiple`
- **THEN** в payload `tag` равно `'a'`

#### Scenario: Одиночное вхождение с пометкой `multiple`

- **WHEN** поле помечено `query({ multiple: true })` и приходит `?tag=a`
- **THEN** в payload `tag` равно `['a']`

#### Scenario: Отсутствие значения остаётся отсутствием

- **WHEN** поле помечено `query({ multiple: true })` и в запросе не
  встречается
- **THEN** поля в payload нет (пустой массив не подставляется), и решение
  об обязательности принимает схема

### Requirement: `rawBody: true` кладёт байты в типизированный стартовый контекст

HTTP-словарь SHALL принимать необязательное `rawBody: boolean`. При
`rawBody: true` транспорт SHALL класть сырые байты тела в стартовый
контекст запроса полем `rawBody: Uint8Array` и SHALL парсить значение из
тех же байтов, не читая поток дважды. Лимит `maxBodySize` SHALL
действовать на это чтение как обычно.

Тип стартового контекста декларации SHALL зависеть от `rawBody`: pipeline,
требующий `{ rawBody: Uint8Array }`, SHALL NOT компилироваться в
декларации без `rawBody: true`. При `rawBody`, не взведённом или
отсутствующем, стартовый контекст SHALL быть пустым.

#### Scenario: Слой проверки подписи получает байты

- **WHEN** объявлено `httpEndpoint({ method: 'POST', path: '/hooks/stripe', rawBody: true, pipeline: <слой, объявленный makePipeline<{ rawBody: Uint8Array }>()>, … })` и приходит запрос
- **THEN** слой видит в контексте `rawBody` с байтами исходного тела, а
  хендлер получает разобранный по схеме payload

#### Scenario: Забытая пометка — ошибка компиляции

- **WHEN** pipeline требует `{ rawBody: Uint8Array }`, а в словаре
  декларации `rawBody` не указан
- **THEN** это ошибка компиляции в точке декларации

#### Scenario: Байты не платятся без запроса

- **WHEN** декларация не указывает `rawBody`
- **THEN** стартовый контекст пуст, сырые байты нигде не удерживаются

#### Scenario: Лимит тела действует и для сырых байтов

- **WHEN** у декларации с `rawBody: true` приходит тело больше
  `maxBodySize`
- **THEN** транспорт отвечает 413, не буферизуя тело целиком
