## Why

Порт HTTP задавался двумя путями сразу: опцией `http({ port })` и ключом
`HTTP_PORT`, причём опция была сильнее конфига. Опция закрывала другую
дыру: секция `HttpConfig` одна на пакет, поэтому `http()` и
`http({ name: 'admin' })` читали один и тот же `HTTP_PORT`. Разделяемая
вещь при этом не порт, а сокет: два слушателя на один порт не биндятся.

Второе: дубликат паттерна из двух фич ловил только find-my-way, и делал
это внутри `serve` — на фазе START, после захвата ресурсов.

Решение зафиксировано записью
[ideas.md [2026-09-06] «HTTP-сервер как ресурс»](../../../docs/decisions/ideas.md)
по ревью [d/12](../../../docs/history/discussions/12-lifecycle-and-composition-review.md)
(пункты 18, 19 исходного списка). Целевое состояние описано в
[transports.md §4.2](../../../docs/design/transports.md); код до него не
доведён.

## What Changes

- **Новое объявление `httpServer({ name? })`** — ресурс, который держит
  `http.Server`. Объявляется в `transports:` корня. Порт и хост читает из
  своей секции по имени: `HTTP_PORT` и `HTTP_HOST` у сервера по
  умолчанию, `HTTP_ADMIN_PORT` и `HTTP_ADMIN_HOST` у `name: 'admin'`.
- **`http({ server? })` присоединяется к серверу.** Без `server`
  транспорт объявляет собственный сервер с тем же именем, что у него.
  Несколько транспортов на одном сокете получают один сервер.
- **BREAKING: опции `port` и `host` у `http()` удаляются.** Эфемерный
  порт в тестах задаётся через `HTTP_PORT=0` в `vars`.
- **BREAKING: `address()` переезжает с транспорта на сервер.** Сокетом
  владеет сервер, он же знает фактический адрес.
- **BREAKING: секция HTTP становится семейством по имени экземпляра.**
  Префикс ключей строится из имени: `HTTP_` и `HTTP_ADMIN_`.
- **Фаза START становится трёхшаговой**: хуки `@OnStart`, затем `serve`
  у транспортов, затем `listen` у серверов. Сокет открывается последним.
  На SHUTDOWN серверы перестают принимать соединения и дренажат их
  первыми, транспорты закрываются следом.
- **Дубликат паттерна — ошибка ASSEMBLE.** Discovery группирует
  декларации по паре «экземпляр транспорта, паттерн»; при совпадении
  ошибка называет обе единицы и оба файла. Правило одно для всех
  транспортов.

## Capabilities

### New Capabilities

- `http-server-resource`: сервер как ресурс — объявление `httpServer({ name })`,
  чтение порта и хоста из секции по имени, присоединение транспортов
  через `http({ server })`, владение сокетом и адресом, порядок `listen`
  и дренажа относительно `serve` и `close`.
- `pattern-uniqueness`: уникальность пары «экземпляр транспорта, паттерн»
  среди обнаруженных деклараций; ошибка ASSEMBLE с именами обеих единиц.

### Modified Capabilities

- `transport-providers`: порт и адрес принадлежат серверу, а не
  транспорту; два требования о порте и о фактическом адресе
  переписываются под ресурс сервера.
- `lifecycle-phases`: START получает третий шаг (`listen` после `serve`),
  SHUTDOWN — симметричный ему первый шаг (дренаж сервера до `close`
  транспорта).
- `dispatch-guarantee`: гарантия «трафик не раньше `dispatch`» держится
  порядком `serve` → `listen`, а не тем, что сокет открывает сам
  транспорт.
- `http-transport-limits`: дренаж соединений при остановке становится
  обязанностью сервера; `closeTimeout` переезжает к нему.
- `http-transport-boundary`: в перечне обещаний пакета адрес и дренаж
  описываются как обязанности сервера-ресурса.
- `config-sections`: префикс секции может задаваться именем экземпляра,
  то есть секция объявляется семейством.

## Non-goals

- TLS у сервера. Терминация остаётся на обратном прокси
  ([transports.md §4.1](../../../docs/design/transports.md)).
- HTTP/2 и WebSocket — вне границы пакета.
- Unix-сокет вместо порта (`HTTP_PATH`) — по потребности, не сейчас.
- Встраивание в чужой `http.Server`, созданный вне приложения. Это
  standalone-путь и satellite-транспорт.
- Пробы `httpProbes()` — отдельный change `health`.
- Изменение правила шины «два владельца операции»: оно уже есть и
  остаётся как есть, новое правило формулируется по его образцу.

## Impact

- `@nestling/transport.http`: `transport.ts` (конструктор, `serve`,
  `close`, `address`, фабрика `http`), `config.ts` (секция-семейство),
  новый модуль сервера, `index.ts`, README.
- `@nestling/app`: порядок фаз START и SHUTDOWN в `root/app.ts`,
  объявления в `transport/declaration.ts`, проверка уникальности
  паттернов рядом с discovery, README.
- `@nestling/testing`: рецепт эфемерного порта переходит на
  `HTTP_PORT=0`.
- `examples/app-with-http` (хелпер `create-test-app.ts` читает
  `transport.address()`), `examples/users-service`,
  `examples/simple-http-server`.
- Гайд: глава 6 (порт из конфига), глава 24 (standalone), README пакетов
  `@nestling/openapi` и `@nestling/testing` в части примеров с `http({ port })`.
- Предпосылка: `@Resource` из change `resources-and-roles`. Этот change
  ветвится после его вливания в `main`.
