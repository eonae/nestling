# declaration-doc-metadata Specification (delta)

## MODIFIED Requirements

### Requirement: Слот `doc:` несёт метаданные, которых нет в схемах

Словарь endpoint-декларации и словарь конструктора операции SHALL принимать
необязательную секцию `doc` со следующими полями и никакими другими:

- `summary?: string` — однострочное название операции;
- `description?: string` — развёрнутое описание;
- `tags?: readonly string[]` — группировка операции;
- `deprecated?: boolean`;
- `status?: SuccessStatus` — статус успешного ответа из словаря статусов
  ядра (`ok`, `created`, `accepted`, `no_content`);
- `hidden?: string` — причина, по которой операция не попадает в
  документацию.

Слот SHALL быть транспорт- и формат-нейтральным: полей, осмысленных только
для OpenAPI (`operationId`, `externalDocs`, `servers`), в нём SHALL NOT
быть — тот же слот читает будущая генерация AsyncAPI.

Ядро SHALL переносить `doc` на значение декларации и SHALL NOT его
интерпретировать: ни один путь исполнения запроса от него не зависит.

#### Scenario: Декларация с документацией

- **WHEN** объявлено `httpEndpoint({ method: 'GET', path: '/users', doc: { summary: 'List users', tags: ['users'] }, … })`
- **THEN** значение декларации несёт `doc` с этими полями, а исполнение
  запроса не меняется ни в чём

#### Scenario: Операция с документацией

- **WHEN** объявлено `makeRequest('users.create', { doc: { summary: 'Create user' }, … })`
- **THEN** значение операции несёт `doc`, доступный и реализации, и
  внешнему потребителю операции из того же импорта

### Requirement: Словарь `doc` проверяется в момент создания значения

Конструктор декларации и конструктор операции SHALL отвергать дефектный `doc` в
точке создания, а не на сборке приложения: не-строку в `summary`/
`description`, не-массив строк в `tags`, `status` вне словаря успешных
статусов ядра, `hidden`, не являющийся непустой строкой, и неизвестное
поле секции.

Формы `hidden: true` SHALL NOT существовать: тип поля — строка, а рантайм
SHALL отвергать не-строку и пустую строку. Причина обязательна ровно по
той же логике, что и у `detached`: тотальный opt-out обязан быть читаем в
diff'е.

Текст ошибки SHALL называть ручку (или операцию), поле и требование.

#### Scenario: Пустая причина скрытия

- **WHEN** объявлено `httpEndpoint({ …, doc: { hidden: '' } })`
- **THEN** создание декларации бросает ошибку: причина обязательна

#### Scenario: `hidden: true` отвергается

- **WHEN** JS-потребитель объявил `doc: { hidden: true }`
- **THEN** создание бросает ошибку, называющую требование причины и
  отсутствие булевой формы

#### Scenario: Статус вне словаря

- **WHEN** объявлено `doc: { status: 'partial_content' }`
- **THEN** создание бросает ошибку, перечисляющую допустимые успешные
  статусы

#### Scenario: Неизвестное поле секции

- **WHEN** объявлено `doc: { operationId: 'listUsers' }`
- **THEN** создание бросает ошибку: имя операции выводится, а не
  объявляется
