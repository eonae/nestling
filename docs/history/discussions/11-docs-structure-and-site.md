# 11 · Структура документации и публикуемый сайт

**Дата:** 2026-09-05.
**Формат:** разбор всей документации репозитория по запросу «гайд не
устраивает, и много дублирования; предложи финальную структуру и план
наведения порядка», затем дополнение про сборку публикуемого HTML.
**Итог:** целевая структура из пяти жанров, план из пяти волн, решение
оставить свой генератор сайта. Записей в `ideas.md` пока нет.

---

## 1. Вопрос

«Посмотри на документацию. Я уже много работал над гайдом, но он всё ещё
не совсем меня устраивает. Кроме того, мне кажется у нас довольно много
дублирования — во всяких README, `docs/preview` и т. д. Предложи финальную
структуру документации и план наведения порядка.»

Второй вопрос, заданный после разбора: «Мне надо ещё чтобы из всей этой
документации собирался html, который можно опубликовать.»

## 2. Что есть сейчас

| Место | Строк | Жанр |
|---|---|---|
| `docs/history/` | 21 843 | заморожено |
| `docs/decisions/` | 8 166 | почему |
| `docs/guide/` | 7 013 | обучение |
| `packages/*/README.md` | 5 061 | смесь всех жанров |
| `docs/design/` | 3 622 | целевая семантика |

Всего 46 050 строк Markdown плюс 10 673 строки сгенерированного HTML.
Жанр здесь означает пару «на какой вопрос отвечает текст» и «кто его
читает».

## 3. Диагноз

Найдено два независимых беспорядка.

### 3.1. Дублирование по жанрам

Правило «папка определяет статус документа» работает внутри `docs/`. У
README пакетов статуса нет, и они собрали в себя все жанры сразу. Пример —
семейства токенов.

| Место | Строк | Что делает |
|---|---|---|
| `design/container.md`, раздел «Семейства токенов» | 47 | семантика и гарантии |
| `packages/nestling.container/README.md`, тот же раздел | 196 | пересказ семантики плюс свой туториал |
| `guide/21-token-families.md` | 280 | туториал по коду примера |

Три текста, три набора сниппетов, три источника расхождения. Так же
устроены пайплайн, секции конфига, `assembleTest` и модель ошибок. README
контейнера занимает 761 строку, README пайплайна 577. В них есть разделы
«Быстрый старт», «Основные понятия» и «Полный пример»: это гайд,
написанный второй раз, не сверенный с примерами и не покрытый
`docs:audit`.

Дублирование по мелочи:

- карта `docs/` и правила ведения написаны трижды: в `CLAUDE.md`, в
  `docs/README.md` и в `docs/design/README.md`;
- таблица пакетов написана трижды: в `README.md`, в `README.ru.md` и в
  `docs/README.md`;
- карта понятий написана дважды: в `guide/README.md` и в
  `appendix-c-coverage.md`.

### 3.2. Гайд смешивает два жанра

Главы 1–18 составляют один рассказ. Они идут по общему примеру, и каждая
опирается на код предыдущей. Главы 19–25 самостоятельны и решают по одной
задаче каждая. Само оглавление это признаёт: «часть 5 читается по
потребности». Но все 25 файлов лежат одним нумерованным списком, и отсюда
следуют неудобства.

1. Читателю предъявляется 25 пунктов, хотя обязательных из них 11.
2. Вставить рецепт в середину нельзя. Номер главы упомянут в оглавлении,
   в приложении В, в README пакетов и в design-доках.
3. Частей пять, а смысловых частей две: «сервис» и «приложение».
4. Глава 12 занимает 471 строку и девять разделов. Она соединяет обе
   половины гайда и перегружена.
5. Приложение Б «Из NestJS» служит входом для читателя с опытом Nest, а
   лежит последним.
6. Приложение В содержит 152 строки путей к файлам примеров. Эти пути
   устаревают при каждом переименовании.

## 4. Целевая структура

### 4.1. Дерево

```
README.md · README.ru.md   краткое описание проекта, принципы, quick start,
                           ссылки; без таблиц пакетов и примеров
docs/
├── README.md              карта и правила ведения; единственное место правил
├── glossary.md            термины
├── conventions.md         имена в коде приложения
├── guarantees.md          «что проверяется до первого запроса», из guide/README
├── from-nestjs.md         вход для читателя с опытом Nest, бывшее приложение Б
│
├── guide/                 путь: две части, сквозная нумерация, читается подряд
│   ├── README.md          «как читать», оглавление, карта понятий
│   ├── 01–11              часть 1, «Сервис»: examples.users-service
│   └── 12–19              часть 2, «Приложение»: app-with-http, split-nats
│
├── recipes/               рецепты: без номеров, имя файла называет задачу
│   ├── README.md
│   ├── webhook.md · cli.md · token-families.md · config-sources.md
│   └── ops.md · standalone.md · extending.md · alternatives.md
│
├── design/                целевое V1, справочник семантики; без изменений
├── decisions/             почему; без изменений
└── history/               заморожено; без изменений

packages/*/README.md       что в пакете сегодня; потолок около 120 строк
scripts/site/              генератор сайта и тема; вывод в .site/, в .gitignore
```

### 4.2. Правило одного жанра

Один факт хранится в одном месте. У места один жанр и один читатель.

| Место | Отвечает на вопрос | Чего там нет |
|---|---|---|
| `design/` | что должно быть и с какими гарантиями | статусов, порядка работ, обучения |
| `guide/` и `recipes/` | как решить задачу на текущем API | семантики вообще, обоснований |
| `packages/*/README.md` | что в пакете сегодня и как называется | туториалов, пересказа семантики |
| `decisions/` | почему так и что отвергли | описания API |

### 4.3. README пакета

Структура: одна фраза «что это», плашка статуса со ссылками на design-док
и главу, установка, таблица экспортов по строке на имя, границы пакета.
Разделов «Быстрый старт», «Основные понятия» и «Полный пример» в нём нет:
эту работу делает гайд, и он сверен с кодом примеров. Потолок около 120
строк сжимает 5 061 строку примерно до 1 500.

## 5. Сайт

### 5.1. Решение: свой генератор

`scripts/preview/build.mjs` занимает 425 строк и уже даёт своё оформление,
тёмную тему, мобильный сайдбар, врезки `:::note`, карточки, подписи файлов
у сниппетов, пейджер и якоря разделов в сайдбаре. Сборка падает, если
состав `guide/README.md` и файлы папки разошлись, поэтому она работает и
как проверка документации.

Принято: генератор остаётся, недостающее дописывается. Он переименуется в
`scripts/site/`, вывод пойдёт в `.site/`, команды станут `yarn docs:build`
и `yarn docs:dev`.

Отвергнут переход на VitePress или Starlight. Он дал бы поиск и мелкие
удобства без написания кода, но потребовал бы переписать врезки и
карточки, потерять инварианты сборки и привести тяжёлую зависимость с
чужой темой. Вопрос стоит вернуть, если понадобятся i18n и версионирование
документации.

### 5.2. Что публикуется

Разделы сайта совпадают с папками, у которых после уборки один жанр. Одно
правило даёт и порядок в репозитории, и карту сайта.

| Раздел сайта | Источник | Публикуется |
|---|---|---|
| `/` | `docs/index.md` | да |
| `/guide/` | `docs/guide/` | да |
| `/recipes/` | `docs/recipes/` | да |
| `/reference/` | `packages/*/README.md` | да |
| `/design/` | `docs/design/` | да, с бейджем «целевое V1» |
| `/roadmap/`, `/deferred/` | `docs/decisions/` | только эти два файла |
| `/glossary/`, `/guarantees/`, `/from-nestjs/`, `/conventions/` | корень `docs/` | да |
| — | `decisions/ideas.md`, `archlog.md`, `history/`, `openspec/` | нет |

Правило отбора: сайт адресован тому, кто пользуется фреймворком, а
репозиторий тому, кто работает внутри него. `ideas.md` занимает 5 079
строк журнала, написанного не для читателя.

Раздел `/reference/` не противоречит отказу от папки `docs/reference/`.
Исходник справочника остаётся в `packages/*/README.md`, рядом с кодом и в
пакете npm. Сайт собирает эти файлы в раздел, не заводя второй копии.

Отсюда следует требование к генератору: ссылка в неопубликованный файл
переписывается в абсолютный URL на GitHub. Плашки design-доков ведут в
`ideas.md`, и на сайте они должны вести в репозиторий, а не в ошибку 404.

Плашки статуса, которых уже требует `docs:audit`, распознаются машинно.
Генератор превращает их в бейджи разделов, и читатель видит рамку
«целевое, не реализованное» на каждой странице `design/`.

### 5.3. Что дописать в генератор

| Что | Зачем |
|---|---|
| разделы вместо одной папки | сейчас источник только `docs/guide/` |
| URL-пути вместо плоских имён | `/guide/01-first-service/` вместо файла в корне |
| ссылки в неопубликованное на GitHub | плашки design-доков перестанут ломаться |
| подсветка кода на сборке через shiki | сейчас в браузере: код без JS не оформлен |
| поиск: индекс JSON на сборке и около 120 строк в `app.js` | публичному сайту нужен поиск |
| стартовая страница отдельным шаблоном | сейчас `index` собирается из README гайда |
| `meta description`, OG, canonical, favicon | ссылки в мессенджерах и в выдаче |
| `sitemap.xml`, `robots.txt`, `404.html` | обязательная гигиена публикации |
| `yarn docs:dev` с локальным сервером | сервер уже есть: `@common/static-server` |

Инвариант «состав README равен файлам папки» распространяется на каждый
раздел. Порядок разделов задаёт короткий конфиг `scripts/site/sections.mjs`,
оглавление внутри раздела остаётся в его README.

### 5.4. Публикация

Файл `.github/workflows/docs.yml` собирает сайт на push в `main` и
деплоит `.site/` в GitHub Pages. На pull request выполняется только
сборка. Генератор падает при рассинхроне оглавления и файлов и при битой
ссылке, поэтому сборка сайта работает как проверка документации в CI.
Каталога `.github` в репозитории сейчас нет, и это будет первый workflow.

`docs:audit` остаётся отдельной командой. Он проверяет то, чего сборка не
видит: свежесть плашек относительно коммитов примеров, неизменность
`history/`, закрытость корня репозитория.

## 6. План волнами

| Волна | Состав |
|---|---|
| 1. Механика | `docs/preview/` переезжает в `scripts/site/`, вывод в `.site/`, из git уходит 10 673 строки HTML. Правила ведения остаются только в `docs/README.md`. Корневые README сокращаются. Переезжают `guarantees.md` и `from-nestjs.md`, удаляется приложение В. |
| 2. Пакеты | Шаблон README и переписывание шести больших: `container`, `pipeline`, `transport.http`, `app`, `ports`, `testing`. |
| 3. Гайд | Разделение на `guide/` из 19 глав в двух частях и `recipes/` из 8 файлов. Глава 12 делится надвое. Оглавление переписывается. |
| 4. Сайт | Разделы, URL-пути, ссылки на GitHub, подсветка на сборке, поиск, стартовая страница, метаданные. |
| 5. Публикация | GitHub Actions и Pages, домен, новые инварианты в `docs:audit`. |

Волны 1–3 не зависят от волны 4: генератор правится один раз, когда
структура папок устоялась. Каждая волна оформляется отдельным change.

Новые инварианты `docs:audit` из волны 5: потолок строк README пакета,
запрет заголовков «Быстрый старт», «Основные понятия» и «Полный пример» в
README пакетов, сверка таблицы экспортов с `index.ts`, проверка того, что
сгенерированный HTML не отслеживается git.

## 7. Отвергнутые варианты

- **Папка `docs/reference/`.** Справочника целиком сейчас нет ни в одном
  месте, и соблазн завести его есть. Отвергнуто: `design/` описывает
  семантику полностью и по подсистемам, а таблица экспортов в README
  пакета отвечает на вопрос «какие есть имена». Четвёртый жанр создал бы
  четвёртое место, где тексты разойдутся.
- **Правка `decisions/` и `history/`.** Это единственные две папки без
  дублирования: append-only и immutable работают. Отдельно стоит обсудить
  только `05-modular-monolith-transcript-raw.md`, где лежит 2 526 строк
  сырого транскрипта при вычитанной версии в той же папке.
- **Генерация таблицы пакетов в корневом README из `package.json`.**
  Механизм ради тридцати строк, которые после волны 1 станут ссылкой.
- **Перевод `design/` и `guide/` на английский.** Не рассматривался в
  рамках уборки.

## 8. Открытые вопросы

1. **Язык сайта.** Документация русская, корневой README английский.
   Предложено: сайт русский целиком, английская страница с описанием
   проекта отдельно и позже.
2. **Домен.** От выбора между `nestling.dev` и `<username>.github.io/nestling`
   зависят `canonical` и базовый путь ссылок.
3. **Публикация `design/`.** Предложено публиковать. Риск принять целевое
   описание за реализованное снимается бейджем раздела.
