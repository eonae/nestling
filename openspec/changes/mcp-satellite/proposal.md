## Why

Операция уже несёт всё, из чего состоит определение MCP-инструмента: имя,
схему входа, схему выхода, список отказов и секцию `doc`. Второго описания
для агента писать не нужно — нужен пакет, который читает объявленное и
отдаёт его по протоколу.

Решение зафиксировано записью
[ideas.md [2026-09-12]](../../../docs/decisions/ideas.md) «Разбор обзоров
d/10 и d/13», пункт 7, по
[d/13 §6.5](../../../docs/history/discussions/13-framework-review-3.md).
Строка 82 [roadmap](../../../docs/decisions/roadmap.md).

Это тот же механизм, что уже дали `@nestlingjs/openapi` и
`@nestlingjs/client`: одна декларация — три потребителя. Для фреймворка на
Node такого предложения сейчас нет ни у кого.

## What Changes

- Новый пакет `@nestlingjs/mcp` — сателлит на публичных примитивах ядра,
  как `@nestlingjs/outbox` и `@nestlingjs/subscriptions`.
- Плагин `mcp({ server, tools, converters, path?, pipeline?, detached? })`
  ставит один endpoint (по умолчанию `POST /mcp`) на уже объявленный
  HTTP-транспорт. Второго порта и второго сервера не появляется.
- Инструмент объявляется значением: `tool(Operation, { name?, description?,
  annotations? })`. Операция даёт имя, схемы и отказы, словарь добавляет то,
  что нужно агенту и чего нет в API.
- Список `tools:` — единственный источник состава. Автоматического
  «все операции становятся инструментами» нет: выбор объявляется, а не
  выводится.
- Схемы переводятся в JSON Schema теми же конвертерами, что у OpenAPI
  (`converters: [zodConverter()]`). Пакет не зависит ни от одного
  валидатора.
- Сессии клиентов держит ресурс: карта «идентификатор сессии — сервер
  протокола», закрывается на DESTROY. Протокол ведёт
  `@modelcontextprotocol/sdk`; пакет даёт ему свою реализацию транспорта
  поверх endpoint'а.
- `Fail` операции попадает к агенту отдельным исходом (`isError` в
  результате вызова инструмента) с кодом и деталями отказа, а не
  исключением протокола.
- Новый рецепт `docs/recipes/mcp.md` на примере `app-with-http`.

Ломающих изменений нет: пакет новый, чужих экспортов не трогает.

### Non-goals

- **Инструменты вне операций.** Второго механизма объявления инструмента
  не заводится. Инструмент, которого нет в HTTP API, — это операция без
  секции `http:`, реализованная `implement`; она получает пайплайн,
  политики и проверку отказов, а `tool(...)` выставляет её агенту.
- **Ресурсы и промпты MCP.** Только `tools` этим change'ем. У ресурсов и
  промптов нет соответствия в декларациях, и им нужна своя форма
  объявления — отдельным решением, не попутно.
- **Server-initiated сообщения.** `GET /mcp` с потоком событий не
  открывается: сервер отвечает на запросы клиента и сам ничего не
  инициирует. Выборка (sampling), нотификации об изменении списка
  инструментов и логирование через протокол — вне объёма.
- **Аутентификация.** Пакет её не делает, как и `@mcteam/mcp`. Заголовки
  запроса доходят до пайплайна endpoint'а обычным путём, и кто вызывает —
  задача слоя приложения (строка 78 roadmap, `auth-layer`).
- **Отдельный процесс со stdio.** Сателлит живёт в приложении, которое
  обслуживает те же операции.
- **Каталог инструментов в `doc:`.** Полей, осмысленных только для MCP, в
  секции `doc` не появляется: она не зависит от формата документации, и
  это её собственное правило.

## Capabilities

### New Capabilities

- `mcp-tool-declarations`: инструмент как производное от операции —
  `tool(Operation, options)`, вывод имени, схем входа и выхода, отказов
  и описания; отображение `Ok`/`Fail` на результат вызова инструмента;
  правила, по которым операция признаётся пригодной.
- `mcp-server-endpoint`: плагин `mcp(...)`, его endpoint на HTTP-транспорте,
  сессии клиентов ресурсом, обработка сообщений протокола и диагностика на
  фазе ASSEMBLE.

### Modified Capabilities

Нет. Секция `doc` не меняется, `endpoint-discovery` не меняется,
`openapi-document` и `typed-http-client` не трогаются.

## Impact

- **Новый пакет** `packages/nestling.mcp` по общему набору конфигов:
  `tsconfig.json`, `tsconfig.build.json`, `eslint.config.js`,
  `jest.config.js`, README с плашкой статуса.
- **Зависимости**: `@modelcontextprotocol/sdk` — первая внешняя
  зависимость рантайма у сателлита; `@nestlingjs/app`,
  `@nestlingjs/operations`, `@nestlingjs/transport.http` — peer.
- **Публичные экспорты ядра**: ожидается, что хватает имеющихся. Если
  сателлиту чего-то не хватает, экспорт добавляется в пакет ядра — так же,
  как это решено для стороннего транспорта в
  `satellite.integration.spec.ts`.
- **Документация**: рецепт `docs/recipes/mcp.md` и строка в
  `docs/recipes/README.md`; строка пакета в таблице `docs/README.md`;
  раздел в `docs/design/operations.md` о третьем потребителе деклараций.
- **Пример**: `examples/app-with-http` подключает плагин и объявляет
  два-три инструмента.
- **Roadmap**: строка 82 переходит в `done`, запись
  `ideas.md [2026-09-12]` получает пометку «РЕАЛИЗОВАНО» по пункту 7.
