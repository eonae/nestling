## MODIFIED Requirements

### Requirement: Фаза 0 поднимает источники до контейнера

`run()` SHALL выполнять фазу 0 BOOTSTRAP отдельным шагом до фазы 1: читалка
конфига создаётся вне контейнера, `init()` каждого привязанного источника
вызывается в порядке зависимостей `needs` (capability
`config-source-needs`), значения читаются в снимок. Готовая читалка SHALL
входить в граф провайдером-значением под приватным DI-токеном ядра.

Асинхронной фабрики читалки SHALL NOT существовать: порядок «источники
раньше секций» SHALL держаться фазой, а не топологией графа.

#### Scenario: Источники подняты до построения графа

- **WHEN** корень привязывает источник с асинхронным `init()`
- **THEN** `init()` завершается до `build()`, и ни один провайдер к этому
  моменту не создан

#### Scenario: Читалка приватна и после переезда

- **WHEN** пользовательский код пытается инжектить читалку или источник
- **THEN** такого экспортируемого DI-токена нет

### Requirement: Снимок фазы 0 — источник значений для секций

Фаза 0 SHALL читать в снимок все ключи реестра объявленных секций.
`read(key)` SHALL отдавать значение из снимка.

Ключи секции, спроецированной для `needs` источника, SHALL попадать в
снимок в момент этой проекции и SHALL NOT перечитываться позже: источник,
поднятый после зависимого, значения координат не меняет.

Ключ, которого в реестре нет — токен семейства `Config(key)` под
unbound-глобом, — SHALL читаться через `get()` уже инициализированных
источников и SHALL попадать в снимок: состав таких токенов семейства известен только
внутри `build()`, а `get()` синхронен по контракту источника.

Проекция секции SHALL считаться из снимка. Валидация полей SHALL оставаться
на фазе 1, как описывает capability `config-sections`.

#### Scenario: Секция читается из снимка

- **WHEN** секция проецируется на фазе 1
- **THEN** значения берутся из снимка фазы 0, и ни один источник не
  опрашивается повторно

#### Scenario: Координаты источника фиксируются проекцией

- **WHEN** источник с `needs` поднят, а привязка, поднятая после него,
  тоже покрывает ключи его секции
- **THEN** в снимке остаются значения, по которым источник поднимался

#### Scenario: Значение прочитано один раз на сборку

- **WHEN** одну и ту же секцию инжектят два провайдера
- **THEN** оба видят значения снимка, снятого на фазе 0

#### Scenario: Ключ семейства вне реестра

- **WHEN** провайдер зависит от `Config('ORDERS_GRPC_ADDRESS')`, а секции с
  таким ключом не объявлено
- **THEN** значение читается через `get()` инициализированных источников и
  запоминается в снимке
