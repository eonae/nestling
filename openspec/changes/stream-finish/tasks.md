## 1. Обёртка завершения `withFinish`

- [x] 1.1 `packages/nestling.app/src/pipeline/core/io/bind-stream.ts`:
  `withFinish` переписан с асинхронного генератора на объект-итератор с
  `[Symbol.asyncIterator]`, `next`, `return` и `throw`. Итератор источника
  берётся лениво, в первом `next()`; состояние — «итератор взят» и
  «финализация выполнена»
- [x] 1.2 Финализация вызывается ровно один раз из каждого завершающего
  пути: источник кончился, источник бросил, `return()`, `throw()`.
  Повторный `return()` отдаёт `{ done: true }` и `onSettled` не зовёт
- [x] 1.3 `return()` до первого `next()` вызывает `onSettled` и закрывает
  итератор источника, не читая его. `throw()` до первого `next()`
  финализирует с этой ошибкой и бросает то, что вернул `onSettled`
- [x] 1.4 JSDoc `withFinish`: сказано, что обёртка не генератор и почему —
  тело генератора не выполняется до первого `next()`; тот же приём
  применён в `Topic.subscribe`
- [x] 1.5 Рантайм-тесты в `src/pipeline/core/stream.runtime.spec.ts`:
  `.finally` с исходом `completed` при `return()` до первого элемента и
  `itemsOut === 0`; исход `disconnected` при взведённом
  `ClientDisconnectedError`; исход `aborted` при ином взведении; двойной
  `return()` даёт один вызов `.finally`; `throw()` до первого элемента
  даёт `failed` и бросает `MidStreamFailure`
- [x] 1.6 Прогнать существующие спеки потокового пути: поток дотёк,
  закрытие на середине, ошибка посреди потока, потребление потока
  `.ok`-юнитом — поведение не изменилось

## 2. Закрытие доводится до источника

- [x] 2.1 `bindOutputStream` возвращает объект-итератор поверх собранной
  цепочки. Пока `next()` не вызывался, его `return()` и `throw()`
  закрывают исходный `AsyncIterable` хендлера через
  `source[Symbol.asyncIterator]().return?.()`
- [x] 2.2 После первого `next()` закрытие идёт обычным путём — через
  цепочку; источник закрывается один раз, повторного `return()` на нём
  нет
- [x] 2.3 JSDoc `bindOutputStream`: неначатый генератор ресурсов не
  держит, поэтому закрывать нужно только источник, и делает это обёртка
  формы
- [x] 2.4 Рантайм-тесты в `bind-stream.spec.ts` или в
  `stream.runtime.spec.ts`: хендлер вернул `topic.subscribe(signal)`,
  ответ закрыт до первого `next()` — `topic.subscribers` стал нулём; то
  же с объявленной item-цепочкой (`throttle`); после чтения одного
  элемента и `return()` источник закрыт ровно один раз

- [x] 3.1 `packages/nestling.operations/src/streams/abort.ts`: ветка

  выходом
- [x] 3.2 JSDoc операции сверен с поведением: источник закрывается в обеих
  ветках
- [x] 3.3 Тесты в `src/streams/combinators.spec.ts` (или в спеке рядом с
  `abort.ts`): при взведённом до вызова сигнале источник закрыт, а
  итерация пуста; при взведении во время итерации поведение прежнее; без
  сигнала обёртка остаётся прозрачной
- [x] 3.4 README `@nestling/operations`, раздел «Итерация под сигналом»:
  фраза про закрытие источника верна для обеих веток
